## 自定义域名方案（说明，未实施）

推荐复用现有 M1 公开服务，使用用户拥有的域名与账户管理的 Cloudflare Tunnel。

1. 用户提供已注册且可管理 DNS 的域名；若尚未拥有，先选定并自行完成购买。域名注册商可以与 DNS 服务商不同。
2. 将域名加入 Cloudflare，核对原 DNS 记录，再在注册商设置 Cloudflare 分配的 nameservers。已有网站与邮件记录必须保留。域名在 Cloudflare Registrar 购买时默认已使用其 DNS。
3. 在 Cloudflare 控制台创建账户管理的持久隧道，在 M1 安装对应连接配置并作为常驻服务运行。凭证本地安全保存，不写到仓库或报告。
4. 添加 Published application route，将选定公开主机名（示例 `f1.example.com`，并非已注册候选）指向 M1 的 `http://127.0.0.1:3000`。后台继续采用既有私网入口。
5. 验证 DNS、HTTPS、首页、真实 feed/详情、静态资源及公开 Admin 拒绝边界；同步微信 `/f1` 巡检的公开 URL，核对重启后仍使用同一域名。切换前保留当前隧道与配置，成功后再停旧入口；失败时保留可用旧入口。

固定域名解决访问地址变化；M1、电源、网络与隧道仍决定源站可用性。此方案无需为源站获取公网 IP 或做路由器端口映射。

官方依据（2026-09-12 查阅）：[Tunnel 创建、路由与 Quick Tunnel 限制](https://developers.cloudflare.com/tunnel/get-started/)、[域名接入及 nameservers 设置](https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/)、[Tunnel 出站连接与公网 IP 说明](https://developers.cloudflare.com/tunnel/)。
