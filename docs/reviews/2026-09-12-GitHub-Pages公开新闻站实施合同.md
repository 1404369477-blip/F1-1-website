## 实施顺序与分工

1. 主控固定合同、正式任务、源码/运行基线和写入边界。前端执行Agent设计公开UI与静态构建适配；同步执行Agent调查M1验证reader与投影身份、导出和持续同步；独立审查Agent只审方案/候选/实际收据，不代写实现。
2. 在隔离目录构建，静态产物只含公开HTML/CSS/JS/必要媒体和公开DTO。禁止包含.env、认证材料、签名私钥、review DB、审计日志、管理页面、后台API、私网地址或源码调试映射。GitHub只接收精确允许文件，不上传完整M1运行目录。
3. 固定一次完整投影generation再导出，过程中发生变更/损坏必须拒绝混合数据；空投影合法时要能发布空站，不能误保留已撤回内容。新部署完整替换公开集合，删除内容必须在成功更新后从当前网站消失。
4. 优先采用固定构建一次的静态UI与后续小体积数据同步，避免每次采集都在M1重建完整Next应用。机器接口见下节。全量重建或新依赖需先说明实际必要性。
5. 部署前通过源码/产物独审与本地静态HTTP验证，再设置Pages并提交精确产物。不同generation串行发布，失败保留最后成功站点；网络结果不明时先查远端ref和部署状态，再决定是否重试，禁止盲目重复发布或覆盖更新版本。
6. M1自动同步只检测已激活公开投影变化，不更改业务调度与发布门。自然一次更新、幂等无变化、断网/失败/恢复、撤回/空站需有对应真实或隔离反例证据。M1不能访问GitHub或所需权限不足时保留真实阻塞，不复制广权限凭证作为临时捷径。
7. 实际Pages首页、列表、详情、资源、404及公开Admin边界验证通过后同步现有微信/f1公开URL；原隧道保留为回退，暂不停止。归档固定产物、生产收据、未验项和接手说明。

## 静态数据接口与权限隔离

- Pages `basePath=/f1plus1`；详情采用 `/f1plus1/stories/?publicId=...` 的真实静态页面，刷新返回200；不借404伪装客户端路由。
- `_public/current.json` 使用 `public-static-pointer-v1`，包含 bundleId（index SHA-256）、generatedAt（UTC）、indexPath 与 indexSha256；index 固定在 `_public/generations/<bundleId>/index.json`。
- index 使用 `public-static-index-v1`，按原公开 API 的 pathname 与排序后 URLSearchParams 绑定 `{status, contentType, path, sha256}`，响应体为原 reader 的封闭 v1/v2/Problem DTO。响应路径固定 `responses/<bodySHA>.json`；客户端校验 pointer/index/body身份与路径，禁止任意外部响应地址。
- 导出固定 generation，覆盖所有公开记录详情（含聚类隐藏成员）与 all/四分类、all/实际来源的12条分页链。版本回退限同一 bundle 内的既有 v2 406 MEDIA_VERSION_UNSUPPORTED 或503 PUBLIC_READ_INTEGRITY_FAILED，其他失败不得静默回退。
- generation变更清理旧cursor及展开缓存；普通网络失败保留已加载内容供重试。缺少合法active pointer必须失败，只有经验证的零活跃集合才允许发布空站。
- 每轮完整替换 `_public`，当前部署移除已撤回记录的响应文件；浏览器已加载的旧内容无法主动擦除，不承诺撤回即时生效。同步串行、幂等，远端结果不明先对账；M1断网时Pages仍展示最后成功部署。
- GitHub deploy key具有新静态仓库范围的写权限；该仓库禁止业务源码、秘密及私有数据；只允许独审冻结的 `.github/workflows/` 发布工作流，公开 `site/` 目录内禁止 workflow。私钥只留M1专用0700目录内0600文件，known_hosts独立固定，现有SSH配置及业务凭据不变。
