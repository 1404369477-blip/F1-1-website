## 回退与失败处理

- 尚未隔离锁：恢复原 backup 调度器加载状态，保留所有新证据；不触碰生产数据。
- 已隔离锁：保留事故目录作为证据，不把失效锁搬回去阻断运行；若需回到原调度状态，仅恢复原 plist 的加载状态。锁隔离属于事故处置，不能靠复活无效锁回退。
- 锁 CLI 返回失败不等于现场未变：rename 后 fsync 或 receipt 写入仍可能失败，错误输出可能没有事故目录名。先检查备份根下此次新建的 `lock-incident-*` 及原锁身份，禁止依据 `ok:false` 直接重试；执行前还要验证备份根所有父目录的所有者与写权限，工具自身未覆盖父目录信任链。
- 新 snapshot / mirror / drill 失败：保留已加密包与失败收据，停止该次流程，不登记、不更新 fence；清理仅限已核对身份的本次隔离明文目录。
