# X 页面候选到自动提炼、审批、发布的最小后继设计

状态：2026-09-06 设计分析，原 `BRIDGE_NOT_IMPLEMENTED` 已由 09-07 本地合成 clone 导入切片接续；生产 bridge/schema/authority/自动链仍未完成。当前实现与接续以 [09-07 交接](2026-09-07-X页面导入本地切片与生产接续.md) 为准。下文原始限制解释为何需要后继，不代表生产部署状态。用户已确认 M1 已登录页面读取和网站自动审批发布；本文定位实现所需合同差异，不重新要求已授予的业务授权。

## 结论

**当前不能仅新增 `x-page/bridge.ts` 经既有合法接口完成落库。** 候选外键、来源类型、采集policy、公开DTO均封闭为RSS；旧X手动收件箱不允许补候选绑定。必须做一次有界的schema/authority successor，随后复用现有审核、发布、投递和签名机制。不能借RSS source ID/feed URL、旧xmanual提交操作、手工SQL或伪造审批事实接线。

已实现的 `x-page/normalize.ts` 是捕获后的纯函数：27个固定账号、status/author/time校验、完整纯文本、关系、媒体引用、去重identity和sourceVersionHash。来源enabled/identityStatus仍须可信registry bridge提供；该函数不证明浏览器接入或授予写入权。

**现行链必须接替，不能另造平行自动链。** 统筹/交接独立审查已在M1找到运行根 `.ac5cc2/runtime/scheduled-refine.ts` 与 `scheduled-review-publish.ts`；它们在签名automatic flags为false时，经 `admin_http` / manual gate承载自动动作。本子任务未再次远端读取脚本，此事实来自该独立现场审查；`docs/当前生产状态与执行待办.md:15,97–99` 也记有sidecar和refiner部署身份。后继实施必须先钉这两个实际脚本、wrapper/调度和导入release的hash，列出它们调用的model/review/publish/snapshot入口，在同一切换窗口由合法automatic owner/capability后继替换。不能只在app新增worker而保留旧sidecar继续自动处理；切换验收须机械证明旧路径不再触发，避免重复模型调用、抢同candidate、重复审批/投影或继续以manual身份记自动行为。迁移前保留其last-good、审计和回退证据，回退需明确哪些自动能力停止，不伪称旧manual gate等同新automatic授权。

页面规范化的媒体版本身份只对官方文档已定义的现代 `pbs.twimg.com/media/{id}?format=...&name=thumb|small|medium|large` 忽略尺寸name参数；原始可见URL完整保留在mediaReferences。format、资源路径、未知参数/尺寸、缩略图及video URL仍参与版本身份，规则不产生下载或公开使用权限。[X官方Photo Media URL Formatting](https://docs.x.com/x-api/enterprise-gnip-2.0/fundamentals/data-dictionary)。

## 推荐的最小数据变更

1. **沿用canonical source ID，新增明确的 `source_kind=x_page / collection_mode=browser_visible_dom` 分支。** 以固定CSV hash和27项身份manifest驱动迁移；对选定27个当前registry行保留source_id，生成后继identity hash、revision/epoch及迁移审计证据。原 `x_manual_source_registry` 59行、提交和历史审计保持原字节，32个未选X行继续禁用；Sky现有RSS使用独立RSS source ID。当前canonical registry的类型约束需受控重建，其他引用表和历史外键不得丢失。
2. **扩展 `source` 允许相同27个X source ID，RSS原映射保持严格。** 新增/明确类型分支，X的feed_url必须NULL，不能填x.com主页冒充feed；RSS采集器只读取rss分支。X source的enabled/stop_epoch与canonical registry在同一授权source操作中同步，不用本地PagePost布尔直接驱动。
3. **新增 `x_page_source_config_v1`。** 最少绑定source_id/revision、canonical handle/page URL、selection hash、正常低频串行参数、adapter/runtime identity、authorization receipt与有效期、source policy、rights/media policy。它只证明已核实的配置，不从normalize成功推导版权/内容安全通过。
4. **新增不可变 `x_page_candidate_capture_v1`。** 每个 `(candidate_id, source_revision)` 绑定status_id、原author、sourceVersionHash、完整text/relations/mediaReferences、capture evidence hash、observedAt、import operation。约束同一status_id跨版本不能改作者/candidate；旧内容版本重见不回滚新版本。保持一份完整原文供提炼读取，不把16KiB预览字段当完整输入。
5. candidate继续复用 `pending_review_candidate`，candidate_id使用独立x-page命名；external_id=status_id，dedupe_key=已定义identity，source_payload_hash=sourceVersionHash。source_revision代表内容修订，不能混用source registry/config revision。title可使用明确的原帖标签作为待处理预览，中文编辑标题只来自后续已验证提炼结果；excerpt若作为有限预览必须显式标注并永不作为X完整提炼输入。

以上是migration设计，不是在运行库中执行的SQL。migration编号/最终schema hash由统筹与当前其他迁移协调，不能预占或覆盖已有0011/0012。需要clone演练保留RSS行、xmanual历史、candidate/review/publication/outbox和外键，随后独立审查。

现有 `automaticReviewSecurityReason()` 主要验证中文机器稿和不可见控制字符，不证明X帖子完整性、F1相关性、版权或媒体许可。自动发布能否准入由明确policy事实决定，不能用“含中文且无控制字符”替代全部来源要求。

首批媒体可保持不公开并保留完整references，仅当现行产品/媒体授权允许这种文本先行出口时采用；不得无授权把pbs/video链接写入RSS media allowlist。内容类别复用公开合同已有 `race_news / driver_social / legends_history / paddock_fun`，由内容规则判断，不能把所有X帖子固定标为race_news或driver_social。

## 必需的authority与运行接线

- 保留已有automatic_reviewer/automatic_publisher、review/publish policy、fence/epoch/CAS/budget语义；扩源前加入来源分支及实际调用入口校验。collect的本地导入权限只可写candidate/capture，不能获得review/publish或projection permit。
- 新owner必须进入gateway TS枚举、DB owner CHECK、owner-supervisor handoff、policy表及authorizer实体方法；旧policy原字节不篡改，新增policy由successor migration固定。若复用通用owner则先正式修改其来源语义，不能继续冒称rss或official API。
- release manifest、capability验证、runtime closure和schema opener采用同一后继合同。旧full_v10保持原能力解释；不能关掉auto-zero检查后声称后继capability已成立。
- 浏览器抓取仍需受支持的M1连接，当前没有可工作的无人值守producer。导入DB权限不代表可以绕过浏览器工具或读取cookie；缺capture evidence时不得生成真实candidate成功。

## 最少验收与交付边界

1. clone迁移前后RSS五源、xmanual59历史行、审核/发布/outbox记录保持；source/capture外键、旧签名reader和回退closure验证。
2. 合成输入测试覆盖created/duplicate/edited/旧版本重放/同status异作者/source禁用/身份过期/epoch漂移；拒绝无candidate、capture或成功审计残留。
3. 完整文本超过16KiB的实际形状能进入模型输入，截断/缺原帖时间不能靠预览字段通过；模型失败/预算耗尽/手工拒绝/旧bundle均不发布。
4. importer尝试审批发布或写projection被拒绝；自动review/publish必须使用对应owner和绑定。捕获授权、导入、提炼、审批、发布各自回执可追溯。
5. 三源真实M1捕获至少一条新增完成全链，重读不重复发布；失败停止和下一自然周期验证后再扩27。所有synthetic测试不计为浏览器或生产证据。

本轮只读审查并输出设计，没有创建 `bridge.ts`、修改共享schema/gateway、执行迁移或写生产。最先可实施的工作是有界schema/authority successor的本地clone实验；真实capture依赖仍是M1受支持浏览器接入。
