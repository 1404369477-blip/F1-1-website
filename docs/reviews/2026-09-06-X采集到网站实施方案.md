## 页面DTO与纯解析边界

先设计独立于生产schema的页面DTO。采集层只输出实际可见DOM；纯解析器只处理输入DTO，无浏览器、数据库、网络或发布权限。未获本轮真实样本前，不冻结页面选择器，不迁移生产表。

| 字段 | 来源和约束 |
|---|---|
| `schemaVersion` | 候选 `x-visible-post-v1`，与observation版本固定 |
| `observedAt / pageUrl / requestedHandle` | 本次读取时间、实际页面URL、已选账号，不使用历史值补足 |
| `browserEvidence` | 工具返回family/instance；host须有可验证接入证据，缺失显式unknown |
| `statusUrl / statusId` | 可见status链接；精确 `https://x.com/{handle}/status/{digits}` 形状，剥离显示参数 |
| `authorHandle / authorDisplayName` | 对应该帖的可见作者；忽略大小写对齐allowlist，保留原显示文本 |
| `publishedAt` | 帖子时间元素绝对时间；缺失或未来异常拒绝准入 |
| `text / textComplete` | 可见正文与可确认完整性；截断/Show more未处理/空正文不自动发布 |
| `kind / relatedStatusUrls` | original/reply/repost/quote/unknown，严格来自可见关系 |
| `media` | 页面显示的资源URL/alt/type和来源关系；使用仍受现行授权/媒体策略约束 |
| `evidenceSha256` | DTO固定canonical编码hash，提供可追溯性，不冒充独立签名 |

解析器输出accepted DTO或明确reason：`PAGE_NOT_READ`、`LOGIN_REQUIRED`、`CHALLENGE`、`RATE_LIMITED`、`ACCOUNT_MISMATCH`、`STATUS_ID_INVALID`、`ABSOLUTE_TIME_MISSING`、`TEXT_INCOMPLETE`、`RELATION_AMBIGUOUS`。连接状态和页面业务状态分别记录。

去重以status ID及原始作者身份建立稳定键。相同键/内容重读不新增候选；内容变化建立source revision并重新初审，不直接覆盖已发布内容。schema桥接复用现有registry、candidate、review/publish gateway、outbox和签名投影，准确接口待真实DTO及现行schema核验后固定。
