# F1+1 第一版快速上线部署方案 v0.1

## 目标

把已经通过最小 production 门的公开只读候选尽快放到公网，以真实日志和用户反馈驱动后续迭代。第一版只承载公开 synthetic 信息流与详情，不接真实采集、AI、飞书 Base、Admin 页面或自动发布。

## 当前已选拓扑

用户于 2026-08-11 明确选择固定 M1 MacBook 作为第一版临时 beta 主机。长期架构仍保留独立 public-host；本次选择用于尽快取得真实公网运行数据，不修改 Admin 长期隔离目标。

```text
公网访客
  → 待确定的 HTTPS 公网隧道
    → 127.0.0.1:3000 F1+1 production allowlist proxy
      → 127.0.0.1:3001 Next production
        → M1 本机 synthetic SQLite
```

production `serve.ts` 在 `public-multimedia-synthetic` profile 下只放行 GET/HEAD：

- `/`
- `/stories/*`
- `/api/public/*`
- `/api/health`
- `/_next/static/*`
- 页面实际需要的同源静态资源

明确拒绝：

- `/api/admin/*`
- `/admin/*`
- 其他未列入公开合同的路径

其他方法和路径也统一返回 404。应用继续只监听 loopback，不直接监听公网网卡。TLS、公网连接与访问日志由待选隧道承担。

## 两种落地方式

### 方案 A：独立云服务器 / VPS

适合正式公开 beta，也是当前推荐方案。

要求：

- 持久 Linux 主机，arm64 或 x64 均可；Node 24 可用。
- 至少 2 vCPU、2 GB RAM、20 GB 可用磁盘；第一版 synthetic 流量较低时足够。
- 公网 IP 或可绑定域名。
- systemd 或等效守护进程。
- Caddy 或 Nginx 负责 HTTPS 与路径 allowlist。
- 数据、receipt、环境变量和日志目录不直接暴露在 Web 根目录。

优点：与 Admin MacBook 和家庭网络分离，24 小时运行更稳定，后续接监控和回滚更清晰。

### 方案 B：固定 M1 MacBook 临时 beta（本轮已选）

只适合用户明确接受的短期公开验证。

要求：

- 关闭自动睡眠，保持供电，使用专用用户与 FileVault。
- 用户级 launchd 守护 Next production，并每 12 小时刷新 24 小时有效的 legacy receipts。
- 应用内 production allowlist + 受控公网隧道；不做路由器端口转发或 UPnP 暴露。
- Wi-Fi 重连、断电、系统更新和隧道中断均要有自动恢复。

主要风险：Wi-Fi、家庭/办公网络、设备睡眠和隧道是单点故障；如果同机还承担 Admin，公网与后台故障域会耦合。该方案可快速验证产品，不适合作为长期正式拓扑。

## 发布顺序

1. 当前 Mac 在 `codex/first-public-release` 提交并推送精确 release 节点。
2. M1 只在非 iCloud 本地目录拉取该 commit，不复制当前脏工作区。
3. 安装精确 Node `24.18.0`，执行 `npm ci`。
4. 执行 `npm run release:bootstrap`：从 `deployment/bootstrap/legacy` 的固定 synthetic 资产建立 0600 本地副本、生成 fresh receipts，并建立/校验 24 条公开多媒体 SQLite。
5. 执行一次 production build，再执行 `npm run release:install-macos-agents` 生成应用与 12 小时 receipt refresh 两个用户级 LaunchAgent。
6. 由操作员显式 `launchctl bootstrap` 两个 plist；应用仅监听 `127.0.0.1:3000/3001`。
7. 本地只检查 `/api/health`、`/`、一个详情和 Admin 404；不跑全量测试。
8. 确定公网隧道与域名后，只把隧道 origin 指向 `http://127.0.0.1:3000`；禁止公网 Admin 旁路。
9. 公网重复同一组最小检查，并记录部署 commit、build hash、隧道身份、时间和回退点。

完整命令入口见 [`deployment/macos/README.md`](../../deployment/macos/README.md)。

## 最小回退

- 保留上一个 release commit 与 build 目录。
- 新版本 health、首页或详情出现 5xx 时，把反向代理切回上一个 loopback 实例或重新启动上一个 commit。
- SQLite 第一版是 synthetic 只读数据；部署期间禁止把运行 WAL/SHM 当备份。需要替换数据时先停服务并使用完整、校验过的 DB 集合。

## 上线后优先观察

- `/api/health` 非 200 和 `reasonCode`。
- 首页、feed、详情、404 的状态码与 p95 响应时间。
- Next 进程退出、内存增长、磁盘占用。
- 反向代理对 `/api/admin/*`、`/admin/*` 的拒绝是否生效。
- receipt refresh LaunchAgent 最近一次成功时间；超过 18 小时立即告警，24 小时前人工刷新或停站。
- 前端真实设备上的 hydration、滚动、筛选、分页、主题与详情焦点问题。

任何问题都绑定 deployment commit、route、时间、request id 和用户操作再修，避免脱离真实现场扩大测试。
