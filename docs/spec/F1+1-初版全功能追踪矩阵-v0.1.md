# F1+1 初版全功能追踪矩阵 v0.1

## 1. 使用规则

本矩阵是初版功能完整性的唯一产品索引。它不替代 accepted ADR、领域 schema、API schema 或冻结设计；遇到冲突时按 `docs/spec.md` → accepted ADR/机器合同 → 本矩阵 → 实现文件的顺序处理，并把冲突回产品部修订。

每个功能只能使用以下一个对外状态：

- `complete`：存在正式可达的本地用户出口，并有独立测试或安全收据；组件预留、静态分支、测试注入、开发自测或文档完成均不够。
- `user-gated`：唯一缺口是明确的用户授权、依赖确认或视觉确认；未经确认不得实施或调用。
- `P1-blocker`：已确认属于初版，但实现、数据出口、正式复验或恢复链尚未闭合；禁止写成 `NOT_RUN`、占位或完成。

状态只描述当前证据，不删除功能。真实外部请求、自动发布、部署、付费、生产权限和跨网络 Admin 始终使用独立用户门禁。

三态转移固定为：任一必需授权轴未回答时为 `user-gated`；全部必需轴获批后，若实现或独立证据尚未闭合，立即转为 `P1-blocker`；正式用户出口与独立证据均存在才转为 `complete`。用户拒绝或尚未回答时，对应功能不能满足 MVP 验收。

当前机械计数：`complete=17`、`user-gated=20`、`P1-blocker=13`，合计 50 个 Function ID。`COLLECT-MOCK-002`、`CONTENT-PROCESS-003`、`SUMMARY-MOCK-004` 的 `complete` 只覆盖固定 Node24、本地 synthetic operator 与 V-OP/contract 收据；不覆盖 Admin 可见性、真实 provider/Base/AI、非 loopback 外部 I/O 或生产。

## 8. 完整性机械规则

- 开发、数据、设计、测试、安全任务都必须引用 Function ID；没有 Function ID 的新增功能先回产品部登记。
- `complete` 行必须同时有正式可达用户出口与独立证据；报告只写代码存在、静态分支、组件预留、人工注入、`NOT_RUN`、TODO 或占位时，状态保持 `P1-blocker`。
- `user-gated` 行必须指出唯一用户问题和确认后的最小范围；批准一个轴不会自动批准另一个轴。
- 任一必需轴未答时保持 `user-gated`；全部必需轴获批但实现或独立证据未闭合时改为 `P1-blocker`；只有正式出口和独立证据齐备才改为 `complete`。
- 一个功能跨数据/API/UI 时，三者必须绑定同一版本候选和 hash 后才能从 `P1-blocker` 变为 `complete`。
- 真实外部能力始终默认关闭；本地 synthetic 功能的完成不得被外推为生产或第三方权利放行。
