# F1+1 存量优先确定性安全初审与条件自动发布实施合同 v0.1

## 1. 单一主链

```text
existing allowlisted source
  → current source revision/full payload hash
  → current Chinese draft + latest immutable Bundle
  → deterministic initial review
  → immutable approved Decision + unique queued Publication
  → system-auto-publish-v1 CAS (disabled by default)
  → one full snapshot + one projection outbox
  → existing single sender / same-delivery reconcile
  → signed active snapshot / last-known-good public reader
```

这条系统路径是现有人工发布路径的窄 successor。人工按钮和 API 仍使用现行 session/Origin/CSRF/Passkey 契约。`publish|correct|withdraw` 与 `start_backlog|enter_live|pause|resume_backlog|resume_live|stop` 全部自动发布 phase control 都必须取得 fresh WebAuthn，并且只能由 manifest 唯一 operator 通过真实 HTTP POST 发起。系统 actor 没有 HTTP 入口，不具有或伪造 fresh receipt 的能力，也不能改变 phase 或 stop fence。

本合同尚未实现。现行 M1 仍使用 SQLite `user_version=4`，自动初审通过只到 `approved/queued`，公开投影仍由人工 fresh WebAuthn 发布产生。

## 2. 唯一控制数据

仅追加 migration `0005_auto_publish_policy.sql`，将 `PRAGMA user_version` 从 `4` 升到 `5`。旧业务表、Decision、Publication、Projection、snapshot 和 outbox 不改名、不复制。唯一新持久表只有一行 canonical policy：

```text
auto_publish_policy
  policy_id           = "auto-publish" (PRIMARY KEY, singleton CHECK)
  phase               = disabled | backlog | live | paused
  policy_epoch        = positive integer
  backlog_cutoff_at   = UTC timestamp | null
  max_batch           = integer 1..20, initial value 20
  updated_at          = UTC timestamp
```

- 新库或迁移后默认 `phase=disabled`，`policy_epoch=1`，`backlog_cutoff_at=null`，`max_batch=20`。单纯存在 v5 表不会启用任何系统发布。
- 无行、多行、unknown phase、epoch 非正整数、cutoff 时区不明、batch 超范围或 schema ≠精确 v5 时，review/publish/collector guard 全部 fail closed。
- 安全规则、allowlist、`max_batch`、新 backlog campaign 或其他会改变准入结果的变更必须先 `paused`，随后单调增加 `policy_epoch`。纯暂停/恢复允许保留 epoch，但恢复前要重验所有门。
- 每次 phase/policy 变更和每个自动批次写入现有 `audit_event`。phase/policy/stop 控制的 actor 只能是 manifest operator；自动发布批次 actor 只能是 `system-auto-publish-v1`。两者不能互换，不新建第二审计主账。

### 2.1 Decision/epoch 与既有操作审计的可实现绑定

- 现有 `review_decision` 没有 `policy_epoch`。v5 不增 Decision 列，不新建 Decision-policy 绑定表。发布事务直接 CAS singleton 的当前 `policy_epoch`，重跑当前安全闭集，再将 epoch 写入 operation/audit payload；Decision 只通过已有 `decision_id + bundle_id + approved_bundle_hash` 绑定 Bundle。
- 现有 `admin_operation` 只允许 `revision|approve|reject|publish`，并强制 `POST/path/http_status`；现行 `OperationReceiptSchema` 也强制 `httpStatus`。同时，现行自动初审每 60 秒由 runtime 直接调用 repository，actor=`system-auto-review-v1`，却复用上述 HTTP-shaped 写法。v5 必须承认该历史事实，不能把旧行统一宣称为真实 HTTP。

#### 2.1.1 新写 operation 的穷举 closed union

`operation_type` 只允许 `revision|approve|reject|publish|correct|withdraw|auto_publish_control|auto_publish_batch`；`operation_channel` 只允许 `http_post|internal_auto_review|internal_auto_publish|legacy_http_shaped_unknown`。v5 后的新写只允许下表前四个非 legacy 行；`legacy_http_shaped_unknown` 仅由 migration 生成：

| operation type | channel | operation actor | fresh | receipt/result |
| --- | --- | --- | --- | --- |
| `revision|approve|reject`（人工） | `http_post` | 当前 deployment manifest 的唯一 `operatorRef`，且来自已授权 session | 必须为 null；沿用当前 session/Origin/CSRF | closed HTTP OperationReceipt |
| `publish|correct|withdraw|auto_publish_control` | `http_post` | 当前 deployment manifest 的唯一 `operatorRef`，且来自已授权 session | 必须为已验证且未消费的 persistent fresh binding | closed HTTP OperationReceipt |
| `revision|approve|reject`（自动初审） | `internal_auto_review` | 精确 `system-auto-review-v1` | 全部 null | closed InternalOperationResult |
| `auto_publish_batch` | `internal_auto_publish` | 精确 `system-auto-publish-v1` | 全部 null | closed InternalOperationResult |
| pre-v5 `revision|approve|reject|publish` | `legacy_http_shaped_unknown` | 从该 operation 匹配计数精确为 1 的 primary AuditEvent 原值读取；其他计数即迁移失败 | null/unknown，不补造 | 原 HTTP-shaped 字段原值只作历史形状，不证明 channel |

任何表外组合都在 repository closed gate 和数据库 CHECK/trigger 两层写前拒绝。特别禁止：`auto_publish_control + internal_*`、`auto_publish_batch + http_post`、system actor + `http_post`、operator + internal channel、`system-auto-review-v1 + internal_auto_publish`、`system-auto-publish-v1 + internal_auto_review`、以及 internal `publish|correct|withdraw`。两个 system actor 都是 server-owned literal，repository 不再接受 caller-supplied `actorRef`、环境变量或请求覆盖。

HTTP operation 的 path 必须由 operation type 精确匹配：revision=`/api/admin/reviews/{candidateId}/revision`，approve=`/api/admin/reviews/{candidateId}/approve`，reject=`/api/admin/reviews/{candidateId}/reject`；publish 的单项形态=`/api/admin/publications/{publicId}/publish`，现行批量 release 形态=`/api/admin/reviews/release`，二者仍只落 `operation_type=publish`；correct=`/api/admin/publications/{publicId}/correct`，withdraw=`/api/admin/publications/{publicId}/withdraw`；phase control 唯一路由为 `/api/admin/auto-publish/control`。这些 mutation 的 method 全部精确为 `POST`，path 不能只靠 `LIKE '/api/admin/%'` 放行。

每个 v5 operation row 都必须有非空 `operation_actor_ref`，并在 operation 自身与 HTTP/internal receipt/result 中逐字相等；actor 不只存在于路由参数或日志。发生领域 mutation 的 completed operation 必须在同一事务写 primary AuditEvent，actor 同样相等，映射固定为 revision=`review_revision_saved`、approve=`review_approved`、reject=`review_rejected`、publish=`publication_published`、correct=`publication_corrected`、withdraw=`publication_withdrawn`、control=`auto_publish_phase_changed`；batch 的 `succeeded|no_work` 映射 `auto_publish_batch_completed`，`failed|blocked` 映射 `auto_publish_batch_failed`。失败 HTTP/auto-review operation 写 immutable failed/blocked operation result且业务增量为 0，不伪造成功领域 event。

`auto_publish_control` 的 operation row、request/result/audit 必须另带 closed `controlAction=start_backlog|enter_live|pause|resume_backlog|resume_live|stop`；其他 operation 的 `controlAction` 必须为 null。任一 phase 前后值、cutoff/epoch/stop-fence 变化必须与该 action 的状态机边精确一致。该 action 同时进入 request hash、resource hash 与 fresh binding，不能把一次已授权 control 换用于另一条 phase 边。

| controlAction | 唯一合法状态变化 |
| --- | --- |
| `start_backlog` | `disabled→backlog`；按 §4 原子建立本 epoch 不可变 cutoff |
| `enter_live` | `backlog→live`；必须满足 cutoff 未决=0 与 outbox succeeded 门 |
| `pause` | `disabled|backlog|live→paused`；不改 source stop fence |
| `resume_backlog` | `paused→backlog`；已有 cutoff 沿用；cutoff 为 null 时按 start_backlog 同一原子门首次建立；不清除 source stop fence |
| `resume_live` | `paused→live`；必须已有 cutoff 且满足与 enter_live 相同的全部门；不清除 source stop fence |
| `stop` | `disabled|backlog|live|paused→paused`；目标 source stop fence 必须单调前进，已 paused 时也要写同一 fresh operation/audit |

表外前后态、resume 时暗中清除 stop fence、pause 时改 stop fence或 stop 时不前进目标 fence均写前拒绝。

#### 2.1.2 HTTP 与 internal receipt/result 的互斥字段

- `http_post`：`http_method='POST'`、精确 operation-specific `request_path`、`http_status=200..599`、`response_json/response_hash` 全部非 null；`internal_result_status/json/hash` 全部 null。`operation_status=completed` 精确对应 HTTP 2xx 且 reason null；`failed` 精确对应 4xx/5xx 且 reason 非 null。
- v5 新写 HTTP receipt 使用 strict successor `schemaVersion=admin-operation-http-v1`，在现行 OperationReceipt common fields 上强制加入 `operationChannel='http_post'`、`actorRef` 与 nullable `controlAction`，`additionalProperties=false`；actorRef 必须等于 operation row。只有 `auto_publish_control` 的 controlAction 为六值之一，其他 HTTP type 为 null。现行 `admin-review-v0.2` 字节只保留为 legacy 只读形态，不能承载 v5 新写或 internal result。
- `internal_auto_review|internal_auto_publish`：`http_method/request_path/http_status/response_json/response_hash` 全部 null；`internal_result_status` 只允许 `succeeded|failed|blocked|no_work`，`internal_result_json/hash` 非 null且 hash 等于 canonical JSON。`operation_status=completed` 只对应 `succeeded|no_work`，`failed` 只对应 `failed|blocked`；`succeeded` reason 必须 null，其余状态 reason 必须非 null。
- strict `InternalOperationResult` 使用 `schemaVersion=admin-internal-operation-result-v1`，固定键为 `operationId,operationType,operationChannel,actorRef,resultStatus,reasonCode,entityIds,policyEpoch,publishedCount,snapshotManifestHash,deliveryId,createdAt`，`additionalProperties=false`。auto-review 形态要求 type=`revision|approve|reject`、channel=`internal_auto_review`、actor 精确 `system-auto-review-v1`、status 只允许 `succeeded|failed|blocked`、`entityIds` 精确一个 candidate、policy/snapshot/delivery/publishedCount 全 null。auto-publish 形态要求 type=`auto_publish_batch`、channel=`internal_auto_publish`、actor 精确 `system-auto-publish-v1`、positive policy epoch：`no_work` 必须 entityIds 空、publishedCount=0、snapshot/delivery 全 null；`failed|blocked` 必须 publishedCount=0、snapshot/delivery 全 null；`succeeded` 必须 entityIds 长度=publishedCount=`1..20` 且 snapshot hash/delivery 同时非 null。任何其他字段相关性都拒绝。
- operation GET 使用以 `operationChannel` 为 discriminator 的 closed union：v5 HTTP receipt、internal result、legacy read receipt三者互斥。legacy wrapper 明示 `operationChannel=legacy_http_shaped_unknown` 并原样携带旧 response bytes；现行强制 `httpStatus` 的 `OperationReceiptSchema` 只解释该旧 payload，不能解析 v5 HTTP successor 或 internal result。

#### 2.1.3 fresh evidence 与 actor 的持久绑定

- `operation_actor_ref` 对所有 v5/legacy 行均非空；`publish|correct|withdraw|auto_publish_control` 另要求非空 `fresh_binding_json` 和 `fresh_binding_hash`，其他新写及 legacy 行的 fresh 两列都必须为 null。`control_action` 仅在 `auto_publish_control` 非空且等于 strict JSON 的 `controlAction`，其余 operation 必须为 null。strict `fresh_binding_json` 固定键为 `schemaVersion,operationId,operationType,actorRef,freshAction,controlAction,requestHash,resourceHash,freshEvidenceRef,verifiedAt,expiresAt`；schemaVersion=`admin-fresh-operation-binding-v1`，hash 为 canonical JSON SHA-256。
- `freshEvidenceRef` 是由现有已验证 in-memory fresh record 生成的 64hex 不透明引用；持久层不保存原始 fresh receipt、session/CSRF token、WebAuthn challenge、credential ID 或 assertion。security 层必须从当前 issued record 生成 server-owned 的授权对象，repository 的高风险入口不再接受独立 caller-supplied `actorRef/freshEvidenceRef/verifiedAt/expiresAt` 字段，只能消费该授权对象并在业务 mutation 的同一 DB 事务写入 binding/operation/audit。operation ID/type、manifest operator actor、request/resource hash、action 和 TTL 必须与授权对象逐字一致，`created_at` 必须位于 `[verifiedAt,expiresAt]` 且窗口不超过现行 5 分钟。
- action 与 type 固定一一对应：`publish→publish`、`correct→correct`、`withdraw→withdraw` 时 `controlAction=null`；`auto_publish_control` 时 `freshAction=auto_publish_control:{controlAction}`，且 `controlAction` 必须是上一节六值之一。primary AuditEvent 的 actor 必须与 `operation_actor_ref` 相等；phase policy row、operation 与 phase-change AuditEvent 在同一 `BEGIN IMMEDIATE` 中提交。
- fresh 缺失、已消费、过期、重放或 actor/action/operation/request/resource 任一错绑时，operation、phase、cutoff、stop fence、Projection、snapshot 和 outbox 增量全部为 0。路由存在、HTTP 200、actor 字符串或 event_json 单独出现都不能替代该持久 binding。

#### 2.1.4 legacy provenance 与双表重建

- v5 的唯一新持久表仍是 singleton policy；上述字段通过重建既有 `admin_operation` 与 `audit_event` 加入，不增加第二 operation/audit 表作为运行时真值。migration 在一个 `BEGIN IMMEDIATE` 中先建 v5 临时父表和引用它的临时子表，再逐列复制父 operation 与子 audit；替换顺序固定为 drop 旧 child → drop 旧 parent → rename 新 parent → rename 新 child，随后恢复 FK、index、immutability/append-only/closed-union trigger，最后执行 count/ID/FK/sequence/hash/integrity 门。任一步无法在当前 SQLite/foreign-key 设置下原子完成时整个 migration 回滚。
- 每个旧 operation 的 11 个既有字段，包括 request/response JSON、hash、`POST/path/http_status`、status、reason 和 created_at，必须保持 SQLite storage class、nullness 与值逐项相等；TEXT/BLOB 另以 `hex(CAST(column AS BLOB))` 前后逐字节相等验证，INTEGER 以 `typeof(column)='integer'` 和精确值验证。channel 写 `legacy_http_shaped_unknown`。primary actor 从与 type 对应的旧 AuditEvent 读取：revision=`review_revision_saved`、approve=`review_approved`、reject=`review_rejected`、publish=`publication_published`；匹配计数必须精确为 1，缺失、重复或无法绑定时 migration 整体回滚。migration 完成后 trigger 永远拒绝新 legacy insert/update。
- 当前 `event_hash` 的实际输入只有 canonical `event_json` 与 `previous_event_hash`；它不覆盖 `admin_operation` 整行，也不覆盖 SQLite record/page。全部旧 `audit_event` 的 ID、`audit_seq`、type、operation/entity/actor、event JSON、previous/event hash 与 created_at 必须逐值复制，既有 hash 禁止重算；`sqlite_sequence` 恢复为原 max seq，下一 event 只能接 max+1。
- 表重建必然改变 schema、record layout 与数据库文件物理字节，合同不使用“零字节变化”。可声明的唯一保持项是上述旧列 value bytes/storage class、旧 canonical audit hash chain逐项复算相等、FK/顺序有效；这些不等于 SQLite page/record bytes不变。任何一项不成立时 migration 写前/提交前失败关闭。

`audit_event.event_type` 追加 `publication_corrected|publication_withdrawn|auto_publish_phase_changed|auto_publish_batch_completed|auto_publish_batch_failed`，`entity_type` 追加 `auto_publish_policy|auto_publish_batch`。phase-change event 只可引用 fresh `http_post/auto_publish_control`；batch completed/failed 只可引用 `internal_auto_publish/auto_publish_batch`。不新建第二 audit ledger。

## 3. 安全初审的闭集

只允许下列确定性门；未出现在闭集中的推断不得成为自动准入理由。

| 门 | PASS | fail-closed |
| --- | --- | --- |
| 来源 | 精确 `source_id`、已启用、当前 allowlist 成员、当前 revision/full payload hash | source/allowlist/revision/hash 任一 missing、unknown、disabled、stale 或 mismatch |
| schema | 现有 closed DTO/strict schema 通过，必填字段/类型/长度精确 | unknown key、缺失、截断、隐式默认或未知 schema |
| URL | 现有 canonical URL、HTTPS、source binding 和安全规则全部通过 | URL 缺失、unknown、无法规范化、source mismatch 或 policy 不明 |
| media identity | 当前 `rss_media_candidate` 的 candidate/source revision/full hash、HTTPS `media_url`、MIME `image/jpeg|png|webp|avif`、`declared_bytes=1..20971520` 与 Bundle `media[0]` 精确相等；或当前无 media candidate 且 Bundle 精确 `media=[]` | identity/url/type/bytes/bundle binding 任一 missing、unknown、stale 或 mismatch |
| media policy | 初版只有“当前无 media candidate + Bundle 精确 0 图”为可机械判定 PASS | 当前 v4 没有 rights/license/policy 字段；任何非空 media 固定 `MEDIA_POLICY_UNKNOWN`/`waiting`，在单独 accepted media-policy successor 实现前不自动发布 |
| 文本控制符 | 全部可公开文本不含禁止 code point | 含 ASCII C0 `U+0000–U+001F`、DEL/C1 `U+007F–U+009F`、bidi `U+202A–U+202E` / `U+2066–U+2069` |

安全 PASS 只表示上述闭集通过。它不表示事实核查通过、新闻准确性已验证、版权或授权合法性已判定，也不表示仇恨、暴力、成人、违法或其他广义语义内容已审核。

## 4. phase 状态机

| 当前 phase | 允许的动作 | 禁止/停止条件 |
| --- | --- | --- |
| `disabled` | 人工 review/publish 照常；可做只读 backlog 预览 | 系统 review/publish 为 0；不改变现行 collector 运行 |
| `backlog` | 只处理 `first_seen_at<=cutoff` 的存量；oldest-first review/refine/system publish | collector 在 DNS/socket 前返回 `BACKLOG_DRAINING`，`externalCalls=0` |
| `live` | 按新内容正常节奏执行同一 review/publish 门 | 任一 policy/source stop、backup/integrity/CAS 失败立即停止新批次；下一自然 `900s` 前不补抓 |
| `paused` | 人工查看/恢复；已有 outbox 只可 reconcile 同一 delivery | 新 review/publish=0；collector 在 DNS/socket 前返回 `AUTO_PIPELINE_PAUSED`，`externalCalls=0` |

转移合同：

1. `disabled → backlog`：由 fresh WebAuthn 授权的 Admin 控制动作发起。唯一合法提交形态是在同一 review DB 的一个 `BEGIN IMMEDIATE` 中取得 writer lock，重读 singleton 的 `phase=disabled`、预期 `policy_epoch` 与本 epoch 全部受控 source fence，证明不存在 `ingest_run.status='running'`，再在该事务内一起写不可变 cutoff、`phase=backlog` 与 phase-change audit。任一 running slot 使整个事务回滚；phase/cutoff/成功 audit 均不得部分落盘，也不得持锁等待 slot 收敛。cutoff 写入后在该 epoch 内不可改动。
2. `backlog → live`：只能由 manifest operator 的 fresh WebAuthn `http_post/auto_publish_control` 发起；事务内重算只决定该授权动作能否提交。cutoff 内 `pending_review|source_updated|approved_waiting_publish|waiting|manual_override|failed|reconcile_wait` 计数必须为 0，且最新 outbox `succeeded` 或不存在。`rejected` 计作已处理终态，原因和 audit 不删除。
3. `backlog|live|disabled → paused`：pause/stop/急停全部只能由 manifest operator 的 fresh WebAuthn `http_post/auto_publish_control` 发起并 CAS。变更与新批次竞争时，phase/epoch/source-stop CAS 使新批次回滚；system actor 只能记录自身失败并停止取得新工作，不能代写 paused。
4. `paused → backlog|live`：resume 只能由 manifest operator 的 fresh WebAuthn `http_post/auto_publish_control` 发起，且重新验证 DB identity/integrity、`backupAge<15m`、source stop fences、policy epoch、cutoff 和前一 outbox。`resume_backlog` 遇到已有 cutoff 时沿用；cutoff 为 null 时必须复用 `disabled→backlog` 的 0 running slot/同事务首次冻结门。`resume_live` 要求 cutoff 已存在并满足与 `backlog→live` 相同的清零门。
5. 存量清零后只在下一个自然 `900s` collector tick 恢复抓取；不调用人工 RunAtLoad/单次补抓来压缩窗口。

### 4.1 collector claim 与 phase 切换的单一 writer-lock 栅栏

- collector claim 必须在自己的 `BEGIN IMMEDIATE` 中先读取 `auto_publish_policy` singleton，再读取 source/旧 slot 并决定是否插入 `ingest_run.status='running'`。singleton 缺失、非法或不可判定时 0 slot、0 外联 fail closed。
- 读到 `backlog` 时插入 0 个 running slot，提交只读结果后在 DNS/socket/HTTP 前返回 `BACKLOG_DRAINING`、`externalCalls=0`；读到 `paused` 时同样返回 `AUTO_PIPELINE_PAUSED`。只有读到 `disabled|live` 且现行 source/slot/采集门全部通过时才可插入 running slot。
- collector claim 与 `disabled→backlog` 都竞争同一 SQLite writer lock。collector 在 `disabled` 先 claim 并提交 running slot后，phase 事务只能读到该 slot并整体失败；它必须释放 writer lock，等待 collector 把该 slot提交为 terminal，再由新的 phase 事务重试。phase 事务先提交 backlog/cutoff/audit 时，随后取得锁的 claim 必须读到 backlog并以 0 slot/0 外联退出。

### 4.2 唯一并发验收

1. **claim 先锁**：barrier 让 collector 的 `BEGIN IMMEDIATE` 先取得 writer lock，在 `phase=disabled` 插入并提交 running slot，再释放 phase 事务。断言 phase 事务整体失败，`phase` 仍为 `disabled`、cutoff 不变、无成功 phase-change audit；collector 提交 terminal 前重试仍失败，terminal 提交后重试才可一次性写 backlog/cutoff/audit。
2. **phase 先锁**：barrier 让 Admin phase 事务先取得 writer lock，在确认 0 running slot 后一次性提交 backlog/cutoff/audit，再释放 collector claim。断言 claim 读到 backlog、插入 0 个 running slot、返回 `BACKLOG_DRAINING`，且 DNS/socket/HTTP 计数与 `externalCalls` 均为 0。

顺序测试、事务外先查 running slot 或只检查最终 phase 均不能关闭此并发门。

## 5. oldest-first 存量选择

- backlog 集合只由现有 `pending_review_candidate.first_seen_at <= backlog_cutoff_at` 推导，不建新工作队列。
- review/refine/publish 都绕过现有 newest-first `list()` 和前 100 条截断，直接按 `first_seen_at ASC, published_at ASC, candidate_id ASC` 选择，每次最多取当前 `max_batch`。
- 系统发布选择器从当前 candidate 出发。它不扫描 raw `Publication=queued`，不通过历史 queued 状态推导可发布性。
- 缺当前中文稿进入 `waiting`；同 source revision/full hash 有旧拒绝且已人工恢复进入 `manual_override`；事务/CAS 错误进入 `failed`。三者均保留 reason/audit 并阻止 `live`，不会被静默跳过。
- 当前 source revision 有非空 media 时，因 v4 无机器可判定 rights/license/policy，该项进入 `waiting/MEDIA_POLICY_UNKNOWN` 并阻止 live。人工可继续使用 fresh WebAuthn 按现行路径决定；系统 actor 不借用人工决定推导媒体政策 PASS。
- 确定性拒绝创建 immutable rejected Decision，原因长期可回读，在 cutoff drain 中计作已处理。人工新建 revision 后，新版本再次进入未决集合。

## 6. approved-only 系统发布 CAS

一个系统批次必须在同一 `BEGIN IMMEDIATE` 事务中完成下列全部检查与写入：

1. 重读 `phase=backlog|live`、当前 `policy_epoch`、固定 cutoff 与 `max_batch`。
2. 重读 source 已启用、当前 allowlist 成员、精确 source revision 及 64 位 payload hash，并通过该 source 当前 stop fence。
3. 候选指向 latest immutable Bundle，Bundle 绑定同一 source revision/hash 和当前中文稿；完整 Bundle hash 由服务端重算。
4. latest terminal Decision 精确为 immutable `approved`，并通过 `decision_id + bundle_id + approved_bundle_hash` 绑定同一 Bundle；不存在更新的 reject/supersede。现有 Decision 不新增 policy 字段，当前 `policy_epoch` 由本批次事务独立 CAS，并在发布前重跑当前初审闭集。
5. 唯一 Publication 精确为 `queued`，并绑定同一 approved Bundle/hash、稳定 publicId、publish generation 和 canonical idempotency key。
6. 对当前公开 payload 重新执行第 3 节全部确定性安全门；任一 unknown 或 stale 都在 0 Projection/0 outbox 时回滚。
7. 上一 projection outbox 必须 `succeeded` 或不存在。事务只将已验证的 Publication 改为 published，为它们创建/更新唯一 PublishedProjection，重建一份全量 snapshot，并创建一条 `snapshot_sync` outbox。
8. 同一事务写 `internal_auto_publish/auto_publish_batch` operation、closed InternalOperationResult 与 AuditEvent，actor 均精确为 `system-auto-publish-v1`，记录 policy epoch、cutoff、候选数、published/rejected/waiting/failed 计数、snapshot generation/manifest hash 和 outbox deliveryId；日志和 operation 不记密钥、session、fresh receipt 或原文全文。

actor 不允许创建 revision、Decision 或 queued Publication，不允许将 `pending_review|source_updated|waiting|manual_override|failed|rejected` 直接改为 published，不允许向 `releaseNow()` 传入 raw candidate。

## 7. snapshot、outbox 与不确定结果

- 任一时刻最多一个未收敛 snapshot/outbox。前一 outbox 为 `pending|leased|retryable_failed|reconcile_wait` 时，新批次为 0。
- sender 继续仅投递已存在 outbox，不生成 Publication/Projection/snapshot/outbox。网络超时、断连或回包不完整只进入同一 delivery 的 `reconcile_wait`。
- receipt GET 只查同一 deliveryId/package hash/generation。明确 404 才能以同一 package 重投；语义失配或签名/hash/generation 失配进入 terminal failure，写 internal failed result/audit并阻止后续批次。phase 保持原值；只有 operator 的 fresh HTTP control 可以切 paused。
- 公开 reader 只指向 last-known-good `active.json` 所指的已验签 generation。新 package 未确认 active 前不改公开指针；新根损坏时返回 fail-closed 错误，不用旧 synthetic 数据伪装成当前成功。
- snapshot 是全站全量快照。继续使用现有 `snapshotManifestHash=hash(generation, previous manifest hash, ordered full records hash/count)` 和 `deliveryId=op-snapshot-${snapshotManifestHash}`；v5 的 outbox idempotency key 精确为 `snapshot-sync:${policyEpoch}:${snapshotManifestHash}`，取代现行将单源 `stop_epoch` 嵌入键的格式。三者都不含 `source_id`、Motorsport 字面值、源数量或单源 stop epoch；每源 stop fence 只在发布事务 CAS。receiver 现行“idempotency key 以 manifest hash 结尾”的校验仍可复用。

## 8. 唯一数据、备份、停止与回退

### 8.1 写前门

每个迁移、`disabled→backlog`、`paused→*`、`backlog→live` 和 system publish 批次都必须证明：

- 运行 manifest 的 `reviewDatabasePath` 与 dev/inode/uid/nlink 精确匹配，文件 existing-only，无 symlink/双 path/请求级覆写。
- SQLite `database_list=main,temp`，无 `ATTACH/DETACH`，WAL/FULL/foreign keys/单 writer/integrity 门通过。
- 同一唯一 review DB 不复制、不双写、不通过 WAL/SHM 在线拷贝建备份。
- 一致性备份已完成，恢复 fence 有效，`backupAge<15m`，隔离恢复的 `integrity_check=ok` 收据存在。
- 当前 source enabled/allowlist/stop fence 和全局急停状态全部 clear。

### 8.2 回退

1. 首先由 manifest operator 使用 fresh WebAuthn 的 `POST /api/admin/auto-publish/control` CAS 到 `phase=paused`，使新 review/publish 为 0，collector 在 DNS/socket 前为 0 外联。若 fresh control 暂不可用，先 unload 自动 reviewer/publisher/collector 并保持 public last-known-good，恢复控制入口后再落 paused；system actor 不代写 phase。
2. 保留 v5 表、Decision、Publication、Projection、snapshot、outbox、拒绝原因和 AuditEvent；已存在 outbox 用同一 delivery 收敛，public 保持 last-known-good。
3. 回到已知 manual-only runtime 后，人工 publish 仍需 fresh WebAuthn。不做 down migration、不删 v5 表、不回拨 active generation。
4. 若旧 collector 代码不识别 v5 phase guard，回退前先 unload collector。只在人工核验采集可恢复时才重新 load。

## 9. 未来 v5 多源兼容约束

- 本合同不开启新 source。每个新 source 需单独 accepted 注册、数据/URL/media 门和停止 fence。
- 本节的“未来 v5 多源”是产品演进标签，没有预留第二个 SQL `user_version=5`。当前 `app/migrations/rss-real/` 精确只有 `0001..0004`，本 successor 使用 `0005/user_version=5`。如果实施前其他 accepted migration 先占用 5，必须新建 successor 重编号，不合并同号 migration，不覆写已用版本。
- 候选、Bundle、Decision 和 Publication 仍按 source 绑定与 CAS；每个 source 的 stop fence 只阻断该 source 的新发布。一个 source 停止时，其他 source 仍需各自通过完整门，不会共享准入收据。
- 全站 snapshot 键与 source 无关，因此添加 source 不会创建每源 snapshot 或改写键 schema。
- 多源 backlog 的 cutoff 语义必须使用同一 policy epoch 内每源已注册范围；全局 `live` 仍要求所有本 epoch 受控 source 无未决阻断项。

## 10. 最小实施、切换与验收顺序

1. **prepare-only**：核对 release/LaunchAgent/manifest 指向，记录唯一 DB path/dev/inode/v4/integrity、active generation/outbox 和回退命令；做一致性备份与隔离恢复。不 load、不迁移、不设 cutoff。
2. **migration/load 但保持 disabled**：同一 inode 原位追加 v5，按 §2.1.4 重建 operational 双表并核对 legacy provenance/hash chain，加载 phase-aware reviewer/refiner、collector claim-first singleton guard 和 approved-only publisher；复验 manual publish 继续 fresh WebAuthn，auto-review 新 operation 使用 `internal_auto_review`，system publish=0。
3. **backlog 启动**：先做只读预览，再用 fresh WebAuthn 发起单一 `BEGIN IMMEDIATE` 切换，原子证明 0 running slot并写 backlog/cutoff/audit；按 §4.2 的两种 barrier 次序验收互斥，再证明 collector DNS/socket 前 `externalCalls=0`。
4. **存量处理**：oldest-first 初审/补稿/发布，每批最多 20，上一 outbox succeeded 后才进入下一批；rejected 原因可回读，waiting/manual_override/failed 均不能被跳过。
5. **live cutover**：在同一事务中证明 cutoff 未决=0 和最新 outbox succeeded，再切 live。不人工触发采集，只观察下一个自然 `900s` 周期。
6. **用户可用验收**：一条新内容在当前 source revision/hash 上经确定性 PASS、形成当前 approved/queued、被系统 CAS 发布，且公开 feed/detail 在同一 active generation 可读；新批次故障时仍可读 last-known-good。

任一步失败时停在当前步骤。不跳过备份、停止、CAS、outbox 或自然 `900s` 门。

## 11. 当前未实现清单

- `0005_auto_publish_policy.sql` 和 v5 singleton 尚未存在。
- 四 channel closed union、HTTP/Internal DTO、persistent fresh binding 与 legacy 双表重建尚未实现；现行 auto-review 仍会写 HTTP-shaped operation，不能被追认成真实 HTTP。

- v4 的非空 media 只有身份/Bundle 绑定字段，没有机器可判定 rights/license/policy；未实现单独 media-policy successor 前，非空 media 全部 `MEDIA_POLICY_UNKNOWN` 并阻止自动发布/live。
- 生产 M1 尚未迁移、未设 cutoff、未进 backlog/live，自动发布仍为 0。
- 本合同未执行 app 测试、SSH、数据库读写、M1 部署、密钥或 tailnet 变更。

## 12. operation closed-union 负例矩阵

以下每项都必须在 0 operation/0 phase/0 Projection/0 snapshot/0 outbox 时拒绝，并以独立数据库 CHECK/trigger + repository 负例共同证明：

1. `auto_publish_control + internal_auto_review|internal_auto_publish`；`auto_publish_batch + http_post`。
2. `system-auto-publish-v1` 执行 control、HTTP 或 auto-review；`system-auto-review-v1` 执行 HTTP、control 或 auto-publish；manifest operator 写任一 internal channel。
3. auto-review revision/approve/reject 使用伪造 `/api/admin/...` path，或 internal 任一 `http_method/request_path/http_status/response_json/response_hash` 非 null。
4. HTTP operation 缺失/错误 method、operation-specific path 或 status，或携带 internal result；internal operation 缺 closed result status/DTO/hash，或被现行 HTTP `OperationReceiptSchema` 接受。
5. publish/correct/withdraw/control 缺 fresh binding，fresh evidence 已消费/过期/重放，或 actor/action/controlAction/operation/request/resource/TTL 任一错绑；以 start_backlog 的 fresh binding 提交 pause 等跨 action 重放。
6. 未经 fresh WebAuthn 的 `disabled→backlog`、`backlog→live`、pause、resume、stop；control_action 与 phase 前后值不相容；system batch失败后尝试自行写 paused。
7. v5 后新插入/更新 `legacy_http_shaped_unknown`；migration 把旧 `system-auto-review-v1` 行标为 `http_post` 或新 internal channel；旧字段、primary actor、audit sequence/hash/FK 任一漂移。
