# F1+1 M5 最小人工审核台纵切产品合同 v0.1

## 1. 合同结论

本合同冻结 `/admin/reviews` 的最小产品语义：审核者从本地 synthetic 待审核候选进入单条证据核对，编辑中文摘要，批准或拒绝；批准后必须再次由用户显式点击“手动发布”，沿既有唯一 Publication/PublishedProjection 链进入公开页。

当前合同为 `proposed`。开发开工还需要两个前置收据：

1. 数据部给出现有领域/内部合同到本合同 DTO 槽位的一一映射；只能补 JSON pointer/字段回指，不新增领域实体、第二字段集或第二真值。
2. 设计部提供 `/admin/reviews` 可视化预览，用户确认视觉与交互方向。

本合同不修改 accepted ADR。若数据映射证明既有 Content、Summary、ReleaseBundle、ReviewDecision、Publication、PublishedProjection 无法承载任一必要操作，停止该操作并回产品部，不在实现中补造实体或弱化栅栏。

## 2. 唯一范围

### 2.1 包含

- 路由：`/admin/reviews`，仅 loopback local-dev。
- synthetic 待审核列表、单条详情和证据核对。
- 浏览器内未保存的中文标题/摘要编辑。
- “保存并生成待审核版本”：创建新的 Summary 版本和新的不可变 ReleaseBundle；旧 Bundle/批准不被原地修改。
- 对当前 Bundle 执行批准或拒绝；拒绝必须填写原因。
- 批准后展示独立“手动发布”确认；发布到既有本地 PublishedProjection。
- 发布成功后提供公开详情入口，并允许刷新公开信息流验证同一唯一投影。
- loading、empty、error、partial、saving、conflict/stale、确认、成功和失败恢复。

### 2.2 排除

- `/admin/sources`、信源增删启停、真实采集、真实内容、真实 URL、Base/provider/Collector。
- 外部 AI、真实摘要模型、外部媒体、图片代理、下载、真实表单或任何外部 I/O。
- 自动批准、自动发布、批准即发布、定时发布、批量批准/发布。
- 生产登录、生产角色、跨网络 admin、代理转发、部署、付费和外发。
- correct、withdraw、急停的 UI 实现；既有 accepted 路由/状态保留，但不进入本纵切。
- 新领域实体、`SummaryDraft` 实体、第二 Publication、第二 public_id、前端状态真值或静态 Demo 回退。

## 3. 权威对象与不变量

本合同只使用现有对象：

```text
Content
  → Summary(summary_status=draft|ready|approved|rejected|superseded)
  → immutable ReleaseBundle
  → immutable ReviewDecision
  → unique Publication
  → read-only PublishedProjection
```

必须持续满足：

- 浏览器表单只保存未提交输入，不是领域记录；持久草稿属于既有 `Summary(summary_status=draft)`。
- ReleaseBundle 不可变。中文编辑产生新 Summary version/hash 和新 Bundle version/hash；旧 Bundle 只保留历史并 supersede，不覆盖。
- ReviewDecision 不可变；批准必须绑定当前 `bundle_hash`，拒绝绑定当前 Bundle 和明确原因。
- 任一冻结字段、hash、五个 fence、rights/policy/schema/source snapshot 变化会使旧批准 supersede。
- 同一 `(release_bundle_id, approved_bundle_hash)` 最多一条 Publication、一个稳定 public_id、一个单调 publish_generation。
- Publication、publish Outbox 和 TaskEnvelope 使用同一 Publication.idempotency_key；未知结果只进入同一 Publication 的 `reconcile_wait`。
- PublishedProjection 只从 `publication_status=published` 派生，复用同一 public_id/generation/version hash；前端缓存不成为第二真值。
- `canonical-json-v1`、hash 输入、五 fence、epoch、manual-only 和 CAS 规则逐字沿用 Spec/accepted ADR；本合同不重定义。

## 4. 用户流程

### 4.1 队列与详情

1. 进入 `/admin/reviews`；服务端先验证 loopback、local-dev session，页面再读取队列。
2. 默认只显示当前可审核 synthetic Bundle：`release_status=ready`，无当前 terminal ReviewDecision，且 Content/Summary/hash/fence 完整。
3. 列表每项只展示：中文标题、来源显示、时间/无时间、媒体状态、当前审核状态和更新时间；不展示原始 payload、内部 hash、session、epoch 或日志。
4. 选择一项加载详情，展示中文标题/摘要、来源证据、时间、无图/媒体快照、Bundle 版本和可读的完整性结论。
5. 任一链缺失、hash/fence 不一致或字段映射 Unknown 时，详情进入阻断态，隐藏 mutation 操作并显示固定原因码。

### 4.2 中文编辑

1. 编辑仅作用于页面内表单；离开未保存页面必须提示丢弃。
2. “保存并生成待审核版本”是一次 mutation：校验 expected bundle/summary hash、local session、Origin、CSRF、operation id 和五 fence。
3. 服务端创建新的 Summary version，按既有字段规则重算 summary hash；组装新的 immutable ReleaseBundle 并重算 payload/bundle hash。
4. 旧 Bundle 和旧 ReviewDecision 不被修改；存在旧批准时必须 supersede。返回新 bundleId/hash/version，页面切换到新 Bundle。
5. 当前数据映射未给出精确可编辑字段 JSON pointer 前，该按钮保持 disabled；实现不得从 UI 猜测字段。

### 4.3 批准

1. 点击“批准”先打开确认层，列出当前 Bundle 版本、标题、摘要、来源、无图状态和“批准后仍需手动发布”。
2. 确认后服务端在同一事务复算 Content/Summary/Bundle/decision hash，检查五 fence、`manual_only`、session/Origin/CSRF 和 expected bundle hash。
3. 创建 immutable `ReviewDecision(decision=approved)`，`approved_bundle_hash=current bundle_hash`。Content 先按既有 content_lifecycle 进入 `approved`；Summary 与 ReleaseBundle 只使用已冻结 enum 进入 `approved`，具体字段写入由数据映射确认，不宣称存在 Summary/Bundle 状态机。
4. 同一原子操作为该批准 hash 取得或创建唯一 queued Publication 和稳定 publicId，并把 Content 从 `approved` 推进到 `publish_queued`；Summary 与 ReleaseBundle 保持 `approved`。不得 dispatch publish Outbox。若数据映射不能证明这些写入原子闭合，批准操作继续阻断。
5. 页面进入“已批准，等待手动发布”，只展示独立“手动发布”按钮。

### 4.4 拒绝

1. 点击“拒绝”打开确认层；原因必填，去除首尾空白后 1–500 字符。
2. 服务端重验当前 Bundle/hash/fence 后创建 immutable `ReviewDecision(decision=rejected)`；Content 按现有 content_lifecycle 进入 `rejected`，Summary 与 ReleaseBundle 只使用已冻结 enum 进入 `rejected`，具体字段写入由数据映射确认。
3. 拒绝不创建 Publication/PublishedProjection，不自动回队列，不删除证据。
4. 同一 Bundle 已批准、已拒绝或 superseded 时，新的不同决定返回 conflict；不得覆盖旧 Decision。

### 4.5 显式手动发布

1. 只有当前 Decision=approved、Publication=queued，或 retryable_failed 已满足同一 key、attempt、批准 hash、五 fence 与人工重试守卫时，才显示“手动发布”。blocked 只显示阻断原因与解除出口；必须先沿既有 `blocked → queued` 守卫解除，不能直接发布。
2. 点击后再次确认：“这会把当前批准版本写入本地公开投影”；默认焦点停在取消。
3. mutation 在同一事务检查当前 Bundle/hash/version、Decision、Publication identity/key、五 fence、session/Origin/CSRF 和 `manual_only`。
4. dispatch 只使用该 Publication.idempotency_key；成功后 Publication=published，并由同事务可见结果派生/更新唯一 PublishedProjection。
5. UI 只有在服务端确认 `published` 且返回的 publicId/generation/hash 与投影一致后显示成功，不做乐观发布。
6. 结果 Unknown 时展示 `reconcile_wait`，只按同一 reconcile_key 查询，不创建新 Publication、不生成新 publicId、不盲重试。
7. 成功后展示 `/stories/{publicId}`，并提供“打开公开页”和“刷新公开信息流”两个非 mutation 出口；公开 GET 仍按既有 projection-first API 验证全链。

## 5. 页面布局与状态合同

视觉方向须由后续设计预览和用户确认；以下只冻结信息层级与行为：

- 宽屏：左侧队列、右侧详情；窄屏：列表进入详情的单列层级，返回时保持列表位置和筛选。
- mutation 主操作固定在详情区；批准、拒绝、手动发布三者不得同时作为同等主按钮。pending 时显示批准/拒绝；Decision approved 且 Publication=queued，或 retryable_failed 已通过人工重试守卫时，才显示手动发布；blocked/reconcile_wait/terminal_failed/emergency_stopped/rejected/published 只显示各自状态与恢复/返回出口。
- 所有确认层含对象版本、动作后果、取消和确认；危险动作默认焦点在取消。
- toast 只作补充，结果和恢复动作必须留在页面文档流。

| 页面状态 | 触发 | 用户可见出口 |
| --- | --- | --- |
| `loading-list` | 初次读取 | 骨架，无 mutation |
| `empty` | 无可审核 Bundle | “暂无待审核内容”；刷新 |
| `loading-detail` | 切换条目 | 保持列表，详情骨架 |
| `pending-review` | 当前 Bundle 可审核 | 编辑、批准、拒绝 |
| `saving` | 任一 mutation 在途 | 锁定该对象所有 mutation；允许等待，不重复提交 |
| `saved-needs-review` | 新 Bundle 已生成 | 显示新版本，批准/拒绝 |
| `approve-confirm` | 批准确认 | 取消 / 确认批准 |
| `reject-confirm` | 拒绝确认 | 原因输入、取消 / 确认拒绝 |
| `approved-manual-publish` | Decision approved 且 Publication=queued，或 retryable_failed 已通过人工重试守卫 | 手动发布 |
| `publish-confirm` | 发布确认 | 取消 / 确认手动发布 |
| `published` | 投影确认成功 | 打开公开页 / 刷新信息流 |
| `stale-version` | expected hash/version/fence 过期 | 放弃本地输入并加载最新版本 |
| `conflict` | 已有不同终态 Decision/Publication | 查看当前服务端状态，不覆盖 |
| `reconcile-wait` | 发布结果 unknown | 查询同一 operation；禁止新发布 |
| `terminal-failed` | Publication 终态失败 | 固定原因、返回队列；禁止新 publicId/新发布 |
| `emergency-stopped` | Publication 急停 | 显示急停；无 mutation |
| `partial` | 列表部分可读，某项损坏 | 可读项保留；损坏项只显示原因码，不能 mutation |
| `error` | 可恢复读取错误 | 重试同一 GET |
| `blocked` | session/Origin/CSRF/hash/fence/manual-only 不通过 | 固定原因与重新加载；无弱校验出口 |

## 6. 最小 Admin API

所有响应 `additionalProperties=false`；字段映射必须由后续数据包给出既有 JSON pointer。DTO 字段是 presentation allowlist，不是新领域 schema。

### 6.1 读取

| Method | Path | 语义 |
| --- | --- | --- |
| GET | `/api/admin/reviews` | 当前可审核 Bundle 队列；支持不透明 cursor，不接受 mutation |
| GET | `/api/admin/reviews/{bundleId}` | 单条完整性核对、可编辑 Summary 映射、当前 Decision/Publication 状态 |
| GET | `/api/admin/operations/{operationId}` | 断网、刷新、503 或 unknown outcome 后查询同一内部 operation 收据；不得改变状态 |

队列响应最小槽位：

```text
schemaVersion, items[], page
item: bundleId, bundleVersion, bundleHash, contentId, summaryId,
      summaryVersionHash, titleZh, summaryZh, sourceDisplay,
      sourceTime, mediaState, reviewState, updatedAt
```

详情在 item 上只增加：`evidence`、`editableSummary`、`decision`、`publication`、`integrity` 和 `allowedActions`。`allowedActions` 由服务端当前状态计算，仅作 UI 提示；mutation 必须重新校验全部 guard。

operation receipt 固定为：

```text
schemaVersion: "admin-operation-v0.1"
operationId
operationType: revision | approve | reject | publish
status: pending | succeeded | failed | reconcile_wait
target: { originalBundleId, currentBundleId?, publicId? }
result: { summaryId?, summaryVersionHash?, bundleId?, bundleVersion?, bundleHash?,
          decisionId?, decision?, publicationStatus?, publishGeneration?, projectionId? }
reasonCode?
updatedAt
```

该响应是从既有 AuditEvent、Outbox/TaskEnvelope、ReviewDecision、Publication 和 Projection 映射的 internal read receipt，不新增领域实体。`operationId` 不存在返回 404；仍在执行返回 pending。只有 `operationType=publish` 且对应唯一 Publication 已进入 canonical `reconcile_wait` 时，receipt 才返回 reconcile_wait；revision/approve/reject 的未决结果只能返回 pending，确定失败返回 failed，并继续通过 receipt 与对象 GET 对账。数据映射未证明每个 result 槽位来源前，相关 mutation 保持阻断。

### 6.2 Mutation

| Method | Path | 语义 |
| --- | --- | --- |
| POST | `/api/admin/reviews/{bundleId}/revision` | 从当前 Summary 输入创建新 Summary version + immutable Bundle |
| POST | `/api/admin/reviews/{bundleId}/approve` | 创建 immutable approved ReviewDecision；取得唯一 queued Publication，不发布 |
| POST | `/api/admin/reviews/{bundleId}/reject` | 创建 immutable rejected ReviewDecision；不创建 Publication |
| POST | `/api/admin/publications/{publicId}/publish` | 用户显式手动发布同一批准 Bundle 到唯一 PublishedProjection |

四个 mutation 的 closed DTO 如下；全部对象拒绝 unknown key。

```text
RevisionRequest {
  schemaVersion: "admin-review-v0.1",
  operationId,
  expected: { bundleId, bundleVersion, bundleHash, summaryId, summaryVersionHash },
  editableSummary: { titleZh: string(1..512), summaryZh: string(1..10000) }
}
RevisionSuccess {
  schemaVersion, operation: { operationId, status: "succeeded" },
  summary: { summaryId, summaryVersion, summaryVersionHash, summaryStatus: "ready" },
  bundle: { bundleId, bundleVersion, bundleHash, releaseStatus: "ready" },
  reviewState: "pending"
}

ApproveRequest {
  schemaVersion: "admin-review-v0.1",
  operationId,
  expected: { bundleId, bundleVersion, bundleHash, summaryVersionHash }
}
ApproveSuccess {
  schemaVersion, operation: { operationId, status: "succeeded" },
  decision: { decisionId, decision: "approved", bundleId },
  contentStatus: "publish_queued",
  publication: { publicId, publishGeneration, publicationStatus: "queued" }
}

RejectRequest {
  schemaVersion: "admin-review-v0.1",
  operationId,
  expected: { bundleId, bundleVersion, bundleHash, summaryVersionHash },
  reason: string(1..500 after trim)
}
RejectSuccess {
  schemaVersion, operation: { operationId, status: "succeeded" },
  decision: { decisionId, decision: "rejected", bundleId },
  contentStatus: "rejected", publication: null
}

PublishRequest {
  schemaVersion: "admin-review-v0.1",
  operationId,
  expected: { publicId, publishGeneration, approvedBundleHash, publicationStatus: "queued" }
}
PublishSuccess {
  schemaVersion, operation: { operationId, status: "succeeded" },
  publication: { publicId, publishGeneration, publicationStatus: "published", publishedAt },
  projection: { projectionId, publicId, publishGeneration, projectionStatus: "published" },
  publicPath: "/stories/{publicId}"
}
```

DTO 中的 hash 用于本地 CAS，不在页面正文、URL、日志或错误消息显示。数据部只需把上述槽位回指到现有字段；如果 `titleZh/summaryZh` 之外还存在 v0.4 展示字段，本纵切仍只编辑已冻结 Summary 的 `title_zh/summary_zh`，其他字段保持当前值并进入 Bundle hash，不由 UI 猜测或清空。

所有 mutation 请求必须含：

- `Content-Type: application/json`；未知字段拒绝。
- `Origin` 精确匹配 canonical loopback origin。
- 有效 local-dev session cookie。
- 一次性 CSRF nonce，绑定 session/method/path/body hash，TTL ≤10 分钟。
- body 中的 expected bundleId/version/hash、summaryVersionHash 和 operationId；publish 另要求 expected publicId/generation/approvedBundleHash。

客户端不得提交 reviewer_ref、decision_hash、Publication.idempotency_key、五 fence 或状态枚举作为权威值；这些由服务端从会话和当前事务读取并计算。revision/approve/reject 的本地请求幂等性由服务端按 `operationId + method + path + canonical body hash` 建立 internal receipt：同 operationId 同 body 返回同结果，同 operationId 异 body 返回 conflict。publish 不接受客户端幂等键；服务端只使用当前 Publication.idempotency_key 作为 publish Outbox/TaskEnvelope/重放的唯一 canonical key，并将 operationId 作为非权威审计相关号映射到该 key，禁止产生第二 publish key。

### 6.3 固定错误语义

| HTTP | reasonCode | 行为 |
| ---: | --- | --- |
| 400 | `ADMIN_REQUEST_INVALID` | 拒绝未知/非法输入 |
| 401 | `ADMIN_SESSION_REQUIRED` | 无 mutation；重新载入本地会话入口 |
| 403 | `ADMIN_ORIGIN_REJECTED` / `ADMIN_CSRF_REJECTED` | 无 mutation；不降级 |
| 404 | `REVIEW_BUNDLE_NOT_FOUND` / `PUBLICATION_NOT_FOUND` | 返回列表或重新加载 |
| 404 | `ADMIN_OPERATION_NOT_FOUND` | 不重放 mutation；返回对象详情确认当前状态 |
| 409 | `REVIEW_STALE_VERSION` | 丢弃本地未提交状态并加载最新 Bundle |
| 409 | `REVIEW_DECISION_CONFLICT` | 展示已有 Decision，不覆盖 |
| 409 | `REVIEW_HASH_MISMATCH` / `REVIEW_FENCE_STALE` | blocked；重新读取，不自动重试 |
| 409 | `PUBLICATION_BLOCKED` / `PUBLICATION_RECONCILE_WAIT` | 保持同一 Publication/key；人工查询/恢复 |
| 422 | `REVIEW_CONTENT_INVALID` / `REVIEW_REASON_REQUIRED` | 保留表单并标出字段 |
| 503 | `ADMIN_STORAGE_BUSY` | mutation 结果未知时先按 operation 查询，禁止盲重试 |

错误响应不得包含 SQL、stack、路径、cookie、CSRF、完整 hash/fence、原始内容或内部拓扑。

## 7. 幂等、并发与恢复

- mutation 使用对象级 CAS；同一 bundle/publication 同时只允许一个在途 mutation。
- revision 成功返回新的 bundleId/hash；相同 operationId/body 重放只返回同一新版本，不再创建版本。
- approve/reject 对同一 Bundle 互斥。相同 operationId/body 重放返回原 Decision；相同 operationId 异 body 返回 conflict，不同 operationId 的并发竞争仍由 Bundle CAS 与唯一 ReviewDecision 约束。
- approve 成功只保证 Decision 和唯一 queued Publication；不得隐式 publish。
- publish 重放复用 Publication canonical key。`published` 返回同一 publicId/generation；`reconcile_wait` 只查询；terminal/emergency stop 不新建身份。
- 网络中断、页面刷新或 503 后，客户端先按 operationId/当前对象 GET 对账，再决定展示状态；禁止直接重复 mutation。
- stale-version 保留用户未提交输入只用于复制参考；重新提交必须基于最新 Bundle 重新确认，不自动合并。
- 页面缓存、React state、toast 或 URL 参数均不写领域状态。

## 8. Local-dev 安全边界

- app 只绑定 `127.0.0.1` 或 `::1`，拒绝非 loopback、Host/Forwarded/X-Forwarded 推导和 wildcard CORS。
- session/CSRF 沿用 accepted R2/R3：CSPRNG ≥256 bit、内存、重启失效；HttpOnly/SameSite=Strict/host-only；nonce 原子消费、常量时间比较。
- GET 不改变状态；所有 mutation 同时通过 session、Origin、CSRF、hash、五 fence、manual-only 和幂等 CAS。
- runtime 保持 no-egress，`external_calls=0`；不增加真实 URL fetch、模型、媒体、Base、provider 或外部发布 registry。
- AuditEvent append-only，只记录脱敏 session hash、operation、reason code、版本/hash 引用、fence、时间和结果；不记录 secret、CSRF、原始内容、完整私密 URL、stack 或路径。
- 生产环境、跨网络绑定或缺少 local-dev profile 时，全部 `/api/admin/*` 路由启动即拒绝或返回不可用，不依赖前端隐藏。

## 9. 验收出口

### 9.1 产品闭环

- [ ] synthetic ready Bundle 出现在队列；详情可核对来源、时间、摘要、无图/媒体状态和完整性。
- [ ] 编辑后只生成新 Summary version + 新 immutable Bundle；旧 Bundle 未被覆盖，hash 可重算。
- [ ] 批准创建唯一 immutable Decision 与唯一 queued Publication，页面不自动发布。
- [ ] 拒绝创建唯一 immutable rejected Decision，不产生 Publication/Projection。

## 10. 回退

- 数据映射或视觉确认未完成：不开始 app 实现，保留本合同 proposed。
- 实现发现现有领域合同无法承载：停止相关 mutation，报告精确冲突；不新增实体或修改 accepted ADR。
- 运行复验失败：关闭 `/admin/reviews` mutation 能力，保留公开 GET 与既有 synthetic 数据；清除本切片生成的可识别测试版本时必须使用受控 fixture 重置任务，不直接删数据库。
- 发布链出现 unknown：保持同一 Publication 的 `reconcile_wait`，公开侧继续 last-known-good/fail-closed；不回退静态 Demo、不创建第二 publicId。
- 回退不开放外部能力、不修改 Base/provider、不影响 accepted 核心。
