# ADR-M4-PUBLIC-READ-001：公开读模型与 API 接线 v0.4 successor（proposed）

> 本文是待用户与正式产品部确认的工作包。它不修改 `docs/spec.md`、accepted ADR、`app/`、`data/mvp-contract-v0/` 冻结产物或任务状态，也不开启 Base、真实平台、AI、媒体、发布、部署或付费能力。本文中的“冻结”均指提议在后续 successor 任务中冻结，当前仍为 proposed。

## 1. 结论

建议保留已确认的 12 条公开前端信息体验，并用一个与 M3 59 行库隔离的 `public-synthetic` 本地 fixture profile/SQLite 文件承载它。该 profile 只复用冻结 v0.3 synthetic fixture 中的 `src-active`，不增加第 60 个 M3 Source，不修改 59×39 projection 及权威 hash `e7a8312c70a9a49922aedb3cfbeaa190db8f5dce8d4ab45db1570748fc329f17`。

12 条内容必须经过唯一领域链：

```text
src-active
  → CapturedItem
  → Content
  → Summary
  → optional MediaCandidate
  → immutable ReleaseBundle
  → approved ReviewDecision
  → published Publication
  → read-only PublishedProjection
  → public DTO
```

`PublishedProjection` 是查询起点；`Publication` + `ReviewDecision` + `ReleaseBundle` + Content/Summary/hash/fence 链逐条校验后才能返回 DTO。禁止增加 `public_story`、禁止直接序列化 `DemoStory`、禁止把 UI 演示数据当作另一份发布真值。

当前 v0.3 不能精确承载现有 UI 的 editorial category、中文 lead/body/key points、source display/byline、媒体 alt/展示元数据及 restricted/time 语义。建议由数据部创建 `mvp-local-v0.4` successor，保留 v0.3 为历史冻结证据，v0.4 接受后由 Spec/ADR 只指向一个活动合同版本。

## 2. 当前 P0 合同张力

### 2.1 不可用 M3 59 行承载 12 条已发布 synthetic 内容

当前 M3 Source projection 有 59 行，全部保持：

- `enabled=false`；
- `collection_onboarding_status=validating`；
- `dedup_status=pending`；
- `adapter_status=unchecked`；
- `adapter_authorization_status=unknown`；
- `platform_allowed=unknown`；
- `lifecycle_status=proposed`。

在这些状态下把任意 UI 合成内容绑定到真实 X Source，会虚构来源关系，并绕过规范化/查重、三门、五 fence、人工审核和发布不变量。该路径按 P0 处理。

### 2.2 v0.3 与 UI 字段的缺口

| UI 需求 | v0.3 可用字段 | 缺口 |
|---|---|---|
| 四类编辑分类 | `Content.content_kind` | `post/article/video/image/thread` 不表达赛事新闻/车手社交/名宿历史/赛场趣事 |
| 中文 lead/body/keyPoints | `Summary.title_zh` / `summary_zh` | 不能无损推导三类详情展开内容 |
| 来源显示名/byline | Source handle + release source snapshot | 不能推导编辑显示名和作者署名 |
| 媒体 alt/caption/credit/tone | `MediaCandidate.asset_ref`/hash/license/safety | 没有可访问展示元数据 |
| restricted/原链状态 | `monitorability`、URL、media status | 不能唯一推导内容可用性和原链禁用原因 |
| 时间显示与排序 | `Content.published_at`可空、`Publication.published_at`可空 | 需要区分源发布时间、发布投影时间和 unknown |

开发不得用“根据标题猜分类”、“按句号拆 body”、“把 handle 当 displayName”或类似启发式补齐。

### 2.3 v0.3 只有 3 条 PublishedProjection

`fixtures.synthetic.json` 现有 18 Source、8 CapturedItem、7 Content、7 Summary、5 Bundle、5 Decision、5 Publication 和 3 PublishedProjection。它们用于 v0.3 A 轴合同证明，不能冒充当前 12 条 UI 内容。新 12 条需要位于同一 `synthetic-case-seed` 层内的独立子集 `public-demo-12-v0.4`，并拥有独立 manifest/hash/count。

## 3. 隔离 fixture profile / DB（用户确认点 U1）

### 3.1 推荐形态

| 属性 | `m3-shadow` profile | `public-synthetic` profile |
|---|---|---|
| 用途 | 验证 59×39 M3 影子 Source projection | 运行 12 条本地 synthetic 公开阅读闭环 |
| SQLite | 现有 `.local/f1plus1.sqlite` | 建议 `.local/f1plus1-public-synthetic.sqlite` |
| Source 输入 | 59 行，全部 disabled | 冻结 v0.3 synthetic fixture 的 `src-active`，Source delta=0 |
| 内容图 | 不生成公开内容 | 12 套 CapturedItem → PublishedProjection |
| 权威边界 | 非真值，不写 Base | 非真值，不写 Base，仅 local synthetic |
| 外部 I/O | 0 | 0 |

运行时只能选择一个 fixture profile，同一进程不得同时 attach/合并两个库，不得在同一 `source_config_fixture` 表中混入 M3 59 行与 `src-active`。每个数据库用 `fixture_profile_ledger` 固定 `profile_id`、contract version、fixture manifest hash、row counts、`synthetic_only`、`external_calls=0`、`writes_to_base=0`；不匹配即拒绝启动。

accepted M4 ADR 当前记录“单一 SQLite 文件”的进程形态，并未逐字接受双 profile/隔离 DB。因此 U1 必须由用户确认，之后产品部才可创建 successor ADR/Spec 修订。

### 3.2 默认建议

为尽快交付可体验的初版，建议 Web 预览命令显式使用 `public-synthetic` profile；M3 59 行验证继续由独立 seed/verify 命令在 `m3-shadow` profile 中执行。不使用隐式默认和通配环境变量，每个命令的 profile 和 DB 路径均须通过 canonical allowlist 和路径安全校验。

## 4. mvp-local-v0.4 最小 successor（用户确认点 U2）

v0.4 保留 v0.3 的 13 个领域对象、6 组状态机、5 类幂等键、9 条不变量、`canonical-json-v1`、TaskEnvelope 和 internal-only 边界。它不增加领域实体、Base 字段或第二发布身份。

### 4.1 字段所有权

| 位置 | v0.4 必须字段 | 类型/枚举 | 语义 |
|---|---|---|---|
| `Content` | `editorial_category` | `race_news \| driver_social \| legends_history \| paddock_fun` | 编辑分类；API `contentType` 的唯一来源 |
| `Content` | `source_time_status` | `known \| unknown` | `known` 时 `Content.published_at` 必须为 RFC3339 date-time；`unknown` 时必须为 null |
| `Summary` | `lead_zh` | string，1–400 Unicode 字符 | 详情导语；不从 `summary_zh` 拆分 |
| `Summary` | `body_zh` | array，1–8 项，每项 1–1200 字符 | 详情正文段落；数组顺序进入 summary hash |
| `Summary` | `key_points_zh` | array，1–8 项，每项 1–240 字符，unique | 关键点；数组顺序进入 summary hash |
| `ReleaseBundle.canonical_payload.source_snapshot` | `display_name` | string，1–120 字符 | 审核时冻结的来源显示名；不回写 Source 39 字段 |
| 同上 | `byline` | string，1–120 字符 | 审核时冻结的公开署名 |
| `ReleaseBundle.canonical_payload.access_snapshot` | `content_access_status` | `available \| source_restricted` | 内容可用性；公开 `state` 的输入 |
| 同上 | `original_link_status` | `disabled_synthetic \| disabled_restricted \| available` | 原链是否可对外返回 |
| 同上 | `original_link_reason` | `synthetic_only \| source_restricted \| verified_available` | 稳定原因码，不使用任意错误文本 |
| `ReleaseBundle.canonical_payload.time_snapshot` | `source_published_at` | RFC3339 date-time or null | 与 Content 时间及 status 相符 |
| 同上 | `source_time_status` | `known \| unknown` | 同 Content 逐字匹配 |
| `ReleaseBundle.canonical_payload.media_presentation` | `mode` | `synthetic_placeholder \| none \| image` | M4 只允许前两项；`image` 继续关闭 |
| 同上 | `asset_ref` | string or null | `synthetic:` asset ref；`none` 必须 null |
| 同上 | `alt_zh` | string，1–300 字符 | 替代文本；`none` 是状态说明 |
| 同上 | `caption_zh` | string or null，最大 300 | 媒体说明 |
| 同上 | `credit_display` | string or null，最大 120 | 公开权利/来源显示 |
| 同上 | `tone` | `night \| blue \| amber \| violet \| slate \| null` | 只用于合成占位符；不代表实际图片颜色 |

`Content.content_hash_input` 必须新增 `editorial_category`、`source_time_status` 和 `published_at`；`Summary.summary_hash_input` 必须新增 `lead_zh`、`body_zh`、`key_points_zh`。ReleaseBundle payload/bundle hash 继续按更新后的 canonical payload 字节复算。v0.3 hash 不得在 v0.4 记录上复用。

### 4.2 公开派生状态

API 的 `state` 只是下列确定性派生，不写入领域表：

```text
if access_snapshot.content_access_status == source_restricted:
  state = restricted
else if media_presentation.mode == none:
  state = media_missing
else:
  state = available
```

`restricted` 优先于 `media_missing`。任何 unknown/缺失/非法枚举都是合同完整性错误，不默认为 `available`。

### 4.3 M4 原链和媒体安全值

- 12 条 synthetic 记录的 `originalLink.enabled=false`、`url=null`；原因只能是 `synthetic_only` 或 `source_restricted`。
- API 不返回 `synthetic.invalid` URL，不返回 Source canonical/evidence URL，不返回 Content external/canonical URL。这些值只用于领域/hash 证明。
- `media.mode` 只返回 `synthetic_placeholder` 或 null（对应 `none`）；没有 HTTP(S) URL、SVG、HTML、远程图像或下载。

## 6. 公开 API v0.1 合同

### 6.1 端点与通用响应

```text
GET /api/public/feed?cursorAt=&cursorId=&source=&contentType=
GET /api/public/stories/{publicId}
```

Route Handler 必须使用 Node runtime。成功响应 `Content-Type: application/json; charset=utf-8`，失败响应 `Content-Type: application/problem+json; charset=utf-8`。本地 synthetic profile 固定 `Cache-Control: no-store`。不返回 CORS 通配头，不信任 Host/Forwarded/X-Forwarded。

### 6.2 Feed request

| 参数 | 类型 | 规则 |
|---|---|---|
| `source` | optional string | Source schema 的 ID 形状，最大 128 字节；过滤 `ReleaseBundle.canonical_payload.source_snapshot.source_id` |
| `contentType` | optional enum | `race_news \| driver_social \| legends_history \| paddock_fun`；过滤 `Content.editorial_category` |
| `cursorAt` | optional RFC3339 UTC date-time | 首页缺省；续页必须与 `cursorId` 同时且仅出现一次 |
| `cursorId` | optional base64url no-padding string | 最大 512 字节；客户端必须视为不透明值；服务端解析后校验筛选绑定 |

仅允许上述四个 query key；未知、重复、空字符串、超长、非法 UTF-8/编码或单边 cursor 都返回 400。第一版不接受 `limit`，page size 固定为 12。

### 6.3 排序与 cursor

排序唯一固定为：

```sql
ORDER BY publication.published_at DESC, published_projection.public_id DESC
```

所有 `published` Publication 的 `published_at` 在 v0.4 中必须非空。服务端查询 `LIMIT 13`，返回前 12 条；第 13 条只用于判定 `hasMore`。续页条件为：

```sql
published_at < :cursorAt
OR (published_at = :cursorAt AND public_id < :cursorPublicId)
```

`cursorId` 内部载荷的 exact schema 为：

```json
{
  "v": 1,
  "publicId": "public-demo-example",
  "publishedAt": "2026-08-02T09:40:00Z",
  "source": null,
  "contentType": null
}
```

载荷使用 `canonical-json-v1` UTF-8 字节再做 base64url no-padding。服务端需要拒绝 unknown key、非 canonical 重编码、非法 `public-*` ID、`publishedAt != cursorAt`、筛选不匹配、目标 tuple 不存在或目标已不是完整 published 投影。这个不透明 cursor 不承诺保密性；它只是服务器合同，编辑正确性由绑定和数据库复核保证。

### 6.4 Public DTO allowlist

#### Feed

```ts
type PublicFeedResponseV1 = {
  schemaVersion: "public-read-v0.1";
  items: PublicFeedItemV1[];
  page: {
    pageSize: 12;
    hasMore: boolean;
    nextCursor: null | { cursorAt: string; cursorId: string };
  };
};

type PublicFeedItemV1 = {
  publicId: string;
  contentType: "race_news" | "driver_social" | "legends_history" | "paddock_fun";
  state: "available" | "restricted" | "media_missing";
  titleZh: string;
  summaryZh: string;
  publishedAt: string;
  sourcePublishedAt: string | null;
  sourceTimeStatus: "known" | "unknown";
  source: {
    sourceId: string;
    platform: "x" | "instagram" | "reddit" | "website" | "rss";
    displayName: string;
    byline: string;
    accessStatus: "available" | "restricted";
  };
  media: null | {
    kind: "synthetic_placeholder";
    assetRef: string;
    altZh: string;
    captionZh: string | null;
    creditDisplay: string | null;
    tone: "night" | "blue" | "amber" | "violet" | "slate";
  };
  originalLink: {
    enabled: false;
    url: null;
    reason: "synthetic_only" | "source_restricted";
  };
};
```

`publishedAt` 唯一来自 `Publication.published_at`，同时是排序键；`sourcePublishedAt` 来自已批准 Bundle 的 time snapshot。`source.sourceId` 唯一来自 `source_snapshot.source_id`，不从 URL/handle 反推。

#### Detail

```ts
type PublicStoryDetailResponseV1 = {
  schemaVersion: "public-read-v0.1";
  story: PublicFeedItemV1 & {
    leadZh: string;
    bodyZh: string[];
    keyPointsZh: string[];
  };
  relatedItems: PublicFeedItemV1[]; // 0..3
};
```

`relatedItems` 只能来自通过同一 projection-first 校验的内容：先按相同 `contentType`、再按全局候选补足，各组均按 feed 排序，排除当前 `publicId`，最多 3 条，去重后保持顺序。

DTO 一律 `additionalProperties=false`。不允许 AuditEvent、TaskEnvelope、Outbox、raw payload、prompt/model output、SQL/stack/path、五 fence、hash、reviewer/session、原始平台标识、未审核 Bundle、未 published Publication 或任意 URL 进入公开 DTO。

### 6.5 Detail request

- `publicId` URL segment 解码后必须符合 `^public-[a-z0-9-]{1,120}$`，否则 400 `PUBLIC_ID_INVALID`。
- 合法 ID 不存在、只存在于 Content/Bundle/Publication 但尚未有 published projection、已下架或未批准，均返回相同 404 `PUBLIC_STORY_NOT_FOUND`，不泄露内部状态。
- 已存在 PublishedProjection，但完整性/hash/fence/join 校验失败，返回 500 完整性 Problem，不降级为静态 demo 或部分 DTO。

## 7. projection-first 读取不变量

每个 feed/detail/related 候选都必须同时满足：

1. `PublishedProjection.projection_status=published`、`synthetic_only=true`、`external_calls=0`。
2. 存在唯一 `Publication`，`public_id`、content/summary/bundle ID、generation、`published_version_hash` 与 Projection 逐字一致。
3. `Publication.publication_status=published`、`emergency_stop=false`、`published_at` 非空。
4. 存在唯一 immutable `ReleaseBundle`，它的 content/summary/hash 与 Publication 逐字一致；`payload_hash`和 `bundle_hash` 从 canonical input 重算相等。
5. 存在唯一当前 `ReviewDecision(decision=approved)`，`approved_bundle_hash=Bundle.bundle_hash`，decision hash 可重算。
6. Content/Summary 存在，各自 version hash 可按 v0.4 输入重算，并与 Bundle/Publication 逐字匹配。
7. Bundle、Decision、Publication 的五 fence 逐字相等且均 `>=1`。
8. v0.4 source/access/time/media snapshots 字段完整，Source ID 等于 `src-active`，profile ledger 和 fixture manifest/hash/count 匹配。

候选行遇到 join 不完整、重复、hash 不一致、未知枚举、字段越界或 profile/manifest 漂移时，整个请求 fail closed：不返回已校验的部分项，不返 206，不跳过损坏行继续补足 12 条。

## 8. Problem JSON 与失败关闭

### 8.1 exact shape

```ts
type PublicProblemV1 = {
  type: string;       // urn:f1plus1:problem:{reason-code-lowercase}
  title: string;      // 稳定短标题
  status: number;
  detail: string;     // 安全、稳定、不回显输入或内部异常
  instance: string;   // 只包含路径，不包含 query
  reasonCode: PublicReasonCodeV1;
  traceId: string;    // 本次请求的脱敏不透明引用
};
```

`additionalProperties=false`；不返回 `error.message`、stack、SQL、DB path、fixture path/hash 实值、密钥、header/query/body、原始 URL 或 publicId 以外的平台标识。

### 8.2 状态码表

| HTTP | reasonCode | 场景 |
|---:|---|---|
| 400 | `PUBLIC_QUERY_INVALID` | 未知/重复/空/超长 query，非法 source/contentType |
| 400 | `PUBLIC_CURSOR_PAIR_REQUIRED` | `cursorAt`/`cursorId` 只有一个 |
| 400 | `PUBLIC_CURSOR_INVALID` | base64url/schema/canonical/tuple 非法 |
| 400 | `PUBLIC_CURSOR_SCOPE_MISMATCH` | cursor 中 source/contentType 与当前请求不一致 |
| 400 | `PUBLIC_ID_INVALID` | detail publicId 不合法 |
| 404 | `PUBLIC_STORY_NOT_FOUND` | 合法 ID 不存在或未公开/已下架 |
| 500 | `PUBLIC_READ_INCOMPLETE_CHAIN` | projection-first join 缺行、多行或 FK 不完整 |
| 500 | `PUBLIC_READ_INTEGRITY_FAILED` | canonical/hash/fence/version/snapshot 不一致 |
| 503 | `PUBLIC_DB_BUSY` | SQLite `BUSY/LOCKED` 在已批准有界等待后仍失败；返回 `Retry-After: 1` |
| 503 | `PUBLIC_PROFILE_UNAVAILABLE` | public-synthetic profile/manifest 未就绪或 profile 不符 |

未分类内部异常不得直接落到 Next 原始错误输出；必须由统一安全错误映射转为上述 closed Problem 或一个单独的通用 500 reason code，并通过安全部确认。

## 9. 前端接线边界

### 9.1 进入 API 的功能

- 四类 category → `contentType`。
- Source filter → `source_snapshot.source_id`。
- Feed 首页/续页、no-more、detail、404、related items。
- 公开内容、来源显示、restricted/media-missing 及原链禁用状态。

### 9.2 继续保留为客户端/本地预览的功能

- 关键词搜索：对当前已加载页的 title/summary 做本地包含搜索；API v0.1 不增加 `q`。
- `default/restricted/empty/no-more` 状态预览器：只属开发/验收控件，不进入生产 DTO 或领域 enum。
- 卡片排版、精选分组、主题、dialog/Chip 和焦点逻辑继续属于 UI。

### 9.3 单一前端数据来源

接线完成后，页面不得继续导入 `DEMO_STORIES`。现有 TypeScript 文案应一次性转移到 v0.4 fixture 生成输入，经 manifest/hash 生成 SQLite 图；之后删除运行时静态数据分支。如需回退，使用上一个已验证应用版本，不新增 `STATIC_FALLBACK=true` 第二读真值。

## 11. 迁移与回退

### 11.1 迁移

1. 记录 v0.3 11 个 artifact SHA、M3 59×39/e7a8 收据、现有 DB schema receipt 和 UI 演示数据 hash。
2. 在新 v0.4 candidate 目录生成 12 条领域图，不修改 v0.3 文件。
3. 新建 public-synthetic DB，只通过迁移器建表；seed 事务要么完整写入 manifest + `src-active` + 12 套图，要么全部回滚。
4. seed 后重读所有行，按 canonical-json-v1 重算 profile/fixture/entity/hash receipt；错一字即 fail closed。
5. API 和 UI 只在该收据通过后启动。

### 11.2 回退

- 迁移/seed 失败：保留错误 DB 作为脱敏证据，停止 Web，使用上一个已验证应用版本与其 DB；不做 down migration，不删改 migration ledger。
- API 完整性失败：停止公开读取，返回 closed Problem，不回退到静态 `DEMO_STORIES`。
- UI 接线回归：回退整个应用版本，不通过运行时开关同时保留 DB 和静态两份真值。
- M3 证据受损：立即拒绝启动；恢复准确的 M3 备份/已验证版本，绝不从 public-synthetic DB 反写。

## 13. 可自主决定与必须用户确认

### 13.1 在已确认方向内可由产品/开发自主落实

- DTO 属性命名、closed JSON Schema、Problem reasonCode 和安全文案，前提是不改变本文语义。
- page size 12、固定 keyset 排序、cursor 编码与筛选绑定。
- migration 的物理列类型、索引、repository 模块划分、SQL 查询细节，前提是服从唯一 v0.4 合同和不变量。
- 演示 actor/reviewer 的 synthetic ID、canonical fixture timestamp 和可复现 hash 生成，前提是不暗示真实人工操作。
- 公开前端的精选布局、本地搜索、主题和可访问性保持。

### 13.2 用户必须确认

1. **U1｜隔离 DB/profile：** 是否接受 M3 59 行库与 12 条公开 synthetic 库物理隔离，Web 预览显式运行 `public-synthetic` profile？
2. **U2｜v0.4 successor：** 是否接受用 v0.4 增加编辑分类、中文详情、来源/媒体/受限/时间 snapshot，并把 12 个 UI ID 更名为合法 `public-demo-*`？

下列事项仍需各自独立用户门禁，不随 U1/U2 自动开启：真实 Source 激活、Base/provider 切换、平台采集、AI 摘要、真实媒体/原链对外、自动发布、部署、付费、生产认证与跨网络 admin。

## 14. 失败路径

1. **隔离方案未确认或不可机械证明：** 停止 12 条 DB/API 接线，继续保留已完成前端为 local synthetic 预览；不把 `src-active` 混入 M3 59 行，不绑定真实 X Source。
2. **v0.4 字段/hash/FK 不可无歧义复算：** 数据任务 FAIL，保留 v0.3 为唯一 accepted 合同；开发不用 UI 派生/启发式补字段，不生成伪 published 图。
3. **读链任一 join/hash/fence/profile 损坏：** 整页/整个详情 fail closed，返回 closed Problem，不返部分内容，不跳过损坏行，不降级到静态第二真值。

## 15. 未验证项
