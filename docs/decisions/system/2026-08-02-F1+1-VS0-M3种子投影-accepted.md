# ADR-M4-VS0-SEED-001：M3 影子种子 Source 投影语义（accepted）

> 本 ADR 是 VS-0 的窄范围实现决策。它只冻结本地 fixture projection 的派生值、日期表示、来源证明和 hash 排序规则，不修改已 accepted 的 M4 技术路线，不修改冻结 v0.3 data schema/state machine，不写 Base，不切 provider，不创建第二套领域 schema。

## 1. 背景与证据

`TASK-20260802-6DAEAE` 的 bridge 复核确认：M3 主信源输入为 33 列、59 行，冻结 v0.3 `Source` required 为 39 列；差集恰为 `platform_allowed`、`source_config_epoch`、`created_at`、`updated_at`、`created_by_ref`、`updated_by_ref` 六项。`source_safety_epoch` 虽在冻结 mapping 的旧 `local_only` 注记中出现，实际已存在于 M3 33 列，必须按 direct field ownership 逐字读取。

唯一待决冲突是 M3 `added_at=2026-07-31 00:00:00` 的 transport 表示与 `Source.added_at` 的 `format=date` 目标约束。数据部 bridge 已完成 59×39 结构校验、59/59 disabled、双跑确定性校验，并给出当前 candidate projection hash `96d5caf625f62d059cc51a41d7c3b6a1db623d07cea00c4d256e2d841c693aa2`；此前总状态仅因该产品语义尚未确认而 `FAIL_BLOCKED_BY_PRODUCT_DECISION`。

## 2. accepted 决定

### 2.1 M3 direct 与六项 derived 字段

M3 的 33 个 direct 字段继续由冻结 `data/mvp-contract-v0/base-mapping.json` 所有，原值、原始字节和输入 hash 不被覆盖。六项缺失的 `Source` required 字段固定为以下确定性规则：

| Source 字段 | accepted 值/规则 | 语义边界 |
|---|---|---|
| `platform_allowed` | `unknown` | M3 没有平台策略、限流或合规证据；不满足 activation gate。 |
| `source_config_epoch` | 整数 `1` | 首个本地 fixture/provider epoch；不表示真实 Base/provider 已切换，不自动递增。 |
| `created_at` | `normalized_added_at + T00:00:00Z` | 从明确的日历日期构造 UTC 午夜；不读取机器墙钟。 |
| `updated_at` | 与 `created_at` 逐字相等 | M3 是 creation-only shadow import，没有更新事件。 |
| `created_by_ref` | `synthetic:seed-m3-v0` | 固定合成 actor，不代表真实用户、账号、token 或凭证。 |
| `updated_by_ref` | `synthetic:seed-m3-v0` | 与创建 actor 相等；同一 creation-only seed event。 |

`source_safety_epoch` 不属于 derived 字段：其优先级高于旧 `local_only` 注记，59 行均从 M3 原值直读，当前值集合为 `{1}`。本决策不把该字段移入第二 schema，也不改变冻结 data 文件。

### 2.2 `added_at` 日期与时区规则

只接受精确匹配以下 transport 形状的 M3 值：

```text
^YYYY-MM-DD 00:00:00$
```

并按同一日历日期投影：

```text
2026-07-31 00:00:00  ->  Source.added_at = 2026-07-31
```

该转换保留 M3 的日期语义，满足 `Source.added_at` 的 `format=date`。它不做字符串静默截断、不转 RFC3339 写入 `Source.added_at`、不推断本地时区、不进行跨日换算、不舍入，也不增加 `raw_added_at`、`added_at_datetime` 或其他业务字段。若任一行出现非午夜时间、其他分隔符或非法日期，validator 必须 fail closed，禁止自行选择时区或修正值。

`created_at` 才使用 `YYYY-MM-DDT00:00:00Z`；`updated_at` 与它相等。`Source.added_at` 保持无时区的 canonical 日历日期。

### 2.3 local fixture projection 与安全默认值

本决策只允许生成本地、不可作为真值的 `Source` fixture projection：

- 59 行按 M3 `source_id` 一一映射，`enabled=false` 保持 59/59；`identity_status`、`relevance_status`、`monitorability` 仍为 `unknown`，`dedup_status`、授权和 onboarding 等 `pending/proposed/null` 保持原值。
- `platform_allowed=unknown`、`source_config_epoch=1` 和 `source_safety_epoch=1` 不触发激活、不创建任务、不切换 provider、不提升状态。
- `migration_batch_id` 和 M3 原始字段值继续保留；bridge manifest 记录输入文件、冻结 schema/mapping、版本、行数、`external_calls=0`、`writes_to_base=false`、`non_authoritative=true`、`second_domain_schema=false` 等 provenance。
- 不访问或写入 Base、飞书、provider、Collector、平台、AI、媒体、发布或部署服务。

### 2.4 canonical projection hash 与排序

实现收据固定为：

```text
projection_object = {
  fields: Source.required in frozen schema order,
  rows: enriched_rows sorted by source_id ascending
}
canonical_projection_hash = SHA-256(canonical-json-v1(projection_object))
```

排序规则是 `source_id` 的 Unicode code point 升序；不做大小写折叠、locale 排序、trim 或隐式类型转换。`source_id` 重复、字段顺序变化、39 列不完整、任一 enabled/unknown/pending/proposed 值升级或输入 artifact hash 漂移均使 validator fail closed。现有 bridge candidate 的 59×39 hash `96d5caf625f62d059cc51a41d7c3b6a1db623d07cea00c4d256e2d841c693aa2` 作为当前实现收据；下一次只读 validator 复跑须按本 ADR 规则确认字节一致后，VS-0 才可将 projection 作为本地 seed 输入。

## 3. provenance、保留与不变量

1. M3 原始 batch、fields、manifest 及其 SHA-256 原值保留；projection 是派生实现输入，不能反写或替代 M3。
2. Source 39 required、M3 direct 33/9 和 `source_safety_epoch` direct ownership 分开记录；不得把 33 误报成 39，也不得把 6 项 derived 字段写回冻结 data schema。
3. 所有投影都必须带有可追溯的输入 hash、mapping/version、`M3-20260801-X59-01` 批次、row count、field count、projection hash 和 `external_calls=0` 证明。
4. 任何不符合精确日期规则、来源 hash、字段顺序、唯一性或保守状态的 projection 都停止；不通过降级、截断、猜时区或补写第二字段来继续。

## 4. 接受范围与后续门禁

- 本 ADR 的 `accepted` 只覆盖上述 VS-0 实现语义，Spec 继续引用它作为唯一投影规则入口。
- 它不接受或升级数据部 bridge 的其他合同，不改变 `mvp-local-v0.3` schema、state machine、mapping、manifest 或 fixtures。
- 它不代表 VS-0 代码、Repository、SQLite seed command、UI/API、完整 R12 或 VS-1–3 已完成；后续任务必须使用本 ADR 的 projection 规则并提交独立收据。
- 它不授权任何真实 Base/provider/Collector/平台/AI/媒体/发布/部署/付费/外发操作。
