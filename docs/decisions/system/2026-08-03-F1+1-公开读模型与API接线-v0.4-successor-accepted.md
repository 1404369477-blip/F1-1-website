# ADR-M4-PUBLIC-READ-001：公开读模型与 API 接线 v0.4 successor（accepted）

> 用户于 2026-08-03 接受 U1 与 U2：使用物理隔离的 `m3-shadow`、`public-synthetic` 两个 profile/SQLite 文件；采用最小 `mvp-local-v0.4` successor，并将 12 个演示公开身份改为 `public-demo-*`。本 ADR 在该窄范围内修订 `ADR-M4-KICKOFF-001` 的“单一 SQLite 文件”进程形态和活动数据合同版本；前任 accepted ADR 的其余正文继续有效且不原地改写。

## 1. accepted 结论与权威边界

M4 公开预览使用一份物理隔离的 `public-synthetic` 本地数据库。M3 影子验证继续使用独立 `m3-shadow` 数据库。每个进程只允许选择一个显式 profile，不得 attach、合并或交叉写入两个数据库。

公开内容只有一条领域链：

```text
src-active
  → CapturedItem
  → Content
  → Summary
  → optional MediaCandidate
  → immutable ReleaseBundle
  → approved ReviewDecision
  → published Publication
  → read-only PublishedProjection
  → public DTO
```

读取从 `PublishedProjection` 起步，再逐条验证 `Publication`、批准的 `ReviewDecision`、不可变 `ReleaseBundle`、Content/Summary、hash、五个 fence 和 profile ledger。以下路径全部禁止：

- 增加 `public_story` 或其他第二公开真值；
- 直接把前端 `DemoStory` 序列化为 API 响应；
- 把 12 条 synthetic 内容绑定到 59 个真实 X 候选 Source；
- 绕过 CapturedItem、人工批准或 Publication 直接生成 PublishedProjection；
- 在 API 完整性失败时降级到静态演示数据。

现有 `mvp-local-v0.3`、M3 输入和 accepted Source 投影均保留为历史冻结证据。`mvp-local-v0.4` 只追加现有 UI 无法由 v0.3 无损表达的字段，不增加领域实体、Base 字段、发布身份或外部能力。

## 2. 双 profile / 双 SQLite 文件

| 属性 | `m3-shadow` | `public-synthetic` |
|---|---|---|
| 用途 | 验证 M3 影子 Source projection | 运行 12 条 synthetic 公开阅读闭环 |
| SQLite 文件 | `.local/f1plus1.sqlite` | `.local/f1plus1-public-synthetic.sqlite` |
| Source 输入 | 59 行 M3 影子 Source | 逐字复用 v0.3 synthetic fixture 的 `src-active` |
| 内容图 | 不生成公开内容 | 12 套 CapturedItem 至 PublishedProjection |
| 权威性 | local fixture，非业务真值 | local synthetic，非业务真值 |
| 外部副作用 | `external_calls=0`、`writes_to_base=0` | `external_calls=0`、`writes_to_base=0` |

### 2.1 M3 冻结不变量

`m3-shadow` 必须持续满足：

- 59 行、每行 39 个 Source 投影字段；
- 59 行全部 `enabled=false`，既有 validating/pending/unknown/proposed 保守状态不提升；
- 唯一权威 projection hash 为 `e7a8312c70a9a49922aedb3cfbeaa190db8f5dce8d4ab45db1570748fc329f17`；
- 不增加第 60 行，不导入 `src-active`，不从 `public-synthetic` 反写；
- 既有 v0.3 artifact、schema、mapping、fixture 和 manifest 的字节与 SHA-256 不因本决策改变。

### 2.2 profile ledger 与启动拒绝

每个数据库必须有 `fixture_profile_ledger`，至少固定：

- `profile_id`；
- active contract version；
- fixture manifest hash 与各实体 row count；
- `synthetic_only`；
- `external_calls=0`；
- `writes_to_base=0`；
- `real_content_imported=false`。

启动命令必须显式选择 canonical allowlist 中的一个 profile 和一个受路径安全约束的数据库文件。profile、路径、manifest、contract version、count 或安全标志任一不匹配时拒绝启动；同一进程发现两个 profile 的表或 Source 混合时同样拒绝。

## 3. `mvp-local-v0.4` 最小 successor

v0.4 沿用 v0.3 的 13 个领域对象、6 组状态机、5 类幂等键、9 条不变量、`canonical-json-v1`、TaskEnvelope 和 internal-only 边界。数据部只能在 successor artifact 中追加下表字段；v0.3 文件保持冻结。

### 3.1 字段所有权

| 所有者 | v0.4 字段 | 类型/枚举 | 公开语义 |
|---|---|---|---|
| `Content` | `editorial_category` | `race_news \| driver_social \| legends_history \| paddock_fun` | API `contentType` 的唯一来源 |
| `Content` | `source_time_status` | `known \| unknown` | `known` 要求 `published_at` 为 RFC3339 UTC；`unknown` 要求 null |
| `Summary` | `lead_zh` | string，1–400 字符 | 详情导语 |
| `Summary` | `body_zh` | array，1–8 项，每项 1–1200 字符 | 详情正文段落，顺序进入 hash |
| `Summary` | `key_points_zh` | array，1–8 项，每项 1–240 字符，unique | 关键点，顺序进入 hash |
| `source_snapshot` | `display_name` | string，1–120 字符 | 审核时冻结的来源显示名 |
| `source_snapshot` | `byline` | string，1–120 字符 | 审核时冻结的公开署名 |
| `access_snapshot` | `content_access_status` | `available \| source_restricted` | 公开状态输入 |
| `access_snapshot` | `original_link_status` | `disabled_synthetic \| disabled_restricted \| available` | 原链可用性 |
| `access_snapshot` | `original_link_reason` | `synthetic_only \| source_restricted \| verified_available` | 稳定原因码 |
| `time_snapshot` | `source_published_at` | RFC3339 UTC string or null | 来源时间快照 |
| `time_snapshot` | `source_time_status` | `known \| unknown` | 与 Content 逐字一致 |
| `media_presentation` | `mode` | `synthetic_placeholder \| none \| image` | M4 只允许前两项 |
| `media_presentation` | `asset_ref` | string or null | `synthetic:` 引用；`none` 时 null |
| `media_presentation` | `alt_zh` | string，1–300 字符 | 可访问替代文本或无图状态说明 |
| `media_presentation` | `caption_zh` | string or null，最大 300 字符 | 媒体说明 |
| `media_presentation` | `credit_display` | string or null，最大 120 字符 | 权利/来源显示 |
| `media_presentation` | `tone` | `night \| blue \| amber \| violet \| slate \| null` | synthetic 占位符视觉提示 |

`Content.content_hash_input` 必须新增 `editorial_category`、`source_time_status`、`published_at`。`Summary.summary_hash_input` 必须新增 `lead_zh`、`body_zh`、`key_points_zh`。ReleaseBundle payload/bundle hash 继续基于完整更新后的 canonical payload 重算。v0.4 记录禁止复用 v0.3 内容或摘要 hash。

### 3.2 公开状态派生

`state` 只在读取时按下列顺序派生，不持久化为第二领域状态：

```text
if content_access_status == source_restricted: restricted
else if media_presentation.mode == none: media_missing
else: available
```

缺失、unknown 或非法 enum 触发完整性失败；不得默认为 `available`。

### 3.3 M4 原链与媒体

- 12 条 synthetic 记录的 `originalLink.enabled=false`、`url=null`，reason 只允许 `synthetic_only` 或 `source_restricted`。
- 公开 DTO 不返回 `synthetic.invalid`、Source canonical/evidence URL 或 Content external/canonical URL。
- `media.mode` 只返回 `synthetic_placeholder` 或 null；不返回 HTTP(S) URL、SVG、HTML、远程图片或下载结果。
- 真实原链、真实图片、媒体代理、平台登录和媒体抓取继续关闭。

## 5. 公开 API v0.1

### 5.1 端点与响应头

```text
GET /api/public/feed?cursorAt=&cursorId=&source=&contentType=
GET /api/public/stories/{publicId}
```

Route Handler 使用 Node runtime。成功返回 `application/json; charset=utf-8`；失败返回 `application/problem+json; charset=utf-8`；本地 synthetic profile 固定 `Cache-Control: no-store`。不返回通配 CORS，不信任 Host、Forwarded 或 X-Forwarded 系列头。

### 5.2 Feed 请求、排序与 cursor

只接受四个 query key：

| 参数 | 规则 |
|---|---|
| `source` | optional；Source ID 形状，最大 128 bytes；过滤批准 Bundle 的 `source_snapshot.source_id` |
| `contentType` | optional；四类 `editorial_category` enum |
| `cursorAt` | optional RFC3339 UTC；续页时与 `cursorId` 成对出现 |
| `cursorId` | optional base64url no-padding，最大 512 bytes；客户端按不透明值处理 |

未知、重复、空、超长、非法编码、非法 enum 或单边 cursor 均返回 400。第一版 page size 固定为 12，不接受 `limit`。

排序固定为：

```sql
ORDER BY publication.published_at DESC, published_projection.public_id DESC
```

查询 `LIMIT 13`，前 12 条进入响应，第 13 条只判定 `hasMore`。续页谓词固定为：

```sql
published_at < :cursorAt
OR (published_at = :cursorAt AND public_id < :cursorPublicId)
```

`cursorId` 解码后的 closed payload 为：

```json
{
  "v": 1,
  "publicId": "public-demo-example",
  "publishedAt": "2026-08-02T09:40:00Z",
  "source": null,
  "contentType": null
}
```

该对象按 `canonical-json-v1` 转 UTF-8 后做 base64url no-padding。服务端必须拒绝 unknown key、非 canonical 重编码、非法 public ID、`publishedAt != cursorAt`、筛选绑定不匹配、目标 tuple 不存在或目标已失去完整 published 链。cursor 不承诺保密性或密码学防伪。

### 5.3 Public DTO allowlist

```ts
type PublicFeedResponseV1 = {
  schemaVersion: "public-read-v0.1";
  items: PublicFeedItemV1[];
  page: {
    pageSize: 12;
    hasMore: boolean;
    nextCursor: null | { cursorAt: string; cursorId: string };
  };
};

type PublicFeedItemV1 = {
  publicId: string;
  contentType: "race_news" | "driver_social" | "legends_history" | "paddock_fun";
  state: "available" | "restricted" | "media_missing";
  titleZh: string;
  summaryZh: string;
  publishedAt: string;
  sourcePublishedAt: string | null;
  sourceTimeStatus: "known" | "unknown";
  source: {
    sourceId: string;
    platform: "x" | "instagram" | "reddit" | "website" | "rss";
    displayName: string;
    byline: string;
    accessStatus: "available" | "restricted";
  };
  media: null | {
    kind: "synthetic_placeholder";
    assetRef: string;
    altZh: string;
    captionZh: string | null;
    creditDisplay: string | null;
    tone: "night" | "blue" | "amber" | "violet" | "slate";
  };
  originalLink: {
    enabled: false;
    url: null;
    reason: "synthetic_only" | "source_restricted";
  };
};

type PublicStoryDetailResponseV1 = {
  schemaVersion: "public-read-v0.1";
  story: PublicFeedItemV1 & {
    leadZh: string;
    bodyZh: string[];
    keyPointsZh: string[];
  };
  relatedItems: PublicFeedItemV1[];
};
```

所有公开 schema 使用 `additionalProperties=false`。`relatedItems` 为 0–3 条：先取同 contentType，再按全局排序补足，排除当前 publicId，去重后保持顺序。AuditEvent、TaskEnvelope、Outbox、raw payload、prompt/model output、SQL/stack/path、五 fence、hash、reviewer/session、未审核 Bundle、未 published Publication、私密 URL 和原始平台包均不得进入 DTO。

### 5.4 Detail 请求

- 解码后的 `publicId` 必须符合 `^public-[a-z0-9-]{1,120}$`；非法形状返回 400 `PUBLIC_ID_INVALID`。
- 合法 ID 不存在、未有 published projection、已下架或未批准均返回相同 404 `PUBLIC_STORY_NOT_FOUND`，不泄露内部状态。
- 存在 Projection 但完整性/hash/fence/join 失败时返回 500 完整性 Problem，不返回静态或部分内容。

## 6. projection-first 完整性不变量

Feed、detail 和 related 的每个候选必须同时满足：

1. Projection 为 `published`，且 `synthetic_only=true`、`external_calls=0`。
2. 唯一 Publication 与 Projection 的 publicId、引用、generation、published version hash 逐字一致。
3. Publication 为 `published`、`emergency_stop=false`、`published_at` 非空。
4. 唯一 immutable ReleaseBundle 的引用和 hash 与 Publication 一致，payload/bundle hash 可重算。
5. 唯一当前 ReviewDecision 为 `approved`，`approved_bundle_hash=Bundle.bundle_hash`，decision hash 可重算。
6. Content/Summary 存在，v0.4 version hash 可重算并与 Bundle/Publication 一致。
7. Bundle、Decision、Publication 的五个 fence 逐字一致且都大于等于 1。
8. v0.4 snapshots 完整，Source ID=`src-active`，profile ledger 与 manifest/hash/count 一致。

任一候选出现缺行、多行、FK、hash、fence、enum、字段界限、profile 或 manifest 漂移时，整个请求 fail closed。禁止 206、跳过损坏行、返回已通过的部分项或补足其他内容。

## 7. Problem JSON 与失败出口

```ts
type PublicProblemV1 = {
  type: string;
  title: string;
  status: number;
  detail: string;
  instance: string;
  reasonCode: PublicReasonCodeV1;
  traceId: string;
};
```

Problem 使用 `additionalProperties=false`。`instance` 只含路径，不含 query。`detail` 使用稳定安全文本，不回显输入或内部异常。禁止输出 error.message、stack、SQL、数据库/fixture 路径、hash 实值、header/query/body、密钥、原始 URL 或内部平台标识。

| HTTP | reasonCode | 失败路径 |
|---:|---|---|
| 400 | `PUBLIC_QUERY_INVALID` | query 未知、重复、空、超长或 enum 非法 |
| 400 | `PUBLIC_CURSOR_PAIR_REQUIRED` | cursorAt/cursorId 只有一项 |
| 400 | `PUBLIC_CURSOR_INVALID` | base64url/schema/canonical/tuple 非法 |
| 400 | `PUBLIC_CURSOR_SCOPE_MISMATCH` | cursor 筛选绑定不匹配 |
| 400 | `PUBLIC_ID_INVALID` | detail publicId 非法 |
| 404 | `PUBLIC_STORY_NOT_FOUND` | 合法 ID 不公开或已下架 |
| 500 | `PUBLIC_READ_INCOMPLETE_CHAIN` | projection-first join 缺行、多行或 FK 不完整 |
| 500 | `PUBLIC_READ_INTEGRITY_FAILED` | canonical/hash/fence/version/snapshot 不一致 |
| 503 | `PUBLIC_DB_BUSY` | SQLite BUSY/LOCKED 经批准的有界等待后仍失败；加 `Retry-After: 1` |
| 503 | `PUBLIC_PROFILE_UNAVAILABLE` | profile/manifest 未就绪或不匹配 |

未分类内部异常进入统一安全错误映射；开发不得让 Next 原始异常直接成为 HTTP 响应或进程错误出口。

## 8. 前端接线边界

API v0.1 承载四类 `contentType`、source filter、首页/续页/no-more、detail/404/related、公开文案、来源显示、restricted/media-missing 和原链禁用状态。

关键词搜索继续只对当前已加载页的 title/summary 做本地包含匹配。`default/restricted/empty/no-more` 状态预览器、精选布局、主题、dialog/Chip 与焦点逻辑继续属于 UI/验收层，不进入领域 enum 或 API。

接线完成后页面不得导入 `DEMO_STORIES`。现有前端内容一次性转移到 v0.4 fixture 生成输入，经 manifest/hash 生成 SQLite 图。回退使用上一套完整已验证应用与匹配数据库；禁止 `STATIC_FALLBACK=true` 或并行静态读分支。

## 10. 迁移与回退

### 10.1 迁移

1. 记录 v0.3 artifact SHA、M3 59×39/e7a8、既有 DB schema receipt 与前端 12 条输入 hash。
2. 在新的 v0.4 successor 目录生成 12 套领域图，不修改 v0.3 文件。
3. 新建 `public-synthetic` DB，只通过只追加 migration 建表；seed 在一个事务内写入 ledger、`src-active` 与 12 套图，任一失败整笔回滚。
4. seed 后重读全部记录，按 `canonical-json-v1` 重算 profile、manifest、实体、hash 与 count；任一不符拒绝启动。
5. API/UI 只在数据、安全与测试门禁通过后接线。

### 10.2 回退

- migration/seed 失败：停止 Web，保留脱敏失败证据，回退整个应用版本及其匹配数据库；不执行 down migration，不改 migration ledger。
- API 完整性失败：返回 closed Problem 并停止公开读取，不启用静态第二真值。
- UI 回归：回退整个应用版本及匹配数据库，避免同一版本并存两套读真值。
- M3 收据受损：拒绝启动并从准确备份/已验证版本恢复 `m3-shadow`；绝不从 public-synthetic 反写。

| UI-02 | 390/1440、dark/light、keyboard、empty/restricted/no-more 无回归 |
| SEC-01 | DNS/HTTP/raw socket/proxy/subprocess 外部调用为 0 |
| SEC-02 | stderr/HTTP 失败出口无 stack/path/URL/SQL/secret |
| OPS-01 | 连续两次 migrate/seed/start 不新增行，hash/count 稳定 |
| RB-01 | 回退不用 down migration 或 static fallback，M3 不受影响 |

## 12. 失败路径与未验证项

### 12.1 必须演练的失败路径

1. **profile 或隔离证明失败**：停止 DB/API 接线；`src-active` 不进入 M3 59 行库，前端只保留上一套已验证预览版本。
2. **v0.4 字段、hash 或 FK 不可无歧义复算**：数据任务失败；v0.3 继续作为历史冻结证据，开发禁止启发式补字段或伪造 published 图。
3. **join/hash/fence/profile 任一损坏**：整个 feed/detail 请求返回 closed Problem；不跳行、不返部分内容、不降级静态数据。

### 12.2 当前未验证

- v0.4 schema、generator、12 套 fixture/manifest/hash 尚待数据部生成和独立审核。
- SQLite migration/repository/API/cursor/Problem/DB busy 映射和前端接线尚未实现。
- 真实原链、真实图片、平台时间可信度、生产缓存、签名 cursor、生产数据库与部署行为尚未验证。
- VS-0 启动错误脱敏、R5 同 UID 威胁模型和完整 R12 由独立任务处理，本 ADR 不提供通过证明。

## 13. 持续关闭的外部能力

本决定不授权或开启：

- Base 业务真值切换、`base_direct`、`base_snapshot` 或 Collector；
- X、Instagram、Reddit、新闻/RSS 的真实访问、登录或采集；
- 飞书真实读写、表单提交、OAuth 重授权/撤权/轮换；
- AI 摘要、真实媒体抓取/代理、真实原链对外；
- 自动发布、外部发布、部署、付费、生产认证、跨网络 admin；
- 对外公开 12 条 synthetic 演示内容。

上述能力各自需要独立证据、风险检查和用户门禁。M4 当前只允许 local fixture/mock、loopback、manual-only、`external_calls=0`。
