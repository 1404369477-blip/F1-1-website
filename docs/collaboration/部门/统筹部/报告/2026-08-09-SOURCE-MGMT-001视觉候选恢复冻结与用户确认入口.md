# SOURCE-MGMT-001 视觉候选恢复冻结与用户确认入口

## 结论

设计部已经生成 Mac/iPhone、深浅主题的可交互信源管理候选和四张视觉证据。原设计部会话曾在最终收口阶段触发用量上限；同一窗口后来恢复，补齐了 v0.3/安全时态、横向浏览与固定操作列说明，并把修订后运行证据仍为 `Unknown` 的边界如实保留。任务 `TASK-20260809-08CCEF` 现已 `completed` 并由统筹 ACK；期间没有新建设计部窗口。

候选可以交用户判断视觉方向。其随附 `SHA256.txt` 和设计报告已由同一设计部窗口更新为当前时态；统筹部同步把闭集冻结 manifest 升级为 v2，绑定已 ACK 的任务、现行候选字节、四张既有参考图、v0.3 与安全复验：

- `docs/collaboration/部门/统筹部/报告/2026-08-09-SOURCE-MGMT-001视觉候选统筹冻结manifest.json`

后续只允许以该 manifest 的闭集身份作为用户确认与开发映射入口；候选目录内清单和设计报告作为支持证据。任何字节漂移都使本确认入口失效。

## 当前候选可判断的内容

- Mac：高密度表格、右侧详情 Drawer、固定操作列。
- iPhone：卡片列表、全屏详情和确认层，功能语义与 Mac 等价。
- 深浅主题、信号橙、44px 控件、焦点样式、safe-area 和 reduced-motion 锚点。
- `source_add`、`source_validate`、`source_activate`、`source_stop`、`source_retire`、`source_requeue` 六类操作。
- loading、empty、partial、error、guard-shell、conflict、stale、blocked、dead-letter、active、stopped、response-unknown 等状态与恢复文案。
- URL 为不可点击纯文本；页面没有可编辑 session、CSRF、command key、business identity 或 lease 字段。

## 1440 裁切复核

四张截图的 Mac 表格右侧内容看起来被视口裁切，这一点不能仅凭截图解释。当前 HTML 已包含三层恢复设计：

1. 表格容器可获得键盘焦点并带“可横向滚动”的区域标签；
2. 表格上方有明确的左右“列”按钮、位置百分比和横向浏览提示；
3. 最右 ACTIONS 列使用 sticky 固定，详情和当前可执行动作保持可达。

因此截图裁切不构成已证实的功能不可达；真实实现仍必须在 1440/1024/390 和键盘/触控环境独立验证。开发不得把 `body{overflow-x:hidden}` 当作隐藏表格内容的手段，表格局部滚动和固定操作列必须同时保留。

## 与 v0.3 的关系

产品 v0.3 当前固定 SHA-256 为 `90ee4ed30d325b7b2833582cc0ac8134aefc7fbc2dcd43ec9d20c0f726b2f1fe`；实施前安全复验已经 PASS，`P0=0/P1=0/P2=0`。当前候选表达了 guard-shell、zero-write conflict、response-unknown、fresh confirmation 和凭据不进入编辑路径，未发现与 v0.3 用户可见语义直接冲突。

合同兼容仍不等于实现完成：raw authority、session、CSRF、identity、SQLite、Outbox、worker、并发和 11+16 golden 均需由真实代码和独立测试证明。

## 用户确认之后的唯一主链

1. 产品部引用统筹冻结 manifest，生成不可变的正式实现视觉映射；
2. 开发部按精确设计 hash、v0.3 合同和 Function ID 实现 `/admin/sources`；
3. 测试部与安全部对同一运行候选独立复验；
4. 设计部对正式运行候选补做独立设计核验，重点关闭修订后 1440 sticky actions、390 无横溢、键盘横滚和四张新截图的 `Unknown`；当前预览任务 ACK 不外推为正式 App 通过。

当前仍未授权开发实现、真实信源、真实外联、远程 Admin 或生产部署。用户确认的对象仅是当前视觉与交互方向。
