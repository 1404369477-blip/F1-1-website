# 首批采集路径官方证据刷新

## 0. 结论

截至 2026-08-08，适合首条纵切的候选收敛为两条公开 RSS 路径，且仅建议做**本地、低频、非生产、链接优先**的技术验证：

1. **Motorsport.com Formula 1 News RSS**：公开 GET 可达，50/50 条含 `title`、`link`、`description`、`pubDate`、`guid` 与图片 `enclosure`；最适合验证 15 分钟发现、解析、去重和删除/失效巡检。其使用条款把内容限定于个人信息用途，并限制未经书面授权的复制、分发和商业使用；生产展示摘要与图片前必须由产品/安全确认权利路径。
2. **Formula1.com Latest F1 News RSS**：公开 GET 可达，10/10 条含标题、描述、原链和 GUID，但 0/10 含发布时间、0/10 含图片 enclosure。其 RSS 条款明确禁止商业聚合，并禁止编辑、翻译或修改 feed 内容；因此可做结构与可达性验证，不能直接证明 15 分钟 SLA，也不能直接驱动中文摘要或图片展示。

**FIA News RSS** 可作为第三顺位的治理/规则补充源：公开 GET 可达且 10/10 含 `pubDate`，但 feed 覆盖 FIA 全项目，并非 F1 专用，正文/图片复用仍受 FIA 权利条款限制。首条纵切若只保留最少实体，不建议把它放进 P0。

平台结论：

- **X**：现有 59 条白名单可用作后续规则输入；官方 API 要求开发者账号、Project/App、Bearer Token，并采用预付 credits 的按量付费。真实调用涉及账号与付款，当前归类为 `needs_user_auth + needs_payment`。`@F1` 已由 Formula 1 自有 corporate 页面回链验证；其余清单身份和可监控性不因 handle 存在而自动升级。
- **Reddit**：官方要求注册 OAuth token、唯一 User-Agent；符合免费资格的客户端为 100 QPM/OAuth client id，但商业用途需要另签协议。当前归类为 `needs_user_auth`，商业场景同时为 `commercial_agreement_unknown`。
- **Instagram**：官方 API 面向 Business/Creator 专业账号并需要 access token；个人消费者账号不可由该路径读取。公开帖子 embed 只覆盖已知 URL、公开账号且启用 Embeds 的展示，不能承担发现。任何网页自动采集都需 Meta 另行明确书面许可。当前 API 路径归类为 `needs_user_auth`，消费者账号发现为 `manual_only`，未经许可的自动网页采集为 `exclude`。

本报告不开放真实平台采集、付费、OAuth、生产展示或新信源启用。技术可达性与内容使用权是两道独立门禁。

## 1. 范围、方法与证据等级

### 1.1 任务边界

- 只使用平台官方开发文档、平台/出版方自有 RSS 与条款页、项目内当前清单。
- 没有登录用户账号，没有购买额度，没有创建 App/OAuth 客户端，没有调用需 token 的 API。
- 没有绕过验证码、登录墙、robots、访问控制或反滥用机制。
- 公开 RSS 仅各执行低频 GET 用于当前证据刷新；响应保存在 `/tmp` 临时目录供本轮解析，未写入业务库、Base、app 或 data。
- GitHub 项目许可证未被当作 X、Reddit、Instagram 或出版方的平台授权。

### 1.2 证据等级

| 等级 | 定义 | 本报告用法 |
|---|---|---|
| A | 2026-08-08 直接访问的官方/第一方公开页面或 feed，并做本地只读解析 | RSS HTTP 状态、字段覆盖、条目数量 |
| B | 2026-08-08 查询到的官方开发文档、帮助中心、条款 | 授权、费用、速率、删除、内容展示边界 |
| C | 项目内现有清单或规范 | 白名单数量、当前 `unknown/proposed` 状态、项目门禁 |

### 1.3 事实与建议的区分

- 表格中的“官方事实”只记录证据直接支持的语义。
- “适配判断”和“下一步”是研究部建议，需由产品、数据、安全按各自职责决策。
- 找不到公开官方价格、速率或资格时记录 `Unknown`，不使用社区报价补齐。

## 4. X 白名单优先级与身份边界

项目文件 `data/x-source-inventory-v0.csv` 当前有 59 条 X 候选，全部为：

- `identity_status=unknown`
- `monitorability=unknown`
- `lifecycle_status=proposed`

因此本报告只把它们视为**待核验的规则输入**。平台 API 的能力、账号身份、内容权利、资源成本四项需要逐条通过各自门禁。

### 4.1 可提交数据部复核的一项身份事实

- `@F1`：Formula 1 自有 corporate 页面在官方直播渠道列表中直接回链 `https://x.com/f1`，可把“handle 与 Formula 1 官方渠道关联”记为 A/B 级事实。
- 本报告没有修改 CSV。该身份事实应由数据部按其变更流程写回，且 `monitorability` 仍维持 Unknown，直到获得官方 API 授权并完成最小调用验证。

### 4.2 授权后的最小 X 试验顺序（研究建议）

若用户之后单独批准开发者账号、付费 credits 与真实调用，可从白名单的高优先级官方组织类开始：

1. `F1`：已有一方站点回链，先验证 user lookup → user posts → created_at/edit history/media fields。
2. 其余车队/赛事 handle：先从各自一方官网或官方新闻稿反向验证 handle，再加入 stream rule。
3. 记者、车手、聚合账号：身份、授权、内容权利和 F1 相关性逐项复核，不与官方组织类混为同一信任层。

当前不建议对 59 个 handle 一次性创建规则。先用 1 个已经一方回链的账号估算每条资源费用、重复读取去重和删除/编辑成本，再决定扩容。

## 5. 删除同步、摘要与图片的共同门禁

### 5.1 删除与编辑状态机

| 平台 | 可见官方机制 | F1+1 最小保守语义 |
|---|---|---|
| RSS | 无统一删除/编辑事件；item 可变或从窗口消失 | `active` → `missing_unconfirmed`；只有原站 404/明确撤稿或权利方通知后才能进入 `removed` |
| X | Filtered Stream 提供 edit history；Enterprise compliance stream提供 delete/edit/protect/suspend 等事件 | 未接 compliance 时不得宣称完整删除同步；定期 rehydrate 只能作为弱补偿 |
| Reddit | 条款要求删除平台已删除内容，官方建议常规 48h 内清理存储的用户数据/内容 | 必须具备删除巡检、作者去标识与全字段清理；无此能力不启用真实采集 |
| Instagram | embed 会随公开/Embeds 状态变化；API 覆盖取决于获授权账号与能力 | consumer/public外部账号保持 manual_only；无授权时不存媒体或正文副本 |

### 5.2 摘要

- 公开可读只证明可访问，不自动授予翻译、改写、聚合或模型处理权。
- Formula1.com RSS 明确禁止翻译/修改 feed 内容，因此该源的中文摘要默认关闭，待书面许可或独立合法依据评估。
- Motorsport.com、FIA、Reddit、X、Instagram 的摘要都需在生产前确认使用场景、归因、存储、商业性和模型处理边界。
- 若产品必须先完成技术纵切，使用 synthetic 文本验证摘要组件。仅在对应来源条款或书面许可允许时，保存稳定 ID、时间、标题和原链的最小必要集合；Formula1.com 当前只做瞬时结构验证，不形成持久内容库。

### 5.3 图片

- Feed/API 提供图片 URL 或 media field 只说明技术可定位资源。
- 首条纵切默认不下载、不代理、不缓存、不生成缩略图，不把第三方 URL直接交给前端。
- 图片展示须同时通过：来源授权/许可、域名 allowlist、HTTPS、内容类型与大小、SSRF、删除同步、归因、缓存期限与前端 CSP。
- Instagram 已知 URL 可考虑平台原生 embed，仍需尊重公开状态和 Embeds 开关；该路径不能替代采集发现。

## 6. 最小验证路线

### VS-RSS-0：当前允许提议的本地试验

前提：统筹确认该动作仍属于已授权的公开只读研究/技术 spike；若被认定为“真实采集”，必须再次向用户确认。

1. 对 Motorsport F1 RSS 和 Formula1.com RSS 各取 10–20 条，仅映射 `source_id`、`external_id/guid`、`canonical_url`、`title`、`published_at?`、`first_seen_at`、`rights_state=unknown`。
2. 连续两个受控时间点低频读取，验证幂等、重复项、时间字段和消失项状态；不抓文章页、不下载图片。
3. 输出内部诊断，不进入公开 feed；验收后删除临时内容。生产化必须经过产品/数据/安全和用户授权门。

### VS-X-1：需要用户授权与付费

1. 用户确认开发者账号、Project/App、预算上限和支付方式。
2. 只对已由一方回链验证的 `@F1` 做 user lookup 与最小 user posts 读取。
3. 记录实际 header rate、按量费用、重复读取去重、字段与删除/编辑可见性；结果通过安全/数据复核后再考虑 59 条扩容。

### VS-Reddit-1：需要用户授权/商业协议判定

1. 明确 F1+1 用例是否构成商业使用，必要时向 Reddit 申请协议。
2. 注册单一 OAuth client，使用唯一 User-Agent；只测一个明确批准的 subreddit newest listing。
3. 在任何公开展示前先实现 48h 删除巡检、作者去标识与全字段删除测试。

### VS-Instagram-1：当前不建议启动

- 用户未拥有/管理白名单账号时，专业账号 API 不能覆盖目标 consumer accounts。
- 已知 URL 的 embed 可独立作为 `manual_only` 展示能力评估。
- 未获 Meta 明确书面许可前，不做网页自动采集实验。

### 7.1 已验证

### 7.2 未验证 / Unknown

- 三条 RSS 的长期稳定性、错误率、地区差异、CORS、连续 15 分钟 SLA 与历史回填窗口。

- X Developer Console 内针对实际项目的最终价格、资格、余额、实际 endpoint headers 与 token 权限；本轮未登录，公开文档价格可能变化。

### 7.3 官方证据冲突/张力

- Motorsport.com RSS 目录称 RSS 是向 viewers 提供的 free service；同站 Terms of Use 把内容限定于信息与个人使用，并限制未授权复制、分发和商业使用。结论：免费访问不等于生产再发布授权。
- FIA RSS 页面鼓励使用 RSS reader；当前链接的 Terms PDF 标注旧版权年份且对复制/传播施加严格限制。结论：技术订阅可用，生产权利范围仍 Unknown。
- Instagram 公开内容可在满足公开账号与 Embeds 开关时嵌入；自动网页采集仍要求 Meta 另行明确书面许可。结论：embed 展示与自动发现是两条不同能力。
