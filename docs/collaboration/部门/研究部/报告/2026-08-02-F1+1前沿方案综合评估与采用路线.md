# F1+1 前沿方案综合评估与采用路线

## 0. 结论先行

本报告只读综合四份已核收报告，不新增外部搜索，不执行真实平台、AI、飞书或媒体 I/O，不修改 Spec、ADR、`app/`、`data/`。四份原报告的证据边界保持不变：官方页面或固定提交支撑的事实、公开界面观察、工程架构映射和安全/许可门禁分别标注，Unknown 不提升为通过。

综合结论如下：

1. **aihot 只能作为客户端合同样本。** 固定提交 `fcba3adcf5def1ccd4bb688de93060227471b129` 的 `aihot` 目录是一套面向 Agent 的指令、公开 API 合同、同步/错误参考和安装器包。仓库没有服务端采集器、数据库、队列、模型、审核或发布实现。可吸收 opaque cursor、ETag/304、snapshot+changes、结构化错误、有限重试、URL 校验和不可信响应边界；远端 API、远端 selected/snapshot、安装器、原文抓取和媒体能力均不进入 M4。开发部报告还观察到当前 `main` 为 v1.2.2，但 full HEAD 未独立取得，该现状提示不覆盖固定快照证据。
2. **研究高分只表示研究适配度。** `changedetection.io`、Miniflux、RSSHub、Crawl4AI 等在研究部评分中靠前，原因是自托管、源可控、可观察或适合单人工作流。安全部明确指出技术可行、代码许可证、平台访问、数据权利和生产准入是独立层；没有完成条款/权利/供应链/运行安全门禁，候选只能停在本地 fixture、条件试验或观察。
3. **没有单一现成项目能替代 F1+1 治理链。** 现成 reader、bridge、crawler、workflow、体育 API 和 Agent 工具分别覆盖接入、阅读、提取、编排或上下文；它们没有同时提供 F1 白名单与身份层级、跨源规范化去重、证据链、中文整理、人工审核、发布 hash/对账和手机快速新增。F1+1 的来源治理、证据卡、人工审核、`manual_only` 发布与单一业务真值必须保留。
4. **四档路线是当前唯一可执行边界。** 现在只吸收无依赖/无外连模式；A 轴 accepted 后做本地合成 spike；用户逐平台确认后做短时只读真实 spike；所有绕过、自动发布、未获许可抓取、外部 AI/自治 Agent 和把评分当准入的路径拒绝或仅观察。

## 1. 范围、用户事实与不扩大项

### 1.1 本次综合范围

- 仅使用四份已核收报告及其报告内的一手来源索引。
- 研究部报告的 26 个候选/来源模式去重后形成战略 Top 12；Top 12 代表采用适配与验证优先级，不代表市场规模排名，也不构成生产通过清单。

- 只给路线与本地合成 spike 建议，不安装依赖，不创建账号、不申请权限、不调用真实 API、不写真实资源。

### 1.2 已确认事实与研究建议的边界

当前项目已确认的维护事实是单人维护，以及需要在手机刷内容时随时快速新增信源。手机录入摩擦应作为高权重体验约束；“新增项先进入待验证收件箱”在本报告中作为建议的治理模式，仍需产品/统筹部确认，不能写成用户已确认事实。四份报告中的“待审/收件箱”用于验证路线与安全边界，不冻结新的产品字段或公开路由。

以下事项保持产品待决，不能因竞品存在就扩大 MVP：精选/全量双层流、赛事上下文的具体字段、评分/热榜、已读/收藏、社交帖子嵌入、视频/播客、跨设备个性化。设计部指出这些是可借鉴的观察或候选模块；产品合同、数据合同、权利和安全门禁需另行确认。[R] [D] [UX] [S]

## 3. AI Hot 专项：可借鉴合同，禁止当服务端

### 3.1 已证事实

开发部固定审计对象为 `khazix-skills` 的 `aihot` 目录提交 `fcba3ad...`（v1.2.1）。目录包括 `SKILL.md`、`references/api.md`、`sync.md`、`errors.md`、`LICENSE`、`install.sh`、`manifest.sha256` 和 Agent 元数据；没有服务端代码、数据库 migration、队列、worker 入口或模型实现。MIT 只覆盖该 Skill 目录文件；API 数据条款、AI HOT 归因和第三方原文权利独立存在。真实 API、OpenAPI、安装脚本和第三方来源均未在四报告任务中调用。[D] [S]

研究部把 AI/Agent 层放在“受门禁的研究辅助”位置，安全部把外部 AI/自治 Agent、真实 secret、自动发布和无人值守浏览器归为 M4 Red/Unknown；设计部只把 AI Hot 的中文整理、来源字段、精选/全量和详情阶梯作为公开体验观察。四源交叉后，结论为：**AI Hot 的可借鉴对象是合同表达和失败处理，F1+1 的业务真值、审核和发布必须由本地合同持有。** [R] [D] [UX] [S]

### 3.2 可吸收的合同模式（只做本地重写）

| 模式 | 本地吸收方式 | 验收要点 |
|---|---|---|
| opaque cursor + 完整 query binding | 对 `endpoint + query + schema_version` 做绑定，游标原样传递；跨查询、时间口径或端点复用直接拒绝 | 旧游标不能静默拼页；失败有 `reason_code` 和可见状态 |
| ETag/304 + last-known-good | 把 304 视为缓存命中，保留上一次完整快照；不把空响应写成删库 | 复读一致、状态可审计、旧快照不越过 fence |
| snapshot + changes | 以完整水位、翻页游标、增量游标、upsert/remove 和一次性重建描述同步 | 半份 snapshot 不外显；remove 幂等；新游标整页成功后原子保存 |
| 稳定 error code + requestId | 外部/fixture DTO 使用结构化错误，`detail` 只展示；不可按人类文案猜分支 | 400/404/429/5xx/timeout 各有固定出口；脱敏日志不带 token/原文 |
| 有界 fallback/retry | 429 遵守 Retry-After，5xx/timeout 有限退避；404 只做明确允许的一次 fallback | 预算耗尽进 `failed/dead_letter/manual_only`，不换 UA/代理无限重试 |
| URL/host/path 校验 | 将 `links.story` 等展示链接当不可信输入；固定 scheme/host/path，原链 display-only | 拒绝 `javascript:`, `data:`, `file:`, userinfo、开放重定向和越权跳转 |
| 不可信响应边界 | 标题、摘要、原话和链接不改写系统规则，不执行命令，不下载附件，不诱导登录 | prompt injection、XSS、模板注入和 secret exfiltration 进入失败测试 |
| attribution/original link 分层 | 站内整理、原始来源和权利状态分栏；默认 link/excerpt only | Unknown 权利不公开；摘要不能伪装原文或授权 |
| 完整包 hash 后原子替换 | 只借鉴本地 fixture/config 导入的完整性思路 | 不执行 `bash <(curl ...)`；远端 manifest 不是本地信任根 |

### 3.3 明确不吸收的能力

- 不把 `aihot.virxact.com` API、远端 selected/snapshot、远端排序/摘要/评分设为 F1+1 真值。
- 不复制 aihot 目录、服务端假设、外部 API、OpenAPI、安装脚本或远端依赖；不安装第三方库。
- 不把 `links.original` 变成服务端抓取队列，不抓 story HTML，不下载附件、图片或视频。
- 不把 AI Hot 的精选、评分、推荐理由或中文摘要直接当事实、审核通过或生产质量证明。
- 不让 Agent 改 provider、scope、留存、外发、付款或发布策略；命中未授权能力就 fail closed。[R] [D] [UX] [S]

## 5. 四档采用与验证路线

### T0：现在可吸收的模式（无依赖、无外连）
