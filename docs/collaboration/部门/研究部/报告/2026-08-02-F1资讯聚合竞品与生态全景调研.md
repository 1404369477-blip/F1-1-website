## 1. 调研边界与方法

### 1.1 任务边界

本报告对应 `TASK-20260802-D11DCA`，检索日期为 **2026-08-02（Asia/Shanghai）**。目标是研究与 F1+1 相近的资讯聚合产品、开源项目、采集工具、体育信息产品以及 agent/skill 生态，不冻结产品实现合同。

已覆盖指定平台：**GitHub、X、Reddit、Product Hunt**，并补充 Formula1/FIA 官方站、官方文档、官方 RSS、App Store/Google Play 和项目官网。所有外部访问均为公开只读页面或公开文档；没有登录、发帖、私信、点赞、关注、提交表单、调用需要凭证的 API、安装第三方项目或写入外部服务。

### 1.2 证据规则

- **A**：官方项目仓库/官方产品页/官方平台文档/官方条款可以直接支撑结论。
- **B**：官方页面可支撑主要事实，但许可证、当前活跃度、API 可用范围或商业限制仍有一项需要复核。
- **C**：Product Hunt、社区页面或公开讨论用于发现和机制观察；不把关注数、点赞数或评论数当作质量、事实或商用许可证据。
- **合理推断**：评分、推荐层级和“适合 F1+1 的借鉴点”属于研究判断，报告中与已验证事实分开。
- **Unknown**：官方资料未证明的许可证、商业再分发权、长期活跃度、稳定抓取能力、账号身份和平台配额保留为 Unknown。

### 1.3 评分维度

Top 10 评分采用 100 分制，原始维度按 1–5 分记录，权重如下：

| 维度 | 权重 | 判断含义 |

## 2. 先给结论

### 2.1 生态已经分层，尚无完整替代品

当前公开生态可以拼出以下能力链：

`官方 RSS/API/公开网页 → RSSHub/RSS-Bridge 等适配层 → FreshRSS/Miniflux/Folo 等阅读层 → changedetection.io/Crawl4AI/Firecrawl 等提取或变更层 → n8n/Huginn/Agent/MCP 编排 → F1+1 自有去重、证据卡、中文整理、人工审核与发布`

没有一个被本轮核验的候选同时满足：

- 用户指定的 F1 白名单与来源身份分层；
- X、Reddit、官方站、RSS/API 的跨源规范化和实体归一；
- 原始链接、作者、发布时间、证据级别和权利状态留存；
- 跨源去重、传闻/分析/正式事实分层；
- 中文摘要与事实核验的人工审核链；
- 单人维护、手机快速新增和 15 分钟采集目标。

因此，候选应作为分层能力参考或受控组件候选，F1+1 自有的信息治理与审核责任链仍需保留。

### 2.2 推荐采用顺序

1. **当前可采用的原则**：优先官方 RSS/API 和官方网页；X/Reddit 只作为线索入口，优先保存 URL、ID、作者、时间和短摘要，回填到 FIA/F1/车队/车手正式来源；Product Hunt 作为新品发现入口。
2. **优先评估的开源/自托管层**：RSSHub、FreshRSS 或 Miniflux、changedetection.io；RSS-Bridge 作为可替代 bridge；n8n/Huginn 只在确有编排需求时评估。
3. **受门禁的提取与 Agent 层**：Crawl4AI、Firecrawl、Browser Use、OpenClaw Skills、GitHub MCP 只用于允许访问的公开页面和研究辅助，必须有网络白名单、版本固定、最小权限、失败停止与人工审核。
4. **竞品能力标杆**：Feedly AI、Inoreader、Folo、官方 F1 App/F1 TV、RacingNews365、The Race 和 Box Box Club用于观察聚合、个性化、实时信息和移动体验；不将其闭源能力或营销指标写成可复制事实。

## 7. 已验证、合理推断与 Unknown

### 7.1 已验证

- RacingNews365、The Race、Box Box Club 的官方页/应用页确认其 F1/赛车内容或移动通知/新闻产品定位；Box Box 明确其独立于 Formula One 公司。

### 7.2 合理推断

- `官方 RSS/API → bridge → 阅读器 → 受控提取/编排 → F1+1 审核` 是与现有开源生态最匹配的分层组合；该组合是研究建议，并非任一候选的官方架构。
- Reddit 的“主社区 + 技术子社区 + 固定帖”适合映射成 F1+1 的内容类型和线索收件箱；X 的“官方/车队/车手白名单”适合作为早期声明信号层。
- RSSHub/FreshRSS/Miniflux/changedetection.io 得分较高，主要因为自托管、源可控和与单人维护更接近；它们并未因此自动满足 F1+1 的证据和编辑责任要求。
- Product Hunt 的关注、upvote、评论和页面 AI 摘要适合产品发现，不适合直接进入事实质量或采用评分。

### 7.3 Unknown / 待复核

- Toopost、Browser Use、OpenClaw Skills 的确切许可证、商业再分发、数据保留、云端处理和版本稳定性。
- Feedly AI、Inoreader 的完整价格、API 额度、套餐变化、社交 feed 的长期可用性和商业输出权。
- X `@F1` 主账号当前公开资料稳定性、车队/车手账号的官方互链复核；关注数不等于近期活跃度。
- Reddit 页面中的第二个规模数字的语义；公开 `.rss` 失败后是否可在合规 API 下稳定访问；帖子、评论、图片、图表和嵌入媒体的长期缓存/商业使用权。
- OpenF1 当前 GitHub 活跃度和 live tier 的实际可用性；Jolpica 2026 年运行稳定性、配额和 Terms of Use。
- RSSHub、RSS-Bridge、changedetection、Crawl4AI、Firecrawl 对每个 F1 目标站的 robots/ToS 具体允许范围、结构变更后的可用率和 SSRF/反爬风险。
- 许可证与商用可行性最终需按 F1+1 的部署方式、是否提供网络服务、是否展示原文/图片/视频和地域进行法务复核。

## 8. 下一步验证建议（不在本任务执行）

1. 用合成 fixture 建立 10–20 条跨源样例：同一新闻的官方公告、车队 X 帖、Reddit 讨论、媒体 RSS；验证 canonical URL、时间窗、作者/车队实体、重复关系和证据等级。
2. 在用户单独确认后，以只读/公开 API 为边界复核 X Recent Search、Reddit Data API、Product Hunt RSS 的配额、删除/缓存义务和真实响应；不先创建账号或扩大平台权限。
3. 只对官方允许的无 RSS 页面做 changedetection/Crawl4AI/RSS-Bridge 小样本试验；将 robots、ToS、失败率、SSRF、提示注入、重复率和原文权利作为退出条件。
4. 由产品/安全部复核 Top 10 取舍和许可证；研究部不直接冻结实现合同，不把本报告评分当作技术选型授权。
