# Node 24 安全 RSS/XML 解析器最小选型

## 0. 结论

截至 2026-08-09，**唯一推荐为精确顶层版本 `fast-xml-parser@5.10.1`（MIT）**，仅进入一次用户依赖确认后的纯本地 disposable spike。推荐理由限于当前三项组合事实：仓库仍活跃、5.10.1 修复了公开的重复 DOCTYPE 绕过、并提供 `processEntities:false` 与 `maxNestedTags` 等可收窄能力。它不会单独满足 VS-RSS-0；调用方仍须承担 1 MiB 输入门、DOCTYPE/ENTITY 预拒绝、XInclude/schema 语义拒绝、10,000 节点/字段 16,384 UTF-8 bytes/20 item 计数、Worker 硬超时、zero-network 运行边界和完整响应原子提交。

**回退为 `@xmldom/xmldom@0.9.10`（MIT）**，只在推荐项的本地 spike 失败、且其严格错误处理与全 DOM 资源开销能在相同攻击样例下过门时复议。它没有运行时依赖，但会构造完整 DOM，也没有原生节点、字段、item 或超时上限。

**`saxes@6.0.0` 不进入推荐或回退。** 它的事件式增量解析与默认仅五个 XML 预定义实体原本最贴合最小攻击面，但官方 GitHub 仓库已归档，npm 当前版本发布于 2021-11-07，不能满足任务的“仍维护”边界。若未来出现由明确维护者接管、发布并完成安全复核的新版本，可重新评估。

本任务没有安装包、修改 lockfile、执行候选包、发出真实 RSS 请求或修改 Spec/ADR/app/data。精确 Node 24 运行兼容性、对抗样例行为和硬超时均保留到获准的本地 spike。

## 2. Node 24 内置能力

Node.js v24.18.0 的官方 globals 文档没有 `DOMParser`；本项目固定的 Node `v24.18.0` 只读探针返回 `typeof DOMParser === "undefined"`，内置模块列表也没有 XML parser。`TextDecoderStream` 和 Node streams 可做有界传输/严格 UTF-8 解码，不能承担 XML 语法解析。

结论：VS-RSS-0 若继续，必须新增受控 XML 解析依赖或自行实现解析器。自行实现 XML 会扩大语法与安全责任，不符合最小选型目标。

证据：[Node.js v24 globals](https://nodejs.org/download/release/latest-v24.x/docs/api/globals.html)、[Node.js v24 modules index](https://nodejs.org/download/release/latest-v24.x/docs/api/index.html)。

### 3.1 `fast-xml-parser@5.10.1` 的安全边界

精确发布包的 `src/xmlparser/OptionsBuilder.js` 显示：默认 `processEntities:true`、`maxNestedTags:100`；`processEntities:false` 会把实体处理归一化为 `enabled:false`。`OrderedObjParser.js` 仍识别并读取 DOCTYPE，再把读取到的实体交给 decoder；因此 `processEntities:false` 不能替代项目合同的“出现 DOCTYPE 即整份拒绝”。调用方需要在严格 UTF-8 解码后、创建 parser 前，对任意大小写的 `<!DOCTYPE` / `<!ENTITY` 进行保守拒绝；注释或 CDATA 中命中导致的假阳性可以接受，因为合同要求 fail-closed。

同一源码提供 `maxNestedTags`，但检查位置和“根节点是否计数”的精确语义尚未通过运行样例证明。项目仍需在解析结果上独立计算深度，并以 spike 固定深度 32 的边界样例。`parse()` 是同步整段解析；同线程的 `AbortSignal` 或计时器无法在一次阻塞调用中硬中断，故总解析时限必须由 Worker owner 执行 `terminate()`。

建议 spike 固定最小配置为 `preserveOrder:true`、`ignoreAttributes:false`、`removeNSPrefix:false`、`trimValues:false`、`parseTagValue:false`、`parseAttributeValue:false`、`processEntities:false`、`maxNestedTags:32`、`stopNodes:[]`、`unpairedTags:[]`，并启用库的 XML validation（`parse(xml, true)` 或等价的先 validate 后 parse）。这些选项分别保留顺序/相邻文本表示、属性、namespace 前缀、前后空白和字符串原值，并禁止类型转换、stop node 与 HTML 式不配对标签；精确选项名与默认行为来自 5.10.1 发布包的 `src/xmlparser/OptionsBuilder.js`、`src/fxp.d.ts` 与 `src/xmlparser/XMLParser.js`。配置能否充分保留 CDATA、相邻文本、空文本和 namespace declaration 的合同计数语义仍是 **spike 阻断项**。

`removeNSPrefix:false` 只保留前缀，不会自动证明 namespace URI。调用方必须维护逐层 `xmlns` / `xmlns:alias` 作用域，用 URI 匹配 `{http://www.w3.org/2001/XInclude}include|fallback` 和 `{http://www.w3.org/2001/XMLSchema-instance}schemaLocation|noNamespaceSchemaLocation`；按字面 `xi:` 或 `xsi:` 判断不合格。若 ordered output 不能无损提供 namespace declaration、属性和相邻文本节点，推荐项直接判 spike FAIL。

安全公告中最相关的是：

- [GHSA-8r6m-32jq-jx6q](https://github.com/advisories/GHSA-8r6m-32jq-jx6q)：重复 DOCTYPE 可重置实体扩展限制，受影响 `>=5.9.3 <5.10.1`，修复版 5.10.1。
- [GHSA-jmr7-xgp7-cmfj / CVE-2026-26278](https://github.com/advisories/GHSA-jmr7-xgp7-cmfj)：实体扩展 DoS，受影响 `>=5.0.0 <5.3.6`，公告 workaround 包括 `processEntities:false`。
- [GHSA-jp2q-39xq-3w4g / CVE-2026-33349](https://github.com/advisories/GHSA-jp2q-39xq-3w4g)：实体限制零值绕过，受影响 `<5.5.7`。

当前 5.10.1 位于上述修复范围之外，但频繁的实体安全修补说明：实体能力必须关闭，精确版本和 lockfile 必须冻结，不能使用宽松顶层范围。

### 3.2 `saxes@6.0.0` 淘汰理由

官方 README 证明它支持 chunk-by-chunk 的 `write()` 和完成检查的 `close()`，并说明不会自行处理 DTD 定义实体；发布源码遇到 DOCTYPE 会触发 `doctype` handler，未定义实体会报错。这些特征对资源计数与最小网络面有利。

阻断项是维护状态：官方仓库 API 返回 `archived=true`，npm 最新版本停留在 2021-11-07。任务明确要求比较仍维护候选，因此不能用“攻击面更小”的推断覆盖已归档事实。其唯一直接依赖 `xmlchars:^2.2.0` 也不是精确传递锁；当前 registry 的 `xmlchars@2.2.0` 发布于 2019-09-06且无依赖。

### 3.3 `@xmldom/xmldom@0.9.10` 回退边界

官方仓库仍活跃，package 声明 Node `>=14.6`、MIT、零运行时依赖。SECURITY policy 说明 1.0 前目标是维护最后两个 minor；当前 0.9.10 修复了多项序列化/递归公告，包括 [GHSA-2v35-w6hq-6mfw](https://github.com/advisories/GHSA-2v35-w6hq-6mfw)。

它会构造完整 DOM；默认只有 `fatalError` 强制抛出，普通 `error` 会报告到 console。若进入回退 spike，必须提供 `onError` 并对 warning/error/fatalError 全部抛出，使用 `application/xml`，再独立预拒绝 DOCTYPE 并遍历所有节点/属性。即使配置正确，它仍没有增量资源门，内存峰值与严格性只能通过 1 MiB 输入上限、Worker 和攻击样例控制，因此只列回退。

### 4.2 必要性与风险

- 必要性：Node 24 没有内置 XML parser；自建 XML parser 的语法、安全和维护成本更高。
- 风险：推荐项除自身外引入 7 个唯一运行时依赖（lock 预期合计至少 8 个运行时包，仍以实际 lock 为准）；顶层精确 pin 仍不能冻结其 caret 传递解析；实体功能有公开安全修补历史；同步整段 parse 需要 Worker 才有硬终止。
- 约束：用户若批准，只允许开发部执行一次精确 `fast-xml-parser@5.10.1` 安装并生成 lock；随后逐条核对 lock 中版本、官方 registry `resolved`、`sha512 integrity`、lifecycle 脚本和许可证。任何 git/file/非官方源、缺 integrity、额外未解释依赖或生命周期脚本均 fail-closed。
- 锁定：提交 `package.json` 精确版本和 `package-lock.json`；CI 使用现有固定 Node 24.18.0 与 `npm ci --ignore-scripts`。不要写 `^5.10.1` 或 `latest`。
- 回滚：删除调用代码和顶层依赖，重新生成并审查 lock，运行现有全套检查；不得只手改 lock。若实现已落库，回滚前确认试验没有写业务表或移动游标。disposable spike 应保持 fixture-only、临时目录、无业务写入，使回滚不涉及数据迁移。

## 5. VS-RSS-0 精确控制映射

| 合同控制 | 库原生保证 | 调用方必须实现 | 仍待 spike 证明 |
|---|---|---|---|
| 响应最大 1 MiB | 无 | 传输层按原始响应字节累计，超过即中止且不解压；严格 UTF-8 fatal decode；parser 只接收已过门字节 | 1 MiB-1 / 1 MiB / 1 MiB+1 与多字节切片边界 |
| DTD/DOCTYPE/外部与参数实体 | `processEntities:false` 禁用替换，但源码仍读 DOCTYPE | parser 前对 `<!DOCTYPE`、`<!ENTITY` 保守拒绝；禁止 `addEntity`；不实现 resolver | 内部子集、重复 DOCTYPE、大小写变体、注释/CDATA 假阳性全部整份拒绝 |
| XInclude / network schema | 无自动获取证据；无合同级拒绝 | 保留 namespace declaration 并维护逐层 prefix→URI 作用域；按 URI 拒绝 XInclude `include/fallback` 与 XMLSchema-instance 两个 schema 属性；未通过独立 no-egress 门时保持关闭 | prefix alias、默认 namespace、作用域重绑、属性顺序变体；无法无损取得声明即 spike FAIL |
| 全文最多 10,000 个 element/attribute/text nodes | 无 | 使用 `preserveOrder:true`、`ignoreAttributes:false`，完整 validation 和 parse 均成功后才全树遍历；文本、CDATA、空文本、相邻文本的计数规则写成单一函数；超限销毁 staged result | 9,999/10,000/10,001；空文本、CDATA、合并/相邻文本语义；表示不保真即 spike FAIL |
| 最大深度 32 | `maxNestedTags` 可作第一道近似门 | 配置 32 后仍独立遍历精确计数 | 根节点计数、31/32/33、self-closing 的精确边界 |
| 单 element 文本或 attribute 最大 16,384 UTF-8 bytes | 无 | 使用 `Buffer.byteLength(value, "utf8")`；元素文本按合同定义聚合后计数，属性逐值计数 | 16,383/16,384/16,385；emoji/CJK；实体关闭后的字面值 |
| 最多 20 item | 无 | 完整解析和结构验证后统计 RSS `item` 或 Atom `entry`；第 21 条触发 `XML_ITEM_LIMIT` | 19/20/21；混合 RSS/Atom 或嵌套伪 item |
| 完整响应拒绝 | 无 | 所有输出先保存在 Worker/函数局部 staged value；任何错误只返回固定错误码，零条目、零 cursor、零 partial state | 第 21 item、尾部畸形、超限字段发生在最后一个节点 |
| 解析终止 / 超时 | 无；同步 `parse()` | spike 初始硬门为 2,000 ms，严格小于 ADR 的 10 s 请求总预算；建议 `resourceLimits={maxOldGenerationSizeMb:64,maxYoungGenerationSizeMb:16,stackSizeMb:4}`，由固定 Node 24 实测决定是否调整；owner 在 deadline 先把 attempt 置 terminal-failed，再 `terminate()` 并忽略晚到 message | CPU 压力 fixture、内存门、超时竞态、Worker 退出后无残留提交；阈值改变须由开发/安全记录理由 |
| zero-network | 包静态源码未见网络 resolver，仍非 OS 级证明 | fixture-only 与外部调用计数 0 只记观测；真正 PASS 需要独立 no-egress、进程隔离或可验证的模块/系统调用阻断收据 | 未取得独立门禁收据前，spike 不得标为 zero-network PASS；系统调用级 no-egress 仍属项目既有 Unknown |

这里的顺序不可互换：严格 UTF-8 → DOCTYPE/ENTITY 预拒绝 → 完整 XML validator → parser → 全树合同检查 → 一次性提交。validator 任一非 success 统一映射 draft ADR 已有的 `XML_SCHEMA_INVALID`（本 spike 同时用它承载 XML well-formedness/结构验证失败），不得启动 parser、生成 staged result 或移动游标。validator 与 parser 必须接收同一份不可变字符串；两者都成功后才允许统计 item。`slice(0, 20)` 会破坏“第 21 条整份拒绝”，禁止使用。

## 6. 最小 disposable spike 验收

用户只需就“新增并锁定 `fast-xml-parser@5.10.1` 及其 lock 图”确认一次。获准后开发部在 fixture-only、无真实 RSS、无业务写入环境完成以下三组验收：

1. **依赖门**：精确顶层 pin；lock 的 registry/integrity/license/dependency/lifecycle 清单通过；固定 Node 24.18.0 可以 import/require；任何差异直接回滚。
2. **解析安全门**：固定上节最小配置并启用 XML validation。攻击集必须覆盖未闭合尾部、错配标签、重复根、根后垃圾、截断 CDATA、截断属性、畸形 namespace declaration、第 21 item 后畸形尾部；DOCTYPE/ENTITY；XInclude/schema 的前缀 alias、默认 namespace 与作用域重绑；超长纯空白 element text、超长 attribute、CDATA+普通/相邻文本；深度、节点、字段、20/21 item、UTF-8 和 1 MiB 边界。任何保真语义无法证明即 FAIL；所有失败统一整份拒绝且不保留条目/游标。
3. **终止与零网络门**：只喂本地 synthetic fixtures；以 2,000 ms 和建议 Worker resource limits 起步，owner 用不可复用 attempt token/epoch 验证消息，只在 deadline 前、正常退出且 token/epoch 精确匹配时接纳结果；超时先终结 attempt 再 terminate，晚到消息永不提交。外部调用计数 0 只构成观测，取得独立 no-egress 收据后才能标为 zero-network PASS。不得访问 Motorsport、Formula1.com、FIA 或任何其他真实 feed。

建议成功判据：全部攻击与边界 fixture 命中预期固定错误码，合法 RSS 2.0 与 Atom 最小 fixture 解析一致，峰值内存/耗时记录为本机证据，现有检查全绿。任一 DOCTYPE/实体样例不能稳定 fail-closed，立即淘汰推荐项并转入回退 spike；两者都失败则停止实现并回报“无可接受候选”。

## 7. 已验证、未验证与错题自检

### 已验证

- Node 24.18.0 没有内置 `DOMParser` 或 XML parser。
- 三个精确版本、发布时间、许可证、package 声明和 registry tarball SHA-1。
- `fast-xml-parser@5.10.1` 的六个直接依赖范围及当前一个新增唯一传递依赖；精确安装图尚未生成。
- 推荐项默认启用实体、可配置关闭、仍读取 DOCTYPE、提供 `maxNestedTags`、同步整段 parse 的源码事实。
- saxes 的增量事件模型、DOCTYPE 事件、默认实体边界，以及官方仓库已归档。
- xmldom 的完整 DOM 模型、零运行时依赖、错误 handler 语义和官方安全 policy。
- GitHub Advisory Database 当前查询结果及列举公告的受影响/修复范围。

### 未验证 / Unknown

- 三候选在本项目固定 Node 24.18.0 上的实际 import、解析、内存和性能；本任务按约束没有执行候选包。
- 推荐项 `maxNestedTags:32` 与 VS-RSS-0 深度 32 的根节点/边界等价性。
- DTD 预拒绝、XInclude/schema namespace 识别、节点与字段计数在攻击 fixture 上的完整性。
- 推荐配置对 namespace declaration、空白/相邻文本和 CDATA 的保真程度；不能证明即淘汰推荐项。
- Worker 硬终止、超时竞态、1 MiB 多字节边界、完整响应零残留。
- 获准安装时的精确 lock 图、所有包的 Node 24 实跑兼容和 lifecycle 状态。
- 系统调用级 no-egress；这仍由既有 R12/安全门禁承担。
- GitHub Advisory Database 的“0 条”或“当前版本不在已知范围”不能证明没有未公开漏洞。

### 错题自检

- 没有把 `processEntities:false` 写成 DOCTYPE 原生拒绝；源码仍读取 DOCTYPE，因此调用方预拒绝是硬门。
- 没有把“静态源码未见网络请求”写成 OS 级 zero-network；真实证明留给独立 no-egress 门禁。
- 没有把 semver 顶层精确 pin 写成传递依赖冻结；只有生成并审查 lock 才能冻结实际图。
- 没有因 saxes 攻击面较小忽略官方归档状态；它按任务维护边界淘汰。
- 没有把 GitHub Advisory Database 的零结果写成“无漏洞”。
- 独立首轮对抗审查发现保真配置与严格 validation 管线缺口；已把完整选项、URI 级 namespace、validator 前置、畸形 fixture、Worker 资源/竞态和 no-egress 独立收据补为硬门。
- 没有安装、执行候选、改 lockfile、访问真实 RSS、修改 draft ADR 或开启真实采集。
