## 3. 前序问题关闭复算

### 3.1 P1-1：raw authority、session、CSRF——已关闭

- canonical bind/origin 仅允许 IPv4 `127.0.0.1` 或 IPv6 `::1` 二选一，端口限制为 1024–65535；禁止 localhost、alias、userinfo、path/query/fragment、wildcard、zone id 与多 origin。
- HTTP adapter 必须在框架合并、规范化和路由前保留 raw request-target 与 raw header multiplicity；非 HTTP/1.1、absolute-form、h2c、duplicate/comma/missing Host、Host+`:authority`、raw/normalized 不一致及 proxy headers均在 session/nonce/业务变化前拒绝。
- socket peer、raw Host 与 Origin 分别有 exact gate；Admin GET 可无 Origin但保持只读；CORS allow header 固定为0，OPTIONS固定405。
- session 固定32-byte系统CSPRNG、43字符base64url无padding、单UNCLAIMED/ACTIVE、单进程内存、host-only HttpOnly SameSite=Strict、absolute 30m/idle 10m、显式refresh轮换、旧ID/nonce与重启失效。
- CSRF固定32-byte系统CSPRNG、TTL 300秒、容量32，绑定session/method/exact path/canonical body SHA；单值header消费、原子 `issued→consumed`、并发最多一个成功、rollback不恢复、tombstone保留。
- raw/session/CSRF/no-egress拒绝时，Source、receipt、Outbox、TaskEnvelope、Inbox、Attempt、DeadLetter、domain AuditEvent和provider/adapter业务增量全部为0；仅允许一条字段allowlist的脱敏security audit及必要的内存单向状态变化。

上述规则与固定 local Admin 安全候选一致，并已在 v0.3 内逐项复述为 MUST，开发无需猜测“继承”的具体对象或强度。

### 3.2 P1-2：identity owner、codec、碰撞与复用——已关闭

七个 identity 域均固定生成方、时点、独立CSPRNG调用、原始字节数、prefix、canonical lowercase hex、exact length、生命周期和复用规则：

| 域 | owner | 原始随机量 | exact格式/长度 |
|---|---|---:|---|
| command operation | 可信UI Web Crypto | 32 bytes | `op-cmd-`+64hex，71 |
| command key | 可信UI独立Web Crypto调用 | 32 bytes | `cmd-key:`+64hex，72 |
| business operation | 首次/新activation事务内Node crypto | 32 bytes | `op-srcact-`+64hex，74 |
| business key | 同事务独立Node crypto调用 | 32 bytes | `srcact-key:`+64hex，75 |
| job id | 同事务独立Node crypto调用 | 32 bytes | `job-srcact-`+64hex，75 |
| task id | 同事务独立Node crypto调用 | 32 bytes | `task-srcact-`+64hex，76 |
| live lease | 每次acquire事务内Node crypto | 16 bytes | `synthetic:lease:`+32hex，48 |

独立复算确认 operation/task/job/lease 均满足现有 schema pattern，idempotency key 长度小于255；16-byte live lease满足128-bit合同。七组 fixture vector 的字节范围、hex展开、prefix与声明长度相符。

command 顺序唯一为：冻结command-independent输入→独立生成pair→组装closed DTO→canonical bytes/hash→申请绑定CSRF→提交逐字相同bytes。服务端只验证codec、绑定和UNIQUE，未把语法检查误写成客户端熵证明。

business operation/key/job/task由服务端在首次或cancelled后新activation的同一事务中成组生成；碰撞组整体丢弃，最多三组，耗尽/CSPRNG失败固定500并全回滚。lease逐attempt独立生成，最多三次，失败时acquisition全回滚且adapter=0。stopped、queue_failed、dead-letter使用新command pair并逐字复用原business/job/task；cancelled后新activation生成全新组。缺失、重复、codec错误或绑定不一致固定409零写。

command receipt 是两个identity域的唯一桥；Source/Outbox/TaskEnvelope和command/worker AuditEvent的字段绑定明确，没有command/business identity混列路径。seed lease零值被明确标为非授权占位，worker与completion必须拒绝；live lease golden同时拒绝零值。

### 3.3 P2：96-bit source_id 碰撞——已关闭

v0.3 保留既有96-bit短ID以维持主体合同，并固定保存/重算所需的完整SHA-256判别语义：

- 短ID相同且full hash相同：409 `ADMIN_SOURCE_ALREADY_PROPOSED`；
- 短ID相同但full hash不同：409 `ADMIN_SOURCE_ID_COLLISION`；
- canonical URL与其他Source冲突：409 `ADMIN_SOURCE_CANONICAL_CONFLICT`。

三条路径均在Source/receipt/lineage/fence/Outbox/TaskEnvelope/domain audit写入前停止，禁止salt、后缀、自动扩位、覆盖或第二Source。用户恢复动作固定为核对现有Source，明确修改synthetic path或platform，再生成新command pair与CSRF提交。未来扩到真实、不可信或高规模输入时必须建立successor重新评估位数。
