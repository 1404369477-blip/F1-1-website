# M4 本地安全门禁与外部 IO 隔离审核报告

## 1. 范围、结论和禁止动作

本任务依据 `TASK-20260801-08E045`，只复核 M4 本地合同是否足以把真实 provider、真实外部调用、凭证、自动发布和管理面越权关在门外。审查对象为 Spec v1 候选、`ADR-M4-KICKOFF-001`、测试部 M4 验收矩阵、数据部本地 MVP 合同和 OAuth 纠偏补充报告。

- 本轮只读仓库文件和任务真值；没有修改 Spec、ADR、`app/` 或数据合同。
- 没有执行 `login`、`device-code`、`logout`、`revoke`、`refresh`、重授权、token 轮换、任何 Base/飞书命令或任何真实外部 IO。
- 没有打开浏览器、访问飞书、访问外部网络，也没有保存 token、open_id、appId、认证原始 JSON、真实 Base URL 或私密链接。
- `app/` 仍只有基础 README；本报告属于合同级安全审查，不把候选命令、文字承诺或逻辑探针写成运行时已通过。

**总判定：CONDITIONAL PASS。** M4-local-fixture-v0 的方向可继续保留。当前 ADR 仍应保持 `status: proposed`，直到 A 层静态合同补齐；B 层运行证据不作为接受技术路线的前置条件。以下最小修订只规定安全合同、实现出口和测试边界，没有授权实现或外部操作。若实现阶段出现真实外部调用、未审核公开投影、可利用的 XSS/SSRF/CSRF/越权、secret 泄露或陈旧任务写入，结论立即转为 FAIL 并停止 Build Loop。

### 1.1 两层门禁裁决

**A. ADR/Spec 定版前（可阻断 accepted）：** 必须把 R1–R13 中涉及 M4 边界的静态文字、默认值、枚举、禁止项、内部 envelope/hash 字段和 fail-closed 行为补进 ADR/Spec 或其正式引用合同。A 层只要求合同明确、可机械检查；不要求 `app/` 已初始化，也不要求先取得运行测试收据。当前阻断 accepted 的原因是这些文字仍有可执行歧义，尤其是单环境绕过、Origin/CSRF nonce 语义、URL/媒体安全边界、日志/SQLite 权限、五 epoch fence 和 ReleaseBundle hash。

**B. app 实现后的 Build Loop/切片完成：** 开发部必须按 A 层合同实现 capability registry、配置 parser、admin fence、repository/worker、safe DTO、hash/manual publish 和测试；测试部必须取得 K/P/S/V/deny-all/供应链/并发/恢复收据。B 层任何缺失或失败都阻断实现验收、真实能力启用和阶段完成，但在 A 层合同完整的前提下，不阻断团队接受所选技术路线。真实 provider、真实 auth、Base/Collector/采集、外部媒体/AI/发布仍需另立门禁和用户确认。

## 3. 审核标准与判定方式

- **P0**：静态合同若允许真实外部 IO、secret 泄露、越权/CSRF、未审核公开或陈旧任务写当前状态，必须阻断 ADR accepted；实现后对应探针可利用、急停失效或旧 hash/epoch 可写入时，立即阻断 Build Loop 和真实能力。
- **P1**：静态合同缺少精确定义、默认值或拒绝条件，导致实现无法审计时，阻断 ADR accepted；实现/运行收据缺失或失败时，阻断实现验收和阶段完成，不自动否定已接受的技术路线。
- **P2**：不改变 M4 安全边界的可观测性或维护性问题；记录后不阻断本地合同。
- `ADR accepted` 一栏表示当前证据是否允许把 proposed ADR 定版，不表示是否可以开始写代码；本任务也没有授权写代码。

本报告的 P0/P1 是威胁一旦进入实现后的严重度和合同优先级。当前 `app/` 没有运行实现、没有真实外部 IO，静态证据未确认已有可利用 P0；A 层静态缺口仍可阻断 accepted，B 层失败按第 1.1 节处理。

## 4. 威胁、证据、严重度和最小修订

### 4.1 外部 IO/Provider 开关绕过（P0｜A层缺口阻断 accepted；B层失败阻断实现）

**威胁。** 单个环境变量、大小写/真假值别名、`SOURCE_PROVIDER`/`REAL_BASE_ENABLED`/`AUTO_PUBLISH` 等旧变量、依赖注入或未登记 provider 入口让进程连接真实 Feishu、外部平台、AI、图片或发布端点；配置读取失败时若采用宽松默认值也会产生同样后果。

**证据。** Spec 和 ADR 已列出 canonical 变量、fixture/mock 枚举、`REAL_*` 为 false 时的启动拒绝以及 disposable probe 变量不能混用；任务 failure path 明确要求“任一配置可由单个环境变量打开真实 provider 或外部 IO”判 P0/P1。当前 `app/` 没有解析器、provider registry 或测试实现，无法证明文字门禁在代码中成立。

**是否阻断 ADR accepted：A 层是，B 层否。** ADR 当前没有双门禁、严格解析和未知变量拒绝的完整静态合同，故阻断定版；代码和 deny-all 收据属于 B 层，缺失时阻断实现/阶段验收。

**精确最小修订 R1（写入实现合同和测试合同）：**

```text
M4 启动和每次能力调用必须同时通过两个独立门：
(a) 编译/代码级 capability registry 只注册 fixture provider、mock adapter、fixture summary、fixture/none media 和 manual_only local publication；真实 provider、HTTP/DNS/socket、模型、媒体下载、外部发布实现不在 M4 registry 中；
(b) 运行时 profile 对 canonical env 做大小写敏感的精确枚举校验。
REAL_FEISHU_IO、REAL_EXTERNAL_IO、REAL_FORM_SUBMIT 只接受字面量 "false"；任何 "true"、"1"、"yes"、空值、未知值或解析异常均拒绝启动，不能回退到安全或真实默认值。
SOURCE_CONFIG_PROVIDER、ADAPTER_MODE、SUMMARY_MODE、MEDIA_MODE、PUBLISH_MODE、ADMIN_ACCESS_MODE 只能接受合同枚举；旧别名、未登记 provider、FEISHU_*/X_*/REDDIT_*/META_*、任何 *_TOKEN/*_SECRET/*_PASSWORD 或 AI secret 环境变量和未知能力开关出现时拒绝启动。
SOURCE_FIXTURE_PATH 必须 realpath 到仓库允许 fixture 根目录，拒绝绝对越界路径、符号链接、硬链接、父目录权限异常和 TOCTOU；读取的 fixture 只能是普通文件并通过 schema/hash 校验。
启动时及 provider/adapter/summary/media/publish 调用前重新断言两门的交集仍为 fixture-only；任一断言失败立即 abort/fail closed，不能靠运行时环境变量注册能力。
```

至少要有“每个 canonical 开关单独翻转、所有组合、别名/大小写/空值、依赖注入和调用前变更”的本地测试收据。

### 4.2 Loopback、Origin、代理和 CORS 绕过（P0｜A层缺口阻断 accepted；B层失败阻断实现）

**威胁。** 进程仍绑定 loopback，但可控的 `APP_PUBLIC_ORIGIN`、`Host`/`Forwarded` 头、代理转发、DNS rebinding 或宽松 CORS 让跨站页面向 admin mutation 发送请求；缺少严格端口/协议/主机校验还会使同源判断失效。

**证据。** ADR 要求 `APP_BIND_HOST` 为 `127.0.0.1` 或 `::1`、拒绝代理、变更请求带同源 Origin；`.env.example` 仍允许设置 `APP_PUBLIC_ORIGIN=http://localhost:3000`，没有写明它必须是 loopback、必须与端口绑定、如何拒绝多值/opaque Origin，也没有写明 CORS 和转发头默认策略。S-07 是测试矩阵 P0。

**是否阻断 ADR accepted：A 层是，B 层否。** canonical origin、代理头和 CORS 规则仍有静态歧义；浏览器/HTTP 收据属于 B 层，不能倒置技术路线接受顺序。

**精确最小修订 R2：**

```text
APP_BIND_HOST 只允许 127.0.0.1 或 ::1；APP_PORT 为 1024–65535 的十进制端口。
APP_PUBLIC_ORIGIN 启动时必须解析为 http（本地）+ localhost/127.0.0.1/[::1] + 与 APP_PORT 相同的端口，禁止 userinfo、path、query、fragment、通配符和其他主机；服务端以实际绑定地址/端口生成 canonical_origin，配置与其不一致即拒绝。
认证不得信任 Host、X-Forwarded-Host、X-Forwarded-Proto、Forwarded 或代理注入的原始 Origin；禁用 CORS 和 wildcard ACAO。
每个 admin mutation 必须收到一个且仅一个 Origin，按 scheme/host/port 与 canonical_origin 精确匹配；缺失、opaque、多值、大小写/编码异常或不匹配均返回拒绝。admin route 不可通过 GET 改变状态。
```

未验证项包括真实浏览器请求、IPv4/IPv6 绑定行为、DNS rebinding 和代理头测试。

### 4.3 会话固定与 CSRF nonce 重放（P0｜A层缺口阻断 accepted；B层失败阻断实现）

**威胁。** “有会话”和“一次性 nonce”若没有熵、绑定、TTL、原子消费和并发语义，旧会话、重复请求或并发请求可能重复 approve/publish/correct/withdraw/stop。

**证据。** ADR 只写“进程启动时生成 local-dev 会话”“HttpOnly/SameSite=Strict cookie”“按会话签发一次性 CSRF nonce”；没有明确 CSPRNG、会话轮换、nonce 对 method/path/body 的绑定、过期、原子单次消费、常量时间比较、失败状态码或旧会话失效。S-07 为 P0。

**是否阻断 ADR accepted：A 层是，B 层否。** nonce 的随机性、绑定、TTL 和原子消费缺少静态定义；实现后的重放/并发测试属于 B 层。

**精确最小修订 R3：**

```text
会话 ID 和 CSRF nonce 均由 CSPRNG 生成，至少 256 bit；仅存进程内，进程重启全部失效，不写日志/URL/HTML hidden raw 值，不使用静态默认密码、仓库凭证或可预测种子。
cookie 使用 HttpOnly、SameSite=Strict、host-only、Path=/；启用 HTTPS 时加 Secure；不得设置 Domain。
nonce 绑定 session_id、HTTP method、规范化 path、请求体 hash 和发行时间，TTL 不超过 10 分钟；服务端用原子 compare-and-consume 和常量时间比较，重放/并发第二次使用、过期、缺失或绑定不符均拒绝；不以 Referer 作为回退。
approve/reject/publish/correct/withdraw/stop 等所有 mutation 一律走该 fence，只接受允许的 mutation 方法和 `application/json`；旧会话、跨 Origin、GET mutation 均拒绝。
```

### 4.4 Secret、日志和客户端泄露（P0｜A层缺口阻断 accepted；B层失败阻断实现）

**威胁。** Authorization header、cookie、OAuth code、带 query 的 URL、原文、prompt、模型输出、错误堆栈或未知环境变量进入 JSON 日志、审计、告警、客户端 bundle 或仓库。

**证据。** Spec/ADR 要求不记录 token、原文全文、私密标识、内部堆栈，客户端只收安全 DTO；测试 S-08 将仿真 token header/错误体/正文/模型输出列为 P0。现有合同没有统一字段 allowlist、未知字段拒绝、query/body/header 的具体脱敏清单、`Set-Cookie`/OAuth code 处理或 client/server bundle 扫描的实现证据。

**是否阻断 ADR accepted：A 层是，B 层否。** allowlist、统一脱敏和客户端/日志禁止项需先写清；扫描与错误路径收据属于 B 层，失败时阻断实现和阶段验收。

**精确最小修订 R4：**

```text
日志和 audit_event 采用字段 allowlist；默认不记录 request/response header、query、body、原文、prompt、模型输出、URL query/userinfo、错误堆栈和内部 task topology。
统一脱敏器必须覆盖 Authorization、Cookie、Set-Cookie、access/refresh token、OAuth code、api_key、secret、password、私密 URL 和个人/平台 ID；未知字段或疑似 secret 命中时拒绝写日志并产生脱敏 incident 摘要。
verify:env、源码扫描和 client bundle 扫描必须拒绝 FEISHU_*/X_*/REDDIT_*/META_*/AI secret 值、token 形状和完整外部响应；脱敏审计只保留 synthetic ref、hash、长度、错误分类和 trace。
```

### 4.5 SQLite 文件、WAL 和路径竞态（P1｜A层缺口阻断 accepted；B层失败阻断实现）

**威胁。** `F1_DB_PATH` 虽位于 `.local/`，但目录、数据库、WAL/SHM、临时文件可被其他本地用户读取；符号链接、硬链接或 TOCTOU 将写入仓库外路径。

**证据。** ADR 只要求路径解析到仓库 `.local/` 或测试临时目录并拒绝任意绝对路径；没有文件模式、umask、WAL/SHM、符号链接/硬链接、父目录权限或原子创建合同。数据合同需要 durable 状态和脱敏审计，实际数据库尚未创建。

**是否阻断 ADR accepted：A 层是，B 层否。** 文件模式、umask、链接和路径竞态尚未形成静态合同；启动权限收据属于 B 层。

**精确最小修订 R5：**

```text
启动时用 umask 077；创建并核验 .local/ 和测试临时目录为 0700，DB、-wal、-shm、journal、临时备份为 0600；F1_DB_PATH 及所有父路径必须 realpath 后仍在允许根内，拒绝 symlink/hardlink 和 TOCTOU，使用 O_NOFOLLOW/原子创建。
路径、权限、WAL/SHM、重启恢复和并发打开均纳入 verify:env/test:contract；失败立即停止，不自动改写到当前目录或系统临时根。
```

### 4.6 SSRF、原链和开放重定向（P0｜A层缺口阻断 accepted；B层失败阻断实现/真实 fetch）

**威胁。** 原始 X/外部链接、媒体 URL、`next` 参数或重定向链访问回环、RFC1918、链路本地、云元数据、IPv4 变体、IPv6 映射地址，或跳转到 `javascript:`/data/外站，形成 SSRF、凭证探测、恶意跳转或 XSS。

**证据。** 测试 S-02/S-04 已把完整攻击集合列为 P0；Spec 把外部内容 URL/SSRF 作为待验证风险；ADR 只有 `server/security` 目录方向，未写 M4 原链是否只展示、媒体是否可抓取、每跳 DNS/IP 校验、代理环境和 `next` 合同。M4 目前宣称无真实外部调用，尚无运行证据。

**是否阻断 ADR accepted：A 层是，B 层否。** M4 原链展示/抓取分离、危险协议/地址/重定向边界仍需写入静态合同；deny-all/SSRF 探针属于 B 层，失败时阻断实现和任何真实 fetch 能力。

**精确最小修订 R6：**

```text
M4 中 original_url 只能作为已存、脱敏 DTO 的展示链接，服务端不得抓取；media 只接受 synthetic:* fixture 或显式无图，任何 http(s) fetch 入口在 capability registry 中不存在。
若未来任务单独启用 fetch，必须只允许 https（除非新门禁明确允许 http），拒绝 userinfo、控制字符、非 http(s)、危险端口、回环、RFC1918、链路本地、保留/元数据、IPv4 整数/八进制/十六进制、IPv6 mapped 地址；DNS 解析、连接地址和每一跳 redirect 重新校验并 pin，默认不跟随 redirect，不读取 HTTP(S)_PROXY/NO_PROXY 绕过；设置连接/读取/响应字节/压缩比/总时长上限。
任何 redirect route 不接受任意 next；只允许合同内 canonical HTTPS URL 或安全中间页，拒绝协议相对、javascript:/data:、控制字符、编码绕过和不受信目标。
```

### 4.7 XSS、XML 资源耗尽和外部媒体（P0｜A层缺口阻断 accepted；B层失败阻断实现/真实媒体）

**威胁。** 标题、作者、摘要、正文、alt、审核备注、HTML/Markdown、CSS/URL 上下文触发脚本；XML 外部实体或压缩炸弹耗尽资源；伪造 MIME 的 SVG/HTML、像素炸弹或多帧媒体在 Web 进程执行。

**证据。** S-01、S-03、S-06 均为 P0，明确要求 safe text DTO、CSP/`nosniff`、禁止外部实体/网络、字节/深度/节点/解压/耗时上限、媒体隔离和无图降级。ADR 只概括“外部内容不可信”“媒体 fixture/none”“security 模块”，没有禁止危险 HTML API、输出上下文规则、CSP、XML parser 配置和 Web/worker 解码隔离的最小文字；当前无 app 实现。

**是否阻断 ADR accepted：A 层是，B 层否。** DTO、渲染、XML、媒体隔离和 prompt capability 规则仍需静态明确；S-01/S-03/S-05/S-06 收据属于 B 层，不能以 mock 豁免实现验收。

**精确最小修订 R7：**

```text
所有 public/admin DTO 默认 text-only；禁止 dangerouslySetInnerHTML、未审计 HTML/Markdown renderer 和用户输入拼接 CSS/URL。若确有富文本，使用固定 allowlist sanitizer，并对 HTML/attribute/URL/CSS 各上下文编码；只允许 https canonical link；响应设置 CSP、X-Content-Type-Options:nosniff、frame-ancestors 'none'、Referrer-Policy:no-referrer。
任何 XML/parser 禁止 DTD、外部实体、网络解析、递归实体；设置输入字节、字段长度、深度、节点、解压比和总耗时上限，超限进入隔离。
M4 media 仅 synthetic fixture/none，不接收 SVG/HTML/active content；若未来处理媒体，必须在无网络、无密钥的隔离 worker 中按 MIME/魔数/尺寸/帧数/像素和耗时限制解码，失败只走无图分支。
```

### 4.8 Prompt injection 与能力越界（P0｜A层定义能力边界；B层失败阻断实现/模型能力；M4-only 可保持关闭）

**威胁。** 外部正文、HTML 注释、alt 或作者名中的“忽略指令/泄露 secret/调用工具/发布”被当作模型指令，触发网络、工具、凭证读取或发布。

**证据。** Spec/ADR 将 summary 定为 fixture/mock，并明确无网络、无工具、无密钥、无发布权；S-05 仍要求不可信数据分隔、输出 schema 和失败隔离，优先级 P0。当前没有 worker capability、进程环境清理或实际 probe 证据。

**是否阻断 ADR accepted：** 对 M4 fixture-only 合同，R1 的 capability registry 和 R7 的 safe DTO 完成后可解除本项对 M4 的独立阻断；对任何真实模型/供应商 profile，必须阻断并新建门禁。

**精确最小修订 R8：**

```text
M4 summary worker 只允许 deterministic fixture function；运行进程无网络/DNS/socket/子进程/工具/secret 环境变量/发布 repository 权限，输入按不可信数据字段传入，输出通过固定 schema/长度/引用校验，异常进入人工隔离。
引入真实模型前必须另建任务，明确 prompt/data 边界、供应商和数据区域、工具 allowlist、密钥隔离、输出验证、审计与用户确认；本 ADR 不预授权。
```

### 4.9 Task envelope、epoch、lease 和急停竞态（P0｜A层缺口阻断 accepted；B层失败阻断实现）

**威胁。** 旧 `source_config_epoch`、`source_safety_epoch`、`authorization_version`、`policy_epoch` 或 `recovery_epoch` 的任务在停用、授权变化、急停或恢复后写入当前状态；租约竞态造成重复 outbox、旧发布或停后自动回弹。

**证据。** ADR/数据合同列出五类 epoch/fence，并要求提交前比较、同事务 observation→inbox/CAS→outbox；测试 P-11、P-12、E-04、E-07、E-10、S-10 为 P0。数据合同的 `Publication`/`OutboxJob` 目前主要显式保存 `source_config_epoch`，测试矩阵还出现 `source_config_version`，`source_safety_epoch` 和其余 runtime fence 没有独立内部 schema。ADR 同时把 envelope 的字段校验和迁移留给后续代码 ADR，尚未规定必填字段、单调性、lease token、过期/截止时间、调用前与提交前的原子 CAS 或停机 60 秒出口。

**是否阻断 ADR accepted：A 层是，B 层否。** TaskEnvelope 必填字段、统一命名和每个副作用前的五 epoch 检查尚未固化；lease/CAS/急停竞态收据属于 B 层。

**精确最小修订 R9：**

```text
内部 envelope 必须包含并校验 task_id、operation_id、payload_hash、source_config_epoch、source_safety_epoch、authorization_version、policy_epoch、recovery_epoch、lease_token、lease_expiry、deadline 和 attempt；缺失、Unknown、默认 0 或非单调值均拒绝。统一使用 `*_epoch` 命名，禁止 `source_config_version` 与 `source_config_epoch` 含义漂移。
取得 lease、调用 provider/adapter 前、outbox dispatch 前、写当前状态/提交 outbox 前以及每次 publication/publish/correct/withdraw 前，分别做同一事务可见的 CAS/fence 检查；五个 epoch 必须全部比较，lease_token 必须原子匹配且过期即失效，旧 worker 不能 ack/commit。
stop/授权失效/合规停用通过递增 recovery/policy/authorization epoch 使旧 lease 失效；新任务在 60 秒内停止，旧结果只记脱敏审计或 reconcile，不更新当前状态，解除 stop 不自动回弹。
```

### 4.10 审核 hash、manual publish 和未知状态（P0｜A层缺口阻断 accepted；B层失败阻断实现/发布）

**威胁。** 编辑后沿用旧批准、hash 只覆盖部分字段、发布竞态绕过人工审核，或超时直接生成第二个 `public_id`，产生未审核/错误公开投影。

**证据。** ADR 要求批准绑定 Bundle hash、publish/correct/withdraw 重验 hash、`manual_only`；数据合同的 `Review`/`Publication` 当前主要保存 content/summary hash，`OutboxJob.payload_hash` 是任务 payload hash，不能替代发布 Bundle hash；媒体、权利、来源证据、政策或 schema 变化可能不改变现有 hash pair。测试 P-08/P-10/P-12、§5.3 将 canonical hash、并发和 reconcile 列为 P0。ADR 没有给出 canonical JSON 规则、hash 覆盖字段、审批 actor/session、原子发布条件和未知状态的完整协议。

**是否阻断 ADR accepted：A 层是，B 层否。** ReleaseBundle canonical hash、approved_bundle_hash 和原子 manual publish 条件尚未写入静态合同；实现后的并发/超时/reconcile 收据属于 B 层。

**精确最小修订 R10：**

```text
payload_hash 固定为 SHA-256(UTF-8 canonical JSON)：键排序、数字/空值/编码规则固定并写入版本；覆盖 content、summary、source provenance、original_url、rights、media、policy、版本、schema、五个 runtime fence 和 release_bundle_id，明确无图也要有稳定字段。
`review_decision`、`publication` 和 outbox 必须保存并比较 `approved_bundle_hash`；同时保存 bundle_id、content_version、summary_version、payload_hash、reviewer_ref、issued_at、session_ref 和状态；任一内容/权利/政策/媒体/schema/source evidence/runtime fence 变化立即 supersede 旧批准。
publish/correct/withdraw 仅在单事务中同时满足当前 Bundle/hash/版本、approved 状态、manual_only、五个 runtime fence、session/Origin/CSRF 和稳定幂等键；超时进入 reconcile_wait，查询同一 key，禁止生成新 public_id 或盲重试；自动触发器和外部发布器在 M4 registry 中不存在。
`approved_bundle_hash` 与 outbox 的任务 `payload_hash` 语义分离，不能相互替代。
```

### 4.11 OAuth 三层门禁与 142 scopes 残余风险（P1；M4-only 不阻断，任何 auth/A-D profile 阻断）

**威胁。** 未来实现误把 app 开通、用户 grant/token scope 或资源 ACL 的任一层当作全部授权，或把当前 `--recommend` 得到的 142 scopes 当作最小权限；refresh/logout/revoke 的 Unknown 被当成成功。

**证据。** Spec/ADR 已写 `app scope ∩ user grant/token scope ∩ resource ACL`、不自动扩权、M4 不创建/交换/刷新/撤权 token；OAuth 纠偏报告保留 refresh 一次性、旧 access 并存、CLI 版本映射与 revoke/grant Unknown。当前没有 auth runtime 或 profile manifest 证据。

**是否阻断 ADR accepted：** M4-local-fixture-v0 严格无认证、无凭证、无网络时，本项可作为未来门禁保留；任何启用 `base_direct`、`base_snapshot`、真实 auth 或 `offline_access` 的 profile 都必须阻断并另立任务/用户确认。

**精确最小修订 R11：**

```text
M4 启动和测试必须证明无 Feishu auth SDK/命令、无凭证环境、无真实 provider 和无 token state mutation。
未来 A/D profile 以版本化 manifest 固定 operation→granular scope→resource ACL；每次读取同时检查 app grant、user token scope、目标 ACL，缺失/额外 scope/ACL Unknown 均 fail closed，不自动添加 offline_access、write/delete、permission 或 scope。
任何 login/logout/refresh/revoke/reauthorize、token 轮换或真实 Base 读写均需新任务、新收据和用户确认；成功 JSON、本地删除或 scope 缩窄不能升级为 grant 删除/服务端撤权证明。
```

### 4.12 依赖安装、供应链与运行时外连（P1｜A层缺口阻断 accepted；B层失败阻断实现）

**威胁。** `npm ci`、包生命周期脚本、DNS/代理环境或构建工具在 M4 runtime 中访问外网、拉取未锁定内容或读取 secret；将安装阶段的网络误写成“全程无外连”。

**证据。** ADR 将 `npm ci` 列为候选命令，测试 K-09/S-09 要求 deny-all、锁文件和供应链扫描；开发预检报告明确目标网络安装尚未验证。当前无 package-lock/app 运行收据。

**是否阻断 ADR accepted：A 层是，B 层否。** 必须在合同中区分 dependency bootstrap 与 runtime no-egress，并规定 lockfile/lifecycle/proxy 边界；K-09/S-09 收据属于 B 层，失败时阻断实现与阶段完成。

**精确最小修订 R12：**

```text
把 dependency bootstrap 与 M4 runtime 分开记账：npm ci 仅在用户单独允许的网络/已审计离线缓存中执行，lockfile 完整性和 lifecycle 脚本来源可核验；它不计入 runtime no-egress 证明。
verify:env/check/test/test:contract/dev/worker:mock 在 deny-all egress 下运行，禁止 HTTP(S)_PROXY/NO_PROXY 绕过，审计 DNS/socket/subprocess/child_process 和 package lifecycle；任一真实外联退出非零并阻断。
lockfile、依赖许可证/漏洞、构建产物和 secret 扫描必须通过或有期限明确的非 P0 例外；M4 不下载未声明内容、不读取真实环境凭证。
```

### 4.13 审计可追溯性与急停可见性（P2，当前不单独阻断）

**威胁。** 即使安全 fence 正确，缺少 trace、错误分类、hash/fixture 版本、stop/reconcile 状态或 retention 也会让事故难以复盘。

**证据。** ADR/数据合同已要求脱敏 audit、trace、hash、状态和恢复 epoch；没有 retention、时钟漂移和审计完整性规则。

**是否阻断 ADR accepted：A 层否，B 层按需。** R13 是可观测性补强；其静态字段和禁止项可随 R4/R9 一并写入，但不单独阻断技术路线。实现后缺少 trace/状态/retention 只阻断可追溯的阶段验收，不能替代 P0 fence。

**精确最小修订 R13：**

```text
每个 task/operation/review/publish/stop/reconcile 记录 synthetic trace、脱敏 payload/fixture/schema hash、epoch、attempt、错误分类、当前状态和下一动作；审计事件 append-only、带本地时间与单调序列，禁止写 secret/原文/私密 ID。保留期、清理方式和时钟异常在测试报告中声明。
```

## 5. ADR accepted 与 Build Loop 的两层收口

accepted 只等待 A 层静态正式合同；B 层实现和运行收据不倒置技术路线接受顺序。

| 门禁 | A 层：ADR/Spec 定版前最小文字 | B 层：app/Build Loop 运行出口 |
|---|---|---|
| 真实 provider/外部 IO | **当前阻断 accepted**：R1 双门、严格 env allowlist、未知/别名/凭证变量拒绝、fixture path realpath、调用前断言 | **阻断实现/阶段**：capability registry、真实 client 不实例化、deny-all、外部调用计数为 0；单变量绕过升级 P0 |
| loopback/admin/Origin/CSRF/会话 | **当前阻断 accepted**：R2/R3 canonical origin、代理/CORS 禁止、nonce/session/JSON/method 精确语义 | **阻断实现/阶段**：HTTP/浏览器、旧会话、Origin、nonce 重放/并发/急停测试；可利用绕过升级 P0 |
| XSS/SSRF/open redirect/XML/media/prompt | **当前阻断 accepted**：R6–R8 safe text、原链展示与抓取分离、URL/IP/redirect/解析/媒体/worker 边界 | **阻断实现/阶段/真实能力**：S-01–S-06、deny-all、恶意媒体/提示探针；可利用结果升级 P0 |
| secret/log/SQLite | **当前阻断 accepted**：R4/R5 allowlist、统一脱敏、`.local`/DB/WAL/SHM/journal 权限与路径规则 | **阻断实现/阶段**：bundle/日志/异常/权限/symlink/备份扫描；secret 泄露升级 P0 |
| epoch/fence/急停/未知状态 | **当前阻断 accepted**：R9 独立 TaskEnvelope、统一 `*_epoch`、五 epoch 和每副作用前检查文字 | **阻断实现/阶段**：lease/CAS、崩溃/并发/急停/reconcile 收据；旧 fence 写当前状态升级 P0 |
| review hash/manual publish | **当前阻断 accepted**：R10 canonical `approved_bundle_hash`、覆盖字段、supersede 和单事务 manual-only 条件 | **阻断实现/阶段**：hash/版本/权限/超时/幂等/第二 public_id 测试；旧 hash 可发布升级 P0 |
| OAuth 三层门禁 | **M4 不阻断 accepted**：R11 明确无 auth/无凭证；未来 profile 固定三层和 Unknown fail-closed | **M4 不启用**；auth/A-D 实现、真实 token/ACL 证据需新任务和用户确认 |
| 依赖安装与 runtime no-egress | **当前阻断 accepted**：R12 区分 bootstrap 与 runtime，锁文件、lifecycle、proxy/deny-all 约束 | **阻断实现/阶段**：K-09/S-09、依赖扫描、外联退出码；失败不改变已接受技术路线，但禁止阶段完成/真实能力 |

因此，当前报告只把 A 层文字缺口列为 accepted 阻断；“app 尚未实现、探针尚未执行、运行收据尚未形成”属于 B 层未验证，不再被写成 accepted 的前置条件。

## 6. 必须立即停止的条件

出现 A 层合同缺口时，保持 ADR `proposed`，停止进入正式实现；出现 B 层运行失败时，停止 Build Loop、阶段验收和真实能力，并提交带 trace 的脱敏差异。B 层失败本身不自动否定已接受的技术路线，除非复核证明路线无法满足 A 层合同。

1. 任一环境变量、未知别名、依赖注入或配置失败使真实 provider、网络、DNS、模型、媒体、Base、表单或发布出口可达。
2. admin 未绑定 loopback，Origin 缺失/不匹配仍可 mutation，CSRF nonce 可重放，旧会话可用，或 CORS/代理头绕过成功。
3. S-01–S-08/S-10 任一安全探针可利用；出现 secret/token/完整 URL/原文/私密 ID 落仓或客户端暴露。
4. 陈旧 epoch、过期 lease、急停后的任务或未知 publish 状态更新当前状态、恢复旧审批、创建第二 `public_id` 或自动回弹。
5. 当前 Bundle/hash/版本/rights/media/policy 与审批不一致仍可 publish，或 publish timeout 通过新 key 盲重放。
6. 任何 `login/logout/refresh/revoke/reauthorize`、token 轮换、Base 访问、真实表单提交、Collector/provider/真值/采集/发布切换被本任务触发。

## 7. 已验证、未验证和证据等级

### 已验证（仓库静态证据）

- 任务 JSON 的只读范围、授权状态、失败路径和验收出口已核对；当前任务不授权实现或认证。
- Spec/ADR 明确当前唯一 profile 为 fixture/mock/manual-only，真实 Base、provider、Collector、表单、AI、图片、自动发布、部署、付费和外发保持关闭；ADR 仍为 proposed。
- ADR 的 provider/API/env/loopback/runtime fence/回滚文字、数据部 9 条不变量和测试部 S-01–S-10/P-01–P-12 目标已逐项对照。
- 测试矩阵把真实外部调用、XSS、SSRF、开放重定向、提示注入、恶意媒体、CSRF/越权、密钥泄露、急停竞态和陈旧 epoch 设为 P0；报告没有把 mock 当生产通过。
- OAuth 纠偏报告的三层门禁、refresh/logout/revoke Unknown 和当前 M4 不执行 auth 的边界已吸收；没有将 142 scopes 写成已收敛，也没有将成功 JSON写成撤权完成。
- 本报告只新增安全部报告文件；没有改写 Spec、ADR、app、数据合同或历史 OAuth 报告。

### 未验证（不得在验收中省略）

## 8. 错题自检与对抗复核

### 错题自检

- 没有把 `fixture` 当作 Base 业务真值、真实 provider 或生产可用证明。
- 没有把 Spec/ADR 的候选命令、M4 逻辑探针或测试矩阵目标写成 app 已通过。
- 没有把 loopback、SameSite 或“有 nonce”单独当成生产认证；保留 Origin/CSRF/会话/代理和并发语义缺口。

- 没有把 token scope 缩窄、logout 成功 JSON、本地删除或事件类型提升为历史 grant 删除/服务端撤权完成。
- 没有把旧报告取证时点改写成当前实现状态；后续真实导入/运行状态仍由统筹部执行收据和测试任务证明。
- 已核查 OAuth 补充报告 mtime；在无法把写入精确归属当前会话时，没有删除或回滚既有有效内容。
- 没有执行任何高风险命令、外部访问、认证状态变化、飞书资源读写或 app 实现。

### 两路本地只读对抗复核结果

两路对抗复核均在本地只读边界内完成：

- `import_gate_review` 路线检查 config/IO/admin/URL/content/storage，结论为条件式 PASS；指出环境 allowlist/代码级双门禁、Origin/CSRF 精确定义、日志/SQLite 权限、URL/媒体和每个副作用前的五 epoch 检查仍需静态补齐；当前没有已发生 P0，若实现可绕过则升级 P0。
- `oauth_scope_review` 路线检查 OAuth 三层、TaskEnvelope/fence、ReleaseBundle hash/manual publish 和外部 IO，结论为条件式 PASS；指出数据合同当前只显式保存 content/summary hash，不能替代 `approved_bundle_hash`，且 `source_safety_epoch`/其余 runtime fence 尚需独立内部 schema；M4 auth 关闭，未来 auth/A-D profile 仍需独立门禁。

## 9. 最终结论

**CONDITIONAL PASS（本地合同层）。** M4 可继续以 `M4-local-fixture-v0` 作为候选路线，保持 fixture/mock、loopback-only、本地 SQLite、人工审核和 manual-only local projection；真实 Feishu/provider/Collector/表单/AI/图片/发布/部署/付费/外发继续关闭。

**ADR accepted：当前仅受 A 层静态合同阻断。** 先补 R1–R13 所列静态默认值、拒绝条件、TaskEnvelope、ReleaseBundle hash、Origin/CSRF、URL/媒体、secret/SQLite、OAuth 和依赖/egress 文字；补齐后可以接受所选本地技术路线，不需要等待 `app/` 运行收据。随后 B 层实现/Build Loop 必须取得代码、测试、deny-all、并发/恢复、浏览器和审计收据；B 层任何失败都阻断实现验收、阶段完成和真实能力启用，不能写成路线已通过。安全部不替产品部接受 ADR，不替开发部实现，不替测试部宣称通过；在 A/B 门禁分别满足前，任何真实认证、外部 IO、Base 访问、provider/真值/采集/发布切换都保持停止。
