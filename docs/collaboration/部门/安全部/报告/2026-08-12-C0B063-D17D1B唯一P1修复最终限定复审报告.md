## 3. D17D1B P1-01 闭合证据

### 3.1 build → 身份预检 → mode 归一 → manifest

`release:build-and-manifest` 固定先运行 production build，再运行 builder。builder 在 `admin-build-release-manifest.ts:21-24` 先调用 `normalizeAdminNextBuildPermissions()`，随后构建 manifest，最后写 `0600` manifest。

归一函数在 `release-manifest.ts:275-349` 先完整遍历身份：

- `.next` real root 必须等于预期绝对路径；
- 每项必须当前 UID、realpath 精确且不越根；
- 文件必须 regular、`nlink=1`，仅接受 fresh-build `0600/0644/0664`；
- 目录仅接受 fresh-build `0700/0755`；
- symlink、special/multi-link、异主、越界及其他 mode 在 chmod 之前拒绝；
- 归一通过已打开的 `O_NOFOLLOW` descriptor，并在 `fchmod` 前复核 dev/inode/uid/type/nlink；
- 纳入闭包的非执行文件固定归一 `0644`，目录固定 `0755`。

当前 executable allowlist 为空，当前 322 项也没有执行文件，未通过扩展名猜测放行执行位。

### 3.2 target verifier 只读重算

`readVerifiedAdminReleaseManifest()` 在 `release-manifest.ts:670-731`：

- 要求 manifest 为当前 UID、regular、nlink1、非 symlink、realpath 精确、mode `0600`；
- 要求外部 expected SHA 为精确 lowercase SHA-256，并先核对 manifest 原始字节；
- 固定 Git commit/tree/parent 与 Node path/version/SHA；
- 重新枚举 runtime、Next 和 production dependencies；
- Next 目录必须精确 `0755`，入闭包文件必须精确 `0644`；
- 重新计算 path/mode/size/SHA 和 roots，再与 canonical manifest 逐字比较。

verifier 路径没有调用 `normalizeAdminNextBuildPermissions()` 或 chmod；target 漂移只能失败，无法被现场修补。

### 3.3 public installer 的外部锚与提交边界

`install-macos-public-beta-core.ts:155-179` 在创建 task stage 或写 live 文件前完成：

- 强制读取 `F1_RELEASE_MANIFEST_PATH` 和 `F1_RELEASE_MANIFEST_SHA256`；
- 调用同一 `readVerifiedAdminReleaseManifest()`，绑定当前 appRoot、target Node、local Node 与完整 release；
- 强制读取外部 `F1_PUBLIC_SYNTHETIC_ROLLBACK_RELEASE/HASH`；
- rollback release 必须等于已绑定 `.next/BUILD_ID`；rollback hash 必须是 lowercase SHA-256 并等于 owner-only、single-link synthetic DB 的实际 SHA。

由此 rollback anchor 由任务外部值约束，目标机只能做匹配验证，不能把目标机漂移值静默自举为锚点。

随后在 task-private stage 内生成 public-beta、quick-tunnel、receiver 及 deployment/log 工件。`beforeCommit` 之前没有 live 写。提交时先备份目标字节和 mode；任一 `atomicReplace` 失败或提交中断，按逆序恢复所有目标。stage 最终被清理。

三份 plist 均包含 `RunAtLoad=false`、`KeepAlive=false`。本范围代码检索没有 `launchctl`。

## 4. 九项 exclude 的限定裁定

明确排除项为：

- `cache/.previewinfo`
- `cache/.rscinfo`
- `cache/.tsbuildinfo`
- `diagnostics/build-diagnostics.json`
- `diagnostics/framework.json`
- `diagnostics/route-bundle-stats.json`
- `trace`
- `trace-build`
- `turbopack`

静态依赖结论：

1. `.previewinfo` 和 `.rscinfo` 是 **build-time cache**。Next build 读取或生成它们，并分别将实际 preview keys 写入受 manifest 绑定的 `prerender-manifest.json`，将 RSC encryption key 写入受绑定的 `server/server-reference-manifest.{js,json}`。当前值逐值比对成立；公开 `next start` 的运行输入来自这些受绑定产物。
2. `.tsbuildinfo` 只由 TypeScript build 增量检查写入 cache，不是 `next start` 执行输入。
3. 三个 diagnostics 文件只由 build diagnostics/route bundle stats 生成，不是公开服务 route、chunk 或配置入口。
4. `trace-build` 是 build trace；`trace` 是 tracing reporter 的可变输出；`turbopack` 当前为空的构建可变文件。它们不作为公开 route、chunk、manifest 或直接可执行文件加载。
5. 九项当前均为当前 UID、regular、nlink1、非 symlink、realpath 精确；没有 executable bit。即使排除字节发生变化，也没有观察到 `next start` 把它们当作代码或权威配置输入的静态路径。

该结论限定在当前 Next `16.2.11` 冻结依赖。升级 Next 时必须重新裁定 exclude allowlist，不能跨版本继承。

### P2-01：prepare-only 成功会替换 live 磁盘 plist，目标机仍需前后身份收据

当前实现保证三份 plist disabled、0 `launchctl`、失败恢复旧字节。成功 prepare 会原子替换真实 public-beta、quick-tunnel、receiver plist 的磁盘内容；这属于明确的 prepare 产物提交。现有静态合同没有保存长期、独立的 pre/post/rollback receipt，也没有静态证明目标机当前 loaded job 如何处理磁盘替换。

该项不阻断 prepare-only，因为新 plist 不自动加载，且本轮授权只到 prepare。M1 prepare 任务必须在操作前后记录三份 plist SHA/mode/uid/nlink、loaded state 和现有公开服务健康；任何异常应使用当次内存/任务收据中的旧字节回退并停止，不得继续 load。
