## 4. 五类 P1 复验

### 4.1 单一 data-native 输入：PASS

两个临时项目根均没有 `app/` 目录，generator 在两套根中各连续生成两次并通过 validator；每轮 9 项字节与正式包完全一致。

AST 与行为证据同时确认：

- generator 不存在 `STORIES` 赋值；
- 不存在 `UI_INPUT` 运行变量；
- `app/src/features/stories/demo-data.ts` 只出现一次，位于一次性 provenance 字面量；
- generator 实际读取并遍历 `stories.input.json`；
- 新增第二个 `stories*.json` 时，generator 以 `exactly one data-native stories.input.json is required` 拒绝；
- 修改 story 后同步重绑 story SHA、artifact SHA、manifest/ledger，但不重生成领域图时，validator 以 `story input Content projection drift` 拒绝。

因此，前端旧文件已从“再生成必需输入”降为不参与运行的一次性溯源收据，数据目录中只有一份可维护 story 输入。

### 4.2 Decision hash-input 与五个 fence 精确绑定：PASS

### 4.3 manifest/profile/ledger 封闭 exact 语义：PASS

### 4.5 no-follow 原子输出：PASS

所有路径攻击均使用影子项目和影子项目根外的 sentinel：

| 攻击 | 实际结果 | 外部数据 |
|---|---|---|
| 把 `schema.json` 改为指向外部 sentinel 的 target symlink | generator reject | sentinel 保持 `SAFE` |
| 把 `schema.json` 改为目录 | generator reject | target 保持 non-regular |
| 把整个 `project/data` 改为指向项目外 data 副本的 parent symlink | generator reject | 项目外副本全文件 hash 不变 |

竞态探针在一个影子项目中一边 40 次启动 generator，一边对 `schema.json` 执行 6,360 次 regular/symlink 交替。结果为 6 次安全生成、34 次拒绝，外部 sentinel 始终为 `SAFE`。代码路径使用 directory fd、`O_NOFOLLOW`、同目录 `O_EXCL` 私有临时文件、file fsync、`os.replace` 和 directory fsync；目标在 `stat` 之后被替换为 symlink 时，`os.replace` 替换的是目录项本身，不跟随其指向的 sentinel。

## 10. P2 及未验证边界

### P2-01：开发运行时 root-of-trust 尚未实现

manifest 、ledger 和 artifact 的包内互相引用不能抵御“同步改写整个数据包和其全部包内收据”。本轮确认了四个正确 root SHA，但 SQLite/API 开发代码尚未存在，因此无法在本数据包内证明运行时已 pin。该项保留为 P2，不阻断本次数据包聚焦 PASS，但是开发接线的强制验收项。

本报告不验证：

- 两个 SQLite 实体、不同 inode、migration/seed 事务、运行时禁止 ATTACH、DB busy 和损坏行失败关闭；
- Repository/API/cursor/Problem JSON、无部分响应与前端单一 API 数据源；
- 生产级同 UID 威胁模型和完整 R5 文件/DB 路径合同；
- 原生 Draft 2020-12 validator 交叉兼容性；
- R12 OS/系统调用级 no-egress；
- 真实 Base/provider/Collector、平台授权与采集、AI、真实媒体、外部发布、部署和付费能力。
