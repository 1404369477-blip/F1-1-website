## 4. 重点独立复算

### 4.1 Task/lease/payload

逐项读取 11 个 `fixtures.synthetic.json:outbox_jobs[*]`，没有调用生成器写入路径。对每个 job 独立重算：

- `task_id = task-synth-` + `job_id` 去掉 `job-` 前缀；
- `payload_hash = SHA-256(canonical-json-v1("synthetic:payload:" + job_id))`；
- `lease_token = synthetic:lease:` + `SHA-256("synthetic:lease:" + job_id)` 的前 32 个十六进制字符；
- job/envelope 的 operation、payload、idempotency、reconcile 字段逐字一致；
- 11 个 task、lease、payload hash 各自无重复；所有 envelope 满足五 epoch ≥1、`attempt <= max_attempts` 和 900 秒窗口。

独立结果：11/11 PASS。`job-content-stale` 的 envelope epoch=1、当前 source epoch=2 的拒绝样例保持独立；epoch=0 不是有效 envelope。

### 4.2 Strict snapshots 与 hash

独立使用项目声明的 `canonical-json-v1`（UTF-8、Unicode code-point 键序、紧凑分隔符、显式 null、`ensure_ascii=false`、`allow_nan=false`、SHA-256）复算：

- 7/7 `content_version_hash` 等于 `content_hash_input` 的 canonical hash；
- 7/7 `summary_version_hash` 等于 `summary_hash_input` 的 canonical hash；
- 5/5 Bundle 的 `content_snapshot`、`summary_snapshot`、根级 content/summary hash、`payload_hash`、`bundle_hash` 全部相等；
- 5/5 ReviewDecision 的 `decision_hash` 可重算，且 `approved_bundle_hash == bundle_hash`；
- 5 个 canonical payload 的根字段集合精确为 `release_bundle_id`、两类 version hash、两类 strict snapshot、source snapshot、original URL、rights、media、policy、schema、五 fence。

没有把“生成器按自身输入能重算”当成唯一证据；同时从落盘 JSON 独立计算，结果一致。

### 4.3 Publication/key 与 projection

- 5 个 Publication 的 `(release_bundle_id, approved_bundle_hash)` 唯一，`public_id` 唯一；
- 3 个 publish Outbox job 的 job key、TaskEnvelope key、Publication key 逐字相等；reconcile key 也逐字相等；非 publication job 的 reconcile key 为 null；
- 3 个 `published` projection 的 `public_id`、Bundle、generation、published version hash 均回指同一 Publication；
- `reconcile_wait`、`retryable_failed` 只保留原 Publication/key，不创建第二 public identity。

独立结果：Publication/key 链 PASS。

### 4.4 Internal schema SHA 与边界

- `manifest.json` 对 `internal-contract.schema.json` 的文件 SHA 与当前字节一致；
- 每个 AuditEvent 的 `schema_hash` 与该文件 SHA 一致；
- `SourceObservation` 的 `(source_id, external_id)` 与 `unique_key` 均唯一；`published_at`、`operation_id`、`idempotency_key` 的可空边界落盘；
- AuditEvent sequence 严格为 1、2、3；`internal_only=true`，根级 `domain_refs=[]`、`base_mapping_refs=[]`；
- `SummaryDraft` 通过 `Summary(summary_status=draft)` 映射，未进入 domain `$defs`；`SourceObservation` 与 `AuditEvent` 也未进入 Base/domain 映射。

独立结果：internal schema SHA、字段 allowlist、映射边界 PASS。

### 4.5 Seed file/subset hash 与 M3 边界

- manifest 的 11/11 artifact SHA-256 与当前文件字节相同；manifest 自身按声明排除，避免递归；
- `seed-layers.json` 三个 layer hash 全部可重算；每个 source artifact 文件 SHA 一致；
- `published-projection-seed` count=3、`snapshot-failure-seed` count=1、`internal-fixtures-seed` count=5，三个 `subset_hash` 均按所选对象 canonical JSON 重算通过；文件 SHA 与 subset hash 分离；
- 三层恰为 `m3-shadow-seed`、`synthetic-case-seed`、`security-error-seed`，每层 `writes_to_base=false`；公开投影、快照失败、internal records 是 synthetic 子集，没有额外顶层 seed；
- M3 upstream 为 33 字段、9 个手机字段、59 行，59/59 `enabled=false`，`source_id` 与 `canonical_url` 各自 59 个唯一。M3 shadow 的原始来源 URL 属上游影子配置，不能被表述为 synthetic case 已无真实 URL；本轮没有把它推导成真实内容导入。

独立结果：file/subset hash、三层 seed、M3 disabled 边界 PASS。

### 4.6 三门、恢复与 no-egress

当前状态机有 6 组 machine、5 类 idempotency key、9 条 invariant、16 个 onboarding enum/state。`validating → activation_pending` 要求 canonical URL 有效、normalization=valid、dedup=unique；`activation_pending → queued` 同时要求 platform=allowed、authorization=valid、adapter=ready、`enabled=false`、stop clear、五 fence，并明确在同一 activation transaction 写 `enabled=true`、queued、一个 outbox/task operation。门优先级严格为 `platform > authorization > adapter`。

恢复出口逐项存在：blocked 三门回 activation_pending；normalization/dedup failure 回 validating；queue failure 可有界回 activation_pending 或 dead_letter；collection failure 可有界回 collecting 或 dead_letter；stopped/cancelled/dead_letter 有显式恢复/人工重排；Publication retryable/blocked/reconcile/emergency stop 和 Outbox retryable/stale/cancel/dead_letter 均保留原 key、重新核对 fence 或要求人工动作。`paused` 只在 lifecycle_status，未污染 onboarding enum。

主 fixture、security fixture、internal fixture、seed layers 的 `synthetic_only=true` 与 `external_calls=0` 均通过；security fixture 的 16 个类别逐条 payload hash 可重算，均声明 `no-secret-no-network`。这只是静态/合成边界证据，不等于真实进程 deny-all 已运行。
