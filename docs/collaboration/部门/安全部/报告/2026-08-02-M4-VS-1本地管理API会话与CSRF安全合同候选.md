# M4 VS-1 本地管理 API 会话与 CSRF 安全合同候选

## 1. 唯一结论

本安全合同候选结论为 **PASS**；实现结论为 **NOT_RUN / Unknown**。

PASS 只表示测试计划 `TASK-20260802-28882C` §16 的缺口 3“admin mutation HTTP 合同”和缺口 5“admin session/CSRF 协议细节”已有一份可供产品、开发、测试吸收的唯一安全候选。它不表示 API、页面、Cookie、端口、数据库、浏览器或 OS no-egress 已实现，也不授权真实账号、跨网络访问、生产认证、外部采集或发布。

候选采用以下固定取舍：

1. **运行边界**：单进程、HTTP/1.1-only、单活动 local-dev session；只绑定一个 IP-literal loopback 地址和一个端口，不信任任何代理头。
2. **session 传递**：只允许 `HttpOnly`、`SameSite=Strict`、host-only Cookie；禁止把 session 放入 JavaScript、Authorization header、query、body、localStorage 或 sessionStorage。
3. **CSRF 传递**：一次性 nonce 只经同源 JSON endpoint 返回并放入 `X-F1-CSRF-Token`；nonce 绑定 session、method、精确 path、canonical JSON body SHA-256 和服务端签发时间。
4. **原子性**：安全 predicate 全部通过后、业务事务开始前，nonce 做单向原子 `issued → consumed`；失败或业务回滚也不得恢复为 issued。
5. **失败语义**：任何拒绝最多产生一条 allowlist 安全审计和必要的内存 session/nonce 状态变化；Source、TaskEnvelope、Outbox、validation/collection job、Publication 或其他业务表写入必须为 0。
6. **HTTP 选型**：VS-1 继续使用 accepted Spec 允许的 loopback HTTP。Cookie 因 HTTP 不带 `Secure`，仅在 IP-literal loopback、无代理、无外部 bind 的本地单用户威胁模型下成立；loopback HTTPS + `__Host-` Cookie 仅列未来增强，当前不启用。

## 3. Canonical loopback、Host、Origin 与 CORS

### 3.1 启动时唯一 canonical 值

启动时只允许二选一，并在进程生命周期内不可变：

```text
IPv4: APP_BIND_HOST=127.0.0.1
      APP_PUBLIC_ORIGIN=http://127.0.0.1:<APP_PORT>

IPv6: APP_BIND_HOST=::1
      APP_PUBLIC_ORIGIN=http://[::1]:<APP_PORT>
```

`APP_PORT` 必须是 1024–65535 的十进制整数。canonical origin 必须从已验证 bind host/port 生成，再与配置逐字比较。禁止 `localhost`、userinfo、path、query、fragment、wildcard、默认端口省略、大小写别名、IPv6 zone id、协议相对 URL 或多个 origin。当前候选只启用 HTTP/1.1；HTTP/2、h2c、absolute-form request-target 或同时存在两套 authority 的请求在任何 session/nonce/DB 变化前拒绝。

若 bind、origin 或端口不满足，进程必须在创建任何 session、读取业务 DB 或监听前非零退出，reason code 为 `ADMIN_BIND_CONFIG_DENIED`。

### 3.2 每请求 gate

按以下顺序执行，任何失败立即停止：

1. socket peer 规范化后必须是 `127.0.0.1`、`::1` 或仅用于 IPv4 loopback 表示的 `::ffff:127.0.0.1`；其余为 `ADMIN_PEER_DENIED`。
2. 在框架合并、规范化或路由前，适配层保留 raw request-target 和 raw header multiplicity；只接受 origin-form request-target。重复 Host、逗号拼接、同时 Host/`:authority`、absolute-form 或规范化前后 authority 不一致，统一为 `ADMIN_HOST_DENIED`。
3. 请求中若出现 `Forwarded`、任意 `X-Forwarded-*`、`X-Real-IP` 或代理覆盖头，直接 `ADMIN_PROXY_HEADER_DENIED`；不得读取其值决定权限。
4. 原始 `Host` 必须只有一个值，并与 canonical origin authority 逐字相等；缺失、重复、逗号拼接、空白变体或别名为 `ADMIN_HOST_DENIED`。
5. mutation、session create/refresh/destroy 和 CSRF issue 必须携带单一 `Origin`，原始值逐字等于 canonical origin；缺失为 `ADMIN_ORIGIN_REQUIRED`，其他为 `ADMIN_ORIGIN_DENIED`。
6. `assertRuntimeNoEgressReady()` 必须证明 canonical local-fixture profile、deny-all capability registry/hook/probe 已安装且未漂移，DNS/HTTP(S)/raw socket/proxy/subprocess/child_process 均拒绝；Unknown/缺失/漂移为 `ADMIN_NO_EGRESS_REQUIRED`。
7. 只读 GET 可以没有 Origin；若浏览器发送 Origin，则仍须 exact match。GET 只允许读取 allowlist DTO，前后业务 hash 必须相同。

### 3.3 CORS 与缓存

- `/admin/*` 与 `/api/admin/*` 不返回 `Access-Control-Allow-Origin`、`Access-Control-Allow-Credentials`、`Access-Control-Allow-Headers` 或 wildcard CORS header。
- Admin API 的 `OPTIONS` 返回 405 `ADMIN_METHOD_DENIED`，不得形成 preflight 放行。
- session、CSRF、Admin API 响应统一：`Cache-Control: no-store, private`、`Pragma: no-cache`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`。
- session create/refresh/destroy 之外不得返回 `Set-Cookie`。
- 错误响应也使用 `no-store`，不回显 Host、Origin、Cookie、nonce、body、URL 或 stack。

## 4. Session 合同

### 4.1 Cookie 与存储

Cookie 名固定为：

```text
f1_local_admin_session
```

属性固定为：

```text
HttpOnly; SameSite=Strict; Path=/; Max-Age=<remaining absolute seconds>
```

- 不设置 `Domain`，因此为 host-only。
- 当前 HTTP profile 不设置 `Secure`；若未来使用 loopback HTTPS，必须新建合同并改为 `__Host-f1_admin_session; Secure; HttpOnly; SameSite=Strict; Path=/`。
- 进程启动时就必须生成唯一未领取 session authority 和 session ID；ID 为系统 CSPRNG 32 bytes，base64url 无 padding。UNCLAIMED 期间明文 ID 只存在一段可清零的进程内存，不进入日志/持久化/通用配置；`POST /api/admin/session` 只在 exact-Origin/no-egress 门通过后原子“领取”该 ID 并用 Set-Cookie 交付，随即清零服务端明文缓冲并只保留固定长度 digest/metadata，不在请求中另生成第二个 session。
- session 只在进程内存中存在；重启全部失效。禁止 DB、Redis、文件、env、URL、HTML、client storage 或 analytics 持久化。
- 最多一个活动 session。并发 create 通过同一原子锁串行；无有效 Cookie 且已有活动 session 时返回 409，不创建第二 session。

### 4.2 TTL 与时钟

固定：

```text
absolute_ttl = 30 minutes
idle_ttl     = 10 minutes
```

- 服务端 TTL 使用可注入的单调时钟；wall clock 只用于脱敏审计时间。
- create 时 `absolute_expires_at = now + 30m`，`idle_expires_at = min(now + 10m, absolute_expires_at)`。
- GET 不刷新 idle TTL，避免把 GET 变成状态 mutation。
- 只有显式 refresh 可延长 idle TTL；refresh 不延长原始 absolute expiry。
- 时钟不可用、倒退或溢出时 session fail closed，`ADMIN_CLOCK_INVALID`。

### 4.3 Session endpoints

| method/path | 请求 | 成功 | 拒绝/冲突 |
| --- | --- | --- | --- |
| `POST /api/admin/session` | exact loopback/Host/Origin + runtime no-egress ready；`Content-Type: application/json`; canonical body `{}`；无需旧 session/CSRF | 启动时 session 仍未领取：原子 `UNCLAIMED→ACTIVE`，`201` + Set-Cookie + allowlist metadata；请求带当前有效 session：`200`，不旋转 | 已有活动 session 且请求无/错 session：`409 ADMIN_SESSION_ALREADY_ACTIVE`；其他安全拒绝见 §8 |
| `POST /api/admin/session/refresh` | 有效 session；exact Origin；body `{}`；fresh CSRF 绑定本 method/path/body | `200`；原子生成新 ID、旧 ID 立即失效；保留 absolute expiry，重置 idle；清除全部旧 nonce；Set-Cookie | 旧 session、过期、CSRF 错绑/重放均拒绝；不产生新 session |
| `DELETE /api/admin/session` | 有效 session；exact Origin；空 body；fresh CSRF 绑定 empty-body hash | `204`；原子销毁 session/全部 nonce；Set-Cookie `Max-Age=0` | 缺失/旧/过期 session 或 nonce 拒绝；不销毁其他状态 |
| `GET /api/admin/session` | exact loopback/Host；有效 session；无 Origin 要求；无 CSRF | `200` 仅返回 `state/absolute_expires_at/idle_expires_at`；业务与 session 状态不变 | 缺失/过期为 401；不创建或刷新 session |

session create/refresh 响应不得返回 session ID。日期只用于 UI countdown，不能作为客户端授权真值。

### 4.4 Session 状态机

```text
PROCESS_START --CSPRNG--> UNCLAIMED
UNCLAIMED --exact-Origin claim--> ACTIVE
ACTIVE --refresh--> ACTIVE(new id, same absolute expiry)
ACTIVE --destroy--> DESTROYED
ACTIVE --idle/absolute timeout--> EXPIRED
ACTIVE --process restart--> INVALIDATED
```

旧 ID 没有恢复路径。refresh/destroy/timeout/restart 同时 invalidate 该 session 的所有 issued/consumed nonce tombstone 之外的可用状态。该模型对 accepted ADR “进程启动时生成”的唯一解释是：启动时生成 authority/ID，浏览器 POST 仅负责原子领取 Cookie；后继产品/代码合同必须逐字吸收，不得实现两套 bootstrap。

## 5. 一次性 CSRF 合同

### 5.1 Token、绑定与签发

CSRF token 为系统 CSPRNG 32 bytes，base64url 无 padding；TTL 固定 **5 分钟**，满足 Spec 的 `≤10min`。最多允许每 session 32 个未过期 issued nonce，超限返回 `429 ADMIN_CSRF_CAPACITY`。

签发 endpoint：

```text
POST /api/admin/csrf
Content-Type: application/json
Cookie: f1_local_admin_session=<HttpOnly session>
Origin: <exact canonical origin>

{
  "body_sha256": "<64 lowercase hex>",
  "method": "POST|DELETE",
  "path": "<registered exact mutation path>"
}
```

成功返回 `201`：

```json
{
  "expires_in_seconds": 300,
  "method": "POST",
  "path": "/api/admin/sources",
  "csrf_token": "<one-time opaque>"
}
```

token 是此合同唯一允许出现在响应体的秘密值；必须 `no-store`，只保存在页面内存闭包，禁止 DOM attribute、URL、console、日志、storage 或错误报告。页面 DTO 任一字节变化都必须丢弃旧 token 并重新签发。

绑定对象由服务端构造，客户端字段不能覆盖：

```text
session_digest
method (uppercase exact)
path (registered exact path, no query/fragment)
body_sha256 = SHA-256(exact canonical request-body UTF-8 bytes)
issued_at_monotonic
expires_at_monotonic
state = issued
```

### 5.2 Canonical body

所有 Admin mutation body 必须：

- UTF-8、无 BOM、单个 JSON object、最大 16 KiB；
- `Content-Type` 仅接受 `application/json` 或 `application/json; charset=utf-8`；重复/其他参数拒绝；
- `additionalProperties=false`、字段类型严格、有限数字、显式 null 仅在 DTO 允许时出现；
- exact bytes 必须等于 `canonical-json-v1(parsed_object)`；因此重复键、非 canonical 空白/排序、NaN/Infinity、隐式类型和 trailing bytes 均拒绝；
- CSRF body hash 与 idempotency input hash 都基于同一 exact canonical bytes，但语义字段分开保存。

session destroy 的 body 为空字节，使用 SHA-256(empty bytes)。

### 5.3 原子消费

mutation 使用唯一 header：

```text
X-F1-CSRF-Token: <one token, no comma folding>
```

消费步骤：

1. 完成 peer/Host/Origin/method/content-type/size/JSON/session 检查。
2. 对 incoming token 做固定长度 digest；无论长度是否合法都走固定长度 dummy compare，避免明显 timing oracle。
3. 在单进程 nonce store 的原子临界区内比较 token digest、session、method、path、body hash、expiry 和 `state=issued`。
4. 唯一成功请求将 `issued → consumed`，记录 `consumed_at`；失败或后续业务回滚也不恢复。
5. consumed/expired tombstone 保留到原 expiry 后 10 分钟，用于稳定返回 `ADMIN_CSRF_REPLAY`/`ADMIN_CSRF_EXPIRED`，随后内存清理。

若引入多进程、cluster、serverless、代理或第二 Admin server，当前内存原子性失效，必须启动拒绝。后续要支持多进程时，需要新的跨进程 CAS 合同和独立复验。

### 5.4 CSRF 状态机

```text
ISSUED --first exact consume--> CONSUMED
ISSUED --ttl--> EXPIRED
ISSUED --session refresh/destroy/restart--> INVALIDATED
CONSUMED --any replay--> REPLAY_REJECTED
EXPIRED/INVALIDATED --any use--> REJECTED
```

任何状态都没有回到 ISSUED 的转换。

## 6. Admin mutation 端点与 DTO 安全候选

### 6.1 通用 envelope

成功 envelope：

```json
{"ok":true,"request_id":"<opaque>","result":{}}
```

错误 envelope：

```json
{"ok":false,"request_id":"<opaque>","error":{"reason_code":"ADMIN_ORIGIN_DENIED","message":"Request rejected"}}
```

错误体只允许 `reason_code/message`；禁止 raw path、URL、header、Cookie、token、nonce、body、source private ID、stack、SQLite error 或任务拓扑。`request_id` 为本地 CSPRNG 128-bit opaque，只用于脱敏对账。

每个 mutation body 都必须含：

```json
{
  "client_operation_id":"<synthetic opaque>",
  "idempotency_key":"<at least 128-bit opaque>",
  "expected_fences":{
    "authorization_version":1,
    "policy_epoch":1,
    "recovery_epoch":1,
    "source_config_epoch":1,
    "source_safety_epoch":1
  }
}
```

add 在 Source 尚不存在时可省略 Source-specific fence，但仍必须给当前 authorization/policy/recovery fence；产品整合时应将 DTO 固定为唯一 schema，不能同时接受别名。

### 6.2 精确端点

| 动作 | method/path | 成功 | 幂等/冲突 | 允许的业务副作用 |
| --- | --- | --- | --- | --- |
| add | `POST /api/admin/sources` | 首次 `202`；返回 allowlist `source_id`、`collection_onboarding_status=validating` | same key + same canonical input：`200` 返回原结果；same key + different input：`409 ADMIN_IDEMPOTENCY_CONFLICT`；输入策略失败：`422 ADMIN_INPUT_REJECTED` | 恰好一个 synthetic Source；activation/collection TaskEnvelope/Outbox/provider call 均 0；validation lane 的表/队列、owner、key、transaction 尚未冻结，不许断言 job 计数 |
| activate | `POST /api/admin/sources/{source_id}/activate` | 事务成功 `200`，返回 queued Source 与同 operation/outbox ref | same key/input：`200` 原结果；state/gate 不满足：`409 ADMIN_STATE_CONFLICT`；fence 变化：`412 ADMIN_FENCE_STALE` | 同一事务写 `enabled=true`、queued、唯一 activation operation/outbox；worker lease 前不得 collecting |
| stop | `POST /api/admin/sources/{source_id}/stop` | 事务成功 `200`，返回 stopped/canonical state 与新 fence receipt | same key/input：`200` 原结果；fence stale：`412`；不允许状态：`409` | 原子写 stop、提升相应 safety/recovery fence、取消/陈旧化旧 lease/task；不得调用 provider 或外部系统 |
| validation retry | `POST /api/admin/sources/{source_id}/validate` | 触发 successor 将来冻结的 validation execution，`202`；完全相同请求读回原 receipt 为 `200` | key 冲突/状态不允许：`409`；fence stale：`412` | enabled 不变；activation/collection TaskEnvelope、Outbox、provider call=0；同步/异步、generation、job/queue/table/owner/transaction 形态全部 BLOCKED，本候选不创造运行对象合同 |
| dead-letter retry | `POST /api/admin/sources/{source_id}/requeue` | 仅 dead_letter；保留并复用原 outbox `operation_id/idempotency_key`，只增加 retry generation/attempt、fresh lease/nonce/fences 和 append-only audit，`202` | same original key/input：`200` 原业务事实/当前 retry receipt；伪造或改换 original identity、非 dead_letter/gate failure：`409`；fence stale：`412` | 保留旧 dead-letter；对同一业务事实重新检查 gate/fence；禁止新 operation/key 或第二业务事实 |

`POST /api/admin/sources/{source_id}/retry` **不注册**。UI“重试”必须根据 canonical state 明确调用 `/validate` 或 `/requeue`；禁止由服务端用模糊状态自动猜动作。未注册 route 返回 404 `ADMIN_ROUTE_NOT_FOUND`，业务写入 0。

VS-1 add 只接受 `synthetic.invalid`/`synthetic:` 输入；真实域名、userinfo、未允许 scheme、超长和会触发 DNS 的输入在纯字符串验证阶段拒绝。任何 M3 shadow source 的 activate/stop/retry 均返回 `403 ADMIN_M3_SHADOW_DENIED`，59 条及层 hash 不变。

### 6.3 Commit、响应丢失与重试

- 业务事务在 CSRF 已消费后开始；transaction 内重新检查 idempotency、state、三门、stop、五 fence 和 CAS。
- 事务失败必须完整 rollback，business write/outbox/job count=0；nonce 保持 consumed，客户端需要新 nonce。
- commit 成功后才发送 2xx。若 commit 后响应丢失，状态记为 `COMMITTED_UNACKED`；客户端用**新 CSRF nonce + 相同 idempotency key + 相同 body**重试，返回原结果，不产生第二 Source/job/outbox。
- 客户端不得在网络错误后自动更换 idempotency key；若无法读回，显示“结果待确认”，由同 key read-back/retry 收口。

## 7. Mutation 前置顺序与零写入语义

顺序固定：

```text
startup config + HTTP/1.1-only + raw authority adapter
→ runtime no-egress readiness
→ peer loopback
→ reject proxy headers
→ exact Host
→ method/route
→ exact Origin
→ content-type/body-size/canonical JSON
→ valid session
→ CSRF binding + atomic consume
→ idempotency lookup
→ input allowlist
→ state/gates/stop/five-fence/CAS in transaction
→ domain + outbox + domain audit commit
→ response
```

| 失败阶段 | HTTP | 允许变化 | 必须为 0 |
| --- | --- | --- | --- |
| no-egress/peer/Host/Origin/method/CORS | 403/405/503 | 最多一条 redacted security AuditEvent；已检出外联企图则日志后进程非零退出 | session claim/refresh/destroy、nonce issue/consume、所有业务表、Outbox、TaskEnvelope、job |
| content-type/size/JSON | 400/413/415 | 最多一条 redacted security AuditEvent | session、nonce、业务表、Outbox、TaskEnvelope、job |
| session | 401/409 | timeout 清理或 security audit | 新 session、nonce consume、业务表、Outbox、TaskEnvelope、job |
| CSRF | 403/429 | 首次 exact 请求可把 nonce 原子 consumed；replay 只追加 audit | Source、Outbox、TaskEnvelope、validation/collection job、Publication |
| idempotency/input/state/fence | 409/412/422 | nonce consumed + redacted audit；事务 rollback | domain/business row、Outbox、TaskEnvelope、provider/adapter call |
| internal error before commit | 500 | nonce consumed + generic audit | 所有业务写入和外部调用 |
| commit 后响应失败 | connection error | 已提交的唯一 operation + audit；标记 committed-unacked | 第二 operation、第二业务事实、盲重试、新 idempotency key |

安全 AuditEvent 是 internal-only allowlist 写入，不计为业务 mutation；若 security audit sink 自身失败，请求必须 fail closed，业务写入保持 0。

## 8. HTTP status 与 reason code allowlist

| status | reason code | 条件 |
| --- | --- | --- |
| 400 | `ADMIN_JSON_INVALID` / `ADMIN_CANONICAL_JSON_REQUIRED` | JSON 无效或 exact bytes 非 canonical-json-v1 |
| 401 | `ADMIN_SESSION_REQUIRED` / `ADMIN_SESSION_INVALID` / `ADMIN_SESSION_EXPIRED` | session 缺失、伪造、旧、过期、重启失效 |
| 403 | `ADMIN_PEER_DENIED` / `ADMIN_PROXY_HEADER_DENIED` / `ADMIN_HOST_DENIED` / `ADMIN_ORIGIN_REQUIRED` / `ADMIN_ORIGIN_DENIED` | loopback/Host/Origin fence 拒绝 |
| 403 | `ADMIN_CSRF_REQUIRED` / `ADMIN_CSRF_INVALID` / `ADMIN_CSRF_EXPIRED` / `ADMIN_CSRF_REPLAY` / `ADMIN_CSRF_BINDING_MISMATCH` | CSRF fence 拒绝 |
| 403 | `ADMIN_M3_SHADOW_DENIED` / `ADMIN_EXTERNAL_CAPABILITY_DENIED` | 触碰 M3 shadow 或请求真实/外部能力 |
| 404 | `ADMIN_ROUTE_NOT_FOUND` | 未注册 exact route，包括模糊 `/retry` |
| 405 | `ADMIN_METHOD_DENIED` | method 不在 endpoint allowlist；含 OPTIONS |
| 409 | `ADMIN_SESSION_ALREADY_ACTIVE` / `ADMIN_IDEMPOTENCY_CONFLICT` / `ADMIN_STATE_CONFLICT` | 单 session、幂等或 canonical state 冲突 |
| 412 | `ADMIN_FENCE_STALE` | 任一 expected fence/CAS 已变化 |
| 413 | `ADMIN_BODY_TOO_LARGE` | body 超过 16 KiB |
| 415 | `ADMIN_CONTENT_TYPE_DENIED` | 非精确 JSON media type |
| 422 | `ADMIN_INPUT_REJECTED` | DTO/synthetic policy/字段 allowlist 失败 |
| 429 | `ADMIN_CSRF_CAPACITY` | 同 session outstanding nonce 达 32 |
| 503 | `ADMIN_NO_EGRESS_REQUIRED` | runtime no-egress capability/env/hook/probe Unknown、缺失或漂移；请求 fail closed |
| 500 | `ADMIN_CLOCK_INVALID` / `ADMIN_AUDIT_FAILURE` / `ADMIN_INTERNAL_FAILURE` | 本地安全基础设施异常；返回体不含内部细节 |

同一失败条件必须稳定使用同一 status/reason。产品可修改用户文案，不能改变 reason code 与零写入语义，除非 successor 合同重新复验。

## 9. 日志与 AuditEvent 合同

唯一允许字段：

```text
event_type
request_id
reason_code
route_id (enum, not raw URL/path)
method (enum)
status_code
outcome
peer_class = loopback|denied
origin_class = exact|missing|mismatch
session_ref = truncated HMAC-SHA256(ephemeral audit key, session id)
operation_ref = synthetic opaque/hash
five epoch integers when applicable
attempt
monotonic_seq
clock_status
redaction_version
retention_class
```

禁止：raw Host/Origin/Forwarded、Authorization、Cookie/Set-Cookie、session ID、CSRF token/digest、request/response body、query、完整 URL、真实 source/platform ID、private path、stack、SQLite error、task topology、prompt/model output、secret-like unknown field。

`session_ref` 的 audit key 仅内存、进程重启换代；输出截断为 128 bit hex。未知字段命中时整条原始事件不得写入，只写 `ADMIN_AUDIT_REDACTED` 的最小 incident。retention/cleanup 与时钟异常继续由 R13 successor 实现收据证明。

## 10. 390 / 1440 浏览器安全约束

### 10.1 两个 viewport 共用

- `/admin/sources` 初次 GET 只能渲染无敏感数据的 guard shell；页面通过同源 `POST /api/admin/session` 建立 session，再读取 Admin API。GET 不创建 session。
- session/CSRF token 不进入 DOM、HTML hydration payload、URL、console、storage、截图或 accessibility tree。
- mutation DTO 在用户最终确认时冻结并 canonical serialize；随后签发 bound CSRF。表单任何字段变化都会丢弃 nonce。
- 第一次点击后立即锁定同一 action，复用同一 in-flight promise 和 idempotency key；重复点击、Enter、触控和恢复焦点不得产生第二请求。
- session/CSRF 失效、Origin 拒绝或 response unknown 时不自动重放 mutation；显示明确 guard 状态，要求重新确认并使用新 nonce，同一 idempotency key读回。
- guard 失败时不渲染可诱导提交的有效控件；已有控件立即 disabled，并把焦点移到可读错误摘要。
- 错误 UI 只显示稳定 reason code 的本地化文案和 request_id，不显示原 URL、body、token、stack 或内部拓扑。

### 10.2 390×844

- add、详情、错误、停止/重试确认使用全屏 Drawer/Dialog；主操作触控目标至少 44×44。
- Drawer 打开后焦点进入，Escape/关闭后回到触发器；session 失效时关闭提交路径并保留非敏感表单草稿，重新确认后再签发 nonce。
- URL 可完整查看/复制，但复制对象只来自 synthetic allowlist；页面无横向滚动，长 reason code 换行且不泄露内部详情。
- pending/success/error/unknown result 都有 `aria-live`，网络响应不确定时文案为“结果待确认”，禁止显示“失败后已自动重试”。

### 10.3 1440×900

- 12 列 Source table、筛选、detail Drawer 保持一个 active mutation target；切换行或筛选会 invalidate 尚未消费的 nonce。
- row action、Drawer action 和 keyboard shortcut 必须汇入同一 action controller；不得出现绕过确认层的第二 handler。
- table 使用 `aria-sort`，展开使用 `aria-expanded/aria-controls`；错误、blocked、unknown 不只靠颜色。
- 容器不超过 1440、无页面级横滚；session expired overlay 不遮蔽可读状态，但阻断全部 mutation。

这两组约束仍需真实浏览器、390/1440 截图、键盘、200% zoom、forced-colors、reduced-motion 和 AT 收据；本报告只冻结安全 golden，不声称 UI 已实现。

## 11. 最小实现接口（无新依赖）

以下接口可用 Node 24/现有 TypeScript 与 `node:crypto` 实现；命名是安全候选，不新增领域实体：

```ts
interface MonotonicClock {
  nowMs(): number;
}

interface RandomBytes {
  bytes(length: 32 | 16): Uint8Array;
}

interface AdminSessionStore {
  create(input: CreateSessionInput): CreateSessionResult;
  validate(rawCookie: string | undefined, nowMs: number): SessionContext;
  refresh(ctx: SessionContext, nowMs: number): RefreshSessionResult;
  destroy(ctx: SessionContext, nowMs: number): void;
}

interface CsrfBinding {
  sessionDigest: Uint8Array;
  method: "POST" | "DELETE";
  path: RegisteredAdminMutationPath;
  bodySha256: Uint8Array;
}

interface OneTimeCsrfStore {
  issue(binding: CsrfBinding, nowMs: number): IssuedCsrf;
  consume(rawToken: string | undefined, binding: CsrfBinding, nowMs: number): CsrfConsumeResult;
  invalidateSession(sessionDigest: Uint8Array): void;
}

interface AdminRequestGate {
  assertRuntimeNoEgressReady(): void;
  preflight(request: RawAdminRequest): GateContext;
  authenticate(gate: GateContext): SessionContext;
  consumeCsrf(gate: GateContext, session: SessionContext): void;
}

interface AdminMutationExecutor {
  execute(command: StrictAdminCommand, ctx: MutationContext): Promise<IdempotentMutationReceipt>;
}

interface SecurityAuditSink {
  append(event: AllowedSecurityAuditEvent): void;
}
```

必须可注入：Clock、RandomBytes、session/nonce store 原子锁、AuditSink、idempotency store、EpochReader/CAS、`RuntimeNoEgressGuard`、raw HTTP/1.1 authority adapter 和 fault point。生产 RandomBytes 只能委托系统 CSPRNG；测试可以 spy 调用次数、并发和故障，但测试 token 不进入报告。

## 15. P0/P1/P2 自审与残余风险

### P0：0

候选已经把 session、exact Host/Origin、raw HTTP/1.1 authority、CSRF 原子消费、单进程边界、业务事务/CAS、每入口 runtime no-egress readiness、M3 和失败零写入写成不可省略 predicate；dead-letter requeue 与冻结 `DEAD-02` 统一为原 operation/key 复用。实现中任一缺失、nonce 非原子、新建 requeue operation/key、多进程共享不安全或安全拒绝仍能 mutation，均应在后继复验直接升级为 P0/FAIL。

### P1：0

端点、Cookie、TTL、进程启动生成+浏览器原子领取的唯一 bootstrap、nonce binding、status/reason、前置顺序、add/activate/stop/两类 retry、response-loss 和 golden 已形成唯一候选。validation job 精确形态/计数已显式 BLOCKED，产品字段吸收与实现证据列为 successor/Unknown，不冒充当前缺陷已通过运行验证。

### P2：2

1. 当前 HTTP loopback Cookie 无 `Secure`。它符合 accepted R3“HTTPS 才加 Secure”，但只适用于本地 IP-literal loopback；若需要更强传输边界，应另建 loopback HTTPS 合同。
2. Origin/CSRF 防浏览器跨站请求，不能认证同 UID 恶意本地进程。生产、多用户或不可信本地进程模型必须使用 OS 身份/真实认证和新 ADR，当前 local-dev API 不可扩展使用。

- validation lane 的表/队列、owner、唯一键、transaction 和精确 job 计数未冻结；实现验收前保持 BLOCKED，不影响本安全候选对 activation/collection/outbox/provider=0 的拒绝语义。
- 同 UID 恶意本地进程、生产角色、真实账号、HTTPS 信任、多进程与跨网络访问均超出本 local-dev 候选。

## 17. 错题自检

- 没有把 contract PASS 扩大为实现、浏览器、生产或真实能力 PASS。
- 没有用 loopback/Origin 伪装成 OS 身份认证；同 UID 本地进程残余风险已明确。
- 没有把 GET navigation 写成 session 创建或 CSRF mutation；bootstrap 使用 exact-Origin POST。
- 没有用 SameSite 替代 Origin/CSRF，也没有把 session 放入可被 JavaScript读取的 header/storage。
- 没有让 nonce 在业务 rollback 后恢复；一次性消费保持单向。
- 没有让 response loss 生成新 idempotency key或第二业务事实。
- 没有让 dead-letter requeue 创建新 operation/key；已与冻结 `DEAD-02` 统一为原业务身份复用。
- 没有把 validation job 尚未冻结的数量写成 PASS golden。
- 没有只在启动时检查 no-egress；session/CSRF/Admin GET/mutation 每个入口都要 fail-closed readiness predicate。
- 没有把 UI“重试”变成模糊 server route；validation 与 dead-letter requeue 分开。
- 没有允许 M3 shadow、真实 URL/provider/Base/AI/媒体/发布进入 VS-1。
- 没有修改 app、Spec、ADR、data、design、历史报告或开放端口；没有安装或联网。
