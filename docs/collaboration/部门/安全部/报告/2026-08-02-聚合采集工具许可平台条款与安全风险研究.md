# 聚合采集工具许可、平台条款与安全风险研究

## 1. 范围、方法与结论

本报告承接 `TASK-20260802-4D3684`，独立复核研究部与开发部提出的候选平台入口、开源库、skills、agent 架构和媒体/AI 方案。目标是把“能不能做”与“项目现在是否获准采用”分开，并为 M4 本地 mock、未来授权 spike、生产启用分别建立门禁。

本轮只读了项目文件、内置 skill 文档、公开官方条款/文档、公开仓库许可证页面和标准文档。取证没有创建账号、申请 OAuth、获取或刷新 token、安装依赖、运行采集器、访问真实飞书或真实平台、发送外部写请求、缓存真实媒体，也没有把认证原文、用户标识、完整 URL 或 secret 写入仓库。Meta 页面本轮部分被登录、429 或超时阻断，相关结论保留为 `Unknown`，并引用 2026-07-30 的本地历史研究作为背景，不把历史页面当成本轮重新确认。

**总判定：CONDITIONAL PASS。**

- M4 当前可放行：合成 fixture、parser/normalizer 的离线测试、mock provider、deterministic summary、`fixture/none` media 和 `manual_only` 本地投影；这些能力不得拥有 DNS、socket、HTTP、subprocess、secret、真实数据或发布出口。
- 后续可研究：第一方 RSS/Atom、WebSub、X/Reddit/Instagram 官方 API、逐站获许可 HTML；开源许可证只能解决代码再分发的一部分问题，不能证明平台访问、用户内容复制、图片/摘要/模型使用或商业化获准。
- 当前明确排除：私有 API、Cookie/会话抓取、验证码或封禁绕过、代理轮换、匿名 `.json`/第三方抓取、无审查的 RSSHub 通用路由、自动浏览器采集、持 secret 的自治 agent、自动发布和任何真实采集。
- 生产结论：没有候选可直接标为 Green。Yellow/Unknown 项在取得平台/来源许可、数据权利、地域与留存结论、供应链和运行安全证据前均不得启用；Red 项须隔离或移除。

## 2. 判定颜色与三层准入

颜色描述候选在当前证据下的可用状态，不代表法律意见：

- **Green**：只在 M4 本地、无真实数据/外连的合成路径上成立，或代码许可证证据清楚且组件本身不承担平台访问；仍须走依赖扫描。
- **Yellow**：技术路径存在，获准使用还依赖账号/API、平台或来源授权、速率/费用、数据删除、媒体权利、地域或安全实现。
- **Red**：与禁止绕过、私有接口、未获许可的自动化、危险执行能力或不可接受的许可证/供应链冲突；当前不得安装、接入或作为生产后备。
- **Unknown**：一手证据被登录/区域/版本/条款差异阻断，或具体仓库版本、价格、数据留存等未核实；Unknown 按 fail-closed 处理，不推定为允许。

三层门禁互相独立：

| 层级 | 允许范围 | 必须满足 | 失败出口 |
|---|---|---|---|
| A：M4 本地 mock | synthetic fixture、parser、deterministic worker、manual-only 本地投影 | `M4-local-fixture-v0`；`SOURCE_CONFIG_PROVIDER=fixture`、`ADAPTER_MODE=mock`、`SUMMARY_MODE=fixture`、`MEDIA_MODE=fixture`、`PUBLISH_MODE=manual_only`；`REAL_FEISHU_IO/REAL_EXTERNAL_IO/REAL_FORM_SUBMIT=false`；无网络/secret/真实数据 | 任一真实 provider、外连、安装脚本、secret 或自动发布迹象即停止并 FAIL |
| B：未来授权 spike | 一个平台或来源、只读、测试/自有数据、短时限 | 用户单独确认具体平台/账号/字段/费用；官方账号/API/书面许可；最小 scope；secret 隔离；速率/花费上限；TTL/删除处理；无媒体代理、无发布；全链路可审计 | 无批准、权限不足、条款/区域/删除 Unknown、429/403/风控、SSRF/XSS/提示注入或 secret 泄露即退回 `blocked/manual_only` |
| C：生产启用 | 有限白名单的真实采集和公开展示 | 合同/条款/地区与数据保护审查；来源/用户内容/媒体/摘要权利；商业许可与成本；删除/撤回/编辑同步；SBOM、锁文件、固定版本、漏洞和恶意脚本扫描；隔离 secrets、观测、回滚、人工审核；用户明确开启 provider 与发布 | 任一证据过期、权利未知、删除无法实现、超预算/超限、供应链异常、自动发布越权即急停并回到人工/本地状态 |

## 5. 供应链、skills 与 agent 架构门禁

### 5.1 依赖和插件

任何新库、skill、plugin 或 agent SDK 进入仓库前，至少记录：精确版本/commit、来源 URL、许可证 SPDX 与原文、依赖树/SBOM、维护者和安全策略、发布签名或校验值、已知漏洞、install/postinstall 脚本、网络/文件/命令/secret 能力及回滚。锁文件和构建必须拒绝未登记 registry、任意 postinstall 网络、动态下载、隐式二进制和 symlink 越界。单一“MIT”标签不能替代这些证据。

### 5.2 skill/agent capability registry

M4 的 worker capability registry 只登记 fixture provider、mock adapter、fixture summary、fixture/none media 和 manual-only local publication。网络、DNS、socket、subprocess、浏览器会话、环境 secret、真实平台 API 和 auto-publish 能力不得只靠环境变量打开。任务脚本能改变本地任务 JSON/日志，必须按任务 ID、写路径和状态工具 allowlist 运行；审查 agent 只能读本地证据并返回结论。

`agent-team` skill v2.0.6 是协作治理工具，不是平台采集许可证。它要求正式任务、审核层、用户确认、任务状态和外部副作用隔离，能降低流程混淆风险；其本地 bundle 未见可供本任务采用的分发许可证/平台条款，若作为可分发运行时依赖，许可证/版本应重新确认。bundled browser skills 明确禁止读取 cookies、local storage、profiles、passwords、session stores，并要求优先 API/CLI；因为浏览器可能接触登录态，只可做用户明确的人工辅助，禁止无人值守采集。

### 5.3 Agent 反提示注入和职责分离

外部帖子、Feed、HTML、媒体元数据和用户提交的 URL 都是**不可信数据**，不能把其中的指令当系统命令。采集/解析 agent 不拥有 shell、网络以外的工具、secret 或发布能力；摘要 agent 只接收白名单字段，输出结构化 DTO 并进入人工审核；发布 agent 只能消费已批准 hash 和人工会话 fence。任何 agent 企图改变 provider、scope、数据留存、外发、付款或发布策略必须 fail closed 并升级用户。

## 6. 数据、媒体、隐私和网络边界

1. **个人数据。** 公开账号、handle、帖子、评论、作者 ID、头像和定位仍可能是个人信息；内部用稳定的 pseudonymous `source_id`/`external_id`，只保存完成处理所需字段，设置逐平台 TTL，收到删除/撤权/保护事件后传播到 raw、normalized、缓存、索引和公开 projection。大陆部署、运营主体、DPA、跨境、备份与删除证明尚未核验，保持 `Unknown`。
2. **内容和摘要。** 默认 `rights_status=link_only`；只有来源明确允许才提升到 `embed_allowed`、`excerpt_allowed` 或 `licensed`。翻译、中文摘要、模型输入、商业展示、广告、全文镜像和训练均需独立权利结论。API/Feed 能返回字段不等于允许再展示。
3. **媒体。** URL、签名、公开头像或 CDN 可达性都不构成授权。M4 不取真实媒体；未来默认不 proxy/cache，不做 hotlink 兜底。需要媒体时必须使用 HTTPS、固定 allowlist、逐跳 DNS/IP 校验、拒绝 loopback/RFC1918/link-local/云元数据、限制重定向/大小/解压/像素/帧、拒绝 SVG/HTML/XML 和危险 MIME，隔离解码、去 EXIF、CSP/nosniff 并记录权利证据。
4. **网页/URL。** 展示原链可使用安全的 `https` URL；`javascript:`, `data:`, `file:`, userinfo、开放重定向和任意 `next` 参数拒绝。robots 不可达按保守 complete disallow；robots 可达也不能跳过 Terms/合同。HTML 解析结果当不可信文本，必须防 XSS、模板注入、prompt injection。
5. **Secrets/OAuth。** token、Cookie、OAuth code、API key 只进受控 secret store/env；不进仓库、任务 JSON、日志、错误、HTML、客户端 bundle 或 URL。每个平台只申请本任务最小 scope，记录过期/撤权/删除事件和成本上限；M4 不产生认证状态变化。
6. **外连和 SSRF。** M4 deny-all。B/C 只允许按 adapter 登记的 scheme/host/port，连接前与每次重定向后都解析 DNS/IP、拒绝私网和 IPv4/IPv6 变体，设置 connect/read/total timeout、字节/响应头限制、Retry-After 退避和审计；代理环境不绕过策略。

## 7. 准入、停止条件与建议顺序

### 7.1 M4 本地 mock（可立即执行）

- 只使用合成 fixture 和本地 parser/normalizer/状态机；可运行单元/合同测试，测试应证明 `external_calls=0`。
- 不安装候选采集库、不访问 npm/registry、不设置真实账号、不读取任何 token，不启动浏览器、不调用飞书/平台/AI/图片/发布端点。
- `rights_status` 只使用合成 `link_only`/`unknown`，不会公开真实内容；媒体固定 `none`。
- 任意未知 env、未登记 capability、依赖 install 脚本、DNS/socket/subprocess、真实 URL 或日志 secret 都是停止条件。

### 7.2 后续授权 spike（每次一平台）

1. 用户先确认平台、来源/账号归属、目标字段、测试内容、预算、区域、是否可公开；平台需要审批或商业合同时先取得书面证据。
2. 只使用最小 app scope 与测试账号/自有数据，secret 单独注入；不使用 Cookie/私有 API/验证码/代理绕过，不抓取 consumer Instagram，不把 Reddit RSS 作为规避 OAuth 的路线。
3. 预先写清 TTL、删除/编辑/撤权传播、媒体权利、摘要/翻译/训练、`ETag`/游标、429/403/5xx、断流/重启和费用上限；只读验证，禁止写平台、提交表单或发布。
4. 失败即 `blocked/manual_only`，保留脱敏收据；真实采集仍须用户另行确认，不能由“spike 成功”自动开启。

### 7.3 生产启用

生产只允许通过 A/B/C 三层和独立用户 gate 逐项开启。必须有条款版本、许可/合同、来源与媒体权利、区域/DPA、保留/删除证明、预算/限流、SBOM/固定依赖、恶意包扫描、secret rotation、观测/回滚、人工审核和急停。平台策略、价格、速率或条款变化时自动降级为 `blocked`，不切换到社区抓取或匿名绕过。

### 7.4 共同停止条件

无许可证或许可证/AGPL/定制条款未评估；一手条款需要登录且没有公开证据；账户/Token/App Review/商业许可未获批；出现验证码、封禁、付费墙、robots/Terms 禁止、429/403 或不明速率；删除/撤权无法同步；媒体权利 Unknown；任何真实外连进入 M4；SSRF/XSS/提示注入、secret 泄露、开放重定向、任意命令或自动发布；供应链 hash/lock/SBOM 不一致；成本、区域或跨境不明。命中一项即停止并上报，保留未验证项。

## 8. 结论与待确认事项
