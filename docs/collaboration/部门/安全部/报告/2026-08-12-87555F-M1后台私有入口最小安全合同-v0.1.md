# F1+1 M1 后台私有入口最小安全合同 v0.1

## 1. 单一推荐

第一版日常后台入口固定采用以下一条路径：

```text
M5 Mac / iPhone
  → 已登记且已批准的 Tailscale 客户端设备
  → tailnet deny-by-default Grant，仅允许 operator → f1-admin-server:443
  → Tailscale Serve 私网 HTTPS
  → 固定 M1 的 127.0.0.1:3101 Admin 进程
  → 应用 WebAuthn/passkey + 服务端 session + Origin + 一次性 CSRF
  → revision / approve / reject / 第二次显式 manual publish / operation、delivery 对账
```

固定 M1 上的 Admin 应用只监听 `127.0.0.1:3101`。Tailscale Serve 在 tailnet 内终止 HTTPS 并反向代理到该 loopback 端口；Tailscale Funnel 全时关闭。M5 与 iPhone 通过同一私有 HTTPS origin、同一应用角色和同一 API 集执行全部已确认 Admin 操作。

现有 Cloudflare Quick Tunnel 继续只指向公开只读入口 `127.0.0.1:3000`。公开 origin 对 `/admin`、`/api/admin`、`/internal` 及其规范化变体采用默认拒绝；任何请求均不得转发到 `3101`，不得返回登录页、重定向、session cookie 或私有拓扑信息。

本合同选择 Tailscale Serve 的原因是：官方明确把 Serve 定义为 tailnet 内共享本地服务，并支持把本地 `127.0.0.1` HTTP 服务代理为自动签发证书的 HTTPS；同一访问控制策略继续作用于 Serve。Funnel 的用途是公网暴露，因此在本项目中保持关闭。

本结论只批准实施规划。安装、登录、设备加入、Tailnet 策略、应用认证、网络、备份、SSH、UU、M1 配置和部署均须进入后继不可变 deployment manifest 与独立授权窗口。

## 2. 已接受输入与冲突检查

本合同逐项继承以下现行真值：

- `ADR-M5-REAL-REVIEW-PUBLISH-001`：真实 RSS 采用私有唯一写主、人工决定、第二次显式手动发布、独立公开投影；自动发布为 0。
- `F1+1 真实 RSS 人工审核与公开投影最小实施合同 v0.1`：Admin mutation 需要 session、精确 Origin、一次性 CSRF、operationId、CAS；publish 需要 5 分钟内 fresh re-auth。
- `ADR-M5-ADMIN-DUAL-HOST-001`：公开端没有 Admin route、私有主库、mutation credential 或签名私钥；Mac/iPhone 功能等价；`RTO≤4h`、`RPO≤15m`。
- `ADR-M5-ADMIN-DEDICATED-MACBOOK-001`：固定 Admin MacBook 最终使用专用、非日常个人工作基线；公网 Admin listener 计数为 0。
- 固定 M1 当前公开 Beta：公开应用在 `127.0.0.1:3000`，Cloudflare Quick Tunnel 只连该端口；公开 profile 已有 allowlist，Admin 路径当前为 404；UU 现行只作运维通道。

发现一项需要显式保留的阶段边界：现行公开 Beta 与后继 Admin 首版都落在同一台固定 M1；accepted 双主机目标要求最终 public-host 独立。单 M1 首版只能声明“两个 loopback 进程、两个资源根、两个服务身份的逻辑隔离候选”，不能声明双主机生产拓扑已经完成。后续迁移 public receiver 时，本合同的私有 origin、认证与业务 API 语义不变。

未发现产品合同与本推荐在 session、Origin、CSRF、fresh re-auth、显式发布或公开投影方向上的冲突。

## 3. 网络、监听与 TLS 不变量

### 3.1 Admin 监听

| 项目 | 必须值 | 失败动作 |
| --- | --- | --- |
| Admin backend | `127.0.0.1:3101` | 发现 `0.0.0.0`、`::`、局域网地址或公网地址监听时立即停 Admin |
| Public gate | `127.0.0.1:3000`，只读公开 allowlist | 指向 Admin 或未知 upstream 时停 Quick Tunnel |
| Serve | tailnet 内 HTTPS `443` → `http://127.0.0.1:3101` | Serve 目标、端口或证书状态不符时远程 Admin 全关 |
| Funnel | disabled，active listener 计数 `0` | 任一 Funnel 配置或公网 Tailscale listener 出现时撤销并隔离 |
| 路由器 | Admin/SSH 端口转发、UPnP 映射计数 `0` | 任一存在即远程 Admin 全关 |

Admin 进程与公开进程使用不同运行身份、数据根、session secret、日志和环境变量。公开进程无 Admin DB 路径、Admin session secret、passkey credential store、Tailscale auth key、投影签名私钥或备份解密材料。单 M1 首版无法证明该隔离前，Admin mutation 保持关闭；只允许本地/fixture 验证。

### 3.2 私有 HTTPS origin

- Admin canonical origin 固定为一条 Tailscale Serve FQDN，例如 `https://f1a-gw-01.<random-tailnet>.ts.net`；实际值只进入受限 deployment manifest。
- M1 machine name 使用无人员、地点、邮箱、GitHub 名或业务秘密的不可识别名称。Tailscale 官方说明 HTTPS 证书名称会进入公开 Certificate Transparency 日志；主机名不能承载敏感信息。
- `Strict-Transport-Security: max-age=31536000` 只针对精确 Admin host，不设置 `includeSubDomains`。
- Admin backend 与 Serve 间只走 loopback。应用只信任来自 loopback Serve 的代理头；其余来源的 `X-Forwarded-*` 和 Tailscale identity headers 一律忽略或拒绝。
- Tailscale identity headers 只用于脱敏审计关联，不能单独完成应用登录、授权或 fresh re-auth。

### 3.3 公网 fail-closed

公开入口采用正向 allowlist，未知路径默认 404。至少覆盖以下负向集合：

```text
/admin
/admin/
/ADMIN
/%61dmin
//admin
/api/admin
/api/admin/
/internal
/internal/projections/test
```

对 `GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS` 均验证：公网和公开 loopback 返回统一通用 404、无 `Location`、无 `Set-Cookie`、无 Admin HTML、无 reason stack、无内部端口/路径；Admin 服务请求计数保持 0。任何代理规范化、大小写、重复斜线或百分号解码不能把这些路径送入 Admin upstream。

## 4. Tailnet 身份、设备与撤销

### 4.1 三台设备

首版设备闭集只有：固定 M1 Admin server、M5 运营 Mac、用户 iPhone。每台独立加入、独立批准、独立撤销；不得通过共享 auth key 批量预批准。

实施时开启 Tailscale device approval。官方行为是新设备在批准前无法发送或接收 tailnet 流量。尾网策略默认拒绝，唯一网络 Grant 形状为：

```json
{
  "groups": {
    "group:f1-admin-operators": ["<operator-identity-ref>"]
  },
  "tagOwners": {
    "tag:f1-admin-server": ["autogroup:admin"]
  },
  "grants": [
    {
      "src": ["group:f1-admin-operators"],
      "dst": ["tag:f1-admin-server"],
      "ip": ["tcp:443"]
    }
  ]
}
```

实际 operator 身份、tailnet ID、machine ID、节点 IP 和设备唯一标识不得进入仓库或普通报告。策略保存前使用 Tailscale policy validator；后继运行验收必须从一台未批准设备、错误身份和已撤销设备证明 443 不可达。

### 4.2 Key expiry

- M5 与 iPhone 保持 node key expiry 开启；到期、重新认证和失效均须实测。
- 固定 M1 若使用 server tag，Tailscale 官方说明 tagged device 在首次应用 tag 并重新认证后默认关闭 key expiry。deployment manifest 必须显式记录该例外、Owner、季度复核和撤销步骤，不能把默认行为遗漏在外。
- 在没有第二条已验证运维路径时，禁止远程执行会中断现有 tailnet 会话的强制重新认证。Tailscale 官方明确提示 `tailscale up --force-reauth` 可能使 SSH/RDP 会话中断。

### 4.3 三层撤销

设备丢失、转售、失陷或不再使用时，按以下顺序执行并回读：

1. 在 Tailscale 管理面撤销/移除对应设备，确认 tailnet 443 不可达；
2. 在 Admin 主库撤销该 `device_ref` 的全部 server-side session；
3. 若 passkey 或 Apple Account 可能受影响，禁用对应 WebAuthn credential，注册新凭据并重新验证；
4. 若 M1 失陷，另行轮换 Admin session secret、投影签名、备份与服务凭据，fence 旧 writer；
5. 审计只保存脱敏 device/session hash、动作、结果和 policy version，不保存节点 IP、Cookie、passkey、公钥原文或恢复材料。

撤销延迟的目标为 `≤15m`；没有真实计时收据前保持 Unknown。

## 5. 应用认证与会话合同

### 5.1 Bootstrap 与 passkey

- 初始 operator 注册只能在受控部署窗从 M1 本地 TTY生成一次性 enrollment nonce；nonce 至少 256 bit、TTL `≤10m`、只保存 hash、单次消费，禁止写日志、URL、剪贴板同步或仓库。
- enrollment 页面只通过已批准的 private Serve origin 可达，并同时要求预登记 operator identity 与设备。完成首个 operator 和两枚 credential 后，bootstrap route 自动关闭且回读为 404。
- 日常凭据使用 WebAuthn/passkey；精确 RP ID 等于 Admin `.ts.net` host，精确 origin 等于 canonical HTTPS origin，`userVerification="required"`。
- WebAuthn challenge 由服务端 CSPRNG 生成，至少 32 bytes，TTL `≤2m`，绑定 purpose/session/operation，单次消费并拒绝重放。W3C 要求 challenge 由可信服务端随机生成且返回值必须匹配。
- 至少登记两条相互独立的恢复路径：一条 Apple iCloud Keychain 同步 passkey，供 M5/iPhone 日常使用；一条独立 FIDO2 hardware credential，离线保存。Apple 官方确认 passkey 可通过 iCloud Keychain 在已批准 Apple 设备间端到端加密同步；同步凭据仍属于一个共同故障域，不能单独满足恢复冗余。

### 5.2 Server-side session

| 控制 | 固定值 |
| --- | --- |
| Cookie 名 | `__Host-f1_admin_session` |
| Cookie 属性 | `Secure; HttpOnly; SameSite=Strict; Path=/`，无 `Domain` |
| Session ID | CSPRNG `≥256 bit` opaque value；数据库只保存 keyed hash |
| 轮换 | 登录、fresh re-auth、角色/设备变化后轮换；旧 ID 同事务失效 |
| 空闲/绝对时限 | idle `≤15m`，absolute `≤8h` |
| 并发上限 | 单一 operator 最多 2 个 active session；超出时先撤销最旧并告警 |
| 绑定 | operator、approved device ref、Tailscale user ref、created/last_seen/auth_time/policy_version |
| 缓存 | Admin HTML/API/错误均 `Cache-Control: no-store` |

每个 Route Handler、Server Action 和数据访问入口都在服务端重新验证 session、角色、设备、当前 writer/backup/stop fence。UI 隐藏、middleware 或 Tailnet 可达性不构成授权。Next.js 官方同样要求把 Route Handler 当作公网 API 审查，并在每个动作中验证授权；DAL 只返回最小 DTO。

### 5.3 Origin、CSRF 与请求闭合

所有 mutation 同时满足：

1. `Content-Type` 精确为允许的 JSON 类型；闭合 schema `additionalProperties=false`；
2. `Origin` 精确等于 canonical Admin origin；缺失、`null`、多值、同站不同源均拒绝；
3. `Sec-Fetch-Site` 缺失或不为 `same-origin` 时拒绝；不得用它替代 Origin；
4. session cookie 当前有效；Tailscale user/device ref 与 session 绑定一致；
5. `X-CSRF-Token` 为服务端签发的一次性 `≥256 bit` token，绑定 session、method、规范化 path、operationId、canonical body hash，TTL `≤5m`；
6. operationId、expected CAS、source/bundle/publication hash 与业务合同完全匹配；
7. CSRF、operation receipt、mutation 与 audit event 在同一事务内消费/提交；失败整笔零写。

CSRF token 只在同源 JSON 响应中返回，禁止放入 cookie、URL、Referer、HTML data attribute 或日志。OWASP 建议以自定义请求头传递同步 token，并以完整 Origin 校验和 SameSite 作为纵深防御。

### 5.4 Fresh re-auth

以下动作必须取得 `≤5m` 的新鲜 WebAuthn user-verification assertion：

- 第二次显式 manual publish；
- 后继 delete/withdraw/correct 的不可逆分支；
- 设备、权限、passkey、session secret、签名/备份凭据管理；
- 启用或关闭 break-glass；
- writer promotion、恢复点提升及 emergency stop 解除。

fresh receipt 绑定 `sessionId + operationId + action + resource/version hash`，单次消费。approve 不得复用为 publish 的 fresh receipt；通过 publish confirmation 后服务端仍重算 Decision、Publication、CAS、backup age 和 writer fence。

## 6. 浏览器、输出与审计控制

Admin 响应至少包含：

```text
Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
Cross-Origin-Opener-Policy: same-origin
Cache-Control: no-store
```

passkey ceremony 如需 WebAuthn 保持浏览器默认能力，不在 Permissions-Policy 中禁用 `publickey-credentials-get/create`。Admin API 不发送 CORS allow-origin/credentials 头，不接受跨源 preflight；公开站不调用 Admin API。

追加式审计 allowlist：`event_id, trusted_time, clock_status, actor_ref, device_ref, session_hash, action, resource_ref, operation_id, result, reason_code, policy_version, trace_id`。禁止 Cookie、CSRF、WebAuthn challenge/assertion、Tailscale identity header 原文、完整 hash、绝对路径、原 RSS 正文、人工私密备注、stack 或密钥材料。

登录失败按 operator+device+会话来源联合计数：15 分钟 5 次后指数退避；禁止永久锁号。普通 mutation 候选上限 30 次/分钟，高风险 mutation 5 次/分钟；超限零写并审计。具体值可在真实合法峰值证据后收紧，放宽必须复审。

## 7. Mac 与 iPhone 全功能等价

两端都必须通过同一 private origin 完成以下真实链路：

```text
登录 → 队列 → 详情 → 保存 revision → approve 或 reject
→ approved 后第二次 fresh passkey + 手动 publish
→ operation / delivery 对账 → active 后打开公开详情
```

iPhone 可以使用单列导航，M5 可以使用双栏。切后台、蜂窝/Wi-Fi 切换、刷新或 response loss 后，都只能使用同一 `operationId/deliveryId` 对账，不能生成第二 identity。任何端缺 revision、approve、reject、publish、operation 或 delivery 恢复能力时，相关 Function ID 保持 `P1-blocker`。

跨网能力依据 Tailscale 官方网络模型可走直连、peer relay 或 DERP relay，三者传输都使用 WireGuard 端到端加密；这不等于中国大陆链路已经可用。启用前必须至少在下列条件各完成一次：

- M5 异地 Wi-Fi；
- iPhone 蜂窝网络；
- iPhone Wi-Fi→蜂窝切换；
- 直连不可用时的 relayed path；
- 设备撤销后再次访问；
- Tailscale control/relay 不可达时的 fail-closed。

任一关键路径持续失败时停止实施，不得回退到公网密码页、Cloudflare Access Admin、Tailscale Funnel 或端口转发；由产品/安全形成新的 successor。

## 8. UU 与三层应急边界

UU 的精确产品、版本、账号、启动方式与安全能力仍为 Unknown。现行项目证据只支持把它作为已解锁系统上的运维通道。边界固定为：

| 通道 | 允许 | 禁止 |
| --- | --- | --- |
| 日常 Admin | Tailscale Serve + 应用强认证 | UU 远程桌面/端口映射充当观众可达或日常业务入口 |
| UU 运维 | 具名维护窗内查看状态、终端、重启/回退已批准服务 | 存 passkey/恢复密钥；绕过 app auth；宣称可在 FileVault 锁定前工作 |
| 启动前恢复 | 后继获批的网关私有 VPN + Apple 原生 SSH/FileVault，或现场恢复 | 宿主 Tailscale/UU 用户态进程充当启动前证据；公网 22 |

Apple 官方确认：Apple silicon 且 macOS 26+ 在 Remote Login 已开启并有网络时，可在重启后通过 SSH 解锁 FileVault；Wi-Fi 只支持此前连接的开放网络或 WPA2-PSK。固定 M1 当前 Wi-Fi 被系统标为低安全旧 WPA，且网关 VPN、Remote Login、启动前重连均未验证，因此无人值守 preboot 恢复继续为 Unknown。UU 可用于系统已解锁后的远程操作，无法单独证明 `RTO≤4h`。

break-glass 默认 `disabled`，不创建公网 URL。启用只能由本地/带外控制台的明确人工动作触发，要求 fresh passkey、具名 reason、单一 session、最小角色、TTL `≤30m`、不可续期。它只修复私有可达性或在本机执行同一应用认证链，不能跳过 passkey/session/Origin/CSRF/CAS/backup/writer fence。到期或手动关闭的顺序固定为：拒绝新连接 → 撤销临时 session/策略 → Serve/通道回读 → 临时材料归零 → 审计告警闭环。任一步失败即隔离 Admin 并保持 mutation=0。

## 9. RPO 15 分钟与 RTO 4 小时

### 9.1 RPO 门

- 每 `≤5m` 尝试一次 SQLite 在线一致快照或经独立验证的等价机制；不得复制运行中的 `db/-wal/-shm` 组合并宣称备份。
- 只有快照关闭落盘、SQLite integrity、schema/ledger/app version、manifest/hash、加密、异故障域持久化与回读全部成功，才推进 `last_successful_recovery_point_at`。
- `backupAge≥10m` 预警；`backupAge≥15m`、时钟不可信或无法证明 age 时，revision/approve/reject/publish、设备/权限/凭据变化全部关闭。队列只读与 public last-known-good 可继续。
- 恢复点密文与解密材料分域。deployment manifest 必须固定目标介质、故障域、key version、保留/删除、告警和至少一个独立恢复器；当前全部 Unknown。

### 9.2 四小时恢复路径

| 累计时限 | 动作 | 必须收据 |
| ---: | --- | --- |
| 0–15m | 宣告、隔离、停 Admin mutation、fence 旧 writer | incident/time、mutation=0、writer≤1 |
| 15–45m | 撤销受影响的 Tailscale device、session、passkey/service credential；选 `≤15m` 恢复点 | manifest/hash/key/failure-domain PASS |
| 45–120m | 已解锁时通过 UU 维护；锁定/重启时只走已验证网关 VPN+Apple SSH 或现场/冷备 | 无公网 listener；临时通道具名且有 TTL |
| 120–180m | 在隔离目标恢复 SQLite，只读验证 integrity/schema/ledger/hash | recovery point 与 writer epoch PASS |
| 180–210m | 恢复 Tailscale Serve、Mac/iPhone 登录、Origin/CSRF、公开 Admin 负向 | 两端同能力；公网 Admin=0 |
| 210–225m | 明确提升唯一 writer，执行 synthetic mutation/回滚/幂等；产生新合格恢复点 | writer=1、audit、backup PASS |
| 225–240m | 重建签名公开快照并原子激活；关闭临时通道 | active receipt、public GET 200、break-glass=0 |

当前无法宣称 RTO/RPO 已达标：异机备份目标/密钥/恢复器未冻结；旧 WPA 下的 preboot 网络不满足已知 Apple WPA2-PSK候选；网关 VPN、Remote Login、现场 Owner、冷备和真实计时演练都未完成。任一环节缺收据时 Admin mutation 持续关闭，公开站继续 last-known-good。

## 10. 实施顺序与回退

### 10.1 后继唯一顺序

1. 形成不可变 deployment manifest，固定 Tailscale 稳定版、三台设备角色、opaque hostname、Grant、Admin port、canonical origin、passkey/bootstrap、secret/backup/alert/rollback；用户批准精确 hash。
2. 先生成一致性恢复点与公开 Beta/collector 精确回退锚；不触碰现行公开 DB。
3. M1 安装 Tailscale 官方推荐的 macOS Standalone 稳定版，加入但先不启用 Serve；M5/iPhone 分别安装并加入。
4. 开启 device approval，逐台人工批准；应用 deny-by-default Grant，确认未批准/错误设备拒绝。
5. 创建独立 Admin 运行身份、私有根和 `127.0.0.1:3101` 服务；完成 passkey、session、Origin、CSRF、fresh re-auth 和审计。
6. 启用 Tailscale HTTPS 与 Serve；确认 Funnel=off、公共 tunnel upstream 仍只有 3000。
7. 先开放只读队列，完成 M5/iPhone 异地真实访问、撤销和公网负向；随后在 backup/writer/fresh auth 门全过时逐步开放 mutation。
8. 独立测试/安全对同一 release 验证后，才允许第一条真实手动发布。

### 10.2 精确回退

私有入口任一关键验收失败时：

1. 立即关闭 Admin mutation，并撤销全部 Admin session/fresh receipt；
2. 关闭 Tailscale Serve 配置并回读 private HTTPS listener 为 0；保持 Funnel=0；
3. 移除/禁用对应 Grant 或 server device，保留审计；
4. 停止 `3101` Admin 服务，保留私有 DB、WAL、manifest 和恢复点用于对账；
5. Cloudflare Quick Tunnel、公开 Beta、RSS collector 和 public synthetic/last-known-good 不变；
6. 已提交 migration 不执行 down migration；恢复时从同一 operation/DB 继续，不新建第二业务身份；
7. 只有公开 `/admin*` 负向、writer=1、恢复点、session=0/按需重建和 Serve/Grant 同 hash 全部复验后，才重新启用。

## 11. 必须验收的闭集

1. `lsof`/等价证据显示 Admin 只监听 `127.0.0.1:3101`，公共 tunnel upstream 只到 3000，Funnel=0。
2. Serve status、TLS 证书、canonical origin、opaque CT name、Grant hash 与 deployment manifest 一致。
3. approved M5 与 approved iPhone 在异地完成全部 Admin Function；未批准、错误身份、已撤销设备均无法连 443。
4. 无 session、错 device、过期/重放 session、错 Origin、缺/错/重放 CSRF、stale CAS、same operation/different body 均零写。
5. publish 需要独立 fresh passkey；approve 后精确保持 `0 Projection/0 Outbox`；fresh receipt 错资源或重放均拒绝。
6. 公网和公开 loopback 的 Admin/internal 负向矩阵全部通用 404，Admin upstream hits=0、无 Cookie/重定向/信息泄漏。
7. lost-device 三层撤销、M1 失陷凭据轮换、UU 关闭、break-glass TTL/关闭失败均有脱敏收据。
8. 相邻两个有效恢复点 `≤15m`；失败备份不推进时钟；超龄即时关 mutation；隔离恢复与完整四小时演练 PASS。
9. 全部实施与证据使用同一 release/config/policy/manifest hash；Unknown、`NOT_RUN`、静态截图或只测一端均不能写 complete。

## 13. Unknown 与实现停止线
