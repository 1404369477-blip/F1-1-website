## 3. P1-01：stop_epoch claim/finalize 围栏

**裁定：CLOSED。**

代码证据：

- `ClaimedRssRun` 现已包含 `stopEpoch`（`app/src/server/rss/types.ts` 第 144–150 行）。
- `claimRun` 在原有 `withImmediateTransaction` 内读取 source、确认 enabled，创建 running run 后把同一 source 快照的 `stopEpoch` 返回（`app/src/server/rss/repository.ts` 第 198–237 行）。
- 新增 `requireLiveSourceFence`，在成功提交前同时验证 run 仍为 running、source 仍启用、当前 `stop_epoch` 与 claim 值相等；任一失配抛 `SOURCE_STOPPED`（`repository.ts` 第 85–102 行）。
- 200 finalizer 在同一个 immediate transaction 的任何候选/run/source 写入前调用该围栏（`repository.ts` 第 240–251 行），随后候选、成功 run 和 validator/cursor 写入均留在该事务内（第 252–329 行）。
- 304 finalizer同样在事务首部调用围栏，之后才写 run 与 source validator/cursor（`repository.ts` 第 332–358 行）。
- 围栏异常会使成功事务回滚；失败 finalizer只收口原 running run，并根据 `stopSource` 决定是否增加 epoch。`SOURCE_STOPPED` 默认 `stopSource=false`，因此不会重新启用 source或重复增加已变化的 epoch（`types.ts` 第 63–89 行；`repository.ts` 第 361–405 行）。

限定测试文件包含 200 与 304 的 stale fence 向量，并断言候选、validator、success cursor 零写入及同一 run 可失败收口（`app/src/tests/rss-real.test.ts` 第 179–293 行）。本安全任务未运行该测试。

## 4. P1-02：IPv6 特殊/文档/6to4 拒绝

**裁定：CLOSED（限原报告明确范围；完整 IANA 穷举不在本任务范围）。**

代码证据：

- IPv6 先解析为固定 16-byte；zone suffix、嵌入 IPv4 与非法压缩格式均拒绝（`app/src/server/rss/transport.ts` 第 57–80 行）。
- CIDR 匹配按完整字节及剩余 bit mask 执行，避免旧实现的字符串前缀 `/28` 覆盖错误（`transport.ts` 第 82–93 行）。
- 默认入口只允许 `2000::/3`，并明确拒绝 `2001::/23` 特殊用途聚合范围、`2001:db8::/32`、6to4 `2002::/16`、`3ffe::/16`、文档 `3fff::/20` 与 AS112 `2620:4f:8000::/48`（`transport.ts` 第 95–115 行）。
- DNS 结果仍执行全量逐项校验；任一结果不通过即整次 `DNS_REJECTED`。连接 lookup 只返回已经校验的选定地址（`transport.ts` 第 258–282、316–333 行）。

测试文件列出上述范围边界、IPv4-mapped 形式及两个全球单播正例（`app/src/tests/rss-real.test.ts` 第 94–110 行）。本安全任务没有运行测试，也没有联网刷新完整地址注册表。

## 5. P1-03：拒绝/304 响应有界终止

**裁定：CLOSED（静态代码门）。**

代码证据：

- 统一终止出口直接调用 `response.destroy()`（`app/src/server/rss/transport.ts` 第 140–146 行）。
- redirect、429、401/403/404、5xx、其他非 200 及 encoding/length/MIME/validator 拒绝均经同一 catch，先 destroy response，再调用 fail 清理 timer 和拒绝 Promise；旧 `response.resume()` 路径已不存在（`transport.ts` 第 288–306、333–405 行）。
- 304 读取有限 validator header 后先 destroy，再结算 not-modified（`transport.ts` 第 356–367 行）。
- 200 body 超过 1 MiB 时先 destroy 再失败；普通 200 未完成路径继续受绝对 10 秒 total timer，timeout 先 destroy request 再结算（`transport.ts` 第 374–401、408–422 行）。

测试文件对统一 destroy 出口有一次纯函数断言（`app/src/tests/rss-real.test.ts` 第 112–119 行）。恶意持续 chunked、半开 socket 与异常 304 的进程级终止时间仍需后续动态门验证；静态代码中已不存在原 P1 的无界 drain 路径。

## 6. P2-01：externalCalls 分阶段记账

**裁定：CLOSED。**

代码证据：

- `networkAttempted` 初始为 false；CLI 只通过 transport 的 `onNetworkAttempt` hook 把它置为 true（`app/scripts/rss-collect-once.ts` 第 56–72 行）。
- transport 在固定 URL、`RSS_REAL_IO`、proxy、请求 validator 与 `now` 校验全部通过后，紧邻 DNS 调用前触发 hook（`app/src/server/rss/transport.ts` 第 240–264 行）。因此这些前置失败保持 0，DNS 及其后的失败记 1。
