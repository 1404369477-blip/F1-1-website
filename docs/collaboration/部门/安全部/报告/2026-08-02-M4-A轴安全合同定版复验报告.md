本轮没有修改 Spec、ADR、data、app 或代码；没有安装依赖，没有启动采集器，没有访问飞书、平台、账号或浏览器登录态，没有运行真实认证/刷新/撤权/发布命令，没有执行网络探测或外部写入，没有读取或保存 token、cookie、open_id、appId、真实 URL、原文或媒体。

**A轴判定：FAIL / NO-GO。**

- R1–R13 的大部分 A 层文字已具体到白名单、默认值、拒绝条件和 fail-closed 语义；就“安全谓词是否写出”这一点，本轮没有新增 P0。
- 补充对抗复核还发现五项 P0：同一 `bundle-synth-001`/approved hash 同时对应 `public-synth-001` 与 `public-synth-reconcile`；Publication 与 Outbox 的幂等 key 也不一致；source 入队 guard 需要 `enabled=true`，而初始/活动 fixture 与 onboarding operation 绑定不能证明唯一入队闭环；状态机对 blocked/queue_failed/collection_failed/retryable_failed 等路径缺少完整恢复出口；ADR 承诺的 canonical payload 覆盖 rights/policy/schema/original_url 等字段，但 generator 未把它们纳入 payload；runtime schema 的 lease regex 允许 `synthetic:lease-003` 这类远低于 128-bit 的 token。
- data v0.2 机器合同的实体集合不包含 ADR §4.6 中的 `SourceObservation`、`SummaryDraft`、`AuditEvent`。`Summary` 虽有 `summary_status=draft`，仍没有写出 `summary_draft → Summary` 的正式映射；`Source`/`Content`/`Event` 也没有 `source_id + external_id` 观察记录实体的唯一映射；`AuditEvent` 没有字段、append-only 序列、trace/hash/epoch 结构、脱敏拒绝语义或 retention/cleanup 合同。这是 A 层 P1 合同缺口，足以使 A 定版不通过。
- `app/` 仍只有 README；B 层脚手架、C 层实现/运行/安全探针/Node24/SQLite/HTTP/恢复收据全部未验证。它们不被倒置为本次 A 层失败原因，也不能被写成通过。
- M4 本地 fixture/mock 方向继续保持安全关闭；A 失败代表合同不得定版 accepted，不表示已经发生真实外连或现实数据泄露。

## 7. B/C 后置出口与停止条件

### 7.1 B：accepted 后最小初始化

只有 A 层三类对象映射、内部 AuditEvent 合同、五项 P0 修订和 P1 时态/epoch 修订被产品/数据/安全共同签收后，才可初始化 `app/`。B 需保持：

- capability registry 只含 fixture/mock/manual-only，旧变量和未知 env fail closed；
- fixture seed 分层（M3 59×33、synthetic、安全 16 case、published projection）互斥、hash/计数稳定、无真实内容；
- `SourceObservation`/`SummaryDraft`/`AuditEvent` 的内部 schema 和 repository owner 明确，不能悄悄映射成第二领域事实或回写 M3；
- deny-all runtime：无 DNS/HTTP/raw socket/subprocess/secret/provider/Collector/发布外连，所有测试记录 `external_calls=0`。

### 7.2 C：Build Loop/阶段完成

C 不是 ADR accepted 前置条件；它阻断实现验收、真实能力和阶段完成。至少需要 `verify:env`、迁移/seed、Node24 `node:sqlite` WAL/锁/恢复、admin loopback/Origin/CSRF、R1–R13 安全探针、并发/lease/CAS、Bundle/hash/reconcile、日志/审计扫描、`npm ci`/lock/SBOM/vulnerability/build/test/check 和审计收据。当前所有这些均未运行。

### 7.3 任一层停止条件

以下任一情况立即 STOP/FAIL，保持本地 fixture 或人工状态：

1. 单 env、旧别名、依赖注入、registry 或未登记 capability 产生真实 provider/HTTP/DNS/socket/subprocess/secret/publish 能力；
2. fixture path 越界、真实 URL/内容/媒体/凭证混入，或任何 fixture case `external_calls != 0`；
3. SourceObservation/SummaryDraft/AuditEvent 没有明确唯一映射、字段 allowlist、内部 owner、retention/cleanup 或 additionalProperties=false；
4. Origin/CSRF/session、SSRF/DNS/redirect、XSS/XML/media/prompt、secret/log、SQLite/path、lease/CAS/hash/reconcile 任一拒绝路径缺失；
5. 旧 epoch/lease/hash、停止/撤权/合规事件后仍可写当前状态；超时盲重试或生成第二 public_id；
6. 未授权安装、npm lifecycle 外连、无 license/来源未知/恶意依赖、Node25 被当作 Node24；
7. 任何真实认证、飞书、平台、AI、媒体、部署、发布、付费或外发动作缺少独立用户确认。

## 8. 复验结论与最小下一步

### 8.1 结论

本轮复验确认：

- A 层 R1–R13 的安全目标、默认值、拒绝方向和 B/C 分层已写在 M4 proposed ADR；R1、R2、R3、R4、R5、R6、R7、R8、R11、R12 的静态安全谓词可继续作为修订基线；R9 因 lease/epoch 约束 FAIL，R10 因 hash/public-id/idempotency 约束 FAIL，R13 因内部审计载体缺口为 P1 partial；
- data v0.2 的主/安全 fixture 是 synthetic、`external_calls=0`，manifest 宣告没有真实导入、外部写入或凭证；
- `app/` 没有实现，当前不存在可被误认为真实 Collector/provider/publisher 的代码路径；
- 合成合同本身存在第二 public_id/key 分裂、入队 guard/operation 不一致、状态恢复出口缺失、hash 生成输入不足、lease regex 过宽五项 P0；§4.6 中三个关键对象未被 data v0.2 定义或正式映射、文档时态未同步、epoch0 例外无证据三项 P1；故 A 轴 `FAIL/NO-GO`，不能将结论收口为仅三实体 P1。

### 8.2 最小修订出口

产品/数据/开发/安全只需在正式合同中选择并固定以下方案之一，再由安全部复验：

1. **内部对象方案（推荐）**：在 data v0.2 的正式引用区新增 `internal-contract` 文件，定义 SourceObservation、SummaryDraft、AuditEvent 的字段、唯一键/版本、读写 owner、权限、retention/cleanup、hash/epoch、`additionalProperties=false`、synthetic fixture 关系和不得进入领域/Base 的边界；同时修复 lease regex、P0 状态/入队/幂等/hash fixture 后再复验；或
2. **领域映射方案**：把 SourceObservation 明确映射至现有 Source/Content/Event 的具体字段，SummaryDraft 明确映射为 `Summary(summary_status=draft)` 并补 model/schema/input hash，AuditEvent 仍保留为 internal-only append-only schema；同步更新 ADR §4.6/R9/R13 的表名和字段引用，并修复 P0 的唯一 public identity、operation、状态恢复、hash 输入和 lease schema。

无论选择哪种方案，都必须保留 M4 synthetic/no-egress 和 A/B/C 分层。安全部不会在本任务中修改这些合同。

报告以 `decision: fail` 提交，原因包括五项 A 层 P0（重复公开身份/幂等、入队 guard/operation、状态恢复、hash 输入、lease schema）和三项 P1（SourceObservation/SummaryDraft/AuditEvent 映射与审计载体、数据任务时态、epoch0 例外证据）。修订前不得将 M4 ADR 置为 accepted 或开始 B 层初始化；M4 真实采集、provider、Collector、媒体/AI 外连、自动发布、部署和付费能力继续关闭。修订后可使用同一任务链重新复验，B/C 收据仍按后置门禁执行。
