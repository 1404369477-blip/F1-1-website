# M5 Admin RPO 15 分钟后继安全决策记录

## 1. 决策与历史边界

- 用户最终选择：**B，Admin `RPO ≤ 15 分钟`**。
- 既有目标继续有效：**Admin `RTO ≤ 4 小时`**。
- 上游 `TASK-20260809-19F245` 已由统筹部 ACK；本文件是其后继决策依据，不修改该任务 JSON、ACK 状态、完成收据或已核收报告历史。
- 当前仅记录合同输入；未创建外部存储、未复制数据库、未运行备份、未修改 App/Spec/ADR/data/design、未开放端口或网络能力。

## 2. 后续安全/产品合同硬要求

1. SQLite 备份必须使用 SQLite 一致性在线备份机制或经独立证明具有等价一致性的单写快照；快照过程必须与唯一写主协调。
2. 成功备份点的最大间隔不得超过 15 分钟。调度触发不等于备份成功；只有完成一致性校验、manifest/hash 落账并持久化到目标故障域后，才更新最近成功恢复点。
3. 备份必须加密并保存到与活动主库不同的主机或故障域；传输与静态存储均需加密。备份入口不得长期暴露在公网。
4. 每个恢复点必须有 allowlist manifest，至少记录备份 ID、数据库逻辑标识、开始/完成时间、源 schema/application 版本、SQLite/WAL 状态、文件/逻辑 hash、加密与保留策略版本、结果和脱敏错误码。禁止记录密钥、凭据、完整路径、会话或私密业务正文。
5. 使用 WAL 模式时，备份必须证明主数据库与对应 WAL 状态属于同一个一致性快照；不得把活动中的 `db`、`-wal`、`-shm` 文件分别复制后拼成恢复点。
6. 每次备份失败、连续失败、超过 15 分钟无成功恢复点、hash/manifest 不一致、目标故障域不可达或密钥不可用，均必须告警。告警本身不得将失败备份标为成功。
7. 恢复验收必须在隔离环境执行：解密、manifest/hash 校验、SQLite 完整性检查、schema/ledger/application 版本校验、关键记录抽样或机械计数、只读启动验证，以及恢复点年龄证明 `≤15 分钟`。
8. 至少季度执行一次恢复演练；重大 schema、SQLite 版本、加密、存储或部署变更后追加一次。只有演练同时满足 `RPO ≤15 分钟` 与 `RTO ≤4 小时`，才能声称恢复目标达标。
9. 数据库保持单写者或具有明确 fencing 的唯一写主。禁止用数据库双活、跨地域双活、无仲裁双写或长期开放第二公网备份入口满足 RPO/RTO。
10. 保留和删除策略必须覆盖加密密钥轮换、不可恢复删除、损坏备份隔离及至少一个已演练的 last-known-good 恢复点；具体保留周期由后续产品/合规合同确认。

## 3. 明确禁止

- 禁止直接复制活动中的 SQLite `db` 文件并将其宣称为一致性备份。
- 禁止忽略或拆分活动 WAL/SHM 状态后宣称快照可恢复。
- 禁止只凭定时任务成功退出、文件存在或上传完成判断恢复点有效。
- 禁止在 manifest/hash 或隔离恢复演练缺失时声称满足 RPO/RTO。
- 禁止数据库双活、跨地域双活、长期公网 Admin/备份入口及自动切换到公网管理面。
- 禁止把本记录解释为外部存储采购、账号创建、密钥生成、网络开放或实施授权。

## 4. 后继实现验收出口

- 连续观测窗口内，相邻两个**已验证成功恢复点**的间隔均 `≤15 分钟`。
- 任意抽取的恢复点可在隔离环境通过 manifest/hash、SQLite/WAL 一致性与应用级完整性校验。
- 一次受控主库不可用演练可在 `≤4 小时` 内恢复唯一写主，且恢复后的数据损失窗口 `≤15 分钟`。
- 失败备份不推进最近成功恢复点；超过 RPO 窗口时产生明确告警并保持 fail closed。
- 演练后无公开入口、无第二写主、无测试数据库或解密材料残留。
