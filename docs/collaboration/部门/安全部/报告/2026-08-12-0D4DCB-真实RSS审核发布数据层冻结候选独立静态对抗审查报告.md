## 5. P1 问题与精确最小修正

### P1-01：Publication 可删除重建，且已发布时间可被改写

**证据**

- `publication` 只有 `decision_id/bundle_id/public_id` 等身份字段的 UPDATE guard；`published_at` 与 `created_at` 未被冻结。
- migration 没有 `publication_no_delete`。
- 因此 queued Publication 可以被删除，释放 `decision_id UNIQUE`、`bundle_id UNIQUE` 与 `public_id UNIQUE`，随后可为同一批准决定创建不同 Publication/publicId；已 published 行的 `published_at` 也可以在提交后被任意改写，且不可变 Projection 中的发布时间不会同步。

**影响**

- 违反每个 Bundle/Decision 只有一个 Publication、一个稳定 publicId 的合同。
- 破坏 PublishedProjection 与 Publication 的时间一致性和可追溯性。

**最小修正**

1. 增加 `publication_no_delete`，任何 DELETE 固定拒绝。
2. 将 `created_at` 纳入身份不可变范围。
3. 增加 `publication_published_at_guard`：只允许在同一语句内执行唯一一次 `queued + NULL → published + non-NULL`；其余 published_at 改写全部拒绝。
4. 聚焦负例必须覆盖 queued 删除、published 删除、发布后改时间、拆成两条语句先写时间/后改状态，全部零增量或抛固定 reason。

### P1-02：ProjectionOutbox 可删除重建，也可从伪造终态开始

**证据**

- `projection_outbox` 没有 DELETE guard。
- INSERT guard 只检查 Publication 已 published 及 Envelope 六个身份字段，未要求 `status='pending'`、`attempt_count=0`、空 lease，也未约束 `attempt_count<=max_attempts`。
- `max_attempts` 与 `created_at` 可被后改；attempt/lease 没有与状态迁移原子耦合。

**影响**

- 删除旧 Outbox 后可为同一 Publication 创建第二 delivery/idempotency/reconcile identity。
- 未经过 dispatcher/receiver 即可落一条 `succeeded` 或 `terminal_failed` 行，伪造投递事实；重置 attempt 可绕过有界重试。

**最小修正**

1. 增加 `projection_outbox_no_delete`。
2. INSERT guard 固定要求 `pending + attempt_count=0 + lease_token/lease_expires_at=NULL`，并把 Envelope 初始 attempt 与行值绑定。
3. 冻结 `max_attempts/created_at`，加入 `attempt_count<=max_attempts`。
4. 将 acquire 约束为 `pending|retryable_failed → leased` 时 attempt 恰好 `+1` 且在预算内、lease 两字段同时出现；非 leased 状态的 lease 清理规则由 successor 固定，禁止仅改字段绕过状态机。
5. 聚焦负例覆盖 DELETE 后重建、直接 INSERT succeeded、pending 携带 lease、attempt 超预算、同状态重置 attempt。

### P1-03：AuditEvent 只有“写后不可改”，没有可验证的事件链

**证据**

- `audit_event_guard_insert` 只把 JSON 中六个字段与外列对齐。
- `previous_event_hash` 可以在任意序号为 NULL 或任意 64 位小写 hex；没有要求首条为 NULL、后续逐字等于上一 `audit_seq.event_hash`。
- `event_hash` 只做格式/唯一检查；`mapping.ts` 没有 AuditEvent canonical hash 的 build/verify 出口。聚焦测试以 `sha256(event_json)` 直接填值，也没有第二事件断链负例。

**影响**

- 攻击者或实现错误可以插入断链事件、伪造 hash 或并行分叉；UPDATE/DELETE guard 无法修复插入时已经伪造的历史。
- 审计记录不能作为 operation、人工发布和急停的完整性收据。

**最小修正**

1. 增加 INSERT predecessor guard：空表首条必须 `previous_event_hash=NULL`；非空表必须逐字等于 `ORDER BY audit_seq DESC LIMIT 1` 的 event_hash。
2. 在 `mapping.ts` 增加唯一 canonical AuditEvent material build/verify，hash 至少绑定 `previous_event_hash + strict event payload`；读出时复算。
3. Repository 必须在同一 `BEGIN IMMEDIATE` 内读取前驱、构建、插入、读后复验；冲突整笔回滚。
4. 聚焦负例覆盖第二条 NULL parent、错误 parent、伪造 event_hash、额外私有字段、并发旧 parent，全部拒绝。

## 6. P2

### P2-01：Snapshot schema 未做最小 parent 形状联动

`ProjectionSnapshotSchema` 分别验证 generation 为正整数、previous hash 为 hash/null，但不要求第一代为 NULL、后续代有 parent。未来 receiver 可以用 active state 拒绝该输入，因此当前没有形成已实现的越权公开；不过 sender 现在可以构建、hash 并持久化明显不可能通过正常链的 snapshot，增加 reconcile/terminal 噪声。

最小修正：schema 增加 `snapshotGeneration===1 => previousSnapshotManifestHash===null` 与正常非 bootstrap `snapshotGeneration>1 => previousSnapshotManifestHash!==null`；受控空 receiver 重建只能由已冻结 bootstrap pin 分支放行，不能用 null 绕过。真实 receiver 仍须独立验证 active+1、previous exact match、签名和 manifest。
