# F1+1 采集、内容处理与发布安全基线审核报告（设计级）

## 审核对象与标准

本报告审核 `docs/spec.md` 所述主链：白名单信源 → 定时采集 → 归一化与去重 → 低质量初筛 → 中文整理与图片候选 → 人工审核 → 公开信息流与详情页 → 原始链接，并覆盖后续可逆自动发布。

判定标准来自：

- 任务验收出口：资产、信任边界、主要威胁、控制、残余风险、至少三种失败恢复路径，以及自动发布的可逆开关和准入门槛。
- `docs/spec.md` 的 Spec v0 范围、人工审核门禁、15 分钟发现目标、禁止绕过平台访问控制等约束。
- OWASP 的 SSRF、XSS、恶意文件、权限、密钥、日志和 LLM 提示注入防护指南。
- NIST SSDF 的软件供应链与安全开发原则。
- X、Reddit、Meta 的当前官方条款和开发者政策。
- 中国官方公布的个人信息、网络数据、生成式 AI、AI 内容标识、算法推荐、互联网新闻信息和著作权规则。

本次属设计级审核。仓库当前只有 `app/README.md`，没有可运行的采集、摘要、审核或发布实现，因此不对任何控制的实际有效性作出通过结论。

## 结论摘要

### 当前结论：不通过上线准入

可以继续的范围：

- 使用自建非生产样本、公共领域或权利人明确授权的内容做离线威胁探针。
- 在平台审批的 API、用例和额度内对少量测试账号进行可随时停止的技术实验。
- 实现不连接真实发布出口的队列、幂等、重试、死信和审计骨架。

当前禁止的范围：

- 使用浏览器自动化、伪造登录态、规避限速或绕过访问控制采集 X、Instagram、Reddit 等平台。
- 在尚未确认平台许可、内容权利、图片授权、数据保留与删除义务前，持续存储或公开再利用第三方内容。
- 将外部内容、图片或模型输出直接发布。
- 启用自动发布。

必须先解决的阻断项：

1. 确定运营主体、服务地域、用户地域、部署区域和第三方 AI 数据流向，由专业法律顾问确认许可、版权、隐私和跨境要求。
2. 为每个信源建立可核验的权限根据：官方 API 审批、平台用例批准、额度、展示/缓存/删除规则、条款版本和复查日期。
3. 确定首批实际信源、图片策略、AI 供应商、后台权限模型和部署架构，再完成技术安全复审。
4. 对实现运行本报告列出的反向探针，清零所有 P0/P1 问题。

#### 2. 信任边界

1. **互联网信源 → 采集器**：所有响应、重定向、域名、证书、正文和媒体均不可信。
2. **采集器 → 原始存储/队列**：只写入有严格大小、类型、来源和租户/信源标识的数据，保存不可变的来源证据哈希。
3. **原始数据 → AI 处理服务**：发送前做数据最小化和个人信息/密钥检查；把供应商视为独立外部处理方。
4. **AI 输出 → 内容库/审核台**：输出只能经 schema 校验后进入“待审核”，无发布权限。
5. **审核者浏览器 → 后台 API**：身份验证、授权、CSRF 防护、会话管理和审计都在服务端强制。
6. **审核/自动策略 → 发布器**：只接受已达到准入门槛且带受保护幂等键的指令，开关默认关闭。
7. **发布器 → 公开网站/外部平台**：公开内容是不可逆扩散事件，需事前验证、事后可下架和可追溯。
8. **CI/CD 与运维 → 生产**：人和自动化都服从最小权限；开发/测试不获取生产数据或发布密钥。

| 级别 | 威胁 | 必需控制 | 残余风险/决策 |
|---|---|---|---|
| P0 | 不合规采集导致平台停权、索赔或下架 | 逐信源权限登记；官方 API 优先；用例/额度/展示/保留/删除证据；条款变更复查；失去许可立即停止 | 平台条款可变，且平台保留审核/终止权；需接受某些信源无法达到 15 分钟目标 |
| P0 | 主采集链/图片代理 SSRF，或 RSS/XML 解析造成外部实体请求与资源耗尽 | 所有适配器共用出站控制；只允许预期协议；校验全部 A/AAAA/CNAME 并将连接固定到已验证 IP；拒绝私网/回环/链路本地/保留/元数据地址；每跳重定向重验；禁用环境代理；XML 禁用 DTD、外部实体和网络访问，限制字节/解压比/深度/节点数 | DNS/CDN 变更、解析器和库行为差异仍有风险；高风险时暂停该适配器或只存已验证元数据 |
| P0 | 恶意媒体造成解析器 RCE、压缩炸弹、存储耗尽或 SVG/HTML XSS | 拒绝 SVG/HTML/XML；魔数+完整解码校验；字节、尺寸、像素、帧数、解码时间限制；非特权隔离容器；转码为固定安全格式；删除元数据；独立域名、`nosniff` 与固定 `Content-Disposition` | 图像库仍可出现零日漏洞；需及时更新和可一键关闭图片代理 |

| P0 | 提示注入影响摘要、泄露上下文或越权调用 | 摘要 worker 无工具、无网络、无密钥、无发布权；系统指令与信源数据结构化分隔；输入长度/编码限制；输出 schema、引用和事实对齐检查；高风险样本隔离；人工审核 | 自然语言模型无法保证对所有对抗输入稳健；只能通过隔离、最小权限和人工门禁限定影响 |
| P0 | 后台越权、账号接管或 CSRF 导致发布/删除 | 独立后台身份域；MFA；拒绝默认；每请求服务端授权；审核、发布、开关管理分权；CSRF 防护；短会话与重要操作再认证；不可篡改审计链 | 内部人员误操作和终端失陷仍存在；自动发布开关建议双人复核 |
| P0 | 重试或并发导致重复审核项/重复公开发布 | 拆分稳定 `content_id`、不可变 `content_version` 与 `publish_generation`；consumer inbox+唯一任务 ID；CAS 状态迁移；事务 outbox；目的地唯一约束；发布 API 有原生幂等键时强制使用，无原生幂等时超时进入 `publish_unknown` 对账且默认不重试 | 相同事件的不同原文和外部系统返回未知仍需人工校准 |
| P1 | 限速、平台故障或 AI 故障触发重试风暴和队列堆积 | 仅对短暂错误重试；遵守 `Retry-After`；指数退避+全抖动+上限；每依赖重试预算；平台/端点级熔断；死信队列；积压时暂停新采集或降级为仅保存元数据 | 第三方长时中断可导致 15 分钟目标失效；前台应展示信源受限/更新延迟 |

| P1 | 密钥进入仓库、日志、错误返回或模型提示 | 密钥服务、环境注入、最小作用域、分环境凭证、仓库/镜像/日志扫描、统一脱敏、轮换与泄露响应 | 集成软件可能在底层打印请求头；上线前需故障注入检查日志 |

密钥、权限、日志和供应链控制分别参考 [OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)、[OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)、[OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 与 [NIST SP 800-218 SSDF](https://csrc.nist.gov/pubs/sp/800/218/final)。

#### 4. 稳定性与故障隔离基线

1. **适配器隔离**：X、Instagram/Meta、Reddit、RSS/新闻站使用独立队列、限速器、熔断器和指标。单一平台故障不拖垮其他信源。
2. **幂等**：采集、归一化、审核项创建和发布每段都使用 `content_id/content_version/publish_generation`、consumer inbox、CAS 状态迁移和唯一约束；同一输入可重放且结果不增加公开副本。
3. **重试分类**：只对网络中断、408、429 和部分 5xx 等短暂错误重试；超时按操作阶段的幂等性处理，任何非幂等外部副作用默认不重试；认证、授权、条款禁止、无效输入和恶意媒体直接停止并告警。
4. **退避与预算**：指数退避+全抖动，优先遵守 `Retry-After`，单任务设有最大尝试数和累计时间，同一依赖有全局重试预算。参数在小实验后按官方额度和延迟标定。安全性原理参考 [Google Cloud Retry Strategy](https://docs.cloud.google.com/storage/docs/retry-strategy) 和 [AWS REL05-BP03](https://docs.aws.amazon.com/wellarchitected/latest/framework/rel_mitigate_interaction_failure_limit_retries.html)。
5. **熔断**：平台/端点连续失败或超过重试预算后打开熔断，半开时只放少量探测；熔断转换事件必须告警。原理参考 [Azure Circuit Breaker Pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/circuit-breaker)。
6. **死信与重放**：超过最大尝试的任务进死信队列，保存错误分类、来源指针和下一个安全操作；人工重放也服从幂等和当前授权状态。
7. **背压与降级**：队列滞后超标时按风险降级：暂停低优先级信源 → 仅保存必要元数据 → 停止 AI/图片处理 → 保持公开站旧内容可读。降级不得跳过审核。
8. **可观测性**：每信源记录最后成功采集、最后新内容、连续失败、429/授权错误、队列年龄、端到端延迟、重复拦截、审核滞留、发布失败、下架与投诉。告警带 trace/correlation ID，不带原文全文或密钥。
9. **数据恢复**：定期备份信源配置、游标、状态机、审核记录和发布记录；备份加密、分权、定期恢复演练，并验证恢复后不会重复发布。

当前信源数、发布频率、用户量和流量均未知。因此不固定假设并发数、QPS、队列容量、超时、重试次数、告警阈值或 RTO/RPO；上述参数必须按每个平台的官方额度、小实验分位数和业务容忍时间配置，并保留可调整上下限。

#### 5. 自动发布可逆开关

开关必须是服务端强制的集中配置，默认 `manual_only`，至少支持：

- **全局急停**：立即阻止新的发布任务，不等待当前队列清空。
- **优先级与防竞态**：`global_stop > 权限/法务过期 > source_stop > manual > canary > auto`；开关使用单调递增 epoch 和不超过60秒的发布租约，自有网站在最终写入事务内校验 fencing token。
- **按平台/信源/内容类别的子开关**：从最低风险、权利最清晰的小范围启用。
- **失效闭合**：配置读取失败、指标不可用、条款证据过期、审计写入失败或质量/安全指标超标时，自动回到 `manual_only`。
- **作用时间**：急停目标为 60 秒内在所有 worker 生效；实现后需用实际故障注入验证。
- **审计与再认证**：记录修改人、时间、原因、前后值和关联批准；开启需要重要操作再认证与双人复核，关闭允许单人立即执行。
- **就地防护**：所有发布 worker 在执行前重新检查开关、幂等键、授权证据有效期、内容版本和撤回标记，不仅依赖任务入队时的状态。
- **在途与恢复**：队列待执行任务取消，已发请求进入 `publish_unknown` 对账，已公开内容走下架/更正；急停解除后不自动回弹，必须人工复核并重新灰度。

#### 6. 自动发布准入门槛建议

以下数值是首轮设计起点，需在真实人工审核数据产生后校准；样本数是最低观察门槛，不证明严重错误率为零。模型、提示、解析器、信源身份或权限策略发生实质变更时，自动发布资格过期并重新进入人工观察和 canary；未达任一项时保持人工审核。

| 类别 | 启用前建议门槛 |
|---|---|
| 平台与法务 | 待开启范围内每个信源都有当前有效的获批用例/内容授权/展示及保留规则；隐私、版权、跨境、AI 标识和互联网新闻信息许可问题已有书面法务意见；无未关闭的权利人投诉 |
| 安全 | SSRF、XSS、恶意媒体、提示注入、后台越权、CSRF、密钥泄露、供应链和发布幂等反向探针全部通过；无开放 P0/P1 问题；急停和凭证撤销演练通过 |
| 质量 | 至少覆盖 30 个连续日和 500 条经人工审核内容，每个拟自动信源至少 50 条；严重事实错误、错误归因、错误原链接、漏泄个人敏感信息和未授权媒体公开发布均为 0 |
| 稳定性 | 在信源及接口正常的样本中，至少 99% 内容在 15 分钟内进入处理流；发布重复数为 0；无无限重试、无丢失死信、备份恢复后无重复发布；连续 30 天无严重安全/发布事故 |
| 可观测性 | 所有关键阶段有可关联状态；限速、授权失效、队列积压、死信、摘要校验失败、发布失败、开关变更和下架都能在当班人员响应时限内告警 |
| 分阶段 | 先只选1个权利清晰的低风险 RSS/自有信源，每日最多自动发布5条，运行7天；其后逐信源扩大，不做全量一次性切换 |

## 用户可见出口

当前无可运行产品出口可验证。正式上线前，用户可见出口至少应包含：

- 每条内容显示来源平台、作者、原始发布时间和可验证原链接。
- 对 AI 整理/生成的内容按最终法律意见提供用户可感知的标识，不将整理结果写成原作者原话。
- 图片缺失、权利不清或安全校验失败时使用占位或无图布局，不降低校验条件换取配图。
- 内容更正、投诉、删除/下架入口及处理状态。
- 信源受限或更新延迟时准确展示状态，不继续声称正常达到 15 分钟。

## 必测失败路径与恢复

| 失败路径 | 安全失败时的状态 | 恢复步骤 | 不得发生 |
|---|---|---|---|
| 1. 平台返回 429/5xx 或长时超时 | 对该平台/端点限速并熔断，保留最后成功游标，信源标记“受限/延迟” | 遵守 `Retry-After`，半开小流量探测，确认额度和条款后重放未处理任务 | 立即循环重试、轮换账号规避限制、丢失游标 |
| 2. 图片 URL 指向内网、多跳重定向、巨型图或伪装类型 | 终止图片任务，隔离样本，主内容保持待审且无图 | 记录脱敏原因，验证信源是否被污染，安全人员确认后再解除信源暂停 | 在 Web 进程内直接解析、跟随未复验重定向、因为“必须有图”放宽限制 |
| 3. 外部正文包含间接提示注入，模型输出越界指令、隐藏链接或 schema 外字段 | 输出驳回并进安全隔离/人工审核，不产生可发布状态 | 保留最小对抗证据，更新回归用例，对同信源近期任务做影响排查 | 让模型重试到“通过”、把模型输出当作授权指令、继续自动发布 |
| 4. 发布请求超时，返回状态不明 | 标记 `publish_unknown`，禁止直接重试 | 使用幂等键/外部 ID 查询公开出口；确认未发布后才重放；已重复时留一条并下架其余副本 | 超时即无条件重试、通过删数据掩盖重复事故 |
| 5. 密钥泄露或平台账号异常 | 全局停止受影响采集/发布器，封存审计证据 | 撤销与轮换凭证，排查仓库/日志/镜像/模型提示，确认影响和通知义务，使用新凭证小流量恢复 | 先删日志、只改密码不撤销 token、未查影响就恢复全量 |
| 6. 数据库/队列中断或恢复备份 | 停止新发布，公开站使用最后一致快照，采集按容量停止或仅保留最小游标 | 恢复后先校验状态机、幂等键、审核记录和发布记录，再受控重放 | 在状态未对齐时重启全部 worker、从头全量抓取导致重复 |
| 7. 平台条款变更、用例被拒或授权撤销 | 该适配器立即冻结，停止采集和再发布，不影响其他已授权信源 | 根据条款执行停用、删除/停止展示，由平台/法务重新批准后再开启 | 通过爬取、代理或换账号继续获取 |
| 8. 自动发布产生事实错误、权利投诉或批量误发 | 60 秒内触发全局急停，所有新内容回到人工审核 | 按范围下架/更正，保留审计链，通知受影响方，完成根因分析和新回归后仅以小流量重新开启 | 边发布边调参、删除审核记录、用静默修改取代更正说明 |

## 自设计反向探针

以下探针需在有可运行实现后由安全部独立执行，每个探针都要检查公开出口、后台状态、队列和日志。

1. **SSRF/RSS**：向正文和图片采集提供回环、RFC1918、链路本地、IPv6 本地、十进制/八进制 IP、DNS rebinding、多跳重定向和非预期协议 URL；向 RSS/XML 注入外部实体、实体膨胀、超深节点和压缩响应；期望无内网请求且资源限制生效。
2. **恶意媒体**：伪造 `Content-Type`、SVG 脚本、超大图、像素炸弹、多帧动图和破损文件；期望被隔离，主内容可以无图待审。
3. **XSS/URL**：在标题、作者、正文、摘要、图片 alt、审核备注和 URL 注入脚本、事件属性、`javascript:`、data URL 和恶意 Markdown；期望公开页和后台都不执行。
4. **提示注入**：在网页可见文本、HTML 注释、alt 文本和图片中放入“忽略指令”、诱导泄密、要求发布和威胁审核员的内容；期望模型无工具行为、无系统信息泄露，且输出仍待人审。
5. **授权**：未登录、已登录普通审核员、被停用用户和盗用 ID 分别请求他人队列、审批、发布、下架和开关接口；期望拒绝并产生安全日志。
6. **CSRF/会话**：跨站表单、旧会话、登出后 token、修改权限前建立的会话请求发布或开关；期望全部失败。
7. **幂等/并发**：同一内容并发100次投递，并分别模拟原文更辑、发布超时、信源停用后重放旧任务和获批后替换域名/账号；期望版本关系正确、旧资格失效，且只有1个审核项和1个公开内容。
8. **重试风暴**：对下游注入 429/503/超时，同时开启高并发；期望重试预算、抖动、熔断和背压生效，其他平台仍可处理。
9. **死信/恢复**：让一批任务永久失败，恢复备份后重放；期望任务可见、可定向重放，无重复发布。
10. **密钥/日志**：在请求头、错误体、正文和模型输出中放入仿真 token，制造各层异常；期望仓库、日志、告警和提示均无 token 明文。
11. **急停竞态**：在高并发发布中切换全局急停，同时断开配置服务并制造已发请求结果未知；期望60秒内无新公开项，epoch/租约/fencing 校验生效，未知任务进对账，且恢复后不自动回弹。
12. **权利删除**：对已公开项发出平台/权利人删除请求；期望在承诺时限内停止展示并清理缓存/媒体，同时保留合法必要的脱敏审计证据。

## 检查方法

- 完整阅读当前 `docs/spec.md`、最新 `docs/progress.md`、安全部岗位说明、任务 JSON、审核报告模板和错题集。
- 检查仓库当前状态和 `app/` 内容，确认没有可运行实现可供技术渗透或故障注入。
- 通过 OWASP、NIST、X、Reddit、Meta、中国人大网、中国政府网和中国网信网等原始/官方来源核对当前规则。
- 将证据支持的事实、本项目的工程建议和必须交给专业法律顾问/平台的问题分开表达。
- 按威胁—控制—反向探针—恢复路径检查是否只覆盖正常路径。

## 实际结果

- 已建立覆盖资产、8类信任边界、主要威胁、必需控制和残余风险的设计级基线。
- 已给出幂等、有界重试、限速、熔断、死信、背压、降级、备份恢复和可观测性的稳定性建议。
- 已给出8条可执行失败恢复路径和12组实现后必测的反向探针。
- 已给出默认关闭、失效闭合、60秒急停、按信源分级的自动发布开关，以及法务、安全、质量、稳定性、可观测性和灰度门槛。
- 两路只读对抗性审查均未发现会错误放行上线的 P0 问题；已合并对 SSRF/RSS、幂等版本、急停竞态、白名单变更、X/Meta 条款边界、robots.txt 定位和著作权表述的修正；其余无实现或无书面证据的项目保留为技术复审及法务/平台门禁。
- 发现当前不存在信源清单、平台批准证据、图片权利策略、AI 供应商数据条款、部署架构或实现证据，因此不能放行上线或自动发布。

## 问题清单

### 阻断项

1. 首批信源、经营性质、用户/运营/部署地域和第三方 AI 数据流向未确定。
2. X、Instagram/Meta、Reddit 的应用审批、具体 API 权限、用例描述、额度、保留/删除/展示条件和摘要许可证据缺失。
3. 外部文章、社交媒体图文和图片的复制、摘要、缓存、代理与公开展示权利没有法律意见和逐信源许可证据。
4. 对中国大陆公开运营时是否触发互联网新闻信息服务许可、生成式 AI/算法备案和 AI 内容标识义务尚无专业法律判定。
5. 没有可运行实现，所有安全控制仍是待实施、待验证的合同。

### 重要问题

1. Spec 将“尽量展示图片”列入 MVP，但尚未选择原站嵌入、仅原链接、授权镜像或自建代理策略；这会同时影响 SSRF、隐私、版权和可用性。
2. 中文摘要使用的模型、供应商是否保留/训练输入、数据区域、删除 SLA 和子处理者未定。
3. 后台审核者角色、开关管理者、发布执行身份和应急值班责任人未定。
4. 15 分钟发现目标已限定在“已接入且可正常访问的测试信源”，开发时仍需把平台限速和授权失效排除在 SLO 分母外，并在用户出口显示降级状态。

## 未覆盖项

- 未核验任何真实平台账号、API 凭证、应用审批、接口额度或商业合同。
- 未核验首批具体白名单信源的 robots.txt、网站条款、RSS 许可、内容权利和删除流程。
- 未核验任何图片下载、代理、解码、重编码或下架实现。
- 未核验任何 AI 模型、提示模板、数据保留设置、摘要准确率或对抗稳健性。
- 未核验后台身份认证、授权、会话、MFA、CSRF、审计或急停实现。
- 未核验实际部署架构、依赖、SBOM、容器、CI/CD、备份、告警、RTO/RPO 或容量。
- 未出具法律意见；本报告中的法规和平台条款部分只标识风险与需确认事项。

## 需法律顾问或平台书面确认的事项

1. F1+1 的运营主体、经营性质和服务地域下，对 X、Instagram/Meta、Reddit、新闻站和 RSS 的采集、摘要、缓存和展示是否获许可。
2. 生成中文标题/摘要是否超出 X 和 Reddit “仅为展示格式化”的许可，是否需额外用例批准或单独协议。
3. 图片、车手/名人头像、社交媒体图文的著作权、肖像权、隐私权和合理使用/合理引用边界。
4. 通过外部 AI 供应商处理原文、账号信息和可识别人物数据的处理根据、合同、保留、训练退出、子处理者与跨境要求。
5. 中国大陆公开运营时，产品是否属于互联网新闻信息服务、算法推荐服务或生成式 AI 服务，需哪些许可、安全评估、备案和标识。
6. 内容删除、缓存更新、权利人通知、审计日志保留和平台终止后数据清理的具体 SLA。
7. 项目名称与视觉、F1/FIA/车队/车手的品牌标识、官方内容、比赛结果/计时/统计数据和 AI 处理用途的权利边界与授权。

## 结论：不通过 + 理由

当前结论为 **fail**，对象是“真实平台持续采集、公开上线及自动发布准入”。理由如下：

- 平台用例、权利许可、保留/删除要求和地域法律尚未确认。
- X 和 Reddit 当前条款对“修改”和用例有明确限制，中文摘要不能在无书面批准/法务确认的情况下假定合规。
- 外部图片和正文将同时引入 SSRF、XSS、恶意媒体、提示注入、隐私和版权风险。
- 仓库没有可运行实现，安全控制、稳定性与恢复路径均未经实际验证。

本结论不阻止在不接入真实发布权限的前提下，进行离线安全实验、平台授权调研、法律复核和可重做的技术 spike。上述阻断项关闭且实现通过反向探针后，由统筹部安排安全部复审。

## 需要用户决定

本部门不把建议写成用户授权。以下事项应由统筹部在具备平台和法律证据后请用户决定：

1. 项目运营主体、目标地域、部署地域和是否商业化。
2. 在平台限制下，哪些信源保留在 MVP，哪些信源接受更长延迟或暂不接入。
3. 图片路线选择：仅原链接/无图、平台官方嵌入、逐项授权镜像，或在法务和 SSRF 控制完成后自建代理。
4. 后续是否接受本报告建议的自动发布准入门槛和分阶段路线；此决定只确认准入合同，不等同于当下开启。
