# M3 影子 Base 最小 ACL 收紧方案审核报告

## 1. 审核范围与边界

- 本报告只复核本机 `lark-cli` 的 typed `drive permission.public patch` schema/help、内嵌 skill、仓库执行收据和当前 M3 ACL 事实。
- 本轮没有访问或修改飞书，没有使用浏览器，没有执行 `permission.public patch`、`--yes`、协作者写入、重授权或撤权。
- 真实 Base token、open_id、appId 和认证原始 JSON 不写入仓库。目标 Base 仅以项目标题和受控运行时上下文识别。
- `decision=pass` 只表示最小 ACL 方案的只读复核通过，允许进入“用户确认后再执行”的计划阶段；它不代表当前 Base 已私有，也不代表任何 ACL 已经修改。

## 2. 当前权限事实与证据边界

统筹部执行收据 `docs/collaboration/部门/统筹部/报告/2026-08-01-M3飞书Base影子建库与59条导入-执行收据.md` 记录的目标为 `F1+1 信源库｜M3影子`，并给出以下 typed CLI 回读值：

| 字段 | 当前值 | 语义 |
|---|---|---|
| `link_share_entity` | `tenant_readable` | 组织内获得链接者可阅读 |
| `external_access` | `true` | 允许组织外分享；不等于已存在外部协作者 |
| `invite_external` | `true` | 允许非管理权限对象发起组织外分享 |
| `share_entity` | `anyone` | 所有可阅读或可编辑者可查看、添加、移除协作者 |
| `security_entity` | `anyone_can_view` | 阅读者可复制、创建副本、打印、下载 |
| `comment_entity` | `anyone_can_view` | 阅读者可评论 |
| 表单 `shared` | `false` | 表单未开放填写 |

当前协作者清单因授权边界无法读取。未知项包括：协作者数量、身份、外部协作者是否存在、每个协作者的阅读/编辑/管理权限、创建前后 ACL 变化。`external_access=true` 和 `invite_external=true` 只证明能力开启，不能推出已经发生外部分享或泄露。

## 3. 本机 CLI/schema/skill 复核

### 3.1 typed 命令与风险

本机 `/opt/homebrew/bin/lark-cli drive permission.public patch --help` 显示：

- 命令：`lark-cli drive permission.public patch`；
- 风险：`high-risk-write`；
- 必填参数：`--token`、`--type`；`type` 枚举包含 `bitable`；
- 请求体入口：`--data`；
- 身份：`--as user|bot`；
- `--dry-run` 可预览；
- `--yes` 是执行高风险写入的确认门禁，必须在用户明确确认后才可传入。

本机 `drive permission.public get --help` 显示读取同一资源公共权限使用 `--token`、`--type` 和 `--as user`，不需要写权限。当前任务不执行该命令，统筹部收据已提供本轮脱敏回读事实。

内嵌 `lark-drive` 权限治理 workflow 将该操作标为 `R2` 高风险权限写入，要求：

1. 先确认准确 target scope；
2. 写前展示当前设置、目标设置和准确字段差异；
3. 先检查 `manage_public` 权限；
4. 用户明确确认后才允许 `drive permission.public patch --yes`；
5. 写后用 fresh `drive permission.public get` 验证；
6. 协作者列表无法读取时，不能声称已验证“仅预期维护者可访问”。

### 3.2 schema 输入字段与枚举

本机 `lark-cli schema drive.permission.public.patch --format json` 的输入 schema 证明 `--data` 支持以下六个 ACL 字段：

| 字段 | 类型 | 允许值 | 目标意义 |
|---|---|---|---|
| `link_share_entity` | string | `tenant_readable`、`tenant_editable`、`anyone_readable`、`anyone_editable`、`closed` | 链接分享范围 |
| `external_access` | boolean | `true`、`false` | 是否允许组织外分享 |
| `invite_external` | boolean | `true`、`false` | 是否允许非管理权限对象邀请外部分享 |
| `share_entity` | string | `anyone`、`same_tenant`、`only_full_access` | 谁可以查看、添加、移除协作者 |
| `security_entity` | string | `anyone_can_view`、`anyone_can_edit`、`only_full_access` | 谁可复制、创建副本、打印、下载 |
| `comment_entity` | string | `anyone_can_view`、`anyone_can_edit` | 谁可评论 |

schema 未把 `lock_switch` 列为请求体可写字段；它只出现在输出 schema，不能猜测或加入请求体。当前报告不扩展其他字段、不使用 `--params` 覆盖 `--data`，也不转 raw API。

## 4. 精确最小 ACL 目标（仅方案，不执行）

### 4.1 目标状态

针对“个人维护、未公开、最小共享面”的 M3 影子 Base，建议用户确认以下六项目标：

```json
{
  "link_share_entity": "closed",
  "external_access": false,
  "invite_external": false,
  "share_entity": "only_full_access",
  "security_entity": "only_full_access",
  "comment_entity": "anyone_can_edit"
}
```

字段选择理由：

- `closed`：关闭组织内和互联网链接访问，降低链接扩散面；
- `external_access=false`：关闭组织外分享能力；
- `invite_external=false`：关闭外部邀请能力；
- `share_entity=only_full_access`：仅拥有管理权限者可查看、添加、移除协作者；
- `security_entity=only_full_access`：将复制、创建副本、打印、下载收紧到管理权限者；
- `comment_entity=anyone_can_edit`：仅编辑者可评论，避免普通阅读者向影子 Base 添加评论；若仍存在编辑者，评论能力仍保留，且协作者清单不可读时评论者范围未知。

该目标是权限字段层面的最小共享面方案。它不能单独清除已经存在的显式协作者，也不能证明只有单一个人拥有访问权；协作者清单不可读时，这一部分必须保持 `Unknown`。

### 4.2 计划中的唯一 typed 写入形状

只有在用户确认目标 Base、六个字段和值，以及“关闭链接/外部分享可能影响现有访问者”之后，才可形成以下 dry-run 计划命令。当前不执行：

```bash
lark-cli drive permission.public patch \
  --token '<受控运行时 Base token；不写入仓库>' \
  --type bitable \
  --data '{"link_share_entity":"closed","external_access":false,"invite_external":false,"share_entity":"only_full_access","security_entity":"only_full_access","comment_entity":"anyone_can_edit"}' \
  --as user \
  --dry-run \
  --format json
```

dry-run 与真实写入是两条独立命令。正式写入必须移除 `--dry-run`，并在其余参数与已确认 body 完全相同的前提下，由用户明确确认后追加 `--yes`；不得把 `--dry-run` 与 `--yes` 作为同一条执行命令。禁止修改 body 以外的字段，禁止并发调用，禁止把该计划改写成 `lark-cli api PATCH` 或浏览器操作。

## 5. 写前只读核验计划

任何未来实际 ACL 写入都必须先完成以下只读步骤；本报告仅定义步骤，不执行：

1. **目标确认：** 以精确标题 `F1+1 信源库｜M3影子` 和受控运行时 token 绑定目标；不要把完整 URL、wiki token 或其他资源 token 当作 `--token`。
2. **Schema 复核：** 重新执行 `lark-cli schema drive.permission.public.patch --format json`，确认六字段及其枚举没有漂移；schema 不一致即停止。
3. **当前设置回读：** 使用 typed `drive permission.public get --as user --format json` 读取当前六字段，不能沿用旧收据直接写入；若任何字段已变化，标记 `changed_since_report`，重新生成计划。
4. **管理权限检查：** 按 workflow 规则执行 `drive permission.members auth` 的 `action=manage_public` 只读检查；结果为 false、授权错误或无法判断时停止。
5. **协作者边界确认：** 尝试使用现有 typed 只读能力确认协作者清单是否可读。若仍不可读，则不得把目标表述为“仅个人维护者可访问”；需要用户选择“接受 Unknown 并由 owner/admin 后续核验”或先提供可审计的协作者清单。
6. **数据与业务不变量：** 以统筹部执行收据为历史基线，确认 ACL 计划不包含记录、字段、视图、表单、workflow、真值/provider/Collector/采集/发布变更；不因 ACL 方案追加记录修复或删除。
7. **用户确认材料：** 展示目标标题、当前六字段、目标六字段、外部访问影响、协作者不可读限制、命令族 `drive permission.public patch`、风险 `high-risk-write` 和写后验证方式，等待用户明确确认。

## 6. 写后只读核验计划

若用户未来确认并由受控执行者完成写入，必须立即使用 fresh typed read 验证：

| 核验项 | 期望值 |
|---|---|
| `link_share_entity` | `closed` |
| `external_access` | `false` |
| `invite_external` | `false` |
| `share_entity` | `only_full_access` |
| `security_entity` | `only_full_access` |
| `comment_entity` | `anyone_can_edit` |
| 表单 `shared` | 保持 `false` |
| 资源类型 | `bitable`，标题仍为 `F1+1 信源库｜M3影子` |
| 协作者清单 | 若仍不可读，记录 `Unknown`，不能写成“仅个人维护者” |

核验要求：

- 响应必须 `ok=true` 或进程退出码为 0；不能只看 `code=0`；
- 六项中任一值不符、返回不完整或状态不明，都判定 ACL 收紧未完成，停止重试并提交差异；
- 保存 fresh-read 结果及可取得的旧/新协作者与权限收敛审计收据；协作者仍不可读时保留该 Unknown 边界；
- 不自动回滚、不删除资源、不修改记录；回滚也属于新的高风险写入，必须另获用户确认；
- 如权限写入造成当前执行者暂时不可读，不能通过切 bot 或浏览器补救；应保留失败收据，由有管理权限的用户处理。

## 7. 必测失败路径与停止条件

1. **schema/枚举漂移：** `permission.public.patch` 不再支持六字段、`bitable` 类型或上述枚举时停止；不猜字段、不构造 raw API body。
2. **管理权限或协作者边界不可读：** `manage_public` 检查失败、权限错误，或协作者清单仍不可读且用户未明确接受 Unknown 时停止；不得声称 Base 已私有或仅个人可访问。
3. **当前状态发生变化：** fresh get 与执行收据不一致，或目标资源/标题不唯一时停止；重新生成计划，禁止沿旧快照写入。
4. **高风险确认缺失：** 用户未明确确认关闭链接分享、关闭外部访问、限制复制/下载/评论及使用 `--yes` 时停止。
5. **写入结果不确定：** 超时、空响应、部分响应或返回不完整时先 fresh get；不得盲重试、并发重试、切 bot 或改用 raw API。
6. **越界副作用：** 发现记录/字段/表/视图/表单数据变化、公开表单、`enabled=true`、真值/provider/Collector/采集/发布切换时停止并回统筹部。

## 8. 用户确认点

实际 ACL 写入前，用户需要逐项确认：

1. 目标是否确认为 `F1+1 信源库｜M3影子`，而不是其他 Base；
2. 是否接受关闭链接分享、关闭外部分享和外部邀请；这可能影响现有组织内读者或外部协作请求；
3. 是否确认六项精确目标值，不接受“尽量收紧”这类模糊授权；
4. 是否接受 `security_entity=only_full_access` 造成复制、创建副本、打印、下载范围收紧；
5. 是否接受 `comment_entity=anyone_can_edit` 造成普通阅读者不能评论，同时知悉现有编辑者仍可评论且编辑者范围尚未核实；
6. 协作者清单不可读时，是暂停写入并先由 owner/admin 提供清单，还是用户明确接受该 Unknown 边界；接受 Unknown 不能改写成个人专属访问已证明；
7. 是否授权执行高风险 typed 命令 `drive permission.public patch`，以及是否允许在原始命令上追加 `--yes`；
8. 写后 fresh read 不符合目标时，是否只停留在差异报告，不自动回滚或删除资源。

在这些确认完成前，本任务只输出方案，不执行任何 ACL 写入、权限申请、协作者修改、重授权或撤权。

## 9. 已验证 / 未验证

### 已验证

- 统筹部执行收据提供的当前六项公共权限值、表单 `shared=false` 和协作者清单不可读边界已逐项记录。
- 本机 `lark-cli drive permission.public get/patch --help` 已核对；patch 被标为 `high-risk-write`，支持 `--dry-run` 和用户确认门禁。
- 本机 `lark-cli schema drive.permission.public.patch --format json` 已核对，确认 `bitable` 类型、六个可写字段和全部目标枚举。
- 内嵌 `lark-drive` 权限治理 workflow、`lark-shared` 与 `lark-base` skill 的写前确认、fresh read、协作者不可读和禁止猜测规则已核对。

### 未验证

- 本安全会话没有执行 `permission.public get`、`permission.members auth` 或任何其他飞书命令；当前值来自统筹部脱敏执行收据。
- 协作者数量、身份、外部协作者是否存在、协作者权限和 ACL 变化前后差异仍未知。
- 目标六字段能否在当前租户策略下成功写入、写入后是否保持 Base 与 M3 记录可访问，尚未验证。
- 当前用户是否拥有 `manage_public` 权限、实际 OAuth scope 是否足够、租户对外分享策略和密级策略是否允许收紧，均未在本轮读取。
- 个人维护者的实际身份名单、owner 关系和权限继承链尚未取得；本报告不声称 Base 已私有。

## 10. 错题自检与结论

- 没有把 `form.shared=false` 推导成整个 Base 私有。
- 没有把 `external_access=true` 或 `invite_external=true` 写成已经存在外部协作者或已经泄露。
- 没有把 `share_entity=only_full_access` 写成已清除既有协作者；协作者清单不可读继续保留为 Unknown。
- 没有猜测 schema 未声明的 `lock_switch` 请求体，也没有扩展 raw API、浏览器或删除路径。
- 没有把 dry-run、schema 或执行收据写成 ACL 已修改；没有执行 `--yes`。
- 没有扩展到真值、provider、Collector、采集、同步、启用或发布授权。

**结论：条件式 PASS。** 本机 typed schema 足以支持六字段最小 ACL 目标和精确核验计划：`link_share_entity=closed`、`external_access=false`、`invite_external=false`、`share_entity=only_full_access`、`security_entity=only_full_access`、`comment_entity=anyone_can_edit`。当前协作者清单不可读，个人维护者边界仍为 Unknown；任何实际 ACL 写入都必须先取得用户对目标、影响、`--yes` 和 Unknown 处理方式的明确确认，写后执行 fresh read 验证。
