# 47EF67 环境阻断后最小替代执行面安全裁决

## 1. 唯一裁决

**PASS；P0=0，P1=0，P2=1。推荐方案为 A。**

推荐在固定 M1 机器的普通 Terminal 中，以当前登录用户、无 `sudo`、无安装、无下载、无候选修改的方式，执行一次冻结的双 Seatbelt 后继 runner。必须先完成独立环境预检；预检不启动 App、Playwright 或浏览器，也不计入功能矩阵。只有 App/Browser 两份 profile 均能 apply，且声明loopback端口正例和未授权端口负例同时成立，runner才可继续唯一一次功能矩阵。

当前任务只形成裁决和后继合同。没有实际运行上述路径；`TASK-20260809-47EF67` 的环境 BLOCKED 历史及五个 Function `NOT_RUN` 保持不变，功能矩阵运行次数仍为0。

## 4. 为什么推荐 A

47EF67 证明的是当前 Codex 执行宿主无法叠加 App Seatbelt；它没有证明固定 M1 的普通 Terminal 同样拒绝 `sandbox-exec`。既有安全裁决已记录本机 `sandbox-exec`、Playwright 1.58.2、固定 revision 1208 headless-shell和精确loopback SBPL结构具备本地可行性。把最外层执行移到普通 Terminal，可以避开已观察到的嵌套宿主限制，同时保留原双Seatbelt强制边界。

该路径不需要新增依赖、外部服务、付费能力、系统设置修改、管理员权限或真实外网请求。唯一新增门是用户同意在固定M1普通Terminal执行一条已经冻结并可检查SHA的本地runner命令。

由于本轮没有在普通Terminal实际apply profile，该环境可行性保持P2/Unknown。后继runner的预检会把Unknown机械收敛；预检失败时不得猜测、不得放宽为C。

## 5. A方案精确后继执行合同

### 5.1 用户门与执行身份

后继测试任务必须先取得一次明确用户确认，内容只授权：

- 在指定固定M1的普通Terminal，以当前登录用户执行一条任务专属、已冻结SHA的本地runner；
- 允许runner启动本地App、固定Playwright驱动与固定headless-shell一次；
- 只访问manifest列出的精确loopback端口；
- 禁止 `sudo`、授权弹窗绕过、安装、下载、外部URL、真实账号、真实secret、候选修改、系统网络/防火墙设置修改。

确认不授权第二次功能矩阵、不授权系统Chrome、不授权把profile apply失败改为无Seatbelt执行。

### 5.2 冻结包

测试部应在功能运行前生成一个任务专属0700临时根和自包含runner包；包只引用现有本地Node/Playwright/headless-shell/candidate，不复制或修改canonical候选。manifest必须在同一时间冻结：

1. 47EF67中全部候选与工具链hash；
2. runner、App SBPL、Browser SBPL、harness、allowlist env和期望输出schema的完整SHA；
3. 唯一run ID、固定M1机器脱敏标识、执行UID、普通Terminal父进程边界；
4. App、proxy、CDP/pipe所需的每个精确loopback host/port；禁止`localhost:*`；
5. 功能矩阵计数初值0及“App/browser first PID产生后原子置1”规则。

runner包必须能在禁用外部网络依赖的情况下自包含运行；任何缺文件、hash漂移、依赖解析到包外未pin位置或env出现proxy/token/cloud key，预检失败关闭。

### 5.3 Phase 0：双Seatbelt apply预检，不消耗矩阵

普通Terminal只允许调用一条冻结runner命令。runner内部先后做两次独立profile预检：

1. 使用App SBPL包裹最小本地探针进程；
2. 使用Browser SBPL包裹同类最小本地探针进程；
3. 每份profile只允许manifest声明的精确loopback端口；
4. 对声明端口做正例，对一个由runner保留且未列入allowlist的loopback端口做负例；
5. 正例必须可达，负例必须稳定被拒，且两份 `sandbox-exec` 均成功apply；
6. 记录exit、stderr allowlist、profile SHA、探针PID/父子关系、端口、开始/结束时间和原始收据SHA。

任一 `sandbox_apply`、profile解析、正例、负例或进程归属失败：立即 `ENVIRONMENT_BLOCKED`，确认App/Browser PID均未产生，functionMatrixRunCount保持0，执行收口后退出。禁止在同任务中更改profile、扩大端口或改走B/C。

### 5.4 Phase 1：唯一功能矩阵

Phase 0全部通过后，runner在创建首个App或Browser PID前原子写 `functionMatrixRunCount=1`，随后：

- 从App SBPL最外层启动App/internal server/fault proxy完整普通后代；
- 从Browser SBPL最外层启动Playwright驱动、固定headless-shell及普通辅助后代；
- 只使用manifest固定的headless-shell SHA与新建任务profile，禁止系统Chrome；
- flags只用于降低C层噪声，不能替代Seatbelt；
- Playwright route与全target CDP在首次导航前安装，B层只允许声明loopback及约定的非网络scheme；
- 启动前、关键状态和收口前冻结进程树、PID→exe、argv与完整PID集连接账本；
- 在同一run中依次执行五个Function的既定矩阵；首个A/B外联、未授权成功连接、候选漂移、进程逃逸或功能失败立即停止，禁止重跑。

### 5.5 归因与证据闭包

- A层：App/server PID、项目guard或日志可绑定的外联命中，对应候选P1；敏感数据/真实副作用按影响升级P0。
- B层：Playwright/CDP页面、frame或worker initiator命中外部URL或未声明loopback端口，对应Function P1。
- C层：固定浏览器辅助PID且无同时间/目的地A/B证据。非白名单成功连接使harness FAIL；Seatbelt阻断且无App数据的尝试只记观察项。
- 无法绑定PID、target和时间时记Unknown；不得推断App泄漏，也不得声明全浏览器从未产生外联意图。

PASS必须同时具有：候选前后零漂移、双profile apply与正/负例通过、A/B外部请求和成功连接均为0、C无非白名单成功连接、五Function全部成功/失败/恢复/视觉/a11y出口通过、完整停止与残留收据。

### 5.6 收口

无论PASS、FAIL或BLOCKED，runner都必须：

1. 停止Browser、App与proxy完整进程树；
2. 确认所有任务端口无监听、任务PID无残留；
3. 回读候选、DB、BUILD_ID、manifest、runner与SBPL hash；
4. 扫描任务前缀profile、DB/WAL/SHM、receipt和临时根；
5. 先保存首错、功能计数、A/B/C账本及各原始文件hash，再精确清理任务临时根；
6. 不清理或改写canonical文件，不用重跑覆盖首错。

## 6. B与C的停止线

### B：固定M1自包含短时离线

B只有在A的Phase 0仍以环境能力失败且功能矩阵次数为0时，才可由新任务和新用户确认启用。B必须保留双Seatbelt、相同候选/tool hashes、全target CDP、进程树与收口；人工断开外部网络只增加成功副作用防线，不能替代Seatbelt和B层账本。离线状态的进入、持续、loopback可用与恢复必须形成可核验收据。不得默认关闭全机网络、不得在当前任务实施。

### C：flags + Playwright +进程账本

C不能作为localhost-only终验执行面。浏览器flags是降噪配置；Playwright route/CDP主要覆盖B层；`lsof`是瞬时快照。三者组合无法强制App及全部浏览器辅助后代只连声明loopback，也无法排除快照间短连接。C可作为开发观察，不得产出五Function最终安全PASS。
