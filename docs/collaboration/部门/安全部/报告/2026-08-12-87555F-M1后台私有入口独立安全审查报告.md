# TASK-20260812-87555F M1 后台私有入口独立安全审查报告

## 1. 结论

**PASS，P0=0、P1=0、P2=2。**

已形成可实施的 proposed 安全合同：固定 M1 上的 Admin 只监听 `127.0.0.1:3101`，通过 Tailscale Serve 提供 tailnet-only HTTPS；M5 与 iPhone 逐台登记、逐台批准，经 deny-by-default Grant 访问同一 origin；应用层继续强制 passkey、server-side session、精确 Origin、一次性 CSRF、operationId/CAS，以及 manual publish 的 5 分钟 fresh re-auth。

公开 Cloudflare Quick Tunnel 只保留 `127.0.0.1:3000` 的公开只读 allowlist。公开 `/admin*`、`/api/admin*`、`/internal*` 统一 404，不能到达 Admin upstream。Tailscale Funnel、公网 SSH、路由器端口转发、隐藏 URL 与公网密码页均为禁止项。

本次 PASS 只评价合同完整性和可实施性。真实设备、网络、账号、TLS、passkey、备份、UU、FileVault、RTO/RPO 或生产能力均未验证，不能写成可用或已放行。

合同路径：`docs/collaboration/部门/安全部/报告/2026-08-12-87555F-M1后台私有入口最小安全合同-v0.1.md`。

### 2.2 官方资料刷新

查询日期为 2026-08-12，使用 Tailscale、Apple、Next.js、W3C 与 OWASP 官方/权威资料。核心核验结果：

1. Tailscale Serve 可把本地 `127.0.0.1` HTTP 服务以 tailnet 内 HTTPS 提供，Serve 继续受访问控制；Funnel 承担公网暴露，两者安全语义不同。
2. Tailscale device approval 可让新设备在管理员批准前无法收发 tailnet 流量；Grants 支持 source/destination/port 最小权限。
3. Tailscale 直连、peer relay 与 DERP relay 都使用 WireGuard 端到端加密；中国大陆可达性和延迟仍需实测。
4. Tailscale HTTPS 证书 FQDN 会进入 Certificate Transparency 公共日志；必须使用无敏感信息的机器名。
5. Apple passkey 可在已批准 Apple 设备间经 iCloud Keychain 端到端加密同步；同步 credential 属单一共同故障域，需独立恢复 credential。
6. Apple silicon + macOS 26+ 在 Remote Login 和网络条件满足时支持重启后 SSH 解锁 FileVault；Wi-Fi 条件是此前连接的开放网络或 WPA2-PSK。当前旧 WPA、启动前重连、网关 VPN 和 Remote Login 未验。
7. Next.js 官方要求 Route Handler/Server Action 自行验证授权，推荐 server-side session、DAL 和最小 DTO；Cookie API支持 Secure/HttpOnly/SameSite/Path 等属性。
8. W3C WebAuthn 要求 RP scope、服务端随机 challenge 与严格匹配；OWASP 支持 `__Host-` session cookie、完整 Origin 与一次性 CSRF token 的纵深组合。

## 4. 失败路径核对

1. **Tailscale 在大陆网络无法稳定连接**：合同要求保持 Admin 关闭并形成新 successor；禁止回退公网密码页、Funnel、端口转发或 Cloudflare Admin。满足任务失败路径。
2. **产品合同冲突**：未发现业务语义冲突；单 M1 与 accepted 双主机之间已标明阶段差距，不能误报双主机生产完成。
3. **需要真实安装/账号/SSH/网络写操作**：本任务停在 implementation manifest 门前；外部配置变化、SSH、网络、app 改动和软件安装均为 0。

## 5. P2 与补偿

### P2-01：HTTPS 主机名进入公开 CT 日志

影响：Admin FQDN 的存在和机器名可被观察，虽然 tailnet 访问仍受限。

补偿：使用随机 tailnet 名和无敏感信息的 opaque machine name；公开地址不可充当秘密；仍要求设备、Grant 与应用强认证。

### P2-02：Apple 同步 passkey 具有共同故障域

影响：M5 与 iPhone 共享 iCloud Keychain credential 时，Apple Account/同步域故障可能同时影响两端。

补偿：production 前登记一枚独立 FIDO2 hardware credential，离线保存；设备访问还需独立 Tailscale approval，设备丢失时执行 Tailscale、session、WebAuthn 三层撤销。

## 6. 当前阻断门与 Unknown

以下是实施门，不属于本文合同缺陷：

- Tailscale 稳定版、tailnet、operator identity、设备 approval、Grant、Serve/Funnel 状态均未创建或验证；
- M5 异地 Wi-Fi、iPhone 蜂窝/换网、DERP path 和撤销延迟未测；
- Admin `127.0.0.1:3101`、独立服务身份、应用 passkey/session/CSRF/fresh re-auth 尚未实现；
- 公网路径规范化负向矩阵尚未对 future Admin release 运行；
- UU 精确产品/版本/启动前能力 Unknown；当前只能作为解锁后的运维候选；
- 固定 M1 Wi-Fi 当前为低安全旧 WPA；Apple preboot SSH 候选所需 WPA2-PSK、Remote Login、网关 VPN 与启动前重连未验证；
- 异机加密恢复点、解密材料分域、冷备、现场 Owner、`RPO≤15m` 与 `RTO≤4h` 真实演练均未形成。

在上述门关闭前，真实 Admin 与 mutation 必须保持关闭；公开 Beta 可继续 last-known-good。
