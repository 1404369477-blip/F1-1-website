# TASK-20260812-7920C6 D8A278 三项 P1 修复限定静态复审报告

## 1. 结论

**FAIL：P0=0，P1=3，P2=1。**

D8A278 确实补上了常规 DELETE、Publication 时间冻结、Outbox 初态/attempt/lease 状态机，以及 Audit canonical hash/前驱校验；普通 `INSERT/UPDATE/DELETE` 路径下，修正方向成立。

限定反向审查仍发现三个原 P1 没有闭合：SQLite `INSERT OR REPLACE` 的冲突处理会隐式删除旧行，而该隐式 DELETE 只有在每个连接明确启用 `recursive_triggers` 时才触发 DELETE trigger；当前三份冻结目标和项目连接配置均没有这项保证。Publication 与 Outbox 的 BEFORE INSERT guard 也没有主动拒绝已存在的唯一身份，因此 `*_no_delete` 可以被绕过。Audit 除同类 REPLACE 问题外，还允许显式插入低于当前最大值的空闲 `audit_seq`，使新事件不成为最大序号并形成分叉。

后端不得使用当前候选的 Publication、ProjectionOutbox、AuditEvent 落库不变量；等待第二个最小 successor 后再复审。

## 5. P1 精确反例与最小修正

### P1-01：Publication `no_delete` 仍可被 REPLACE 绕过

静态反例：已有一条合法 queued Publication 后，以同 `decision_id/bundle_id`、新的合法 `publication_id/public_id` 执行 `INSERT OR REPLACE`。新行满足 `publication_guard_insert`；唯一冲突触发 REPLACE 隐式删除旧行。当前没有连接级 `recursive_triggers=ON` 证明，INSERT guard 也没有查重拒绝，所以 DELETE trigger 不能作为完整防线。

最小修正：

1. 在 Publication BEFORE INSERT guard 中显式拒绝任何与现存 `publication_id OR decision_id OR bundle_id OR public_id` 冲突的行；该拒绝必须发生在冲突替换前。
2. Repository 禁止 REPLACE/UPSERT 覆盖语义，仅用 plain INSERT；连接级 `recursive_triggers=ON` 可作纵深防御，不能替代 INSERT guard。
3. 新增静态同形的真实负例：queued Publication `INSERT OR REPLACE` 改 publicId，必须固定 reason 失败且旧行逐字节不变。

### P1-02：Outbox `no_delete` 仍可被 REPLACE 绕过

静态反例：已有合法 pending Outbox 后，以新的 `delivery_id/idempotency_key/reconcile_key`、同一 `publication_id` 和合法 pending/attempt0/空 lease Envelope 执行 `INSERT OR REPLACE`。新行通过当前 initial guard；`publication_id UNIQUE` 冲突可删除旧 Outbox，从而产生第二投递身份。

最小修正：

1. Outbox BEFORE INSERT 显式拒绝与现存 `delivery_id/publication_id/idempotency_key/reconcile_key/(generation,manifest hash)` 任一唯一身份冲突。
2. Repository 只允许 plain INSERT；连接级 recursive trigger 仅作第二层防御。
3. 聚焦负例必须证明 REPLACE 后旧 delivery、key、Envelope、attempt 与时间全部零漂移。

### P1-03：AuditEvent 仍可替换或以非最大序号分叉

静态反例 A：用现有 `event_id` 执行 `INSERT OR REPLACE`，让新 payload 的 `previous_event_hash` 指向替换前当前 max hash。BEFORE predecessor guard 可通过；隐式删除旧事件后，新事件指向已经不存在的 hash。

静态反例 B：首条事件显式使用较高 `audit_seq`；第二条显式使用较低但空闲的 `audit_seq`，previous 正确指向首条 hash。当前 predecessor guard 只校验 parent，不校验新行必须成为最大 audit_seq，所以第二条插入后最大事件仍是首条；下一事件继续引用首条，形成两个子节点。

最小修正：

1. Audit BEFORE INSERT 显式拒绝与现存 `audit_seq/event_id/event_hash` 冲突，封住 REPLACE。
2. 增加可在 SQLite 中可靠工作的 latest-sequence guard：插入完成后 `NEW.audit_seq` 必须等于全表 `MAX(audit_seq)`；不要求连续，但禁止任何非最新序号插入。该 guard 抛错时整条 INSERT 回滚。
3. Repository 不允许客户端或调用者提供 `audit_seq`，只让 SQLite 生成；同一 `BEGIN IMMEDIATE` 读取当前最大事件、build、plain INSERT、读后 verify。
4. 聚焦负例覆盖同 eventId REPLACE、同 eventHash REPLACE、先显式高序号再插低序号、旧 parent 并发插入；全部失败且原链逐行不变。
