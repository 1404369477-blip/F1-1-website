# VS-RSS-0 离线恶意样本与原因码向量包报告

## 结论

**FAIL：P0=0、P1=1、P2=0。** 包结构可供合同讨论和开发预读，四个未决原因码闭合前禁止把它作为可执行生产期望。本轮没有任何网络、DNS、TLS、外部来源、Base、provider 或真实 Source 操作。

## 产出与已验证

- `manifest.json`：包状态、哈希、结构校验命令与四个阻断。
- `vectors.json`：46 个注入式/描述性向量，覆盖精确 URL、DNS 公私混合、IPv4-mapped IPv6、3xx、TLS、3/5/10s 超时、MIME/content-encoding、1 MiB、DTD/XInclude、10000 nodes、depth 32、16384 UTF-8 bytes、20 items、identity missing/collision、schema/unknown semantics/fence、原子事务、日志和公开出口。
- `minimal-valid.xml`：唯一小型 synthetic XML；超大、超深和高节点样本只保留生成规则元数据，未生成资源耗尽文件。
- `validate.py`：离线自校验返回 `STRUCTURE_OK_WITH_BLOCKERS`，确认 46 个 ID 唯一、10/10 合同覆盖、所有已定义拒绝例均为完整响应拒绝/`cursor_advanced=false`/`data_retained=false`，且未决例有显式 blocker。
- 三个产物 SHA-256 已写入 manifest 并本地复算一致。

## P1 阻断

draft §6 对下列拒绝行为给出了精确政策，但固定 reason-code 集合无法唯一映射：

1. `items=21` 超过 20-item 上限。
2. observation 已提交、inbox intent 未提交的部分事务失败。
3. 日志出现 title/stack 等禁止字段。
4. 产生 Publication/PublishedProjection 或放宽第三方 `img-src` 的出口违规。

按任务失败路径，安全部没有自行新增生产 reason code，四个向量以 `primary_reason_code=null + blocking_conflict` 封闭。产品部需在 draft 中为四类失败各冻结一个主 reason code；修订后再生成可消费向量包。
