# fresh Next 三项重复空目录只读安全裁定

## 1. 裁定

**PASS；P0=0，P1=0，P2=1。**

三个精确路径的裁定均为 **delete**：

1. `app/.next/server/app 2`：DELETE；
2. `app/.next/server/chunks 2`：DELETE；
3. `app/.next/static/chunks 2`：DELETE。

删除必须由后继受控任务完成；本轮严格只读，未执行 `rmdir`、builder、build、测试、Git、SSH 或任何修改。

删除三项后 **不需要重新 production build**。只允许重新执行 builder 一次，因为 production build 已 PASS，三项均为无文件字节、无symlink、无特殊对象的重复空目录；精确 `rmdir` 只修正 builder 遍历边界，不改变 Next 生产文件闭包。

## 2. 生产 normalize / nextBuild 语义

### `inspectNextBuild()` / `normalizeAdminNextBuildPermissions()`

`inspectNextBuild()` 递归收集 `.next` 下的每一个目录和文件。对目录要求：

- non-symlink；
- uid = 当前用户；
- realpath exact；
- mode 仅可为 0700 或 0755。

因此 `server/app 2` 的 0700 本身是 fresh-build 允许输入，不是当前首错。`normalizeAdminNextBuildPermissions()` 会打开它，核对 dev/ino/uid/对象类型，然后将所有目录归一化为 0755。

### `nextBuild()`

`nextBuild()` 要求每个目录都已为 0755，并遍历全树；但 manifest 的 `nextBuild.files` 只记录 regular files 的 path/mode/size/SHA-256，不记录目录条目。

这导致一个关键边界：

- 空目录的存在与否不改变 `nextBuild.files`、`totalBytes` 或 `contentRootSha256`；
- 但它会被 builder 遍历、归一权限，并可作为目标 stage 中 manifest 未显式表达的多余容器。

因此只删 0700 的 `server/app 2` 并不更稳妥。剩余两个 0755 重复空目录会继续通过 normalize/nextBuild，且不进 manifest 文件根。三者具有相同语义：同名fresh-build目录的带空格数字副本，当前空且不被任何闭包文件引用。

## 3. 删除前精确身份谓词

后继必须按每一个路径独立重验以下全部谓词，任一失败即整体停止，不删其他两项：

1. 输入路径必须逐字节等于上述三个白名单之一；
2. 必须位于精确 `.next` real root 内，relative path 不含 `..` 且不是绝对路径；
3. `lstat` 必须是 real directory，禁止 symlink；
4. `realpath(path) === path`；
5. uid 必须为 501，gid 必须为 20；
6. dev 必须与 `.next` root 相同；
7. nlink 必须为 2；
8. size 必须为 64；
9. entry count 必须为 0，包括 hidden entry；
10. mode：`server/app 2` 只接受 0700；另两项只接受 0755；
11. 不得存在 ACL、file flags、extended attributes 或 mount point 异常；
12. 紧邻 `rmdir` 前使用 descriptor/目录身份重核 dev/ino/uid/type/empty，防止验证后替换。

一旦任一目录非空、身份或权限与固定值不同，不得改用 recursive delete，不得修正权限或删内容，也不得继续处理其他目录。

## 4. 后继执行原语

只允许对三个精确路径各执行一次 non-recursive `rmdir`，顺序建议：

1. `app/.next/server/app 2`；
2. `app/.next/server/chunks 2`；
3. `app/.next/static/chunks 2`。

任一 `rmdir` 返回非零立即停止；不重试、不改用 `rm -r`、不更改顺序、不继续 builder。三项全部成功后，只读确认三路径均 absent，并确认三个对应正常同名目录仍存在、非空且身份没有变化。

## 5. Builder 重试边界

三项精确 `rmdir` 完成后：

- 不重build；
- 重新只读核对 89 runtime 仍为 clean HEAD/blob等值；
- 只允许 builder 再执行一次；
- builder 必须使用原 production build 的其他 `.next` 字节，不得修改 runtime 或依赖；
- 新 manifest 必须记录 runtime=89、M1 target Node、fresh Next file count/bytes/root、package count/root、content/release roots；
- manifest 必须 uid501/mode0600/nlink1/realpath exact，并形成新外部 SHA；
- builder 任一首错不得继续 harness、delta、传输、prepare 或 M1。

新 Next file root 理论上应与删除前相同，因为三项没有文件记录。但不得把这一推理写成预先已验证的 root；只以重跑 builder 的实际收据为准。

## 6. P0 / P1 / P2

### P0

0。现有证据显示三项均为空目录，无文件、symlink、特殊对象或多链文件。

### P1

0。在严格身份谓词 + non-recursive `rmdir` + 首错停止边界下，删除三个重复空目录不会删除 production Next 文件字节，不要求重build。

### P2-01：Next manifest 不记录空目录集合

`nextBuild.files` 只对文件建根，空目录的存在与否不进 content root。本次正因该语义可以不重build地精确清理；长期也意味着target verifier 无法仅靠 manifest 区分“没有多余空目录”。

后续可选加固：对 `.next` 目录集合也记录 canonical path/mode，或在 stage 验证时拒绝任何不是闭包文件父链所必需的空目录。该加固不阻断当前精确清理。

## 7. 失败路径

- 任一路径不存在：停止，不推导为已由本任务清理；
- 任一路径非空：停止，禁止删除；
- symlink、realpath、uid/gid、dev、nlink、size、mode、ACL/flag/xattr 任一漂移：停止；
- descriptor 重核时 dev/ino/type/empty 改变：停止；
- 任一 `rmdir` 失败：停止，不重试、不 recursive delete、不跑 builder；
- 对应正常非空同名目录漂移：停止；
- builder 重跑首错：停止，不继续 harness/delta/传输。

## 8. 错题自检

- 没有把 0700 误当作 normalize 的非法 fresh-build 输入；生产逻辑明确允许 0700/0755 目录后归一 0755。
- 没有只处理导致当前首错的 `app 2`；三个目录的“重复+空+不进manifest”语义相同。
- 没有把历史两目录清理直接当作当前三项身份证据；后继仍要求逐项fresh重验。
- 没有要求重build，也没有预判 builder 重跑必然 PASS。
- 本轮没有执行删除、测试、build、builder、Git、SSH 或任何写操作。
