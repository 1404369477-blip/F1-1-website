## 5. P1 发现

### P1-01：`decision_hash_input` 与顶层 Decision/fence 可分裂后仍被接受

**独立复现**：在影子 fixture 中把第一条 `ReviewDecision.decision_hash_input.source_config_epoch` 从 1 改为 2，按受审核的 `canonical-json-v1` 重算 `decision_hash`，同时仅重算外层 fixture/manifest/ledger 收据以跳过文件包装检查。顶层 Decision、Bundle、Publication 和 payload fence 仍为 1。验证器退出 0 并输出 `result=PASS`。

**根因**：验证器只检查 `decision_hash == hash(decision_hash_input)`，没有从 Decision 顶层字段构建唯一 expected `decision_hash_input` 并逐字段比较。

**影响**：批准 hash 可对一套 fence 背书，而发布链校验另一套 fence，破坏五 fence 与批准链的唯一绑定。

**修复出口**：验证器必须从 `review_decision_id/release_bundle_id/approved_bundle_hash/review_version/decision/canonical_json_rule_version/五个fence` 顶层值构建 exact expected object，先验证整体相等，再重算 hash；增加 5 个 fence 逐一分裂的负向用例。

### P1-02：manifest/profile 的关键安全语义没有被验证器封闭校验

在重算相关 artifact/manifest/ledger 外层 hash 后，以下影子副本均退出 0 并输出 PASS：

1. `manifest.external_calls: 0 → 1`；
2. `profile-boundary.profiles.public-synthetic.sqlite_path → /tmp/public.sqlite`；
3. `profile-boundary.profiles.public-synthetic.source_id_allowlist → [一个M3真实source_id]`；
4. 从 `profile-boundary.forbidden` 删除 `ATTACH m3-shadow`。

对照探针中，`profile-ledger.external_calls: 0 → 1` 会被 schema const 拒绝，`process_rules.sqlite_attach_allowed: false → true` 会被 exact rule 拒绝。这说明现有保护是局部的，没有对 manifest/profile 全部安全语义形成封闭绑定。

**影响**：一个形式上自洽的包可以声明允许外联、改写 DB 路径、把 `public-synthetic` allowlist 指向 M3 Source，或移除 attach 禁止项，却仍被当前 validator 接受。

**修复出口**：

- 对 manifest 的 `synthetic_only=true/external_calls=0/writes_to_base=false/real_content_imported=false/source_id=src-active/source_delta=0/counts/contract/fixture_set` 逐项 exact 校验；
- 对 profile 两侧的 ID、精确相对路径、contract、count、field count、allowlist、source canonical hash、public graph count 做封闭 schema 和 exact 校验；
- 将 `profile-boundary.public-synthetic.sqlite_path` 与 ledger path 逐字一致绑定；
- `forbidden` 与 `import_preconditions` 不能只检查数量，应使用封闭 reason-code/enum 或 exact canonical object。

### P1-03：DTO 映射只校验 key set，映射值改指内部 URL 后仍 PASS

**独立复现**：在影子副本中保持 `feed_item` key set 不变，把 `publicId` 的映射值改为 `ReleaseBundle.canonical_payload.original_url`，然后重算 artifact/manifest/ledger 包装 hash。验证器退出 0 并输出 PASS。

**根因**：`verify_artifacts()` 只检查 DTO 映射的字段名集合，没有检查每个字段允许的唯一来源/派生规则。

**影响**：后续 Repository/API 若消费该机器映射，可将 original/canonical/evidence URL、hash/fence/reviewer/raw/internal 字段重定向到看似合法的公开 key。

**修复出口**：把自然语言 mapping value 改为封闭、机器可验证的 `{kind, owner, json_pointer, transform}` 枚举；验证器对整个 mapping 与 accepted allowlist exact 比对；增加所有 URL、hash、fence、reviewer、raw/internal/private 指针的负向用例。

### P1-04：生成器跟随已有输出符号链接，可越界覆写任意可写文件

**独立复现**：在完整影子副本中，把输出 `schema.json` 替换为指向副本项目目录外 sentinel 的符号链接。运行生成器后：

- 进程退出 0，输出 `result=GENERATED`；
- sentinel 从内容 `SAFE` 被覆写为 81,884 bytes 的 schema JSON；
- 生成器没有拒绝或警告。

**根因**：`write_json()` 直接对固定输出路径调用 `Path.write_bytes()`，写入前没有 `lstat`、symlink 拒绝或 no-follow/原子替换。

**影响**：运行本地生成器可覆写项目目录外的任意用户可写文件，与本任务明确的“不越界写”门禁冲突。

**修复出口**：对输出父目录和每个目标先执行边界/lstat 检查，任一 symlink、非 regular file 或越界 resolve 立即拒绝；将内容写入同目录新建临时 regular file，`fsync` 后用原子 replace 替换目标，并用符号链接负向用例回归。

## 6. P2 发现

### P2-01：8 项收据的运行时 root-of-trust 尚未定义

manifest 因避免递归不包含自己和 ledger，ledger 反向绑定 manifest。当 artifact、manifest 和 ledger 同步被重算时，当前 standalone validator 没有第三个不可同步修改的信任锚。本报告的 8 项 SHA 只是独立审查收据，不是已实现的启动防护。

开发接线时应在受审核代码/只读配置中固定 accepted contract root（至少固定 manifest 和 ledger 字节 SHA，并绑定 validator/generator 版本）。启动不能只依赖包内互相引用的 hash。
