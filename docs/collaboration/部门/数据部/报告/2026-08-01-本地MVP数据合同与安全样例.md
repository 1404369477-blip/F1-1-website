## 3. 最少实体模型

| 实体 | 责任 | 关键边界 |
|---|---|---|
| `Source` | 信源配置、启停、授权、epoch 和 M3 迁移字段 | 保留 `unknown/pending/proposed/false/null`；不凭分类推断身份 |
| `CapturedItem` | 手机/采集候选、规范化和查重处理 | 原始输入与处理状态分开；失败保留原始 URL |
| `Content` | 外部内容标识、内容版本、规范化内容和来源证据 | 版本 hash 不可变；同一版本只能产生一个摄取事实 |
| `Event` | 跨内容事件聚合和去重指纹 | canonical 内容与成员列表可追溯，重复不公开 |
| `Summary` | 中文整理版本 | 每次编辑递增版本并重算 hash |
| `MediaCandidate` | 图片候选、授权与安全状态 | 合成样例只使用 `synthetic:` 资源引用 |
| `Review` | 人工审核决定与批准 hash | 批准绑定内容/摘要当前版本，旧批准不可覆盖新版本 |
| `Publication` | 公开发布状态、尝试次数和版本绑定 | 发布只接受当前批准 hash 对；重试复用同一 key |
| `OutboxJob` | 事务 outbox 与异步任务状态 | 操作 key 不变；epoch 过期任务停止，不更新当前结果 |

审计字段统一为 `created_at`、`updated_at`、`created_by_ref`、`updated_by_ref`。fixture 中 actor 仅使用 `synthetic:*` 引用。

- 主信源表字段数量：33；手机捕获表字段数量：9；映射文件逐项保持 M3 字段名、方向和原值。

- 本地新增的 `source_config_epoch`、审计字段、`Content` 版本和审核/发布字段不反写 M3 或 Base。
- `migration_batch_id` 继续用于迁移追踪；批次内 URL 唯一性不等同于平台稳定账号 ID 或跨批次查重完成。
- accepted A→D 路线只提供“Base 是唯一业务真值、D 只能单向生成只读快照、切换需独立门禁”的跨阶段约束；本任务没有把 ADR 之外的 proposed 字段、阈值或工具选择升级为 accepted。

## 5. 状态、幂等与安全不变量

### 状态转换

- 信源：`validating → activation_pending → queued → collecting → active`；规范化、重复归属、授权、平台和队列失败分别进入明确阻断状态。
- 捕获：`pending → valid | invalid | needs_review`；invalid 保留 `raw_url`，不生成 Content。
- 内容：`captured → normalized → dedup_pending → review_pending → approved/rejected → publish_queued → published/failed`。
- 审核：`pending → changes_requested/approved/rejected`；内容或摘要版本变化后旧批准进入 `superseded`。
- 发布：`queued → publishing → published/retryable_failed/terminal_failed/blocked`。
- 任务：`pending → leased → succeeded/retryable_failed/terminal_failed/stale_epoch`。

### 幂等键

- 信源激活：`onboarding_operation_id`；重试复用同一操作，不生成第二个激活任务。
- 内容摄取：`platform + source_id + external_content_id + content_version_hash`；同一版本只产生一条内容事实。
- 去重：`dedup_fingerprint`；重复内容复用 canonical Event，成员追加幂等。
- 发布：`publication_id + approved_content_version_hash + approved_summary_version_hash`；重试保持同一批准版本和 key。
- 快照同步：`source_config_epoch + snapshot_manifest_hash`；不完整快照不能替换 last-known-good。

### 强制不变量

1. Base 是 A/D 唯一业务真值；本地合同、快照、Collector 和运行遥测不反写或裁决 Base。
2. M3 的 `unknown`、`pending`、`proposed`、`false`、`null` 在独立验证前保持原值。
3. `source_config_epoch` 不匹配时，任务不得调用 provider 或更新当前结果。
4. 重试复用不可变幂等键，不产生重复内容、任务或发布记录。
5. 公开发布要求 Review 批准的内容 hash、摘要 hash 与当前版本完全相等。
6. 内容或摘要编辑会产生新版本，旧批准失效并回到人工审核。
7. 临时发布错误可以重试同一版本；永久错误或安全停止进入终态，不自动换版本。
8. 空、残缺、无效或过期快照保留 last-known-good，并产生新鲜度告警。
9. 合同与合成 fixture 不保存凭证、个人标识、真实帖子正文或未授权媒体。

## 6. 合成失败样例

| 案例 | 触发 | 期望行为 |
|---|---|---|
| `case-source-seed` | M3 影子 Source 种子 | 保持 `enabled=false` 和 `identity_status=unknown` |
| `case-capture-normalization` | canonical URL 规范化失败 | 保留 raw URL，进入 invalid，不生成 Content |
| `case-duplicate-ingest` | dedup fingerprint 命中 | 复用 canonical Event，不公开重复内容 |
| `case-idempotent-retry` | 激活任务重试 | 复用同一 operation key，不创建第二任务 |
| `case-stale-review` | 当前版本 hash 与批准 hash 不同 | 阻断发布，要求新的审核版本 |
| `case-publish-retry` | 临时上游发布错误 | 同一批准版本、同一 key 重试，递增 attempt |
| `case-stale-epoch` | job epoch 早于当前配置 epoch | 停止，不调用 provider，不更新结果 |
| `case-snapshot-failure` | 快照部分或空响应 | 保留 last-known-good，标记新鲜度风险 |

## 7. 已验证 / 未验证

### 已验证

- schema、映射、状态机、fixture、manifest 均可被标准 JSON 解析。
- 自定义机械校验通过：实体 required/properties、枚举、类型、格式、正则、数组唯一性和追加字段限制均通过。
- 33/9 Base 映射逐项等于 M3 字段合同；8 个 fixture case 全部有可解析引用和预期结果。
- 关系校验通过：Content→Source/CapturedItem、Event→Content、Summary/Review/Publication→Content 等引用闭合。
- 审核 hash 过期案例能被识别；发布重试案例保留批准 hash；epoch 过期任务被识别为停止条件。
- 生成内容只含合成文本、`synthetic.invalid` URL 和 `synthetic:` 资源引用；敏感标记扫描为 0。
- 没有访问或修改飞书，没有切 Base 真值，没有真实内容导入，没有写 `app/` 业务实现。

### 未验证

- 真实数据库或飞书 Base 对 JSON Schema 的平台级落地行为。
- Collector、同步器、人工审核服务和发布服务的真实运行时故障演练。
- 外部平台授权、API 限流、媒体授权和生产数据规模下的性能。
- A/D provider 切换门禁及用户后续确认。
