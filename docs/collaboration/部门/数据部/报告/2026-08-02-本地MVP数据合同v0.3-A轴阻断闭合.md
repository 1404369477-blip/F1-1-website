## 3. 第二轮 P0/P1 修正闭合

### 3.1 状态、身份与恢复

- `state_machines` 收敛为 6 组：`source_onboarding`、`capture_normalization`、`content_lifecycle`、`review_decision`、`publication`、`outbox_job`。`lifecycle_status` 的 proposed/active/paused/retired 规则嵌入信源合同；paused 不进入 onboarding 枚举。
- `validating → activation_pending` 严格要求 `canonical_url_valid=true`、`normalization_status=valid`、`dedup_status=unique`。
- blocked 优先级固定为 `platform > authorization > adapter`，每个 blocked 分支均回到门禁复核路径。
- `normalization_failed`、`dedup_needs_review`、`queue_failed`、`collection_failed`、`stopped`、`cancelled`、`dead_letter` 均有恢复或人工重排路径；queued/collecting 的 stop/cancel 统一使用 `source_stop_status`，恢复 guard 重验三门和五 fence。
- publication 增加 `blocked → queued`；retryable/reconcile 出口保留批准 hash、idempotency key、reconcile key 和五 fence。
- 激活 fixture receipt 将 `Source.onboarding_operation_id`、`OutboxJob.operation_id`、`TaskEnvelope.operation_id`、task/job/key 绑定在同一事务证据中；`enabled=false → true` 与 `queued` 同时发生。
- TaskEnvelope 由完整 `job_id` 派生 `task_id`、lease 和 payload hash。11 个 envelope 的 `task_id`、`lease_token`、`payload_hash` 全局唯一；此前 `*-001`、`*-retry` 后缀碰撞已消除。

### 3.2 Publication、Bundle 与可重建 hash

- 同一 `(release_bundle_id, approved_bundle_hash)` 只保留一个 Publication、一个 `public_id` 和一个 generation；3 个 published projection 均为只读派生。
- Publication、publish Outbox、TaskEnvelope 逐字复用 `Publication.idempotency_key`；publish/reconcile envelope 的 `reconcile_key` 与同一 Publication 逐字一致，其他任务为 null。
- `content_version_hash` 仍只从 `content_hash_input` 重算。Release canonical payload 新增严格的 `content_snapshot`：hash input 加 `content_version_hash`、`capture_id`、`external_url`、`published_at`、`captured_at`；payload 根同时显式冻结 `content_version_hash`。
- `summary_version_hash` 仍只从 `summary_hash_input` 重算。`summary_snapshot` 加 `summary_version_hash`，payload 根同时显式冻结 `summary_version_hash`。
- 每个 Bundle 的 `payload_hash=SHA-256(canonical-json-v1(canonical_payload))`，`bundle_hash` 从明确的 `bundle_hash_input` 重算；ReviewDecision 的 `decision_hash` 和 `approved_bundle_hash` 与 Bundle 绑定。
- 四个 reconcile outcome case 独立覆盖 confirmed published、confirmed not submitted、terminal failed、emergency stopped；snapshot failure 使用 `job-snapshot-partial`，stale epoch 使用独立 `job-content-stale`，job ID、operation type、operation ID、idempotency key 均不共享。

### 3.3 Internal 合同和映射边界

- `SourceObservation` 保留 `source_config_epoch`、`source_safety_epoch` 两个 observation epoch，并补齐可空 `published_at`、`operation_id`、`idempotency_key`；没有引入 observation 的 authorization/policy/recovery 三个额外 epoch。
- `AuditEvent` 使用产品候选命名 `event_id`、`occurred_at`、`owner`、`cleanup_after`、`retention`，并保留 monotonic sequence、clock status、trace/session hash、reason、operation/task、五 epoch、attempt、payload/fixture/schema hash、redaction 和 append-only。
- 每条 AuditEvent 的 `schema_hash` 等于当前 `internal-contract.schema.json` 文件 SHA-256；生成器在写入前由同一序列化字节计算，写入后再次校验。
- `internal_only_entities` 只有 `SourceObservation`、`AuditEvent`；`SummaryDraft` 通过 `summary_draft_mapping` 映射为领域 `Summary(summary_status=draft)`，不产生独立领域实体。
- `Source`、`CapturedItem` 只在 `base_mapped_entities` 中出现；`domain_only_entities` 仅列本地领域对象。ActivationTransaction 明确标记为 `fixture_receipt`，未进入 schema `$defs`。

### 3.4 Canonical JSON、lease 与窗口

项目规则固定为 `canonical-json-v1`：UTF-8、Unicode code-point 键序、紧凑逗号/冒号、显式 null、不做 NFC/NFD 归一化、有限 JSON 数值、`ensure_ascii=false`、SHA-256；代码同时以 `allow_nan=false` 拒绝 NaN/Infinity。规则明确声明为项目自定义规则，不使用 `jcs-v1` 或 RFC 8785 JCS 名称。

`state-machine.json.runtime_fence.required_fields` 已包含 `reconcile_key`；`max_task_window_seconds=900` 同时写入 state machine、manifest 并由 `validate_semantics()` 断言。合成 envelope 均满足 `now < lease_expiry <= deadline <= now+900s`，epoch0 只作为安全拒绝输入，所有有效 envelope epoch 从 1 起。
