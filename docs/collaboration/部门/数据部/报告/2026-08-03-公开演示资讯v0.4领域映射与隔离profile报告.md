## 3. v0.4 字段与 hash 所有权

### 3.1 Content

在 v0.3 Content 之上新增：

| 字段 | 约束 | hash |
|---|---|---|
| `editorial_category` | `race_news / driver_social / legends_history / paddock_fun` | 进入 `content_hash_input` |
| `source_time_status` | `known / unknown` | 进入 `content_hash_input` |
| `published_at` | `known` 时 RFC3339 UTC，`unknown` 时 null | v0.4 明确进入 `content_hash_input` |

本次 12 条全部为 `known`。原 UI 的“本地演示时间”按 Asia/Shanghai 转为 UTC，例如 `2026-08-02 09:40` 映射为 `2026-08-02T01:40:00Z`，没有把显示文本作为数据库时间值。

### 3.2 Summary

新增并进入 `summary_hash_input`：

- `lead_zh`：1–400 字符；
- `body_zh`：1–8 段，每段 1–1200 字符；
- `key_points_zh`：1–8 条，每条 1–240 字符，数组内唯一。

UI 的 `title/summary/lead/body/keyPoints` 逐字段转移。转换未采用按句号切分、按标题猜测分类或其它启发式规则。输入 TypeScript 文件 hash 固定为 `e6a8fb65374ec71722f8cf0c3234dfdef4ea8df691991d3f6615fdbf6de9881b`；该文件漂移时生成器直接拒绝运行，要求重新审阅转移。

### 3.3 ReleaseBundle canonical payload

`source_snapshot` 新增：

- `display_name = 本地合成演示资料`；
- `byline = F1+1 演示编辑台`。

新增三个不可变 snapshot：

1. `access_snapshot`：内容访问状态、原链状态、稳定原因码；
2. `time_snapshot`：源发布时间和 `known/unknown`；
3. `media_presentation`：M4 只生成 `synthetic_placeholder` 或 `none`，`image` 仍关闭。

10 条具有 `MediaCandidate`，`practice-notebook` 与 `circuit-map` 两条为无媒体状态。`training-lap` 与 `radio-mixup` 两条为 restricted；受限状态优先于媒体状态。派生结果机械验证为：available 8、restricted 2、media_missing 2。

### 3.4 hash 链

每条记录均机械复算并绑定：

```text
Content.content_hash_input
  → content_version_hash
Summary.summary_hash_input + input_content_hash
  → summary_version_hash
ReleaseBundle.canonical_payload
  → payload_hash
ReleaseBundle.bundle_hash_input
  → bundle_hash
ReviewDecision.decision_hash_input
  → decision_hash
approved_bundle_hash == bundle_hash
Publication approved content/summary/bundle hashes
  → published_version_hash identity
PublishedProjection published_version_hash == Publication published_version_hash
```

Bundle、Decision、Publication 和 payload fences 的五个 epoch 均逐字段一致且为 1。没有跳过人工审核对象，没有用 UI 对象直接生成 PublishedProjection。

## 5. 双 profile / 双 SQLite 边界

| 边界 | `m3-shadow` | `public-synthetic` |
|---|---|---|
| SQLite 路径 | `app/.local/f1plus1.sqlite` | `app/.local/f1plus1-public-synthetic.sqlite` |
| 合同 | frozen `mvp-local-v0.3` | successor candidate `mvp-local-v0.4` |
| Source | 59×39，全部 disabled | 1 个 frozen `src-active` |
| 公开图 | 0 | 12 |
| 外部 I/O | 0 | 0 |

运行与导入规则：

- 一个进程必须显式选择一个 profile；不允许隐式默认；
- 两个 SQLite 路径必须不同且为本地 regular file；
- 禁止 SQLite `ATTACH` 另一个 profile；
- 禁止跨 profile copy 和合并 Source 表；
- 禁止把 59 行与 `src-active` 组成 60 行；
- 禁止生成 `public_story` 表、Base write、真实 provider/platform I/O 或静态 runtime fallback。

后续开发部导入前必须满足：

1. 选择的 profile 精确为 `public-synthetic`；
2. DB 路径精确为 `app/.local/f1plus1-public-synthetic.sqlite`；
3. manifest 与 ledger hash 在 `BEGIN IMMEDIATE` 前验证通过；
4. Source 精确等于 frozen `src-active`，且库中没有任一 M3 59 行 source_id；
5. 12 套 required/enum/FK/hash/fence/approval/projection 不变量全部通过；
6. ledger + Source + 12 套图在一个 seed 事务中全部写入或全部回滚；
7. capability flags 精确为 synthetic only、零外联、零 Base write、零真实内容。

本任务没有创建第二个 SQLite 文件。本文和机器包只定义后续开发 migration/seed 的唯一输入与拒绝条件。

## 8. 未验证与后续门禁

- v0.4 仍是 successor 数据候选，尚未经过安全部/测试部独立静态审查和统筹核收；
- 产品部负责的 accepted successor ADR 与 Spec 指针不在本任务文件边界；
- SQLite migration/table/index/ledger、事务 seed、Repository、projection-first verifier、API、cursor、Problem JSON 和前端接线尚未由开发部实现；
- 双 SQLite 的不同 inode、禁止 attach、启动 profile allowlist、DB busy、损坏行 fail-closed、seed rollback 和重启幂等要在实现后验证；
- 本包只表达 synthetic 演示数据，不证明真实 Source、平台采集、真实审核人员、真实媒体/原链、AI、部署或自动发布可用；
- `src-active` 是 frozen synthetic Source，其 `platform=x` 只服务既有合同样例，不代表任何真实 X 账号或真实平台调用。

## 9. 失败路径与回退

1. 任一 v0.3 artifact、59×39 count/hash 或 `src-active` 原值漂移：生成/验证立即失败，停止导入，不修改旧文件。
2. 任一 v0.4 required/enum/FK/hash/snapshot/fence/批准链不一致：整包 fail closed，不生成部分公开读模型，不回退到 UI 静态第二真值。
3. 两 profile 路径相同、发生 attach/混行/跨库 copy 或出现第 60 个 M3 Source：停止启动和 seed，保留旧 M3 DB 不动。
4. SQLite/API 接线失败：回退整个应用版本与对应 public-synthetic DB，不执行 down migration，不从 public DB 反写 M3/Base。
