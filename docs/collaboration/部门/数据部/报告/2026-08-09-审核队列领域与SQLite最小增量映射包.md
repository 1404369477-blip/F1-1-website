# 审核队列领域与 SQLite 最小增量映射包

## 1. 单一结论

推荐 `review-synthetic` 第三个物理 SQLite profile，并使用 profile 专属的 `0003_review_synthetic_workflow.sql`。它复用冻结 v0.3 的 Source、CapturedItem、Content、Summary、MediaCandidate、ReleaseBundle、ReviewDecision、Publication、OutboxJob、PublishedProjection，以及 internal-only AuditEvent；不新增领域实体，不建立第二套领域 schema。

当前实现存在 P1 successor 门禁：Spec 和 runtime 只接受 `m3-shadow`、`public-synthetic` 两个 profile；现有 migration 也没有 OutboxJob、TaskEnvelope 持久化与 AuditEvent。产品接受 profile successor、通用 `published_version_hash` 规则和 profile-scoped migration root 前，开发不得实施审核写入。

选择独立 profile 的原因是现有两个 profile 都有 fail-closed 精确集合约束：

- `m3-shadow` 要求所有 public graph 表为空；加入审核记录会触发 `PROFILE_GRAPH_MIX`。
- `public-synthetic` 每次读取都要求 Source/CapturedItem/Content/Summary/Media/Bundle/Decision/Publication/Projection 精确为 `1/12/12/12/10/12/12/12/12`，并逐表比较全部 stored payload；增加一条待审核记录即触发 `PUBLIC_SEED_DRIFT`。
- 0003 的 SQL CHECK 只允许 Content=published、Summary=approved、Media=selected、Bundle=approved、Decision=approved、Publication=published、Projection=published。

在同一 `public-synthetic` DB 中追加待审核行会破坏已 ACK 公开读门禁；在同库另建同义 review 表会形成第二 schema。独立物理 profile 是当前最小、可回退且不会污染 12 条公开快照的选择。

## 3. profile 与 migration 选择

### 3.1 推荐形态

- 新物理文件：`app/.local/f1plus1-review-synthetic.sqlite`。
- 新 profile ID：`review-synthetic`。
- migration root：复用 0001 foundation、0002 Source DDL；第三步使用 profile-scoped `0003_review_synthetic_workflow.sql`，不运行 `0003_public_synthetic_profile.sql`。
- fixture profile：只允许 synthetic review cases；`external_calls=0`、`writes_to_base=0`、`real_content_imported=0`、`PUBLISH_MODE=manual_only`。
- 每个进程仍只打开一个 profile；禁止 ATTACH、跨库事务和从 review DB 反写 public-synthetic。

该选择需要 accepted successor，因为当前 Spec 和 `AppConfig.dataProfile` 只有两个 profile，migration reader 也只有一个公共 root。开发任务必须实现 profile-scoped migration root、独立 ledger/root pin 和启动拒绝逻辑，不能用环境变量绕过现有 allowlist。

### 3.2 禁止方案

- 不在 `public-synthetic` 现有表追加待审核行。
- 不在 `public-synthetic` 建 `review_*` 同义表。
- 不把审核队列塞入 payload_json 而绕过列约束。
- 不把 `m3-shadow` 当审核数据库。
- 不修改或重生成 v0.3/v0.4 frozen data、12 条 public-demo 投影、manifest、ledger 或 root pins。

## 4. profile 专属 0003 的 DDL 约束

表名继续沿用现有实体映射；物理 DB 已隔离，因此不增加实体前缀。

### 4.1 Content / Summary / Media

1. `public_content`
   - PK `content_id`；FK Source/CapturedItem。
   - `UNIQUE(content_version_hash)`；`UNIQUE(source_id,external_content_id,content_version_hash)` 由 repository 与索引共同保证。
   - `content_status` 使用冻结九值 enum。
   - `published_at` 可 null；不得用 capture time 补值。
2. `public_summary`
   - PK `summary_id`；FK `content_id`。
   - `UNIQUE(content_id,summary_version)`、`UNIQUE(summary_version_hash)`；移除 `content_id UNIQUE`。
   - `summary_status` 使用 draft/ready/approved/rejected/superseded。
   - 草稿就是 Summary(draft)，禁止 SummaryDraft 表。
3. `public_media_candidate`
   - PK `media_candidate_id`；FK `content_id`。
   - `UNIQUE(content_id,media_hash)`；允许同 Content 多候选。
   - candidate_status=pending/selected/rejected；license_status 与 safety_status 继续使用冻结 enum。
   - 未通过权利与安全时不得 selected；无图不创建占位业务行。

### 4.2 Bundle / Decision

1. `public_release_bundle`
   - PK `release_bundle_id`；FK Content/Summary。
   - `UNIQUE(content_id,summary_id,bundle_version)`、`UNIQUE(bundle_hash)`；移除 content/summary 单列 UNIQUE。
   - release_status=draft/ready/approved/superseded/rejected。
   - `immutable=1`；immutable 指 canonical payload、payload_hash、bundle_hash_input、bundle_hash 和五 fence 不可变。生命周期状态可 CAS 更新，hash 输入不得变化。
2. `public_review_decision`
   - PK `review_decision_id`；FK Content/Summary/Bundle。
   - `UNIQUE(release_bundle_id,review_version)`、`UNIQUE(decision_hash)`；移除 content/summary/bundle 单列 UNIQUE。
   - decision 使用冻结五值 enum。
   - approved_bundle_hash：approved/superseded 必须 64 hex；pending/changes_requested/rejected 必须 null。跨表等于当前 Bundle.bundle_hash 由同事务 repository 断言。
   - `immutable=1`；每次复审追加新 review_version。相同 `(bundle,review_version)` 重放时，decision_hash 相同返回既有记录；hash 不同 fail closed。

### 4.3 Publication / Projection / Outbox / Audit

1. `public_publication`
   - PK `publication_id`；`UNIQUE(release_bundle_id,approved_bundle_hash)`、`UNIQUE(public_id)`、`UNIQUE(idempotency_key)`、`UNIQUE(reconcile_key)`。
   - publication_status 使用冻结八值 enum；published_at 在 published 前可 null。
   - public_id、publish_generation、publication_id、两类 key 创建后不可变。
   - approved content/summary/bundle hashes 与五 fence 必须逐字冻结。
2. `published_projection`
   - 仅 projection_status=published；`UNIQUE(public_id)`、`UNIQUE(published_version_hash)`。
   - 只在 Publication 成功提交的同一事务插入；它是只读派生，不承担审核真值。
3. `outbox_job`
   - 精确覆盖 `schema.json#/$defs/OutboxJob` 20 required 字段。
   - PK job_id；`UNIQUE(operation_id,idempotency_key)`；Publication/Outbox/TaskEnvelope 的 publication idempotency_key 与 reconcile_key 必须逐字相等。
   - task_envelope 按 runtime envelope required、五 fence、lease、deadline≤now+900、payload_hash 机械校验。
4. `audit_event`（internal-only）
   - 精确覆盖 internal schema 25 required 字段；PK event_id、`UNIQUE(monotonic_seq)`。
   - append-only、redacted、retention/cleanup 明确；不保存 session 原文、CSRF、正文或凭证。

## 5. hash、fence 与幂等规则

### 5.1 保持既有规则

- Content、Summary、canonical payload、payload_hash、bundle_hash_input、bundle_hash、decision_hash 均按 `canonical-json-v1` 重算。
- Bundle 的冻结字段任一变化时创建新 bundle version/ID，旧批准转 superseded；不得更新旧 hash。
- ReviewDecision 的五 fence 必须等于 Bundle 与当前 runtime fence；批准 hash 必须等于当前 bundle_hash。
- Publication、OutboxJob、TaskEnvelope 复用同一个 publication idempotency_key；reconcile query 复用同一个 reconcile_key。
- stale/zero/missing fence、旧 lease、过期 deadline、hash drift、stop 或 emergency stop 均 fail closed。

### 5.2 需要 successor 接受的唯一 hash 缺口

冻结 schema 只规定 `published_version_hash` 为 64 hex，当前 public-synthetic 实现使用 synthetic 专用 label，没有通用人工发布公式。建议 successor 接受：

```json
{
  "approved_bundle_hash": "<bundle hash>",
  "approved_content_version_hash": "<content hash>",
  "approved_summary_version_hash": "<summary hash>",
  "public_id": "<stable public id>",
  "publish_generation": 1,
  "release_bundle_id": "<bundle id>"
}
```

`published_version_hash = SHA-256(canonical-json-v1(上述对象))`。

该公式未 accepted 前，开发不得沿用 synthetic label、ID 拼接或随机 hash；这是 P1 实施阻断。

## 6. 三个原子事务

### 6.1 审核批准

`BEGIN IMMEDIATE` 后依次：

1. 读取 review_pending Content、ready Summary、ready immutable Bundle 和当前五 fence。
2. 重算 Content/Summary/payload/bundle hashes；确认 Bundle 引用当前版本且无更高 review_version。
3. 构造 approved ReviewDecision，approved_bundle_hash=bundle_hash，重算 decision_hash。
4. INSERT ReviewDecision；CAS Summary ready→approved、Bundle ready→approved、Content review_pending→approved，每次要求 changes()=1。
5. append AuditEvent；COMMIT。

任一步失败整笔 rollback；不创建 Publication/Projection。

### 6.2 审核拒绝

同样先重算当前 hashes/fences；ReviewDecision.decision=rejected、approved_bundle_hash=null。INSERT immutable decision 后 CAS Summary ready→rejected、Bundle ready→rejected、Content review_pending→rejected，append AuditEvent 后提交。拒绝不创建 public_id、Publication、Outbox 或 Projection。

### 6.3 显式手动发布

分两个事务保持 lease 与失败恢复：

1. **enqueue transaction**：验证最新 Decision=approved、Content/Summary/Bundle 均 approved、approved hash/five fences/current session/Origin/CSRF/manual_only；为唯一 `(bundle,hash)` 插入 Publication(queued) 和 OutboxJob(pending)，TaskEnvelope/key/reconcile key逐字一致，CAS Content approved→publish_queued，append AuditEvent。
2. **completion transaction**：worker 持 fresh lease 与同 key，将 Publication CAS publishing→published，同时 CAS Content publish_queued→published并 INSERT PublishedProjection；published_at 和 successor published_version_hash 一次写定，append AuditEvent后提交。

重复 enqueue 命中同 `(bundle,hash)` 时：payload/hash/key 完全相同返回既有 Publication/Outbox；任何冲突 fail closed。未知结果进入同一 Publication 的 reconcile_wait，保留 public_id/generation/key，不创建第二 Publication。

## 7. fixture 形态

新 profile 使用独立 synthetic fixture 和 manifest，ID 前缀 `review-synth-*`，不得复用 `public-demo-*` 或 `src-active`：

1. `case-review-approve`：Content(review_pending)+Summary(ready)+Bundle(ready)，无 final Decision/Publication/Projection；预期批准事务生成一条 approved Decision。
2. `case-review-reject`：独立 Content/Summary/Bundle；预期 rejected Decision、无 public identity。
3. `case-manual-publish`：已 approved Content/Summary/Bundle/Decision，但无 Publication；预期 enqueue 后唯一 Publication/Outbox，completion 后唯一 Projection。

fixture 顶层固定 `synthetic_only=true`、`external_calls=0`、`writes_to_base=false`、`real_content_imported=false`。三个 case 使用不同 content/summary/bundle/decision/publication/job/operation/key，避免一条样本同时承担互斥路径。

## 8. 负例与失败出口

| 负例 | 必须出口 |
| --- | --- |
| bundle/payload/content/summary hash 漂移 | rollback；Decision 不落盘 |
| stale 任一 fence | rollback/CAS conflict；不批准、不拒绝、不发布 |
| 同 bundle/review_version 不同 decision_hash | fail closed，人工诊断 |
| rejected Decision 携带 approved_bundle_hash | schema/transaction reject |
| approved Decision hash 不等当前 bundle_hash | rollback |
| Publication 重放 key 相同、payload相同 | 返回既有 identity；不新增 Outbox/Projection |
| key 相同但 bundle/hash/public_id 不同 | idempotency conflict，fail closed |
| lease 过期、token/attempt 不匹配 | changes()=0；不写 published/Projection |
| publish outcome unknown | reconcile_wait；保持同 public_id/generation/key |
| Projection 先于 Publication published | FK/state guard reject |
| emergency stop/CSRF/session/origin/manual_only 任一失败 | 不入队或 emergency_stopped |
| AuditEvent append 失败 | 包含业务状态的事务整体 rollback |
| public-synthetic 任一 hash/count/byte 漂移 | 阻断 review profile 启动/发布，不修补旧 profile |
