## 3. v0.2 关键闭合项

### 信源门禁与状态可达

`activation_pending → queued` 和 `queued → collecting` 均要求同时满足：`adapter_status=ready`、`adapter_authorization_status=valid`、`platform_allowed=allowed`、`enabled=true`、停止状态清除且五个 epoch 匹配。缺少任一门禁分别可达 `blocked_adapter_missing`、`blocked_authorization`、`blocked_platform`。`linked_existing`、`stopped`、`cancelled`、`dead_letter`、`paused` 等状态均有转换入口或出口，并通过枚举可达性检查。

### ReleaseBundle、ReviewDecision 与公开身份

ReleaseBundle 带 `payload_hash`、`bundle_hash`、canonical JSON 规则版本、来源证据、五个 epoch 和 `immutable=true`。ReviewDecision 以 `approved_bundle_hash` 绑定不可变 Bundle，并保存独立 `decision_hash`。Publication 只接受相同批准 hash，保存稳定 `public_id`、`publish_generation`、`reconcile_key`、`reconcile_status` 和查询时间。

### 发布未知与对账

发布超时统一进入 `reconcile_wait`。查询沿用同一个 `reconcile_key`，可确认成功、确认未提交、终态失败或急停；确认成功时保持原 `public_id` 与 `publish_generation`，不会隐式生成第二个公开身份。主 fixture 提供 `publication-synth-reconcile` 及对应 outbox job。

### TaskEnvelope 与 stale epoch

TaskEnvelope 使用唯一字段名 `source_config_epoch`，并要求 `source_safety_epoch`、`authorization_version`、`policy_epoch`、`recovery_epoch`、lease、deadline、attempt 和 payload hash。stale fixture 使用可对账上下文：envelope 的 `source_config_epoch=1`，当前上下文 `current_source_config_epoch=2`；它在 provider 前被拒绝。快照失败单独使用 `job-synth-004` 及独立 idempotency key，`snapshot_reconciliation` 绑定该 job，保留 last-known-good manifest hash 和未提升的候选 hash；stale 的 `job-synth-008` 只验证 epoch 拒绝。

### Canonical JSON hash

项目规则命名为 `canonical-json-v1`。规则在 schema、state machine、fixture、security fixture 和 manifest 中显式记录：UTF-8 编码；键按 Unicode code-point 字典序；紧凑逗号/冒号分隔；保留显式 null；不做 NFC/NFD 归一化；仅接受有限 JSON 数值，避免 NaN、Infinity 和指数重写；对紧凑 UTF-8 字节执行 SHA-256。该规则明确标为项目自定义 canonical JSON，不宣称 RFC 8785 JCS。
