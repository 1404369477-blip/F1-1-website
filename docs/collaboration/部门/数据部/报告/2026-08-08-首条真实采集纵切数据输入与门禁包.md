### source_item

18 个输入字段逐项映射到既有合同：

- `source_id` 贯通 SourceObservation、CapturedItem、Content。
- `external_id` 贯通 SourceObservation 和 Content.external_content_id；优先使用非空 GUID/Atom ID，缺失时使用规范化 entry canonical URL，两者都缺失则拒绝。
- 主幂等键为 `SHA-256(UTF8(source_id + U+001F + external_id))`；同 external identity 的内容变化使用既有 Content version hash 产生新版本，不制造第二来源身份。
- `published_at` 缺失时保留 JSON null，`timestamp_confidence=unknown`；禁止用 `observed_at` 伪装发布时间。
- media 默认空数组、`rights_status=unknown`；不下载、不代理、不永久保存，不因 enclosure 存在推导许可。
- normalization/dedup 成功后，Content 最多进入 `review_pending`；不会生成 Publication 或 PublishedProjection。

## 4. 游标、错误与退避

游标是 adapter runtime receipt，通过 `SourceObservation.cursor_ref` 引用，不新增 Source/Base 字段。canonical receipt 包含 ETag、Last-Modified、last seen external ID、response hash 和 committed_at；只有在所有新 observation 与 inbox intent 成功提交的同一事务中才能推进。

以下情况均不推进游标：timeout、network error、429、5xx、invalid XML、partial parse、schema error、stale epoch、authorization/stop gate。

- network timeout / 5xx：60、300、900 秒有限退避。
- 429：遵守有效 Retry-After，并夹在 60–3600 秒。
- XML/parse failure：300、900、1800 秒；三次后 dead-letter + 人工检查。
- 401/403、authorization/platform/compliance stop：不自动重试，等待门禁变化。
- 每次重试重新读取 authorization、stop、Source 两个 epoch 与 TaskEnvelope fence。
- 304 只记录 poll health，不创建 SourceObservation，也不改变 `last_collected_at`。

## 5. 15 分钟指标

`discovery_latency_ms = observed_at - published_at`，目标为 `900000 ms`。只有 `published_at != null` 且 `timestamp_confidence` 为 `source` 或 `page_metadata` 的条目进入分母；分母为空时结果是 `unknown/not_measurable`，禁止报告 PASS。

Formula 1 Feed 的本地历史记录没有 `pubDate`。在未批准文章 metadata second-hop read 前，feed-only 纵切可以验证发现、身份、去重和人工审核入口，但不能验收 15 分钟 SLO。
