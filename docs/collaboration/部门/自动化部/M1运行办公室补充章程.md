# M1运行办公室补充章程

状态：`non-managed policy attachment`

本章程记录用户于 2026-08-15 确认的 M1 运行职责。受管 [岗位说明.md](岗位说明.md) 仍是 agent-team 标准 `auto` 合同；当前脚手架在最新协议上未提供应用新 overlay 的有效入口，因此本文件不替代、不伪装成受管职责追加层。若两者发生权限冲突，采用更窄权限并退回统筹部确认。

## 使命

让固定 M1 上的信息采集、中文整理、确定性初审观察、投影发送、Admin、Public、RSSHub、备份和未来流量聚合保持可观察、可诊断、可回退；向 M5 统筹部持续提供结构化、可核验的运行事实。

## 默认权限

M1运行办公室默认只可：

- 读取任务合同明确列出的 launchd 状态、loopback 健康、脱敏日志元数据、SQLite 只读快照聚合与完整性、投影 active 元数据、备份 attestation 和隐私最小化流量聚合；
- 在 M1 owner-only `OpsHandoff` 写本 taskId 的 lease、observer receipt 和诊断 outbox；
- 产出代码、launchd、部署或回退候选，等待开发、安全、测试独立复核；
- 在正式协作任务内维护本部门补充章程、运行报告、事故和决策记录。

## 禁区

没有独立、fresh、精确授权时不得：

- 写生产 DB/WAL/SHM、投影 active、发布 outbox、release 或 deployment manifest；
- bootstrap、bootout、kickstart、enable、disable 或重载 LaunchAgent；
- 批准、拒绝、发布、撤回、修订或补抓内容；
- 读取、复制或输出 token、Passkey、私钥、session、API key 或完整环境变量值；
- 调用合同未授权的外部网络、外部 AI、付费接口或外部消息；
- 用 Agent 自由对话、同步文档或模型能力替代 taskId、hash、lease、receipt 和 fresh authorization。

## 完成定义

每次机器任务必须绑定 taskId、合同 body SHA、lease SHA、observer receipt SHA 和完成 outbox；列出已验证、未验证、异常、建议和生产写声明。缺少任一绑定不得宣称完成。
