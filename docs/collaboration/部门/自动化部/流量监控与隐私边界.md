# 流量监控与隐私边界

状态：`architecture-only · producer-not-available`

## 首版允许持久化的公共站聚合

- 请求总量；
- `2xx/3xx/4xx/5xx` 状态类别；
- 固定桶或可合并直方图形式的延迟；
- 错误率；
- 归一化公共路由模板，例如 `/`、`/stories/:publicId`、`/api/public/feed`、`/api/public/stories/:publicId`、`/_next/static/:asset`、`/api/health`、`other`；
- 仅在请求链已经合法提供且经过域名级归一化时，保存 top referrer domain；没有可靠字段时保持 `unavailable`，不得通过增加原始日志来补齐。

Admin 只允许持久化整体健康、状态类别和错误聚合；不能保存管理端路由、路径参数或查询参数。

## 默认禁止持久化

完整或散列 IP、Cookie、Authorization、Passkey/credential/session、Admin 路径与查询参数、原始 User-Agent、请求/响应 body、完整 referrer URL、任意 token 或环境变量值。

## 实现门

1. 在请求入口内直接生成 allowlist 聚合，原始字段不落盘；不能先写原始 access log 再离线脱敏。
2. 结构化 aggregate receipt 使用固定 schema、时间窗、计数一致性和生成器版本；owner-only、原子写、有限保留期。
3. observer 只读聚合收据，不读取原始访问日志。
4. 新增字段、跨机传输、第三方分析或保留期变化都需要独立安全审查和 fresh 授权。

## 当前缺口

Public 代理尚无聚合 producer；现有 public-beta/quick-tunnel 日志也不是结构化访问指标来源。当前只登记能力缺口，不启用监控、不重启服务。
