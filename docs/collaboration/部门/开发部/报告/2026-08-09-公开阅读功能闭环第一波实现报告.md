## 2. Function ID 逐项结论

### `PUB-DETAIL-001`｜独立详情成功链

- 正式用户入口：`/stories/public-demo-qualifying-window`。
- 数据/状态链：页面通过相对同源 `GET /api/public/stories/{publicId}` 读取唯一 projection；页面显示标题、中文摘要、关键点、来源元数据和最多 3 条关联。
- production 收据：标题精确出现；“中文摘要”1、“关键点”1、related `3`；“资讯流”返回入口可达。
- 失败与恢复：由 `PUB-DETAIL-005` 承担。
- 结论：本任务候选 **PASS**。

### `PUB-DETAIL-004`｜inline 404 / 通用错误 / 同对象恢复

- 正式用户入口：首页条目摘要按钮；错误 UI 和重试按钮均来自正式 production bundle。
- 验收触发方式：3012 loopback 代理只在下一笔同源 detail GET 返回一次 404 或 503，随后自动回到 3011 透传。
- 404 收据：首条保持 `open=1`，显示“这条内容已不可用（404）”，重试按钮精确为 1；重试同 `publicId` 后恢复中文正文。
- 503 收据：第二条保持 `open=1`，显示“提炼内容暂不可用”，重试按钮精确为 1；重试同 `publicId` 后恢复中文正文。
- 失败不关闭已读时间线，也不回退静态内容。
- 结论：本任务候选 **PASS**。

### `PUB-DETAIL-005`｜独立详情 404 / 通用错误 / 恢复

- 正式用户入口：独立详情 URL。
- `public-demo-missing`：正式 API 404 后页面显示“不存在或当前不可用”；“重试当前地址”再次读取同一 URL 后仍保持 404，不泄露额外存在性；“返回资讯流”恢复 `/`，时间线 12 条可用。
- 有效详情的一次性 503：显示“公开内容暂时不可用”；重试同一 URL 后恢复标题、正文、关键点和 3 条关联；顶栏品牌在失败态仍可返回信息流。
- 结论：本任务候选 **PASS**。

### `UI-TOP-001`｜回到顶部

- 正式用户入口：冻结设计右下角/移动 Dock 的“↑ 回到顶部”。
- 1440 production：鼠标激活从 `scrollY=5763` 回到 `0`，`activeElement=#main-content`；键盘 Enter 激活同样为 `scrollY=0` 且阅读主区取得焦点。
- shipping 代码的 reduced-motion 分支使用 `behavior:auto`，并在恢复焦点后再次把最终滚动位置固定为 0。
- 实机差距：当前内置浏览器把 `matchMedia` 暴露为不可改的只读宿主能力；一次性 HTML 环境注入未能改变真实 media query。按统筹收敛指令停止继续探测。新回顶逻辑的 reduced-motion 实机路径仍为 **P1 successor**。
- 结论：鼠标/键盘 **PASS**；Function ID 依矩阵整体仍为 **P1-blocker**。

### `UI-ACCORDION-001`｜连续互斥、整条居中、外点

- 正式用户入口：首页连续点击前两条摘要。
- production 收据：连续第二条后 `.tl-item.is-open=1`，唯一 open id 为 `public-demo-pit-wall-notes`；整条中心与视口中心差 `9.82px`；外点后 open 数为 `0`。
- 详情从 loading 进入 ready/error/404 时会重新按整条居中，避免正文加载后几何漂移。
- reduced-motion 即时定位的 shipping 分支存在，受上述浏览器能力限制没有取得本轮真实 media-query 收据。
- 结论：互斥/居中/外点 **PASS**；Function ID 依矩阵整体仍为 **P1-blocker**，只剩 reduced-motion 实机出口。

### `UI-THEME-002`｜刷新、重开、异常存储

- 正式用户入口：冻结设计主题按钮。
- 非法 cookie HTTP：`Cookie: f1p1-theme=invalid` 的 SSR HTML 只输出 `data-theme="dark"` 与“当前深色主题，切换为浅色主题”。
- 主题 cookie 只保存显示偏好，键为 `f1p1-theme`，值由类型守卫严格限制为 `dark|light`；写入属性为 `Path=/; Max-Age=31536000; SameSite=Strict`，没有敏感信息，也没有外部 I/O。Root Layout 读取 cookie，因此公开路由保持动态 SSR；合法值直接形成首屏 `html/body data-theme`，非法值回到 dark。
- 当前浏览器环境 `localStorage` 不可用；从 dark 点击切换后，非敏感 cookie 保存 light，刷新和新开页面均恢复 light；两个页面 console `[]`、React#418 命中 0。最新补丁保证 Storage 属性访问或读取异常时，客户端快照继续沿用服务端已白名单化的 `initialTheme`。
- 聚焦测试使用 getter/setter 都抛 `SecurityError` 的 Storage：无服务端偏好时 `readThemePreference()` 安全回 dark，合法 SSR light 作为 fallback 时保持 light，`writeThemePreference()` 返回 false；Shell 对 `window.localStorage` 属性访问另有外层 try/catch，客户端快照以已白名单化的 `initialTheme` 为 fallback，cookie 写入也 fail closed。
- 实机差距：浏览器没有提供可控的“真实 Storage 方法抛错”能力；按统筹指令不继续扩工具。该精确实机故障仍为 **P1 successor**。
- 结论：非法 cookie、cookie-only 刷新/重开、hydration 零错误 **PASS**；Function ID 依矩阵整体仍为 **P1-blocker**，等待 Storage 抛错实机复验。
