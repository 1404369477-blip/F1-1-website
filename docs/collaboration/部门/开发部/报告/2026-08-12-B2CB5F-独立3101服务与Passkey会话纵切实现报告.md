## 2. 依赖与官方依据

新增唯一直接依赖为 `@simplewebauthn/server@13.3.2`，以 exact 版本写入 `package.json`/lockfile；npm registry 记录 `engines.node >=20.0.0`，与项目固定 `Node 24.18.0` 兼容。只引入 server 包，没有安装 browser 包或手写 WebAuthn 签名验证器。

## 3. 产品合同差异闭合

接线时发现原合同同时要求浏览器提交完整 64 位 `sourcePayloadHash`，并规定完整 hash 不进入页面。现有 ReviewList/Detail 也没有返回该值，真实 UI 无法构造 revision。

统筹已裁定最小 successor：

- `RevisionRequest.expected.sourcePayloadHash` 改为 `sourceVersionTag`，格式固定 12 位小写十六进制；
- `ReviewDetail.integrity.versionTag` 的唯一语义固定为当前完整 `sourcePayloadHash` 前 12 位；
- Repository 在服务端用当前完整 hash 前 12 位进行 CAS，完整 hash 继续写入 Bundle、关系列和审计；
- Bundle CAS 仍单独使用 `latestBundleVersionTag/bundleVersionTag/approvedBundleVersionTag`，不混合 source tag。

对应最小代码改动只落在 schema、Repository 与原聚焦后端测试；没有新增第二 wire DTO 或把完整 hash 暴露给客户端。

## 4. 安全实现

- listener 常量固定为 `127.0.0.1:3101`；启动后精确回读地址与端口，不提供环境覆盖。
- canonical origin 只接受无 path/query/fragment 的 HTTPS；RP ID 精确为 hostname。
- 所有请求先校验 loopback、HTTP/1.1、Host、规范化 path、method、可信 Tailscale login/device allowlist；POST 再校验精确 Origin、`Sec-Fetch-Site: same-origin` 和 `application/json`。
- session cookie 沿用 `__Host-f1_admin_session; Secure; HttpOnly; SameSite=Strict; Path=/`；每个私有业务入口增加 session 与当前 Tailscale user/device 的服务端绑定复核。
- bootstrap token 只写 0600 本机文件，状态只保存 SHA-256；最长 10 分钟、成功单次消费。credential 目录 0700、文件 0600，以 no-follow 独占 stage、fsync、rename、父目录 fsync 原子持久化。
- login 更新 authenticator counter 后才签发 session。fresh re-auth 绑定完整 PublishRequest 派生的 operation/action/resource hash，验证成功后轮换 session，并调用既有 `acceptVerifiedFreshReauth`。
- HTTP body 分层上限为 auth 128 KiB、review 64 KiB、签名 projection 2 MiB；请求/headers/keepalive 有界超时；错误响应固定 allowlist reason，不输出 stack、token、assertion、绝对路径或 Tailscale header 原文。
- 静态根只有 `index.html/app.css/app.js` 三个固定文件映射；服务不拥有 `/`、`/stories/*` 或公开 API。

## 5. 数据与 receiver 接线

`openReviewAdminDatabase` 的顺序固定：

1. 使用既有安全 SQLite opener 打开 RSS 私有库；
2. `user_version=0|1` 时以冻结 SHA 应用/验证 `0001_rss_real.sql`；
3. 以冻结 SHA 应用/验证 `0002_admin_review_publish.sql`；
4. 对最终 42 个业务对象执行完整 canonical `sqlite_schema` 指纹 `46a71403…f638e`；
5. 上述全部通过后才构造 `ReviewRealRepository`。

服务接入既有 `ReviewAdminRoutes`，并增加 receiver 的签名 package 接收、内部 receipt 与 Admin delivery receipt 查询。它没有实现 sender、outbox worker、public Next reader 切换或真实网络传输。

- `app/src/server/admin-service/webauthn.ts`：`a34bc0ace8a627fb2d6431f964fc6eb7c5cd15c261359b54d447cd170d33aa79`

机械 successor 已在 SimpleWebAuthn 调用边界显式新建普通 `ArrayBuffer`，构造目标 `Uint8Array<ArrayBuffer>` 后用 `set()` 复制原字节，再传入官方 `generateRegistrationOptions()`。没有 `as` 强转、`any`、`ts-ignore`、第三方配置或接口类型放宽；输入长度和字节顺序不变。successor 按合同没有重跑已 PASS 的 Vitest，只执行一次 Node24 typecheck 和一次 diff-check，均 PASS。
