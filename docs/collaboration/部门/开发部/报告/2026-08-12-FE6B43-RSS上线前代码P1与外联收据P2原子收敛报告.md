## 3. E60186 问题处置

### P1-01：stop epoch 成功提交围栏

- claim 在原有 `BEGIN IMMEDIATE` 中读取并返回 source 当前 `stopEpoch`。
- 200 与 304 成功 finalizer 在各自已有的同一个 `BEGIN IMMEDIATE` 事务中，写候选、run 成功状态或 source validator 前先验证：run 仍为 `running`、source 仍启用、当前 `stop_epoch` 等于 claim 值。
- 任一条件失配固定抛出 `SOURCE_STOPPED`，事务回滚，因此候选、validator、成功游标保持零写入。
- 失败 finalizer 仅要求同一 run 仍为 `running`，允许该 run 随后收口为 `failed/SOURCE_STOPPED`；该错误不重新启用 source，也不再次递增已变化的 `stop_epoch`。

### P1-02：IPv6 特殊地址拒绝

- IPv6 先规范解析为 16-byte，再按位执行 CIDR 判断；含 zone suffix、嵌入 IPv4 或 IPv4-mapped 形式直接拒绝。
- 默认只接受 `2000::/3`，并排除 `2001::/23` 特殊用途聚合段、`2001:db8::/32`、`2002::/16`、`3ffe::/16`、`3fff::/20` 与 `2620:4f:8000::/48`。
- DNS 仍按“所有结果逐个校验，任一非公共地址则整次拒绝”处理；连接仍只 pin 到已校验地址。
- 聚焦向量覆盖 `2002::/16` 和 `3fff::/20` 边界、ORCHID 所在特殊聚合范围、文档地址、AS112 特殊段与 IPv4-mapped 形式，并保留两个明确全球单播正例。

### P1-03：拒绝响应有界终止

- redirect、429、401/403/404、5xx、其他非 200、MIME/encoding/length/response validator 拒绝统一进入 `destroy()` 出口，删除无界 `response.resume()`。
- 304 在读取有限 header 后立即销毁 response/socket 再结算；大于 1 MiB 的 200 body 也先销毁再失败。
- 200 未终结路径继续受原绝对 10 秒 total timer 约束；拒绝路径只有在已经销毁 response 后才清理 timer 并完成 Promise。
- 纯函数测试证明静态统一终止出口会调用一次 `destroy()`；本任务未建立真实恶意持续 chunked 服务。

### P2-01：externalCalls 分阶段准确记录

- CLI 的 `networkAttempted` 初始为 false；固定 URL、`RSS_REAL_IO`、proxy、请求 validator 与时间值检查全部通过后，transport 在开始 DNS 前调用阶段 hook 将其置为 true。
- URL、I/O 门、proxy 与请求 validator 前置拒绝收据保持 `externalCalls=0`。
- DNS、request、HTTP 已发生，以及成功响应后的 parser/repository 错误统一记录 `externalCalls=1`。
- `rssFailureForReceipt` 克隆原失败的 `reasonCode`、`nextAction`、`httpStatus`、`retryAfterSeconds` 与 `stopSource`，仅按真实外联阶段归一化 `externalCalls`。
