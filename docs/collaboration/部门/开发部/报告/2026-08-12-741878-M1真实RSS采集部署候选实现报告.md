## 2. P1-N01 最小闭合

### 每次运行的验证顺序

1. wrapper 拒绝任何参数，并严格要求 `RSS_RELEASE_MANIFEST_SHA256` 为一个小写 64 位 SHA-256。
2. wrapper 校验固定 macOS arm64/Node24/app root 主机门。
3. 以外部 SHA 核对 release manifest 原始字节，并根据当前安装树重新计算显式运行文件、lock 递归生产依赖文件/content root、目标 Node 路径/版本/二进制 SHA 和确定性 release root。
4. 以同一个外部 SHA 回读 deployment manifest，并重算 plist、wrapper/collector/deployment/installer/control 等 artifact、日志/DB/plist 私有权限。
5. 只读打开固定私有 DB，执行完整 `assertRssSchema` integrity/fingerprint 门并关闭连接。
6. 前述门全部通过后，才动态 `import("./rss-collect-once.ts")`；collector 及其 parser/transport 顶层在此之前不会加载，collector 写连接、run claim、DNS/HTTP 均不可达。

### plist、installer 与 manifest 绑定

- plist 的 `ProgramArguments` 通过 `/usr/bin/env -i` 注入实际 `RSS_RELEASE_MANIFEST_SHA256`，执行固定 Node 与 `scripts/rss-scheduled-run.ts`，不再直接执行 collector。
- installer prepare 先用 `RSS_EXPECTED_RELEASE_MANIFEST_SHA256` 验证实际 manifest，再把该实际文件 SHA 传给 plist 生成、deployment manifest 生成与回读；三个位置使用同一个锚。
- release manifest 的显式运行闭包加入 `scripts/rss-scheduled-run.ts`。
- deployment manifest 的 artifacts 同时绑定 wrapper 与 collector SHA；回读会重算两者以及带锚 plist。
- 临时 plist render 模式要求显式 64 位预览锚，只渲染到 Node 真实 tmpdir，不读取 release/DB。
- package 新增 `rss:scheduled-run`；保留原 collector 内部入口供 wrapper 动态导入，runbook 不再直接调用它。
