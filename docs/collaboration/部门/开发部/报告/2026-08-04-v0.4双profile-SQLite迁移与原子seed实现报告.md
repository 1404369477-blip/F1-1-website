## 2. 实现边界

### 2.1 配置与 profile

新增 canonical 环境键 `F1_DATA_PROFILE`，只接受：

- `m3-shadow` + `.local/f1plus1.sqlite` + M3 frozen fixture；
- `public-synthetic` + `.local/f1plus1-public-synthetic.sqlite` + v0.4 public fixture。

profile、数据库路径、fixture 路径任一混合均以 `DATA_PROFILE_MIX` 拒绝。P1 隔离套件需要随机临时 SQLite 名称，只有 `NODE_ENV=test` 的 runtime loader 才能设置 `testDatabasePathOverride`；该通道仍绑定已选 profile、fixture 和实际数据库 basename，普通 local runtime 无法开启。

### 2.2 migration 与 on-disk 图

`0003_public_synthetic_profile.sql` 追加：

- `fixture_profile_ledger`；
- `public_captured_item`；
- `public_content`；
- `public_summary`；
- `public_media_candidate`；
- `public_release_bundle`；
- `public_review_decision`；
- `public_publication`；
- `published_projection`；
- 公开发布时间/ID 索引。

表间 FK 和唯一约束固定 CapturedItem → Content → Summary/Bundle → approved Decision → published Publication → PublishedProjection 链。payload 使用 `canonical-json-v1` 等价的稳定 JSON 字节保存，后继 Repository 可以从 `PublishedProjection` 起步读取，无 `public_story` 第二真值。

schema v3 在 Node 24.18.0 / SQLite 3.53.1 下的静态 fingerprint：

```text

```

### 2.3 四 root 与写前拒绝

应用代码独立固定：

```text
manifest  3b296868dc0c0000fb94856b334ff7d1f698e3e80d4bb02e7062142dc1a0e554
ledger    1f7719490a18a49842427907b53c3dbde5813709a2ad611f7cfaca891880caf1
generator 34ecfa83fec1f89a22d877e554c4ce5c4d11c1bad6b7f09f123fea3ede1cb81a
validator 058be83bdded7f5c60028f0a2e537c510e9386934284684fffb119d2e487360c
```

四项文件均经既有 no-follow、单硬链接、owner、权限、稳定 descriptor 读取。随后再核 fixture bytes `c7d9d88b…941e4` 和 graph `4be9f7e…a526`，才允许检查数据库和进入写事务。任一 root 漂移时，`source_config_fixture`、public 图和 profile ledger 都保持零写。

### 2.4 profile ledger 与幂等

public ledger 固定：profile/path/contract/fixture set/manifest root/graph root/实体计数、`synthetic_only=1`、`external_calls=0`、`writes_to_base=0`、`real_content_imported=0` 及四 root。

M3 ledger 固定：59 条 Source、public 图全零、M3 contract/bridge/projection receipt、`external_calls=0`、`writes_to_base=0`、`real_content_imported=0`。已有 v2 M3 数据库迁移到 v3 后会在独立事务中补 ledger，Source 行不重写。

二次 seed 先逐项核 stored Source、各表 canonical payload、精确 count 和 ledger；全部相等时返回 `inserted=false`，任何无 ledger 的部分行或 stored payload 漂移均 fail closed。
