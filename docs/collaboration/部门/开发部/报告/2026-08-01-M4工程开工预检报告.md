## 4. 中国大陆依赖风险

当前风险等级为“待验证，首装存在中高风险”，依据如下：

1. npm/pnpm/Yarn 使用公共海外 registry；未配置镜像，目标网络下的 DNS、TLS、下载速度和稳定性没有现场证据。
2. pip 缓存不可用，首次安装 Python 依赖需要重新访问包源。
3. 仓库没有锁文件或包清单，依赖解析、版本漂移和 transitive dependency 数量尚未受控。
4. Node 当前是 v25.5.0；`node:sqlite` 的 experimental 状态不能当作生产稳定性证据。
5. Postgres、Redis 和 Docker 均不可用，任何依赖它们的本地启动合同都未验证。

建议的缓解条件：

- 正式锁栈前，先在目标中国大陆网络或可复现的内网构建环境执行一次无缓存安装，并保存失败类型、耗时和包源证据。
- 选定包管理器后提交 lockfile；构建使用 frozen/locked 模式，避免每次重新解析。
- 如需镜像或内部代理，由环境维护者确定域名、证书、同步策略和供应链审计；代码中不硬编码镜像。
- 能用标准库、数据库内置 outbox 或少量成熟依赖解决的部分不引入额外 broker、SDK 或自动化 SaaS。
- 依赖安装通过后，再做许可证、漏洞、维护活跃度和离线缓存检查。

本节结论不代表公共 registry 当前不可用；它只说明本轮按任务边界没有做网络验证，无法为安装成功或中国大陆稳定性背书。

## 5. 可抛弃闭环探针

探针路径：`scratch/product-experiments/m4-preflight/probe.py`

运行命令：

```bash
python3 scratch/product-experiments/m4-preflight/probe.py
```

探针流程：

```text
MockAdapter.poll()
        ↓
两个独立 worker 进程（spawn）
        ↓
临时 SQLite 文件：唯一观察记录 + 唯一 task inbox
        ↓
InProcessApp.handle(path)
        ├─ /healthz
        ├─ /api/items
        ├─ /
        └─ unknown path → 404
```

验收覆盖：

- 两个 worker 对同一批合成观察重复投递，最终只有 2 条唯一观察记录和 2 条唯一任务。
- 每个 worker 都接收 1 条坏载荷；坏载荷被拒绝，没有写入业务表。
- `/api/items` 能读出 SQLite 内容；`/` 能渲染 2 个合成条目。
- `/healthz` 返回进程内传输标识；未知路由返回 404 和 `not_found`。
- mock adapter 的 `rate_limited` 返回 `Retry-After=3` 语义；`permission_denied` 没有自动重试提示。
- SQLite 文件放在探针目录的临时子目录，运行结束清理；没有留下数据库、日志或网络产物。
- `external_calls=0`，探针不导入 socket server、不绑定端口、不调用外部 URL。

验证结果：

- 第一次运行：`status=pass`。
- 第二次并行重复运行：两次均 `status=pass`。
- 语法检查：`compile:pass`。
- 运行时：Python `3.14.6`，SQLite 使用标准库。

这项结果只证明本地逻辑合同、进程并发和 SQLite 幂等路径在当前机器上可行。它不证明真实 HTTP 端口、生产 Web 框架、Postgres/Redis、真实平台采集或 15 分钟时效。

此前尝试使用本机随机回环端口时被执行环境拒绝绑定；按照统筹部处理阻断指令，验收已收窄为进程内请求/handler 调用。真实 `127.0.0.1` 服务器启动列为正式 app 在可绑定环境中的独立验证项。

## 6. 候选架构与代码 ADR 候选

### 6.1 系统级候选

沿用系统决策包中的候选 A：模块化核心 + 隔离 Worker + 异步任务 + 事务状态库 + 公开投影。探针对应其中最小可验证部分：核心读路由、worker 写入、数据库唯一约束、错误分类和重试语义。

候选 A 仍为 proposed。具体语言、框架、数据库、队列、部署平台和基础模型没有被本任务冻结。

### 6.2 `ADR-CODE-001` 候选（proposed）

**标题：首版以单运行时模块化核心承载 Web/API/worker，数据库 outbox 优先于额外 broker。**

建议内容：

1. 正式栈先保持单运行时，避免 Web、API、worker 分别引入多套依赖和跨语言合同。
2. Web/API/worker 通过明确模块边界协作；高风险适配器、媒体处理和 AI 整理保留独立进程/权限边界。
3. 本地开发先用 SQLite 验证事务、唯一约束、outbox/inbox 和幂等；生产数据库是否采用 Postgres，要在路线接受后另立实施决定。
4. 任务队列优先采用数据库 durable outbox + lease/CAS；只有容量、延迟或故障域实验明确需要时才增加 Redis/独立 broker。
5. 真实 provider 默认 `mock`；真实 Base、平台 API、采集、发布和 AI 凭证均由环境变量注入，默认关闭。
6. 自动发布保持关闭，`AUTO_PUBLISH=false` 为不可缺省的安全默认值。

待选择的运行时方向：

| 候选 | 优点 | 当前证据与风险 |
|---|---|---|
| Node LTS + TypeScript | Web/API/worker 可共享类型和工具链，适合单运行时 | 当前机器只有 Node 25 非 LTS；项目没有依赖和 lockfile；需验证 LTS、包源和 SQLite/生产 DB 适配 |
| Python 稳定版本 + Web 框架 | 本次标准库探针通过，采集和内容处理生态较成熟 | FastAPI 等包未安装；前端交互仍需静态/JS方案；需验证 Python 版本、包源和 Web 运行时 |

当前不把任一方向写成 accepted 技术选择。若产品/架构路线接受后倾向单运行时，先做同一组合同测试和目标网络安装实验，再由统筹部提交正式代码 ADR。
