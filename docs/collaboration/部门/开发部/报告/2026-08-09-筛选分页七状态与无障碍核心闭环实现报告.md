### 2.2 七状态真实出口

下表是离线修复前候选的操作者观察。状态故障由一次性 loopback 代理触发；代理没有写入 App、配置或第二数据真值。原始逐态收据未持久化，且 Chrome harness 有后台外联尝试，因此下表不能作为当前候选 PASS 证据。

| 状态 | 真实观察 | 唯一恢复动作 / 结果 |
| --- | --- | --- |
| loading | 同源 API 延迟 `900ms` 时显示加载状态 | 请求完成后恢复 `12` 条 |
| empty | API 返回合同合法空页 | `刷新 →` |
| error | API 返回失败时显示 alert | `重试 →`，恢复 `12` 条 |
| 404 | API 返回正式 404 时显示 alert | `返回时间线 →`，恢复 `12` 条 |
| nomore | 第二页合并后 `hasMore=false` | 明确“已读到本批次末尾”，无伪加载入口 |
| partial | page2 首次失败，第一页 `12` 条和阅读位置保持 | 仅 `重试失败项 →`；同 cursor 成功后变为 `24` 条 |
| offline | 浏览器离线条件与同源请求失败同时成立 | `刷新 →`；恢复网络条件后回正式同源 API |

客户端合并器拒绝页内重复 publicId、跨页重复 publicId、重复 next cursor 和失序污染；失败不覆盖已加载条目。
