## 7. 幂等、重复创建预防与回退

### 7.1 幂等规则

1. Base 幂等键是精确标题 `F1+1 信源库｜M3影子`；发现精确同名即转为读后核对，禁止再创建。
2. 表、字段、视图和表单均以真实父资源 ID + 精确名称定位；同名时先读类型与配置，匹配则复用，不匹配则停止。
3. 导入幂等键是 `migration_batch_id + source_id`。响应超时或未知时先全量读回；不得直接重放 59 行。
4. 单批 59 行低于 CLI 的 200 行上限，保持串行单批；后续补缺也必须先确认缺失 source_id。

### 7.2 可恢复回退

- **建表或字段中断：** 保留已创建资源和真实 ID；读回差异，从第一个缺失项继续。不得删除重建来掩盖冲突。
- **视图/表单配置中断：** 不影响 59 条影子数据；保留资源并提交真实 readback。只允许继续使用已验证的 CLI typed 命令或安全部固定表单字段 PATCH;若 CLI 路径不能安全完成则停止,不得改走浏览器/UI。
- **记录写入部分成功：** 保留本批已写记录，先逐行验证现存子集的 33 字段、默认值和唯一性；全部正确后才通过 `migration_batch_id + source_id` 找出缺失项并只补缺，任一现存记录错误即停止。
- **发现错误映射：** 立即停止所有后续写入。由于 Base 尚非真值且 provider 未切，可先导出/保存本批 `record_id + source_id` 对照；删除或覆盖属于高风险写入，必须另获明确确认后，只针对该批精确 record ID 执行。
- **放弃本次 M3：** 保持 `enabled=false` 且不连接 Collector；不删除 legacy，不改变业务真值。是否删除影子 Base/记录另走用户确认。

任何回退都不得把运行遥测写入 Base、把本地清单反写裁决业务状态、启用记录或触发采集。
