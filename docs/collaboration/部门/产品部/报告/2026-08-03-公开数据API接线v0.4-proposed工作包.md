# 公开数据/API 接线 v0.4 proposed 工作包交付报告

## 1. 交付结论

已形成一份可供用户、统筹部和正式产品部决策的 proposed 工作包：

- [ADR-M4-PUBLIC-READ-001：公开读模型与 API 接线 v0.4 successor（proposed）]([M5-HOME]/Documents/F1+1/docs/decisions/system/2026-08-03-F1+1-公开读模型与API接线-v0.4-successor-proposed.md)

工作包关闭了两份独立只读分析提出的主要缺口：

1. M3 59 行全 disabled/validating，不能合法承载 12 条已发布 synthetic 前端内容。建议用独立 `public-synthetic` profile/DB 复用 `src-active`，保持 M3 59×39/e7a8 零漂移。
2. v0.3 无法唯一表达现有 UI 的 category、lead/body/keyPoints、source display/byline、media alt/展示元数据、restricted/time 语义。建议新建最小 v0.4 successor，不创建新领域实体或 `public_story`。
3. 公开 API 从 PublishedProjection 起读，逐条验证 Publication、approved ReviewDecision、immutable Bundle、Content/Summary/hash/fence；任一部分 join 或 hash 失败时整个请求 fail closed。
4. 公开端点固定为 feed/detail，page size=12，`source=source_snapshot.source_id`，`contentType` 为四类编辑分类，cursor 绑定筛选，Problem JSON 封闭，M4 原链/外部媒体继续 null/disabled。

## 6. 自检与不确定性

### 自检通过

1. 没有把 59 个真实候选 X Source 中的任意一个伪造成 12 条合成内容的来源。
2. 没有增加第 60 行 M3 Source，没有改动 59×39/e7a8，没有建议 `public_story`。
3. 每条 synthetic 内容都要求 CapturedItem、approved ReviewDecision、published Publication 和 PublishedProjection，没有绕过人工审核合同。
4. DTO 只使用审核后 snapshot 和可复算发布链，internal/private/未审核字段有明确禁止列表。
5. 原链与外部媒体保持 null/disabled，无外部 I/O 或真实资产暗示。
6. 回退不依赖 down migration 或静态第二真值。

### 仍需后续验证

- v0.4 精确 JSON Schema、generator 和 12 套 hash 需数据部实施；本报告只提供字段/不变量合同。
- 隔离 DB/profile 是建议，accepted M4 ADR 尚未包含这项决定。
- Cursor 当前只是不透明、绑定、可校验的公开分页合同，不承诺密码学保密/防伪；若未来需要跨重启防篡改，须独立设计 key lifecycle。
- DB busy 等待、repository 查询、Route Handler 和浏览器行为均尚未运行验证。
- 启动脱敏 P1、R5 同 UID 威胁和完整 R12 仍由其他任务处理，本报告不声称这些门禁已通过。

## 7. 建议的统筹下一步

1. 将 U1/U2 作为一次用户决策；推荐同时接受。
2. 确认后由正式产品部创建 successor ADR/Spec 修订任务，由数据部创建 v0.4 机器合同任务。
3. v0.4 机器合同经安全/测试独立 PASS 后，再由开发部执行 migration/repository/API/UI 接线。
4. 最终由测试、安全、设计三方分别复验，统筹部根据收据决定是否 ACK。

本报告为 proposed 工作包的交付证据，不表示 U1/U2 已确认，也不表示任何实现或外部能力已开启。
