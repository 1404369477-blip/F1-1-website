# TASK-20260802-124BE1｜方案 B 适用范围澄清附录

## 1. 附录边界

本附录是已 ACK 的 TASK-20260802-214FED 报告的增量澄清，不修改原报告正文，不修改 accepted ADR、Spec、app、data 或外部资源。214FED 的方案比较、方案 B 推荐和原用户确认点继续有效；本附录只拆开 R5 威胁模型与 VS-1 至 VS-3 的其他阶段门禁。

## 2. 方案 B 的 R5 可信范围

如果用户确认方案 B，并由后续 successor ADR 正式接受其适用范围，R5 的窄范围定义如下：

- 信任边界是同一台本机、同一可信 owner 账户、owner-only 的 M4 本地运行环境；允许普通应用进程与 mock worker 以同一账户进行协作和正常并发。
- 明确排除恶意同 UID 进程竞争、共享文件系统/网络文件系统、容器共享目录、多用户部署、备份/恢复介质攻击、生产存储和任何外部真实能力。
- R5 仍覆盖同一可信本机上的 SQLite 主库、父目录、DB、WAL、SHM、journal、backup 的路径、权限、身份、WAL、恢复、并发和失败关闭行为。0700/0600、单层路径、全祖先身份、O_NOFOLLOW、原子创建、pre/post sidecar 与 SQLite location 复核仍属于本地门禁。
- 该范围可以覆盖同一台本机上 VS-0、VS-1、VS-2、VS-3 使用同一 SQLite 状态库时的存储层操作。worker 只要属于同一可信 owner-only 本地运行面，也属于该 R5 存储范围。

因此，“B 不能用于 VS-1”应精确改读为：B 不能单独证明 VS-1 通过，也不能把 B 的 R5 收据外推到 VS-1 的非存储安全合同。B 的 R5 范围可以覆盖 VS-1 至 VS-3 的 SQLite 存储层；每个切片仍需独立满足各自的阶段门禁。

## 3. VS-0 至 VS-3 的分层状态

用户确认方案 B 且 successor ADR、范围化安全复验均完成后，预期状态如下。当前仍处于选择前状态，以下“可进入”均表示满足出口后才可进入，不构成预先放行。

| 切片 | B 的 R5 作用 | 仍需独立通过的门禁 | 选择后的最小出口 |
|---|---|---|---|
| VS-0 安全地基与 fixture provider | 覆盖本地 SQLite 打开、迁移、WAL、恢复、并发和失败关闭的存储层 | R1 配置/fixture allowlist、R4 日志、R12 runtime no-egress、seed/data gate；范围化 R5 复验 | R5 范围化复验 P0=0/P1=0，Node24/SQLite/迁移/权限/恢复收据完整后，才可给 local-only VS-0 PASS |
| VS-1 来源读取、规范化、查重与 outbox | 覆盖 Source、observation、inbox/outbox、ledger 等 SQLite 读写的存储层 | R1 fixture/mock registry；R9 worker/lease/五 fence/CAS/epoch/idempotency；R12 deny-all worker/no-egress；R13 脱敏审计；loopback/Origin 等适用的 R2/R3 门禁 | 重复投递唯一、lease/fence 单调、stale 结果拒绝、事务与 outbox 一致、external_calls=0、审计收据通过；真实平台与 provider 仍关闭 |
| VS-2 中文整理、媒体降级与人工审核 | 覆盖 Summary、MediaCandidate、ReleaseBundle、ReviewDecision 等本地 SQLite 状态的存储层 | R7 text-only/媒体隔离；R8 deterministic fixture summary；R10 可重建 hash、批准 hash、supersede；R12 no-egress；R13 审计 | 提示注入/越界/恶意媒体隔离、无图可继续、hash/fence 变化使旧批准失效、审计和 no-egress 收据通过；不调用真实模型或媒体服务 |
| VS-3 本地公开读模型与发布急停 | 覆盖 Publication、published projection、reconcile、stop/withdraw 等 SQLite 状态的存储层 | R2 loopback/origin/CORS；R3 session/CSRF；R4 日志；R7 DTO/CSP；R10 manual-only、稳定 public_id、同 key reconcile_wait；R12 no-egress；R13 审计 | 未批准不公开、同 key 不增 public_id、unknown 只进入 reconcile_wait、急停阻断新公开项、会话/Origin/CSRF/审计收据通过；仍限本地手动发布 |

## 4. 选择前与选择后总状态

### 选择前

- accepted R5 仍保持强威胁模型要求；现有安全终审的 P0 仍阻断 SQLite-backed VS-0 安全放行。
- VS-1、VS-2、VS-3 均为 pending/closed；不开始依赖 SQLite 的阶段性放行，不启动真实外部能力。
- C local preflight、fixture 或迁移收据只说明基础能力，不能替代 R5 或各切片独立门禁。

### 用户确认 B、successor ADR 接受且范围化 R5 复验通过后

- R5 可信范围扩展为“同一可信 owner-only 本机上的 VS-0 至 VS-3 SQLite 存储层”，排除项保持不变。
- VS-0 可以依据范围化 R5 出口重新申请 local-only PASS；VS-1 至 VS-3 仍逐项等待各自独立门禁，不会因 R5 范围确认自动变为 accepted 或 completed。
- VS-1 至 VS-3 必须继续保持 fixture/mock、loopback、manual-only、external_calls=0；不连接真实 Base/provider/Collector，不采集、不发布、不部署。
- R12、worker/lease/fence、session/CSRF、日志、hash、审核和 reconcile 这些合同继续独立验收；VS-1 至 VS-3 的任一独立门禁未通过，相关切片保持 pending/closed。
- 生产、多用户、共享文件系统、网络文件系统和真实外部能力不属于方案 B 的范围。若要开放，需要方案 A 等价强隔离或新的用户确认和 successor ADR。
