## 3. 产品决策

### 3.1 唯一推荐

选择 Motorsport F1 RSS：固定 URL、最多三次 GET、最小间隔 15 分钟、每次最多 1 MiB/20 项、零重定向、零 second-hop。原始内容不落盘，条目级临时诊断最多保留 24 小时。

该范围足以验证运输、稳定身份、发布时间、重复读取与去重。它不能验证长期 SLO、生产权利、摘要、图片或公开展示。

### 3.2 不采用的方案

- 同轮增加 Formula1.com 会扩大来源和权利边界，对主试验没有必要贡献。
- 继续只用 synthetic 风险最低，但无法验证真实 MIME、条件头与源端身份稳定性；用户拒绝时采用该路径。

## 4. 用户门禁

唯一问题已经逐字写入 draft §11，包含：

- 唯一 URL，以及首次请求最晚 `2026-08-15 23:29:00`、全部请求及响应处理最晚 `2026-08-15 23:59:59`（北京时间）的授权有效期；无法按时完成则取消后续请求；
- 最多三次、15 分钟间隔、失败不补请求；
- 1 MiB、20 item、零重定向、零 second-hop；
- 允许的临时字段、禁止字段和 24 小时删除；永久收据只保留 `source_id` 与 allowlist 配置 hash，不重复记录完整 URL；
- 十项控制及测试/安全 `P0=0 / P1=0` 前置；
- Base/provider/Content/Publication/公开页/摘要/图片全部关闭；
- 用户批准与第三方权利、生产放行相互独立。

默认答案是拒绝。用户未明确回答“批准”时保持零真实请求。

## 9. 四类唯一 reason code 整改（TASK-20260809-018CA4）

安全部离线向量任务 `TASK-20260809-88561C` 已由统筹部 ACK。其 46 个向量中有 4 个攻击输入保持有效，但原先缺少唯一主 reason code。产品合同现按以下一对一关系冻结；安全部无需改变攻击输入即可回填：

| 离线向量 | 固定 `primary_reason_code` | 机械触发 |
| --- | --- | --- |
| `xml-items-over-limit-unresolved` | `XML_ITEM_LIMIT` | 结构、schema 与 unknown-semantics 检查通过后，RSS/Atom item 数量 `>20` |
| `atomic-partial-unresolved` | `ATOMIC_COMMIT_PARTIAL` | 已尝试写事务中 observation 集合内部部分提交，或 observation/inbox intent/cursor 三者提交状态不全相同；现有输入的 observation/inbox mismatch 直接命中 |
| `log-policy-violation-unresolved` | `LOG_POLICY_VIOLATION` | 本次 operation 的 trial log 拟写字段包含 allowlist 外字段，包括 `title` 或 `stack` |
| `egress-policy-violation-unresolved` | `EGRESS_POLICY_VIOLATION` | 本次 operation 新产生/关联的 Publication/PublishedProjection 任一非零，或本次 pilot profile 的第三方媒体 CSP/等价出口被允许 |

唯一主码优先级固定为 `EGRESS_POLICY_VIOLATION` > `LOG_POLICY_VIOLATION` > `ATOMIC_COMMIT_PARTIAL` > 其余执行管线首次失败；完整文档先完成 XML 结构、schema 与 unknown-semantics 校验，再统计 item 数量，因此既有 reason code 先于 `XML_ITEM_LIMIT`。四类失败均固定为拒绝完整响应或运行、取消剩余请求；向量的 `cursor_advanced=false` 与 `data_retained=false` 是受控恢复后的失败关闭出口，任何部分事务、游标推进、违规日志或本次 operation 的本地公开出口仍有残留时继续保留 blocker。

`EGRESS_POLICY_VIOLATION` 的计数隔离在本次 VS-RSS-0 `operation_id`/`source_id` 与独立 pilot store/profile；现有 `public-synthetic` 等无关 Publication/PublishedProjection 不计入、不删除、不修改。安全向量中的 publication/projection/CSP 字段定义为当前 pilot operation 的隔离输入，因此无需增加或改变攻击输入。`LOG_POLICY_VIOLATION` 同样只检查当前 operation 的独立 trial log sink，并在 emit、数据事务与游标 commit 前完成 allowlist 校验。

本次整改没有改变来源 URL、最多 3 次 GET、15 分钟间隔、授权窗口、20 item/1 MiB、0 redirect、0 second-hop、24 小时删除或 §11 唯一用户问题；真实请求仍保持关闭。没有修改 accepted ADR、Spec、app、data、Base 或 provider。

本轮三路只读对抗审查已收口：原因码/事务审查、离线向量机械映射审查与产品范围审查最终均为 `P0=0 / P1=0`。审查发现的事务三参与者、trial 日志域、pilot 出口隔离域、XML 判定顺序和全局 Publication 误计问题均已在上述合同中关闭；现有 `public-synthetic` 保持只读且不纳入本次计数。
