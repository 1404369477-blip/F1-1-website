# M5 Admin 独立主机与双端实施合同报告

## 1. 结论

`TASK-20260809-061961` 验收出口已闭合，决策为 **PASS**。

用户已确认的 A 拓扑已固化为窄范围 accepted successor：

- 公开站与 Admin 分属两个主机/信任边界；
- Admin 主机承载唯一可写 SQLite 主库；
- 公开主机只接收可重建的全量只读投影，无 Admin mutation/主库/备份解密权限；
- Admin 主动 push 签名 full snapshot，公开主机不主动查询 Admin；
- Mac 与 iPhone 使用同一 Admin origin/API/权限集，队列、编辑、批准、拒绝、显式手动发布与对账恢复全部等价；
- 恢复目标为 `RTO≤4h`、`RPO≤15m`，标准冗余不引入数据库双写；
- 生产仅保留一个不可变 `PRODUCTION-DEPLOYMENT-MANIFEST`/hash 用户批准门禁。

本结论不批准 `ADR-M5-REVIEW-SYNTHETIC-001` 业务实施、Admin 视觉或任何真实生产部署。

## 3. 实施判断闭合

| 主题 | 已固定的唯一判断 |
| --- | --- |
| 业务真值 | 只有 Admin 主库；public-host 是可丢弃技术副本，不反向修复 |
| 投影形态 | 当前全部 PublishedProjection 映射为一份按 publicId 升序的 full snapshot |
| 跨机方向 | Admin 主动 `PUT` 快照，按同 delivery `GET` 收据；public-host 不拉 Admin |
| 幂等身份 | `snapshotManifestHash` 内容寻址；`deliveryId=operation_id=op-snapshot-<hash>`；唯一字段沿用 `{source_config_epoch,snapshot_manifest_hash}` |
| 事务崩溃窗 | 无未结算 intent 时 PublishedProjection 与snapshot Outbox同 Admin DB 事务；有前任务时由可重建 root 差异扫描补后继，不增 dirty 实体 |
| 分发串行 | 最多一个未结算 snapshot intent；父节点只取 receiver confirmed active/空机 sentinel/受控重建 receipt |
| 空机重建 | 精确 bootstrap pin 绑定当前签名 full snapshot，不重放 1..N |
| 原子激活 | prepared 文件/fsync 后单次 atomic pointer swap 为唯一 commit point；收据可从 committed manifest 重建 |
| 故障重试 | 包外可恢复错误复用原 intent/key/package；包字节/代际 terminal 只在 manifest core 真实变化后 replacement，相同 hash 禁止循环 |
| unknown | 业务 publish unknown 仍属 Publication `reconcile_wait`；snapshot unknown 仅属 internal Outbox/same-delivery receipt |
| RPO | 尝试间隔≤5m，10m预警，15m或时钟不可信即关高风险 mutation |
| RTO | fence→恢复只读→双端安全验证→明确提升唯一写主→重建公开投影，全链≤4h |
