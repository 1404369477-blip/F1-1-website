## 3. v0.2 已冻结的唯一开发输入

### Profile 与真值

- 唯一 profile：`source-management-synthetic`。
- 候选路径：`app/.local/f1plus1-source-management-synthetic.sqlite`。
- 每进程单 profile、单 SQLite handle、单 writer。
- baseline 由受 pin 的本地只读 artifact/manifest 读取；新 DB 不 seed、不复制、不覆盖 59 行。
- effective set 只有冻结 baseline 59 行与 local synthetic 完整 39 字段行的确定性 union。
- m3/public SQLite 不打开；public DB、Repository、API 与 App 零写入、零切换。

### 字段与状态

- Source persisted/API core 键集合严格为 `Source.required` 39/39。
- runtime fence、source version/hash、alias、actions 和 operation links 都是 internal/read-model，不进入 Source。
- onboarding 只使用 frozen 16 状态；lifecycle 只使用 frozen 4 状态。
- validation 复合结算逐边使用既有 transition；UI alias 和 `manual_only` badge 永不回写 canonical state。

### Command 与 Outbox

唯一 command receipt 枚举：

```text
source_add
source_validate
source_activate
source_stop
source_retire
source_requeue
```

唯一规则：

- add 只写 Source、command receipt、lineage/fence 和 AuditEvent，Outbox/TaskEnvelope=0；
- validate 是同步 deterministic no-egress command，Outbox/TaskEnvelope=0；
- activate 才可创建新的 `source_activation` Outbox/TaskEnvelope；
- stopped/queue_failed 恢复与 dead-letter requeue 复用原 business operation/key/Outbox；
- stop/retire 不创建 Outbox；
- receipt status 只有 `pending|succeeded|failed`，conflict/stale/rejected 只走 HTTP/reason code；
- DELETE 和模糊 retry route 永远不注册。

### 用户与恢复出口

- `/admin/sources` 的列表、四类筛选、详情、add/validate/activate/stop/retire/requeue 均有 closed route/DTO。
- response loss 只查询同 command operation 后刷新 Source；客户端不自动换 operation/key。
- stop 提升 config/safety fence，旧 lease/result 不得提交；retire 保留 Source、lineage、operation、Outbox、attempt/dead-letter 与 audit。
- 390/1440、深浅主题、loading/empty/partial/error/conflict/stale/blocked/dead-letter/active/stopped/unknown、焦点、键盘、触控和 AT 出口已进入合同。

### 未来 Admin master

当前 profile 只服务 non-authoritative local synthetic 单 writer。未来并入唯一 Admin master 必须另有 accepted 数据迁移和生产部署合同，并持续证明 writer=1、旧 writer 已 fence、hash/ledger 可迁移、public 仍为只读投影。本任务没有实施合并、同步、双写或生产切换。
