# ADMIN-REVIEW-001 后端先行与视觉门解耦裁决报告

## 1. 唯一结论

选择 **B：当前合同要求全部等待，现阶段不得派 ADMIN-REVIEW-001 后端实现**。

技术层面已经具备 11 类 DTO / 111 槽位映射、approve 预留 Publication 与 manual publish 独立 dispatch 的闭合输入，设计候选也没有改变后端字段或事务时序。但现行产品真值仍把 `ADMIN-DECISION` 与 `ADMIN-VISUAL` 同时列为开发开工门；负责解耦后端与视觉的 `ADR-M5-REVIEW-SYNTHETIC-001` 仍是 `draft / user_required / closed_pending_user_decision`。本只读裁决不能用报告替代用户批准，也不能用未 accepted 的 successor 覆盖现行合同。

因此，本结论只关闭 A/B 解释分歧：**现在不可实施；用户先批准既有 review-synthetic successor，并由后继任务形成 canonical accepted 入口后，才可在 UI 继续关闭的条件下单独派后端波次。** Admin UI/CSS/页面与真实浏览器仍须另行取得用户视觉确认。

## 3. 精确冲突与裁决

### 3.1 现行合同明确要求等待

- 产品合同 frontmatter 将实施门写为 `blocked_by_data_mapping_and_user_visual_confirmation`（产品合同 `:8`）。
- 产品合同规定开发开工需要数据映射与用户视觉/交互确认两份前置收据（`:17-22`）。数据收据已闭合，视觉收据仍缺失。
- 产品合同回退条款逐字规定“数据映射或视觉确认未完成：不开始 app 实现”（`:321-326`），当前阻断表又规定阻断解除前开发不得把该合同解释为 App 开工授权（`:329-336`）。
- 全功能追踪矩阵把 `ADMIN-PROFILE-001`、`ADMIN-SEC-002`、`ADMIN-QUEUE-003`、`ADMIN-EDIT-004`、`ADMIN-APPROVE-005`、`ADMIN-REJECT-006`、`ADMIN-PUBLISH-007`、`ADMIN-RECOVER-008` 全部标为 `user-gated`，并在实施波次明确写明：`ADMIN-DECISION` 与 `ADMIN-VISUAL` 均获批前，开发只读合同，不写 `review-synthetic`、Admin API 或前端（矩阵 `:99-106`、`:140`）。
- `docs/progress.md:13` 的现行时态仍为“正式纵切等待视觉确认，用户确认前不派正式 Admin 实现”。

### 3.2 后端解耦候选尚未成为真值

review-synthetic successor 草案确实把后端与前端视觉拆开：其 `§4` 允许用户批准后实施第三 profile、SQLite、Repository/API、session/Origin/CSRF 与 mock worker，同时把 `/admin/reviews` 前端继续留在视觉门后。但该文件 frontmatter 与首页说明明确要求：只有 §12 获得用户“批准”并由后继任务固化为 accepted，开发才可实施；当前默认拒绝，运行能力关闭（successor `:1-22`、`:72-105`、`:280-306`）。

草案不能修改 accepted ADR，也不能覆盖 proposed 产品合同的现行开工门。若本报告选择 A，会产生三项越界：

1. 用部门裁决替代 `ADMIN-DECISION` 用户授权；
2. 在 accepted profile allowlist 尚未增加 `review-synthetic` 时修改 SQLite/profile/migration；
3. 违反矩阵明确的“两个用户轴获批前只读合同”派单规则。

因此，字段与事务语义没有 P1 冲突；真正阻断是**授权与系统真值层级**。这足以判 B。

## 4. 已冻结但当前不可实施的真实出口

下表用于锁定后继派单的精确对象，不表示当前可写代码或运行。

| 审核动作 | 未来真实入口 | 唯一成功事务/状态 | 失败与恢复 |
|---|---|---|---|
| 队列 | `GET /api/admin/reviews`，最终由 `/admin/reviews` 页面调用 | 只读当前可审核 Bundle；损坏项只进入 partial，零 mutation | 读取错误重试同一 GET；映射/hash/fence Unknown 时 blocked。 |
| 详情 | `GET /api/admin/reviews/{bundleId}` | 返回证据、editable Summary、Decision/Publication、integrity 与服务端派生 allowedActions | 404 返回队列；完整性失败隐藏全部 mutation，重新加载当前对象。 |
| 保存新版本 | `POST /api/admin/reviews/{bundleId}/revision` | 同一事务创建新 Summary version + 新 immutable ReleaseBundle；旧 Bundle 不覆盖；同 operationId/body 重放返回同一新版本 | `REVIEW_STALE_VERSION`、hash/fence 失败或 CAS 冲突零覆盖；加载最新 Bundle 后重新确认。 |
| 批准 | `POST /api/admin/reviews/{bundleId}/approve` | 同一原子事务创建 1 immutable approved Decision、预留 1 queued Publication/publicId/key，Content 提交态 `publish_queued`；精确 `Outbox=0 / TaskEnvelope=0 / Projection=0` | 任一步失败整笔 rollback；同 Bundle 的不同 Decision 返回 conflict；不得 dispatch 或公开可读。 |

## 5. 当前可做与不可做边界

- 只读引用本报告、产品合同、数据 mapping、设计候选和 successor draft。

- 创建 `review-synthetic` SQLite、第三 profile selector、ledger/root pins、fixture/seed/reset、Repository、API、session/CSRF、operation receipt、worker 或测试代码。

- 真实 Base/provider/AI/媒体/账号/内容、外部 I/O、生产认证、公网 Admin、部署、付费或外发。

## 6. 唯一用户门禁与条件式派单

### 6.1 后端唯一用户问题

沿用 review-synthetic successor §12，不新增第二问：

> 是否批准将 `review-synthetic` 固化为第三个物理隔离的本地 SQLite profile，并在 loopback local-dev、`external_calls=0`、`PUBLISH_MODE=manual_only`、零既有 profile 漂移、禁止 ATTACH/跨库事务/双写/跨 profile copy 的边界内，允许实施已冻结的 Admin 后端、session/Origin/CSRF、approve 预留唯一 Publication、显式 manual publish dispatch 与同 profile Projection；本批准不包含 Admin 前端、真实内容、Base/provider、自动或外部发布、生产认证和部署？请只回答“批准”或“拒绝”。

未获得逐字“批准”时，默认拒绝，后端保持关闭。

### 6.2 获批后的直接派单条件

只有以下条件全部成立，统筹部才能派后端开发：

1. 用户对上述问题明确回答“批准”；
2. 产品后继任务把当前 draft 固化为唯一 canonical accepted successor，并记录准确文件 SHA；
3. 开发任务绑定本报告 §2 全部输入 hash、`ADMIN-PROFILE-001/SEC-002/QUEUE-003/EDIT-004/APPROVE-005/REJECT-006/PUBLISH-007/RECOVER-008`、真实 Route Handler、三阶段事务、reasonCode、恢复和停止条件；
4. 开发范围只含第三 profile/SQLite/migration/ledger/root、Repository、server API、local session/Origin/CSRF、operation receipt、mock worker、后端 golden 与 public-zero-drift；UI/page/CSS/client/browser 继续排除；
5. 数据部先冻结 successor 所需 migration/fixture/manifest/root 与 companion transition delta；开发不得改 ACK mapping 或现有领域 schema；
6. 开发完成后，测试与安全分别验证 profile/path/root、单库单写、11 DTO/111 槽位、approve `1/0/0/0`、enqueue `1/1/1/0`、completion 单 Projection、重放/并发/unknown/rollback、session/CSRF、no-egress 与旧 profile 零漂移；P0/P1 均为 0 前后端不可记为本地可用。

用户视觉确认仍是另一条独立门：只有用户确认固定候选路径与 SHA 后，才能派 `/admin/reviews` UI/CSS/client/真实浏览器波次。后端批准不能替代视觉批准，视觉批准也不能替代 review-synthetic successor 的系统授权。

## 7. 三条失败路径收口

1. **字段、状态或 Publication 时序冲突**：当前数据 mapping 为 PASS，未发现第二套语义；若后继实现发现不一致，立即停止并回产品/数据，禁止发明字段、实体或时序。
2. **固定输入缺失、hash 或时态不一致**：本轮固定输入均存在且 hash 可解析；future dispatch 任一 hash 漂移、successor 未 accepted 或用户批准收据缺失时直接 fail closed，不派开发。
3. **越出本地 synthetic 边界**：任何自动发布、真实外部 I/O、生产认证、公网 Admin、Base/provider/AI/媒体或部署诉求从本波次删除并保持 closed。
