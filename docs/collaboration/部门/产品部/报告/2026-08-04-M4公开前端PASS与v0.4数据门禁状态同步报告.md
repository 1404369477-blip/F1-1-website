## 4. v0.4 数据 FAIL 与整改出口

首轮 v0.4 包的当前正常快照、12 套批准发布图、v0.3 11 项冻结 artifact 和 M3 59×39/59 disabled/`e7a831…9f17` 均有通过证据；首轮审核曾确认下列五类 P1，因此首轮数据包没有取得开发接线资格：

1. `decision_hash_input` 可与顶层 Decision/五 fence 分裂并在重算后通过。
2. manifest/profile/ledger 的关键安全语义没有封闭 exact 校验。
3. DTO mapping 值可改指内部 URL 等禁止来源并在重绑外层 hash 后通过。
4. 生成器会跟随已有输出符号链接，可能越界覆写用户可写文件。
5. 生成器把待退役的 `app/.../demo-data.ts` SHA 设为前置条件，实际内容来自内嵌 `STORIES`，会形成维护双源或再生成失效。

整改任务 `TASK-20260803-D53BF3` 已 `completed` 并提交新机器包，把这五类出口实现为：data-native 单一机器输入、exact decision hash input/fence、封闭 manifest/profile/ledger、DTO 字段 allowlist 来源与 transform、symlink-safe 同目录临时文件 + fsync + 原子 replace。任务收据记录双临时目录生成、9 项字节一致、29 项故障 reject、五个 decision fence 分裂 5/5 reject、v0.3/M3 零漂移与无临时残留。上述结果为数据部整改交付与自验收据，原安全部与测试部尚未按新 SHA 聚焦复验，因此开发接线继续关闭。安全 P2 root-of-trust 继续留给后续开发代码 pin，不能在数据包内部伪装闭合。
