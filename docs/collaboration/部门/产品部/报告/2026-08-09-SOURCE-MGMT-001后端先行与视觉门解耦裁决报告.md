# SOURCE-MGMT-001 后端先行与视觉门解耦裁决报告

## 1. 唯一结论

选择 **A：允许纯后端实现先行，视觉与页面继续关闭**。

当前合同允许开发独立完成 `source-management-synthetic` profile、SQLite migration/ledger/closed receipt、Repository、raw-session/CSRF、安全边界、显式 Admin API Route Handlers、activation worker，以及后端归属的 golden。`/admin/sources` 页面、浏览器客户端、组件、CSS、响应式与视觉验收仍须等待用户对冻结视觉候选的确认。

此裁决只解释现行 v0.2/v0.3 合同的门禁作用域，不新增系统真值，不形成 v0.4，不改变 `SOURCE-MGMT-001=P1-blocker`。后端波次通过后也不得将整个 Function ID 宣称为 complete。

## 3. 可直接派给开发部的后端波次

### 3.1 唯一候选与固定输入

- 产品入口：v0.3，SHA-256 `90ee4ed30d325b7b2833582cc0ac8134aefc7fbc2dcd43ec9d20c0f726b2f1fe`。
- 被吸收前序：v0.2，SHA-256 `a4b7230c89b0083f6d3f412d2c3f3f767c7f131d4ea422f85fe5721f75df686b`。
- 必须沿用已 ACK 的数据候选、安全 PASS 合同和冻结 59 条 disabled baseline 引用；不得复制 59 条基线到可写 DB，不得另造 Source schema、第二写主或跨 profile join。
- 依赖图和锁文件保持不变；不得新增依赖。若现有依赖不足，任务失败关闭并回产品部重新裁决。

### 3.2 允许实现

1. 独立 `source-management-synthetic` profile：单进程、单 SQLite handle、单 writer；禁止 `ATTACH`、跨 profile 查询、public DB 写入。
2. scoped migration、migration/profile ledger、schema fingerprint、closed receipt、runtime bootstrap 与 health/readiness。
3. Source baseline hash/row identity 引用与稀疏可变覆盖；本地新增 Source、validate receipt、activate/stop/retire、两类 requeue 的既定语义。
4. Repository 与显式 server Route Handlers：
   - `GET/POST /api/admin/sources`
   - `GET /api/admin/sources/{sourceId}`
   - v0.3 已冻结的 validate、activate、stop、retire、requeue 命令路径
   - `GET /api/admin/operations/{commandOperationId}`
   - `POST /api/admin/session`、`POST /api/admin/session/refresh`、`POST /api/admin/csrf`
5. raw authority、loopback/local session、Origin、raw-body hash、single-use CSRF nonce、command/business/task/lease identity 分离与 command codec。
6. activation worker：只消费既定 `source_activation` Outbox，使用 fresh lease 与五 fence；validate 只产 command receipt，不创建 Outbox；retry 必须复用既定业务身份，不新增第二 intent。
7. 后端归属的 mandatory golden、固定向量、事务/并发/失败恢复、no-egress 和 public-zero-drift 验证。

开发部可按勘察报告 §5.1 的现有后端落点修改配置、profile/database、fixture provider、seed、closed receipt、health、migration/bootstrap/serve 脚本，并新增 scoped migration、source-management Repository/runtime/security/worker、显式 API Route Handlers 与后端测试。`app/package.json` 仅允许增加基于现有依赖的本地脚本；`app/package-lock.json` 必须零漂移。

### 3.3 后端波次验收出口

- 绑定同一候选 hash，migration、ledger、schema、manifest 与 closed receipt 可机械复算。
- 冻结 59 条基线只读引用不漂移；本 profile 的可变数据和业务收据闭合，旧 profile 与 public runtime 零漂移。
- add/validate/activate/stop/retire/requeue 的状态、receipt、Outbox 数量、幂等、CAS、lease、五 fence、retry/dead-letter 与恢复出口符合 v0.2/v0.3。
- v0.2 后端归属 golden 和 v0.3 后端归属安全 golden 全部 PASS；任何需要真实浏览器、用户代理 Web Crypto 或视觉交互的分支保持 NOT_RUN，不得以服务端替身冒充。
- `external_calls=0`；无真实账号、真实信源、真实平台、飞书 Base、provider、部署或外部副作用。
- 后端波次报告必须逐项列出已验证、未验证、候选 hash、旧 profile/public/package-lock 零漂移收据，以及后续 UI 门禁。

## 4. 继续关闭的 UI/视觉波次

下列内容在用户视觉确认前保持关闭：

- `app/src/app/admin/sources/page.tsx`
- 浏览器侧 source-management API/client command generator
- 页面体验组件、CSS module、布局与全局样式改动
- `/admin/sources` 的占位页、debug 页或临时视觉替代
- 390px/1440px 页面 golden、真实浏览器 Web Crypto/表单交互、响应式、焦点、错误恢复与视觉验收
- 任何 design 定稿资产修改

后端 Route Handler 可存在，但不构成 `/admin/sources` 用户入口已开放。若某一安全 golden 同时包含 server 和 user-agent 两侧，后端波次只验 server 侧固定向量与拒绝规则；浏览器侧继续 NOT_RUN。

## 5. 状态与后继派单边界

- 当前：`SOURCE-MGMT-001 = P1-blocker`。
- 后端波次 PASS 后：仍为 `P1-blocker`，原因收窄为 UI/CSS/page、浏览器侧安全链、用户视觉确认及对应独立验收未完成。
- 用户确认冻结视觉候选后：另派 UI 波次；仍须通过设计、测试与安全的独立验收，才能评估 complete。
- 本裁决不授权 App 页面、data、design、Spec、accepted ADR 修改；不授权真实外部 I/O、真实资源或部署。
