## 3. 本轮固定的唯一合同

1. 信源只有在 `canonical_url_valid=true`、`normalization_status=valid`、`dedup_status=unique` 后进入 `activation_pending`。三门、stop clear、五个 fence 通过时，一个事务同时写 `enabled=true`、`queued`、唯一 onboarding operation 和唯一 outbox；Source、TaskEnvelope、Outbox 复用同一 `operation_id`。worker 取得 lease 后才进入 `collecting`。多门失败按 `platform > authorization > adapter` 选择 blocked 状态；重试、恢复、停止、取消、死信出口重新取得 gates/fences，`paused` 只在 `lifecycle_status`。
2. 同一 `(release_bundle_id, approved_bundle_hash)` 只有一个 Publication、`public_id`、`publish_generation`。Publication、publish Outbox、TaskEnvelope 逐字复用 `Publication.idempotency_key`；`reconcile_key` 只用于该 Publication 查询，publish/reconcile envelope 逐字复用它，其他 envelope 为 null。timeout 进入同一记录的 `reconcile_wait`，所有恢复保留 identity/key。
3. `content_version_hash` 与 `summary_version_hash` 分别从 v0.3 候选的不可变字段对象复算：Content 使用 `content_hash_input`，Summary 使用 `summary_hash_input`（含 input content hash、summary schema version、synthetic summarizer 和 deterministic 标记）。release canonical payload 冻结 content/summary snapshot、source snapshot（含 identity status）、原链、权利、媒体、政策、schema、五 fence；`payload_hash` 只 hash `canonical_payload`，`bundle_hash` 按 `bundle_hash_input` 固定公式重算，`approved_bundle_hash=bundle_hash`，冻结字段变化会新建 Bundle 并 supersede 旧批准。D80846 已交付并 ACK；若聚焦复验发现字段需调整，只能由数据部统一修订。
4. `SourceObservation` 与 `AuditEvent` 才是 internal-only 记录，引用候选路径 `data/mvp-contract-v0/internal-contract.schema.json`；没有单独的草稿实体，草稿就是领域 `Summary(summary_status=draft)`，只有生成过程运行元数据进入 internal contract。内部记录不属于领域实体、Base 映射或公开真值。
5. seed 只有 `m3-shadow-seed`、`synthetic-case-seed`、`security-error-seed` 三层；published projection 和 snapshot reconciliation 属于 synthetic 子集。`epoch=0` 永远在 schema 层拒绝，不能作为有效 envelope。
6. v0.3 产品基线继续使用 6 组状态机、9 条不变量和既有领域实体；任何额外状态机、额外不变量或新领域实体均须由数据部收敛，不反向写入本产品合同。
