## 6. 开放 P1：当前 snapshot 必须 FAIL

### P1-01：预占同名弱 schema 可被 migration 登记为成功

`app/migrations/0001_local_foundation.sql` 和 `0002_source_fixture.sql` 对 application-owned table/index 使用 `CREATE ... IF NOT EXISTS`。`migrateDatabase()` 核对文件顺序、SQL hash、ledger 和 `user_version`，没有对应用后的 `sqlite_master.sql`、列约束、CHECK、PK 和 index predicate 做 schema fingerprint。

同一轮统筹对抗探针已确认：先预建同名弱表，再运行两个 migration，结果仍是 `applied=[0001,0002]`、`user_version=2`；实际表可保留 attacker extra column 且没有冻结 CHECK。统筹指令本测试子轮无需重复运行该已确认探针，本报告如实保留证据来源；对 SQL 和 `database.ts` 的静态检查与该结果一致。

影响：migration ledger/hash 只能证明 SQL 文件被登记，无法证明物理 schema 符合 59×39 与唯一/约束合同。该项直接命中 P1/FAIL 门禁。

### P1-02：已应用后加列/删唯一索引，migrate 和 seed 仍通过

本测试部在全新 DB 独立复现：

```sql
ALTER TABLE source_config_fixture ADD COLUMN attacker_extension TEXT;
DROP INDEX source_config_fixture_canonical_unique;
```

随后的有效收据：

```json
{
  "repeatMigration": {"applied": [], "userVersion": 2},
  "firstSeedInserted": true,
  "repeatSeedInserted": false,
  "columns": 40,
  "canonicalUniqueIndexPresent": false,
  "rows": 59,
  "disabled": 59,
  "projectionHash": "e7a8312c70a9a49922aedb3cfbeaa190db8f5dce8d4ab45db1570748fc329f17"
}
```

该探针没有篡改 migration ledger，因此不存在 ledger 篡改的混杂解释。重复 migration 与 seed 同时把 40 列/缺唯一索引状态当作成功，直接违反任务的 59×39、唯一性和篡改 fail-closed 出口。该项独立足以导致当前最终 FAIL。

### 修复后最小重验出口

1. 首次应用前拒绝所有 migration-owned 预存表/索引，或移除关键 DDL 的 `IF NOT EXISTS` 以使预占状态原子失败。
2. 对 migration-owned schema 建立稳定 fingerprint，至少覆盖 `sqlite_master.sql`、列名/顺序/类型/NOT NULL/PK、CHECK、普通/唯一/partial index 及 predicate、ledger 表结构。
3. fingerprint 在 migration 后、重复启动和 seed 前均复核；预占弱 schema、加列、删/替换索引及约束漂移均应非零退出。
4. 修复后重跑本报告的完整链和两个 P1 最小负例，P0/P1 归零后才可重新判 PASS。
