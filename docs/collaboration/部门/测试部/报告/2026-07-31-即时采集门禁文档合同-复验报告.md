### 2. Spec 验收标准可测性

Spec 第 9 节已经给出可观察的输入、动作和结果：

- 有效输入：URL 规范化和查重通过，适配器能力与合法授权有效。
- 正向结果：立即产生幂等采集任务；身份或相关性 unknown 不阻断。
- 负向结果：URL 无效、重复归属不明、适配器缺失、授权失效、平台受限、入队失败或采集失败时写明确状态并告警。
- 原子性：配置状态与唯一入队意图同一事务写入；队列重试复用不可变操作 ID。
- 在途失效：每次平台调用及结果提交前重查启停、授权、合规停止和安全 epoch；过期任务不能继续请求或写当前结果。
- 公开门禁：批准绑定不可变内容版本及 hash；编辑后回到待审核；公开只接受当前 hash 与批准 hash 完全一致的版本。
- 失败出口：采集、处理和发布失败均有可见状态与安全重试路径，不能绕过人工审核。

这些条目能转化为实现期的状态断言、队列观察和公开出口测试；当前静态复验只判合同可测，不判实现通过。

### 3. 默认状态、入队谓词与状态机

决策包为新提交定义安全默认值：规范化与查重 pending，身份、相关性、可监控性 unknown，适配器 unchecked、授权 unknown，`collection_onboarding_status=validating`、`lifecycle_status=proposed`、`enabled=false`。

受控门禁只有在以下条件全部成立时创建一次激活操作：

```text
normalization_status = valid
canonical_url_valid = true
dedup_status = unique
adapter_status = ready
adapter_authorization_status = valid
monitorability = monitorable
source_stop_status = clear
```

同一配置事务写 `activation_pending`、保持 `enabled=false` 并追加唯一 `onboarding_operation_id` 的 outbox 事件。dispatcher 重试复用该 ID；队列确认后才迁移为 `queued` 并置 `enabled=true`。消费者若早于状态确认取得任务，只能无副作用重试，不能调用平台。

正常状态迁移为：

```text
validating → activation_pending → queued → collecting → active
```

失败表分别归属规范化、查重、适配器、授权、平台、队列和首次采集状态。`queue_failed` 保持关闭并复用原操作 ID；`collection_failed` 记录在 onboarding 状态和独立运行遥测中，信源保持启用以便在门禁仍有效时安全重试。该划分没有把首次采集失败误写成入队未发生。

### 5. 幂等、停用与在途栅栏

- 激活操作 ID 创建后不可变；outbox dispatcher 和队列重试复用同一 ID。
- 任务携带 `source_config_epoch` 与 `source_safety_epoch`；每次平台调用和结果提交前读取当前门禁。
- 人工停用原子写 `enabled=false`、`source_stop_status=manual` 并递增 `source_safety_epoch`，自动门禁不能重新启用。
- 授权失效或平台能力不可用时置对应 stop 状态、关闭来源并递增安全 epoch；旧任务转 blocked/cancelled。
- 后续身份或相关性被拒绝时，同一事务写拒绝、关闭、停止原因、递增 epoch，并追加移除/取消 outbox 事件。
- A/D provider 切换另由 `source_config_epoch` 围栏；旧 provider/配置在途结果只留审计。

反向时序“任务已排队 → 人工停用或授权过期 → Worker 准备平台调用/提交结果”会在调用或提交前命中当前门禁、stop 状态或 epoch 差异，不能继续请求平台或写入当前结果。

### 6. 人工审核与确定版本绑定

用户确认只改变“信源何时开始采集”，没有开启自动公开。决策包要求：

```text
内容编辑 → 新 content_revision + content_hash → review_status=pending
人工批准 → approved_content_hash
公开门禁 → current content_hash == approved_content_hash
```

公开任务以 `content_id + content_revision` 幂等。采集入队、采集成功、中文整理完成或来源身份后来核验通过均不能代替人工批准；hash 不一致、待审、拒绝或失败状态不能公开，也不能复用旧版本批准。该合同与 Spec 的人工审核验收项一致。

## 自设计反向探针

1. **unknown 放行探针：** 身份、相关性和 verification 保持 unknown/pending，其余技术门禁满足，发布谓词允许进入 Collector。
2. **monitorability 反探针：** 身份已核验但 `monitorability=unknown`，谓词仍阻断，避免把身份事实替代技术可采集性。
3. **重复消息探针：** 同一 `onboarding_operation_id` 投递两次，只能对应同一激活意图，不能创建第二信源或第二独立操作。
4. **早到消息探针：** 队列消费者早于状态确认取得消息，只能无副作用重试，不能调用平台。
5. **停用竞态探针：** 入队后人工停用并递增安全 epoch，旧 Worker 在调用和提交两个时点都必须失败关闭。
6. **批准篡改探针：** 批准后修改标题、摘要、媒体或原始链接导致 hash 变化，旧批准不能用于公开。
7. **授权扩张探针：** 将即时采集确认尝试解释为创建飞书 Base 或选择 D，三文档均由 proposed/待授权声明截断。
