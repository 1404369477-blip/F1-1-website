## 支持与不支持的结论

### WX-R4-01 / P2：将记录和业务进度外推为任务执行、存活状态

最终回复写“之后无采集”，末尾又写“RSS 采集和备份任务仍卡在 10:20 前后”。原标准正文只说最近成功记录、队列及登记恢复点，并明确“采集任务、备份任务的存活状态未采样，异常根因未查”。

本次 DTO 的三源最近尝试和成功时间均仍为 9 月 10 日 10:20；备份登记恢复点为同日 10:08:43.925。这些值支持“没有更新的记录/已登记恢复点”，不能据此断言没有发生任何采集尝试、任务进程卡死或备份任务停在某一时刻。任务可能未触发、执行失败、没有推进记录或存在其他状态，本巡检没有取证区分这些情况。笼统将 RSS 与备份任务合称卡在 10:20，也把两类不同时间和未知存活状态合并了。

“根因未查”不消除前半句已经作出的任务状态断言。准确表述可限于：“三源最近尝试/成功时间、队列计数及已登记恢复点没有更新；采集和备份任务存活状态未采样，根因未查。”

### WX-R4-02 / P3：压缩回复时遗漏重要未知范围

标准正文有“Admin：loopback 边界拒绝已验证（HTTP 404）；私网登录可用性未知”，实际最终回复只在进程列表中提到 Admin，没有保留此认证边界。回复没有明确伪称登录成功，本发现是未知范围被遗漏。

磁盘标准正文将“容量正常”和“可用空间变化率未知”分开。最终回复仅剩“磁盘：正常，可用 197.75 / 460.43 GiB”，没有保留变化率未知。容量数字和容量判断是正确的，不能把它升级解释为磁盘所有检查项均健康。

### 对“与上次 23:15 相比无变化”的精确评价

审核者将本次 DTO 与 [r3 微信冻结证据](../../../../../scratch/hermes-site-status-review-20260910/wechat-evidence-r3.json) 中 `23:15:10.789` 的 DTO 逐项比较。三源的最近尝试/成功时间、缺当前草稿/待审核/待发布数量、处理队列计数、同一备份恢复点和 package、备份验签结果、HTTP 状态类别和状态码均相同。

因此，**“这些业务进度指标未变”有证据支持，不单独列为新的准确性缺陷。** 问题在于把它进一步写成任务卡住或无采集。全量指标也并非完全没有变化：可用空间从 `212927610880` 字节（约 198.304 GiB）变为 `212329336832` 字节（约 197.747 GiB），减少约 0.557 GiB，年龄和观测时间也正常增长。这里仅比较两份已保存的原始值，没有将它冒充工具已建立的可靠增长率基线；本次 sampler 的增长率状态仍是 `unknown`。

## 标准正文可达性与既往缓存结论更正

标准正文已经进入该次实际工具消息，包含正确时间、Admin 未知项以及任务存活未采样说明。现役 `tools/mcp_tool.py:3363–3381` 将 MCP 文本和结构结果组合为 `{result: text_result, structuredContent: structured}`；`agent/tool_executor.py:1478–1484` 将该字符串加入本轮 `messages` 并写入会话库；`run_agent.py:4650` 对普通文本原样返回。实际 message 1088 与这一链条一致，未出现截断、丢失正文或只保留 DTO 的情况。随后聚合工具预算的下限为 16,000 字符，本轮唯一消息只有 12,473 字节，字符数更不可能越界，因此这条聚合预算路径也不会裁掉本次报告。

MCP 内容被 `untrusted_tool_result` 包装为数据，这是现役框架的正常行为。标准报告中的观测和未知范围已进入供模型继续处理的本轮消息；本次没有截取完整模型 API 请求，不能把这一事实等同于工具描述中的新指令已经逐字节进入本次请求。

**撤回原 r4 报告中“工具名称相同也刷新描述和定义”的判断。** `/reload-mcp` 的确调用 `refresh_agent_mcp_tools`，但现役 `tools/mcp_tool.py:4641–4646` 在 `new_names == current` 时提前返回，保留 `agent.tools`，只提升记录的 generation；描述或参数 schema 变化本身不触发快照替换。此前审核只依据上层调用作出结论，未覆盖这个返回分支。

审核者提取 M1 原函数 `4535–4654`，在本地以合成 agent/registry 执行独立最小反例：名称集合相同、描述和 schema 更新时，旧工具对象保留，新描述及 schema 均未应用，generation 却更新；增加一个合成工具名的对照会应用新定义。所读模块 SHA-256 为 `5ce1903bfff58e87b8ff0d33352802b30c97db34109aa42ac0fabbce70a71457`。

因此，旧缓存会话存在保留 r3 描述的真实代码路径。安装 r4 模块当前声明的新描述 SHA-256 为 `f7aa27c57768eecbd5da6f52f887a30b44b4133df084e9f2946e5d8fc9c7c7e2`；本次没有读取 Gateway 内存 agent 对象或完整模型请求体，不能断言这条指令确实被当前模型看到，也不能把缓存问题认定为本次回复错误的唯一原因。原报告的技术通过范围及其他事实保留，缓存段以本附录更正为准。
