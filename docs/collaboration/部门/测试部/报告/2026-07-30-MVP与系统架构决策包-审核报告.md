被审文件第 133–143、357–366、379–382、428–430 行共同约束：

## 自设计反向探针

### 探针 A：标签降级探针

把“参考站存在某能力”“平台 API 技术可达”“安全部给出数值”分别尝试推导为“MVP 已获范围授权”“平台已允许生产接入”“自动发布门槛已接受”。三条推导都被文档中的 `[推断]`、`[建议]`、`[待确认]`、平台门禁和 proposed 声明截断。

### 探针 B：双命名空间交叉探针

分别追踪证据 E0–E4 和实验 E1–E6，确认退出条件引用实验时没有被误当作正式输入证据。语义可辨认，但同名编号增加人工引用错误概率，记录为一般问题 1。

### 探针 C：发布竞态探针

组合“Bundle 审核完成 → 授权撤销/急停 → Publisher 执行”的时序。Publisher 必须在最终事务内重查审核、急停、授权、撤回和 hash，异步任务还携带相应版本/epoch；旧批准或旧任务不能越过最终写入门禁。

### 探针 D：恢复单调性探针

组合“内容已下架、授权已撤销 → 旧备份恢复 → 旧 Worker 完成 → 重启消费者”。恢复合同要求单调撤销/删除/下架版本、`review_required`、更新撤销日志合并和 `recovery_epoch` 围栏，因而旧状态不能单独恢复 active 或重新公开。

### 探针 E：无图降级探针

将图片权利设为 `unknown` 或注入私网 URL、伪 MIME、巨型图。媒体任务必须终止，主内容可以无图待审，不能为提高有图率放宽权利或安全门禁。

3. **P-07 没有在正文重述安全报告的全部急停操作细节。** P-07 保留全局急停、子开关、失效闭合、epoch、发布租约和未知状态对账，但没有逐字重述 E3 的 60 秒目标、开启再认证/双人复核和解除后不自动回弹。当前自动发布保持关闭，未来开启还要求新 accepted 决策和独立安全复审，所以本轮不构成重要缺口；制定未来 accepted 自动发布合同时必须从 E3 原文完整继承并实测这些条件。
4. **适配器示例合同没有显式列出全部上位 epoch。** 第 362、501 行的强制不变量要求 `policy_epoch`、`recovery_epoch` 围栏陈旧异步结果；第 388–400 行的 `poll`/游标 CAS 示例只显式列出配置、授权版本和 fencing token。上位不变量仍约束实现，所以当前不构成重要缺口；未来接口合同应显式携带并校验这两个 epoch，且保证恢复代次不会随旧备份回滚或复用。
