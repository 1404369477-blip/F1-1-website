### 4.2 installer crash-atomic 表述

本地固定 `install.sh` 逐行复核结果与 E4706F 一致：

- 第 116–131 行的 `restore_on_failure` 只是在正常 shell `EXIT` 路径、`COMMITTED=0`、target 缺失且 backup 存在时尝试恢复；
- 第 238–242 行创建临时目录并设置 `EXIT` trap；`SIGKILL`、进程崩溃或断电不保证执行 trap；
- 第 250–305 行只校验 6 个 manifest 路径、hash、frontmatter、agent interface 和数量；不扩大到 9 文件 tree；
- 第 307–319 行先移动旧副本/旧 target 到 backup；
- 第 321–324 行再把已校验 package 移到 target，并在成功后设置 `COMMITTED=1`；期间存在 target 短暂缺口；
- 第 326–329 行的 backup cleanup 与激活不构成单一持久化事务；
- 代码未证明 `fsync`、目录持久化、信号处理或断电恢复协议。

E4706F 已明确撤销“全过程 crash-atomic”含义，只允许把单次同文件系统 `rename` 的正常操作性质与整个 installer 事务分开表达。当前采用结论继续为 `installer_unknown`、installer closed；因此原 P1 的过度安全表述已关闭，实际 crash-atomic 能力继续 Unknown，不构成当前 A 层放行。
