## r3 修复及自设计反例

r2 原本地验证使用三个成员的合成 manifest，未覆盖现役 producer 收集全部历史 generation 的行为；同时把 `sqliteMasterSha256` 错与登记 schema SHA 直接比较。这两个摘要口径不同：producer 使用全部 `sqlite_master` 行及分隔符拼接，登记 schema 使用过滤 SQLite 内部对象的 canonical JSON。真实只读试跑曾因此错误报告 `BACKUP_MANIFEST_MISMATCH`，不能据此推断生产备份损坏。

r3 在同一个短只读数据库事务内保留两种摘要，将 producer 摘要放在私有备份上下文中，继续独立验证 deployment/schema 身份。manifest 可包含有界历史成员，每个成员必须属于固定路径集合、路径唯一、长度有界；数据库、active pointer、登记当前 generation 必须存在且绑定登记身份。全体成员继续参与 content hash、文件集合 hash 与总字节数校验，manifest 原始 SHA、固定公钥、双签名、登记证据 hash 和时效校验全部保留。

审核者新增 12 个独立探针。一个 363 成员的有效包，同时得到 sampler 健康与现役 producer `parseManifest` 接受，且两种 schema 摘要确实不同。其余反例即使由 fixture 生成一致的 manifest 哈希、登记及真实签名，仍被拒绝：拿登记 schema 摘要冒充 producer 摘要、错误 producer 摘要、重复历史路径、路径穿越、绝对路径、额外子目录、大写 generation 名、尾换行路径、成员长度超过 uint32、缺当前 generation、缺 active pointer。结果为 12/12，证据 `historical-manifest-r3.json`。

原有 15 个独立采样反例在 r3 全部重新通过，覆盖未来 RSS/ingest/备份时间、非法登记 owner/kind/capability/egress/schema/release/manifest/writer/recovery、pointer 绑定，以及签名真实但 release/package 错配的回执。r1、r2 的发现、复现与关闭轨迹继续保存在 [r2 历史报告](2026-09-10-TASK-20260910-E37D5D-Hermes只读巡检r2独立审查.md)，它不再是最终安装候选。
