# M1 当前 RSS 审核状态分布独立只读裁定报告

## 1. 结论

**FAIL；P0=0，P1=1，P2=0。**

DF7FF9 的 `RSS_REVIEW_BASELINE_INVALID` 与 M1 当前数据不相符。当前值使其第二段失败布尔表达式为 **false**，因此不会抛出该错误。远端任务专属 observe 原字节及 SHA 未保留，本轮无法还原当时究竟哪个子项为真。当前可证的精确失配只有：**task JSON 记录的错误名/行号与本地保留 observe 及当前 M1 数据不一致**。

同时，当前 schema 状态是：

- `user_version=1`，DF7FF9 要求也是 `1`，当前数据可通过这一子项；
- 然而当前库只有 `0001` 的 3 张业务表，`0002`/`0003` 的审核、决策、发布、投影、outbox、audit 表全部不存在。这与 9287D8 要求按 `0001/0002/0003` 终态 schema 查询的前提冲突。

因此，当前状态可归类为 **Admin 首次启动迁移前的正常已存在状态**，同时是 **DF7FF9 preflight/oracle 的 P1 证据归因错误**。本结论不授权执行 migration、prepare、load 或 cutover。

## 4. DF7FF9 精确谓词还原

DF7FF9 observe 第 263–271 行的实际短路顺序为：

1. 先判 `userVersion !== 1 || integrity !== ok || source != 1/4/OK`，失败时报 `RSS_SEMANTIC_BASELINE_INVALID`；
2. 通过后再判 run/candidate 分布与人工字段，失败时报 `RSS_REVIEW_BASELINE_INVALID`。

将本次实值代入第 2 段：

```text
runs.total < 0                         = false  (53)
runs.running != 0                      = false  (0)
candidates.total < 0                   = false  (22)
pending_review != total                = false  (22 == 22)
machine_invalid != 0                   = false  (0)
editor_fields_set != 0                 = false  (0+0+0+0)
```

所以第 2 段不可能产生当前记录的错误。由于远端任务专属 observe 文件在失败收口后已不存在，无法直接证明当时远端字节与当前本地保留字节相等。就当前可证事实，DF7FF9 task JSON 的错误名/行号收据与实际代码语义不一致。

## 5. 建议的最小 pre/post 语义不变量

- 路径是固定唯一 review DB，并且 regular/canonical/UID 501/mode 0600/nlink 1；
- dev/inode 与已冻结的 deployment receipt 相等；
- `integrity=ok`，`user_version IN (1,2,3)`；

### 5.2 只更换代码、不启动 Admin 后
