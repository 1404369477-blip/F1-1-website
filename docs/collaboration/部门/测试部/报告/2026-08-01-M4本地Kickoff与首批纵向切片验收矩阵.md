# M4 本地 Kickoff 与首批纵向切片验收矩阵

## 1. 目的、证据等级与边界

本报告把当前 Spec v0、MVP 与系统架构 `proposed` 包、设计规范 v0.1、安全基线和 A→D `accepted` 路线转成实现前可执行的测试合同。测试部只写策略和矩阵，不修改 `app/`、Spec、ADR、设计、数据或安全产物，不写正式测试代码。

### 1.1 当前允许的实验面

- 仅使用本地 fixture、mock adapter、确定性假数据和本地状态存储。
- 不访问真实 X、Instagram、Reddit、新闻站、RSS、AI 供应商、图片服务或任何其他外部平台。
- 不使用真实平台凭证、真实用户数据、付费服务、部署环境或生产域名。
- 不把 M3 影子 Base 设为业务真值，不连接 `base_direct`、`base_snapshot`、Collector、同步器、采集器或发布链路。
- 不实现或开启自动发布；本地发布只能在测试中由明确的人工审核动作触发。
- 测试证据必须使用 fixture/seed、构建版本、测试命令、结果摘要、脱敏日志和必要的可视化预览；禁止保存 token、密钥、个人真实信息、私有链接和原始外部响应。

### 1.2 证据分层

| 层级 | 目的 | 当前状态 |
|---|---|---|
| L0 静态合同 | 检查 Spec/设计/安全/ADR 语义、状态和门禁是否无冲突 | 本报告建立合同；尚无实现执行 |
| L1 本地工具链 | 安装、启动、构建、lint、类型和单元测试 | 实现后执行；当前 `app/` 只有占位说明 |
| L2 组件与状态 | 页面组件、状态机、hash、幂等和安全边界 | 实现后执行 |
| L3 首批纵向切片 | mock adapter → 归一化 → 去重 → 摘要占位 → 人工审核 → 本地发布 | 实现后执行 |
| L4 体验与可视化 | 四个用户出口、主题、响应式、键盘、状态和可视化预览 | 必须在正式实现前后分别执行 |
| L5 破坏性探针 | XSS/SSRF/开放重定向/提示注入、故障、恢复、并发 | 实现后执行；不得连接真实外部服务 |

当前报告只对 L0 合同交付 `pass`。它不代表 L1–L5 已通过。

## 2. 不变量与测试对象

### 2.1 产品与路线不变量

1. MVP 核心闭环是“白名单信源 → 采集 → 归一化/去重 → 中文整理 → 人工审核 → 公开信息流 → 详情 → 原始链接”。
2. 未经有效人工审核决定，不得产生公开投影。
3. 审核决定绑定当前 `release_bundle_id + payload_hash`；标题、摘要、来源、媒体、权利、政策或版本任一变化都使旧审核失效并创建新 Bundle。
4. 同一业务内容只允许一个稳定 `public_id` 和一个 active 公开投影；重试、重启和并发不得增加审核项或公开副本。
5. 任务携带 `source_config_version`、`authorization_version`、`policy_epoch`、`recovery_epoch` 等版本围栏；陈旧结果只能记录审计，不能更新当前状态。
6. A→D 路线只接受“先 A、稳定后 D”；本 M4 本地切片不进入任何业务真值或 provider 切换门禁。
7. 外部内容、URL、图片和模型输出都是不可信输入；摘要 worker 无网络、密钥、管理工具和发布权限。
8. 自动发布默认关闭；当前 slice 的“本地发布”是人工审核后的本地投影，不是自动发布或外部发布。

### 2.2 四个用户出口

路径由实现部在 kickoff 时登记；测试合同使用稳定逻辑标识，避免在技术栈未确定前猜测 URL：

| 逻辑出口 | 核心用户 | 最小功能 |
|---|---|---|
| `feed` 公开信息流 | 访客 | 中文标题/摘要、来源、作者、原始发布时间、图片或无图状态、筛选、加载/空/失败/受限/无更多 |
| `detail` 内容详情 | 访客 | 可追溯中文整理、来源证据、原始链接、媒体权利/失败状态、更正/下架状态 |
| `review` 人工审核队列 | 审核者 | 来源证据、整理结果、版本 hash、编辑、通过、拒绝、回审和审计 |
| `sources` 信源管理 | 管理者/审核者 | URL、平台、启停、最近采集、错误/限流/积压、授权和可监控状态、受控恢复 |

实际路由、端口和启动命令必须在实现的 README/命令合同中登记；未登记不算可测。

## 5. 首批纵向切片合同

### 5.1 Fixture 与 mock adapter

固定 fixture 至少包含：正常 RSS-like observation、重复 observation、损坏 XML、缺失发布时间、429/`Retry-After`、5xx、超时、授权过期、恶意 URL、提示注入文本、恶意 HTML/Markdown 和多媒体失败样本。每个 fixture 有稳定 seed 与 hash。

`MockAdapter.poll(source_config_version, authorization_version, cursor, lease_token, deadline)` 只返回内存/本地数据：

```text
observations[] + next_cursor + rate_limit_state + error_class
```

mock 必须记录调用次数、输入版本、游标、lease/fencing token、输出 hash 和是否被重放；不得调用网络、shell、真实模型或真实密钥。

### 5.2 Pipeline 矩阵

| ID | 阶段/输入 | 步骤 | 预期不变量 | 必须自动化 | 优先级 |
|---|---|---|---|---|---|
| P-01 | Mock adapter 正常 observation | poll → 持久化 inbox/证据引用 → CAS 提交游标 | 先持久化 observation 再推进游标；source/version/authorization 对齐；一页一次幂等 | 是 | P0 |
| P-02 | 同一 observation 重复投递 | 重复 poll、重启消费者、重复任务 | 只产生一个来源身份/修订或确定的同一 revision，不增加审核项 | 是 | P0 |
| P-03 | 规范化输入 | URL、平台字段、时间戳、编码进入 normalization | canonical URL、时间戳 confidence、证据引用确定；缺时间不得用抓取时间伪造发布时间 | 是 | P0 |
| P-04 | 去重输入 | 相同 `source_id + external_id`、相同 content hash、canonical URL 近似重复 | 确定性键去重；语义相似不静默合并；重复状态可审计 | 是 | P0 |
| P-05 | 摘要占位 worker | 将最小纯文本/来源字段送入本地 deterministic stub | 固定 schema：标题、短摘要、事实要点、来源引用、待核对项、模型/提示版本；无工具/网络/密钥 | 是 | P0 |
| P-06 | 摘要输出异常 | schema 缺字段、事实引用不对齐、提示注入标记 | 输出隔离为待人工核对，不进入 approved/release；原始证据仍可追溯 | 是 | P0 |
| P-07 | Review approve | 审核者对当前 Bundle 执行通过 | 生成 `ReviewDecision(bundle_id, payload_hash)`；仅当前版本可发布；审计有 reviewer/time | 是 + 人工 | P0 |
| P-08 | Review edit/reject | 通过后编辑、拒绝待审 Bundle | 旧批准自动失效；编辑创建新 Bundle/hash；拒绝无公开投影 | 是 | P0 |
| P-09 | Local publish | 仅对人工 approved Bundle 执行本地投影 | 一个稳定 public_id、一个 active projection；outbox 与投影同事务；没有外部调用 | 是 + 人工 | P0 |
| P-10 | Publish retry | 相同 publish idempotency key 重试、超时后查询本地事务 | 不创建第二 public_id；已成功则返回同一结果；未知状态进入本地 reconcile 状态 | 是 | P0 |
| P-11 | Source stop | source 被停用/授权过期/合规停止后重放旧任务 | 任务 blocked/cancelled；旧 epoch 结果不更新当前状态；不恢复 legacy 第二真值 | 是 | P0 |
| P-12 | Full slice | 从 mock poll 到人工 approve 再到 local publish | 四页可看到正确状态；证据链、hash、审计、唯一键、错误状态均可追溯；无真实外部调用 | 是 + 人工 | P0 |

### 5.3 版本、hash 与幂等合同

必须在本地测试中显式断言：

- `content_version`、`summary_draft_version`、`release_bundle_id`、`payload_hash`、`source_config_version`、`authorization_version`、`policy_epoch`、`recovery_epoch` 和 `publish_generation` 的来源与递增关系。
- `payload_hash` 对规范化、字段排序和编码确定；等价 JSON 生成相同 hash，标题、摘要、原链接、媒体、权利、版本或政策变化生成不同 hash。
- 发布幂等键至少绑定稳定 `public_id`、Bundle/hash 和当前 generation；相同键重复调用只返回同一投影。
- 并发 2、10、100 次同一输入，以及重启/网络模拟超时后重试，最多一个审核项和一个 active 公开投影。
- 旧 `ReviewDecision`、旧 epoch、旧 source config 或旧授权不允许更新当前聚合；被拒绝/撤回事实不能由陈旧任务恢复。
- 证据哈希、测试 fixture hash 和 schema 版本写入脱敏审计；不写入 token、完整原文或个人隐私。

## 6. 错误、重试、限流、积压与恢复矩阵

| ID | 注入 | 预期状态 | 恢复/验证 | 优先级 |
|---|---|---|---|---|
| E-01 | mock 429 + `Retry-After` | 进入有界退避；共享预算与端点限流生效 | 遵守等待后半开探测；不轮换账号、不绕控 | P0 |
| E-02 | mock 408/5xx/短暂网络错误 | 仅允许可重试分类；指数退避+全抖动+最大次数/累计时间 | 达上限进 dead letter 并告警；不无限重试 | P0 |
| E-03 | mock 授权失效/条款阻断/恶意 payload | 适配器冻结或任务 blocked；不进入摘要/发布 | 修复授权/规则后按新版本人工恢复 | P0 |
| E-04 | 消费者崩溃/队列重启 | inbox、CAS、outbox 状态可恢复 | 重放不重复；旧 lease/fencing 失效 | P0 |
| E-05 | 队列积压超预算 | 显示积压年龄/数量；按顺序暂停低优先级→仅保存元数据→停止 AI/媒体→停止新发布 | 公开旧一致内容仍可读；恢复后定向重放 | P1 |
| E-06 | dead letter 永久失败 | 记录错误分类、载荷 hash、attempt、trace、下一安全动作 | 人工选择重放；沿用业务幂等键并重新校验授权 | P1 |
| E-07 | 数据库/队列恢复 fixture | 提升 `recovery_epoch`，冻结新发布 | 先对账公开 ID、审核、撤回、幂等键，再受控恢复消费者 | P0 |
| E-08 | 发布事务超时/本地状态未知 | 标为 local `reconcile_wait`，禁止直接创建新 public_id | 依据稳定 id/hash 查询本地事务；确认未提交后同键重试 | P0 |
| E-09 | 配置/开关读取失败 | 失效闭合回 `manual_only`；停止自动动作 | 人工复核后重新生成版本；不自动回弹 | P0 |
| E-10 | 旧 epoch 任务在新配置后返回 | 只记审计；不更新当前状态或公开投影 | 用当前版本重建/重放；旧结果可追溯 | P0 |

**恢复完成阈值：** P0 错误路径必须 100% 保持不变量；P1 路径必须有可见状态、有限恢复和人工升级出口。任何“连接超时即无提交”“空响应即清空白名单”“重试即新任务/新公开项”的行为均为 P0。

## 7. 安全反向探针矩阵

所有探针使用本地 mock sink、假 DNS/解析器和仿真 worker；网络出口默认 deny-all。不得把探针 URL 指向真实内网、云元数据、真实平台或第三方服务。

| ID | 探针输入 | 预期 | 优先级 |
|---|---|---|---|
| S-01 XSS | 标题、作者、摘要、正文、alt、审核备注注入 `<script>`、事件属性、HTML/Markdown、CSS/URL 上下文 payload | 公开页和后台均不执行；输出按上下文编码；CSP/`nosniff` 和 safe text DTO 生效 | P0 |
| S-02 SSRF | `http/https` 之外协议、回环、RFC1918、链路本地、保留/元数据地址、IPv4 变体、IPv6、DNS rebinding、多跳重定向 | mock sink 无外连；协议、DNS/IP、每跳重定向和最终连接均校验；失败进入隔离/无图 | P0 |
| S-03 XML/资源耗尽 | 外部实体、DTD、实体膨胀、深层 XML、超大压缩比、超长字段 | 禁止外部实体/网络访问；字节、深度、节点、解压和耗时上限生效 | P0 |
| S-04 开放重定向 | `next`/原文链接包含外站、`javascript:`、data URL、协议相对 URL、编码绕过 | 只允许符合合同的 HTTPS 原始链接或安全中间页；不把用户输入当 redirect target | P0 |
| S-05 提示注入 | 正文、HTML 注释、alt、作者名含“忽略指令/泄露 secret/调用工具/直接发布” | worker 无工具/网络/密钥；内容作为不可信数据分隔；输出 schema/引用失败即隔离人工 | P0 |
| S-06 外部媒体 | 伪造 MIME、SVG/HTML、像素炸弹、多帧、破损文件 | 主内容可无图；媒体任务终止/隔离；不在 Web 进程直接解码 | P0 |
| S-07 权限/CSRF | 未登录、普通审核者、停用账号、伪造对象 ID、跨站表单和旧会话执行 approve/publish/stop | 服务端拒绝越权；CSRF/会话围栏/审计生效 | P0 |
| S-08 密钥/日志 | 仿真 token 出现在 header、错误体、正文和模型输出 | 仓库、日志、告警和 prompt 不出现明文；统一脱敏生效 | P0 |
| S-09 供应链 | lockfile、依赖、构建产物和容器清单注入仿真漏洞/secret | 扫描阻断或产生有期限例外；正式构建不下载未声明内容 | P1 |
| S-10 急停竞态 | 高并发本地发布中切全局 stop、配置不可读、请求状态未知 | 新任务 60 秒内停止目标范围；epoch/lease/fencing 生效；未知进入 reconcile；解除不自动回弹 | P0 |

## 8. 自动化与人工体验分工

### 8.1 必须自动化

- K-01–K-09 工具链和无外连检查。
- 四页路由/状态/DTO/权限和公开字段泄露检查。
- fixture 解析、归一化、去重、hash、版本围栏、幂等和并发。
- 429/5xx/超时/授权失效/积压/dead letter/恢复/急停。
- XSS、SSRF、开放重定向、XML 资源耗尽、提示注入、CSRF/越权和 secret 扫描。
- 任何 P0 失败都必须使 CI/本地验收退出码非零。

### 8.2 必须人工体验或人工确认

- 四页真实信息层级、中文可读性、来源证据、错误解释和恢复路径。
- 深浅主题、图片最差裁切、手机/平板/桌面重排、200% 缩放、键盘和屏幕阅读器。
- 审核者是否清楚当前 Bundle/hash、编辑后回审、拒绝/下架影响和不可逆操作。
- 设计规范可视化预览与用户视觉/交互确认；没有确认不得进入正式 UI 实现。
- 本地发布动作是否明确是“人工批准后的本地投影”，不会被误解成自动公开或外部发布。

## 9. P0/P1/P2 判定阈值

### P0：必须阻断 M4 Build Loop

- 无法在干净环境安装/启动/构建，或没有可重复的 lint/type/test 入口。
- 四个用户出口任一缺失、无法访问或核心状态/证据不可用。
- 未经人工审核、未绑定当前 Bundle/hash 就产生公开投影。
- 重试、并发、恢复或陈旧任务产生重复审核项/公开项、丢失审计或恢复旧状态。
- 任何真实外部调用、Base 真值/provider/Collector/采集/同步/发布切换或自动发布行为。
- XSS、SSRF、开放重定向、提示注入、CSRF/越权、恶意媒体、密钥泄露等安全探针任一可利用。
- 急停失效、配置读取失败不失效闭合、旧 epoch 可写当前状态。
- UI 可视化预览或用户确认门禁缺失而进入正式页面实现。

### P1：不得宣称首批纵向切片稳定

- 错误/限流/积压/死信没有可见状态、有限恢复或人工升级。
- 主题、响应式、键盘、对比度、状态语义、200% 缩放或移动端表格策略不满足设计合同。
- 缺失来源时间可信度、权利状态、原文证据或版本 hash 的可追溯显示。
- 依赖/许可证/供应链扫描有未评估问题；测试证据无法重复。
- 本地发布、审核队列或信源管理的次要操作存在可恢复但用户可感知的错误。

### P2：不阻断 Build Loop，但必须记录

- 非关键视觉 token 漂移、间距/圆角/文案细节、非关键动画节奏或低风险布局改进。
- 不影响安全、数据、状态和用户主路径的可读性/性能优化。

## 10. M4 Build Loop 进入/退出门禁

### 10.1 进入 Build Loop 前

### 10.2 首批纵向切片退出标准

## 12. Murphy 失败路径总表

1. `app` 没有声明安装/启动/构建脚本：按 P0 阻断，不用测试部猜命令。
2. 本地启动偷偷访问网络或读取真实环境变量：立即停止并判 P0；使用 deny-all 证据定位。
3. 只测底层 API 没有四页真实出口：P0；补齐页面、状态和人工体验证据后才可重跑。
4. mock adapter 先推进游标再保存 observation：P0；重放会造成漏采或陈旧游标覆盖。
5. 相同输入在重试/并发后出现第二审核项或公开项：P0；保留差异，不删除数据掩盖问题。
6. 编辑已审核内容仍沿用旧批准 hash：P0；旧决定必须 invalidated。
7. 发布超时直接生成新 public ID：P0；进入 reconcile_wait，使用同一幂等键对账。
8. 队列积压只显示“处理中”没有年龄/数量/降级：P1；必须有背压和人工升级。
9. 429/授权失败被当成可无限重试：P0；冻结对应适配器，保留游标和错误分类。
10. 外部 URL 能打到 loopback/metadata 或跳转到 `javascript:`：P0；mock sink 必须零命中。
11. 外部文本诱导模型调用工具、泄露 secret 或直接发布：P0；无工具 worker、schema 隔离和人工审核必须同时存在。
12. 只验证颜色数值而不测图片最差裁切/浅深主题/强制颜色：P1；补真实页面人工体验。
13. 视觉预览缺失或用户未确认即进入正式 UI：P0；停在预览门禁。
14. 测试把本地 mock PASS 写成真实平台、Base 真值或自动发布可用：P0；报告必须分开“本地已验证”和“生产未验证”。
