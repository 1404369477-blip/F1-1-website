# 697D1B 公开前端 API 单一数据源独立功能验收报告

## 结论

`FAIL`。P0=0、P1=2、P2=0。使用固定 Node 24.18.0、canonical `public-synthetic` seed、真实 `127.0.0.1:3000` HTTP 和浏览器页面完成一次聚焦验收。正常首页、筛选、分页、详情成功态、related 与明确 404 的验收出口无法完成。

设计部 TASK-20260804-897075 的独立结论同为 fail，并确认 feed/详情 closed 500；该结论仅作交叉印证，测试部判定来自本窗口亲自执行的 HTTP 与浏览器证据。

## 问题

### P1-01：canonical public-synthetic 下 feed 与详情完整性失败，成功态不可稳定到达

- migration 和 seed 成功，收据为 `public-demo-12-v0.4`、12 个 publication/projection、`syntheticOnly=true`、`externalCalls=0`。
- 真实 `GET /api/public/feed` 返回 HTTP 500、`application/problem+json`、`PUBLIC_READ_INTEGRITY_FAILED`。
- 浏览器首页只显示“公开信息流暂时不可用”，12 条首页、四类筛选结果、游标加载及 no-more 成功态均不可验收。
- 现存详情曾短暂返回一次 HTTP 200，随后同一运行窗口转为 closed 500；浏览器最终显示“公开内容暂时不可用”，详情正文和 related 无法稳定到达。
- 违反任务验收出口和第一、第三条失败路径，判 P1。

### P1-02：合法未知 publicId 未进入明确 404

- `GET /api/public/stories/public-demo-not-present` 在真实运行中返回 closed 500，而非 `PUBLIC_STORY_NOT_FOUND` 404。
- 浏览器 `/stories/public-demo-not-present` 进入通用“公开内容暂时不可用”，没有进入明确 not-found 用户出口。
- 页面未沿用上一条详情，也未显示静态详情，但任务要求的明确 404 不成立，判 P1。

## 通过的失败状态合同

- Feed 500 后页面显示安全中文错误和唯一“重试”按钮；点击重试仍保持安全 error 状态。
- 服务停止后，详情重试模拟网络失败；页面保持错误态、可重试，没有静态标题、旧详情或 related 残留。
- 页面未出现 `/Users/`、SQL、SQLite、stack、payload、内部 reasonCode 或响应正文泄露。
- 错误时没有 demo、fixture、SQLite 或静态内容 fallback。
- HTTP Problem 为 closed JSON，`Cache-Control: no-store`，未观察到 CORS 放开。

## 已验证

- canonical public-synthetic migration/seed 与真实本地 HTTP 启动。
- 首页真实 API 请求、closed 500 页面、重试及零 fallback。
- 现存详情、合法未知详情、related 可达性与错误映射。
- 服务停止后的网络失败、重试、安全文案、旧内容清空及无内部泄露。
- 服务/端口/DB/sidecar/`.next`/临时文件与浏览器标签清理。

## 未验证

- 因 feed 成功态不可达，四类筛选结果、cursor 加载、去重/排序、empty 与 no-more 的真实浏览器行为未能验证。
- 因详情成功态不稳定，正文、related 0–3 和 related 导航未完成正式通过证明。
- 按任务边界未运行 full check、build 或额外测试套件；未验证生产部署、真实外部资源与系统调用级 no-egress。
- `npm run dev` 经安全包装器两次返回脱敏 `CLI_INTERNAL_ERROR`，直接运行包装器内部同一 Next CLI 可以启动。该差异本轮未追加诊断，保留为 Unknown，不另计 P1/P2。
- 390px 筛选 dialog 的 `340×104` 问题由设计部报告为 P1-02；本测试报告不重复视觉测量，也不把其计入本报告 P1 数量。

## 清理收据

- 已停止唯一 `127.0.0.1:3000` 服务，确认端口无 LISTEN。
- 已删除本轮生成的 `app/.local/f1plus1-public-synthetic.sqlite` 及 sidecar、`app/.next`、临时 HTTP 收据和临时目录。
- 未修改实现、Spec、ADR、data、design 或 lockfile。

## 错题自检

- 首次 seed 因继承环境含禁用变量被 `ENV_FORBIDDEN` 拒绝；改用 `env -i` canonical 环境后 migration/seed 成功。拒绝发生在业务数据生成前。
- 安全启动包装器隐藏 Next 子进程错误；仅直接运行其内部相同 Next CLI 以取得真实 HTTP 用户出口，没有修改实现或扩大端口。
- 设计部复用服务的协调消息到达时服务刚被停止；如实短报后仅恢复同一 3000 服务并保持到统筹收口通知，没有启动第二端口。
- 没有因失败界面表现正确而误判整体通过；成功态与明确 404 属于强制验收出口，故唯一结论为 FAIL。
