## 影响验收的问题

### WX-R3-01 / P2：UTC 钟点被错标为 UTC+8

原 DTO：`observedAt=2026-09-10T15:15:10.789Z`、`expiresAt=2026-09-10T15:16:10.789Z`。准确的北京时间分别为 **23:15:10.789** 与 **23:16:10.789**。

实际回复写成“观测 15:15 UTC+8，采样有效至 15:16”，使观测和有效期相差八小时。RSS 的 `02:20Z` 及恢复点的 `02:08Z` 同样未在分项说明中正确转换，容易与标题所称的 UTC+8 混用。RSS 最后成功实际对应北京时间 10:20，最近已登记恢复点实际对应 10:08。

### WX-R3-02 / P2：把采样现象外推成执行历史和原因

实际回复包括“任务也没跑”“同时停了”“不是人为停止”，并提出调度器/worker 卡死或隧道故障的猜测。DTO 只提供 RSS 成功时间、已登记恢复点新鲜度、当前控制状态和 HTTP/进程观测，没有备份 worker 的执行历史或故障诊断证据。

恢复点过期不能区分任务未执行、任务失败、结果未登记等情况；当前 stop clear 也不能排除人工操作、定时任务停止或此前的控制变化。公网网络错误只代表 M1 运行主机的该次观察，隧道进程启动时间不能建立公网故障原因。需要把这些原因保留为尚未确定，不能在标准状态报告中将其当作已经取得的诊断结论。

### WX-R3-03 / P3：遗漏 Admin 认证观察边界

实际回复没有声称 Admin 已登录，但完全省略了 Admin 分项。原 DTO 是 loopback 边界拒绝 404，`authenticatedPrivateAccess=unknown`。标准报告应说明该观察的范围，以免读者从总体服务状态推导私网登录已经可用。

## 最小修复的后续验收范围

主控准备 r4，仅让 Python MCP 返回预格式化北京时间文本，并同时提供不变的严格原 DTO 作为 `structuredContent`；工具描述要求使用标准报告、保留 unknown 和观察范围、禁止外推任务执行或故障原因。Node 采样器继续使用已验证字节。

已核查现役 M1 `tools/mcp_tool.py`：当 text 与 structuredContent 同时存在时，它向 Agent 返回 `{result: text_result, structuredContent: structured}`，文本作为模型主载荷，结构数据仍可保留。此说明客户端具备所需能力，不等于 r4 已实现或已验收。
