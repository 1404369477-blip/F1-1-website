## 6. 最短关键路径

开发应先把以下 12 项跑通。任一步失败就停止长矩阵，保留 DB 与 receipt：

1. `PRE-01` 冻结输入、Node/npm、离线/deny-all 与隔离 DB 通过。
2. `SEED-01` 三层分离，M3 59/59 disabled 基线通过。
3. `SRC-01` 新 synthetic Source 按 canonical 默认值写入。
4. `SRC-07` 三门、stop、五 fence 全通过后执行 activation 原子事务。
5. `LEASE-01/06` worker 先取得 fresh 128-bit CSPRNG lease，且每次换代让旧 token 失效，再进入 collecting 和调用 mock adapter。
6. `TX-01` observation→inbox→CAS→outbox 同事务 commit，随后才 ack。
7. `IDEM-01` 同一 task/observation 顺序重复与并发重复只产生一条逻辑结果。
8. `HASH-01` Content hash 按 canonical-json-v1 可重算；固定 Event dedupe 复用一条 Event。
9. `FENCE-02` 五类 epoch 各自 stale 时 provider/commit/ack 均为 0。
10. `RETRY-01` 429/503/collection failure 有界重试，预算耗尽进入 dead-letter。
11. `ADMIN-SEC-01` loopback+session+exact Origin+一次性 CSRF 仅允许一次 mutation。
12. `UI-390-01` 与 `UI-1440-01` 完成状态、结构、键盘和无横滚验收。

`PRE-01` 至 `ADMIN-SEC-01` 必须自动化。两个 UI 主宽度优先自动化结构与 accessibility assertion，视觉差异另附 `M-V` 收据。

| `FENCE-03` | P0/A-I | 在 lease acquire、adapter 前、adapter 后/outbox dispatch 前、current state/outbox commit 前逐检查点提升五个 epoch 中的一项 | 每个检查点都重新 CAS；旧 worker 无 dispatch/commit/ack，新 worker 需新任务/lease；旧结果只进 internal audit |
| `FENCE-04` | P0/A-I | envelope epoch 高于 current 或跨越式跳号 | 拒绝为 non-monotonic/future；禁止用 worker 值反写 current epoch |
| `STOP-01` | P0/A-I | queued/collecting/active 时设置 manual/compliance/authorization/platform stop | 对应 fence 递增，旧 lease 失效；新任务在注入时钟 60s 内停止；没有自动回弹 |
| `STOP-02` | P0/A-I | stop 后立即 resume 请求 | 仍需显式 resume、全 gates/fences、fresh lease；旧 operation 不得继续 |
| `LOCK-01` | P0/A-I | SQLite `BEGIN IMMEDIATE` 锁住关键事务 | 有界等待后稳定 retryable/locked 结果；不 ack、不部分提交；释放锁后同 key 重试成功一次 |
