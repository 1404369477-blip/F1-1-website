## 0. 结论速览

- 根因（已实测复现）：手机端（390）有 4 张缩略图的条目（r1/r8），右侧操作区 `.ev-right`（前往原文 + 缩略图）过宽，触发 `.tl-ev` 的 `flex-wrap: wrap` 在**预收缩前**就把 `.ev-right` 整体换到下一行，使缩略图与左侧来源文本**不在同一行**——复现结果与用户实测一致：**r1/r8 `diffBottom=44`、`sameLine=false`**；1-3 图条目不受影响（`diffBottom=0`）。
- 修复（仅移动断点 CSS）：`@container (max-width:700px)` 与 `@media (max-width:700px)` 两处移动块内收紧为**单行**——`.tl-ev { flex-wrap: nowrap }` 阻止整块换行；`.evs`（来源文本区）`flex:1 1 auto; min-width:0` 允许收缩（内部换行）；`.ev-right` `flex:0 0 auto` 不收缩；`.tl-ev`/`.ev-right`/`.ph-thumbs` 间距收紧；移动缩略图 `28px → 22px`。
- 验证（Playwright 真实 390 视口，深/浅 × 折叠/展开 r1）：**全部带缩略图条目 `diffBottom=0`、`sameLine=true`**；桌面 1440/1024 保持 `flex-wrap: wrap` 且 `diffBottom=0` **不回退**；前往原文行内化、滑动切图、lightbox 等交互未改。
- **未进入正式实现**：仅修订设计草案 `index.html` 与产出证据 PNG；未改 `app/`、`docs/spec.md`、accepted ADR、`data/`；未触发部署/真实外网（渲染时拦截字体与真实 CDN 图片，以 16:9 占位图代替，仅本地静态服务）。

## 1. 需求与根因

### 1.1 需求
手机端**所有条目**的缩略图与左侧来源文本（信源 · 作者 · 时间）**同一行、底部对齐**（和桌面一致）；并确保 1-3 图条目、桌面端、前往原文行内化、滑动切图等既有成果不回退。

### 1.2 根因（2026-08-08 实测复现）
证据行 DOM 结构：`.tl-ev` = `.evs`（来源文本，左）+ `.ev-right`（前往原文 + `.ph-thumbs` 缩略图，右）。

| 项 | 值 |
|---|---|
| 触发面 | 手机端（≤700px）4 图条目（r1/r8） |
| 直接原因 | `.tl-ev { flex-wrap: wrap }` 换行决策在**收缩之前**按各项 max-content 计算。r1/r8 的 `.evs`（≈190px）+ `.ev-right`（4×28px 缩略图 ≈ 220px）+ gap(16px) ≈ 426px > 容器 356px → `.ev-right` 被换到下一行 |
| 复现（修复前 CSS 注入） | r1：`diffBottom=44`、`sameLine=false`；r8：`diffBottom=44`、`sameLine=false`；r4/r5/r9（3/3/2 图）不受影响 |
| 后果 | 缩略图与来源文本错行（diffBottom=44），与用户实测一致 |

### 1.3 为何 1-3 图不触发
3 图（r4/r5）：`.ev-right` ≈ 155px，与 `.evs` 合计 < 356px，不触发换行；2 图（r9）更窄。故仅 4 图条目错行。

## 2. 修复设计决策与理由

仅移动断点内收紧，**不改 DOM、不改交互、不动桌面**。桌面 `.tl-ev` 仍是 `flex-wrap: wrap`（空间充足时来源文本与右侧操作自然同排，已验证不回退）。

| 规则（移动断点 @container + @media 双块） | 值 | 依据 |
|---|---|---|
| `.tl-ev` | `flex-wrap: nowrap; gap: var(--s1)` | **关键修复**：阻止 flex 在收缩前把 `.ev-right` 整体换行；间距 16px→12px |
| `.tl-ev .evs` | `flex: 1 1 auto; min-width: 0` | 来源文本区允许收缩，**内部换行**消化剩余宽度，不再把右侧操作挤到下一行 |
| `.ev-right` | `flex: 0 0 auto; gap: 6px` | 右侧操作组不收缩（缩略图固定高不溢出）；前往原文↔缩略图间距 12px→6px |
| `.ph-thumbs` | `gap: 3px` | 缩略图间距 4px→3px |
| `.ph-thumb` | `height: 22px`（移动） | 28px→22px，4 图 + 前往原文 + 来源文本在 356px 内同排有余量 |

### 2.1 宽度核算（390，16:9 占位图，容器 356px）
- 折叠 4 图：`.ev-right`（4×39 + 3×3 ≈ 165）→ `.evs` ≈ 179px，来源文本单行/双行均可，同排。
- 展开 r1：`.ev-right` ≈ 165 + 6 + 前往原文 ≈ 62 ≈ 233px → `.evs` ≈ 111px，来源文本内部换 2 行，缩略图底对齐最后一行。
- 无溢出：实测 `overflowRight=0`（`.ev-right` 右缘 = `.tl-ev` 右缘 = 373）；`.evs` 与 `.ev-right` 恒留 `12px` 间距（`horizontalGap=12`），不重叠。

### 2.2 与已确认布局的取舍
- **不推翻**：单张主图、右下角缩略图、滑动切图（pointer + wheel）、lightbox、就地展开、深浅主题、trace、reduced-motion / reduced-transparency、44px 触控（桌面/触屏）全部保持。
- **唯一视觉变更**：移动断点缩略图 28px→22px。取舍理由：①触屏 40px 规则本就被移动 28px 覆盖（cascade 后生效），移动缩略图本就不是主操作入口（主图可滑切、lightbox 可翻页），缩略图仅导航小图；②22px 仍可点（浏览器最小触控实践），且保证 4 图同排 + 前往原文行内不回退。是否接受该更小尺寸交由用户确认。
- 无页面级水平滚动（既有断言保持）。
