## 1. 当前 app 实现 review（问题定位）

review 对象：`app/src/features/stories/feed-experience.tsx`（媒体区渲染 + lightbox 交互）、`app/src/app/globals.css`（`.ph-main/.ph-thumbs/.ph-thumb/.lightbox` 样式）。对照用户 3 项需求，问题具体在：

### 1.1 主图偏小，与「放大一点」不符
- **app 桌面** `.ph-main { max-height: 320px }`（globals.css L1593）：对 16:9 图片实际渲染 ≈569×320（高度封顶），用户要求再放大。
- **app 移动** ≤700px 断点 `.ph-main { max-height: 220px }`（L2061/L2087）——更小。
- **设计草案**（`index.html`）仍是 `max-height: 255px`（v0.2 旧档）——规格与实现、与用户期望三方不一致。
- 修订值：桌面 360px / 移动 280px（用户建议的「320–360px 档」取上限）。

### 1.2 缩略图：设计草案仍为「主图下方横向排」，与需求冲突
- **设计草案**（`index.html`）`.ph-thumbs` 为 `display:flex; flex-wrap:wrap`，`.ph-thumb` 为 `height:40px; width:auto`（横向排、移动端 `height:32px`），仍在主图下方——与用户「移到主图右侧、竖向排列」直接冲突。
- **app**（globals.css L1600-1607）已实现右侧竖向列（`flex-direction:column`，80px），但存在两个比例问题：
  1. 移动端 `calc(100% - 64px)` 实际预留不足：56px 缩略图 + 6px 列内间距 + 12px 主图间距 ≈ **74px**，`max-width` 只预留 64px，靠 flex 收缩兜底，数值不自洽（建议 64px 列 + 12px 间距 = 76px）。
  2. 缩略图列无高度上限：高/竖图主图 + 多缩略图时会把整卡撑高（无滚动、无对齐上限）。
- 修订值：桌面右列固定 88px、移动 64px；列高与主图限高对齐（360/280px）+ `overflow-y:auto`。

### 1.3 lightbox 滑动翻页：设计草案缺失、契约未文档化
- **设计草案**（`index.html` lightbox JS）只有 ‹› 按钮 / 左右方向键 / Esc / 点击关闭，**没有任何滑动手势**；实现级契约 §4.4 也只写「‹› 按钮 / ArrowLeft / ArrowRight / Esc」，未文档化滑动。
- **app**（`feed-experience.tsx` L475-494）已用 pointer 事件实现滑动（48px 阈值、横向主导、`swipedRef` 与点击关闭区分），`.lightbox` 有 `touch-action: pan-y`——但这是隐式实现，规格未固化为设计语言，用户看到的「设计」与其不符。
- 修订：把滑动翻页**正式写进设计草案 JS**（pointerdown/up/cancel，48px 阈值，dx<0→下一张 / dx>0→上一张，`swiped` 标记抑制随后的点击关闭），并保留 Esc / 方向键 / ‹› 按钮 / 计数 / 焦点管理；`img.draggable=false` 避免鼠标横向拖拽被原生图片拖拽接管。

### 1.4 触控命中区
- 竖向缩略图 64px（移动）下，16:9 缩略图视觉高度 ≈44px，基本达标；88px（桌面）≈60px 舒适。契约 §6.4 已有「命中区扩展 ≥44px」建议，本次以 88/64px 固定宽列 + `flex:0 0 auto` 给出落地口径，命中区扩展建议留给开发在真实触控设备复核（见 §4 未验证）。

## 2. 修订设计决策与理由

仅改设计草案 `design/ui/F1+1-v0.2-全站设计/index.html`（CSS + lightbox JS + 证据墙 `evidence.html`），未触碰 v0.2 token/视觉语言基线（玻璃克制、trace 悬停浮现、深浅主题、reduced-motion/reduced-transparency 降级、44px 触控、4px 图片硬边）。

### 2.1 主图尺寸
| 断点 | 旧（草案 255 / app 320） | 新 | 理由 |
|---|---|---|---|
| 桌面 ≥701px | 255 / 320px | `max-height:360px` | 用户建议档上限；配合右列 88px 预留后，16:9 主图实际渲染宽度主导（≈541×360），高度上限只对竖/方图封顶 |
| 移动 ≤700px | 220px | `max-height:280px` | 移动端宽度才是约束（≈280px 宽），280px 上限服务竖/方图 |

实测渲染（Playwright DOM 复核）：桌面 541×360、移动 280×186（16:9）——较 app 现版 569×320 / 294×165 明显放大，且卡片纵向占用可控。

### 2.2 右侧竖向缩略图列
- 布局：`.tl-media` 改 `display:flex; align-items:flex-start; gap:12px`；主图左、缩略图右。
- 右列固定宽：桌面 `flex:0 0 88px; width:88px`、移动 `64px`；列内 `flex-direction:column`。
- 主图预留宽：桌面 `max-width:calc(100% - 100px)`（88+12）、移动 `calc(100% - 76px)`（64+12）——修正 app 移动端 64/74 不自洽问题。
- 列高上限：`max-height:360px`（移动 280px）+ `overflow-y:auto`，防止高/竖图多缩略图把卡片撑高；`.ph-thumb { flex:0 0 auto }` 防止滚动容器内被压扁变形。
- 交互不变：悬停临时预览、移走恢复、点击/键盘固定（`.is-active` + `data-cur`），单图内容不渲染缩略图。
- 保持 v0.2 视觉：4px 圆角、`.55→1` 不透明度、激活项 `--accent` 边框、柔和投影、`zoom-in` 光标。

### 2.3 lightbox 滑动翻页
- 手势契约：pointer 事件（触摸 + 鼠标）；阈值 **48px** 横向位移且横向主导（`|dx|>|dy|`）才翻页——与 app 现版阈值一致，避免误触/误关。
- 方向：**左滑下一张 / 右滑上一张**（与用户原话一致）。
- 区分点击关闭：滑动结束时置 `swiped=true`，随后的 click 事件被拦截不再关闭；新指针按下即重置。
- 保留既有：Esc / ArrowLeft / ArrowRight / ‹› 按钮 / 计数（`N / M`）/ 焦点进/返回 / reduced-motion 跳过缩放与淡入淡出。
- CSS：`.lightbox { touch-action: pan-y }`，横向拖动交给 JS、纵向仍可滚；`img.draggable=false` 保证鼠标横滑不被原生拖拽接管。

### 2.4 与已确认 v0.2 方向的取舍说明
- 用户本轮反馈即新方向；修订只改**媒体区与 lightbox 交互**这一处，**未推翻** v0.2 其余已确认方向（时间线、就地展开、状态、玻璃、reveal、主题降级等一律不动）。
- 契约 `F1+1-v0.2-实现级设计合同.md` 中 §2.3「主图限高 255px / 缩略图高 40px(移动 32px)」、§3「主图+缩略图导航（左下方缩略图）」、§5「缩略图 32px」等数值与本次修订冲突——**本任务不修改该契约**（属实现级基线），已在 §4 记入待同步项，待用户确认后由开发落地任务统一对齐，不在本草案内擅自改写契约。
