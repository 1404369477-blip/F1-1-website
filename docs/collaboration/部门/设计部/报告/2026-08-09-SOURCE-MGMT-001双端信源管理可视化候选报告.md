### Mac 1440×900

- 使用高密度语义 table，详情和收据从右侧 Drawer 打开。

- 1440 证据中曾出现右侧列截断风险。本次最小修订将 actions 设为固定最右列；表格上方持续显示“固定操作列”提示和两个 44px 的“← 列 / 列 →”按钮，按钮带 `aria-controls` 并使表格 region 获取键盘焦点。表格本身也可获得焦点并使用原生横向滚动；按钮与原生输入共享同一列位置读数。页面本身没有横向滚动。

## 4. 功能与状态覆盖

### 固定对象和操作

- 59 条 baseline 以受 pin 的 `data/m4-vs0-seed-enrichment-v0/source-seed-enriched.json` 的真实本地投影呈现，artifact SHA 为 `d4da9fc24c792c0471bcd24c525a46dcef1e521b36a870fd111e7310243888b2`、sorted root 为 `e7a8312c70a9a49922aedb3cfbeaa190db8f5dce8d4ab45db1570748fc329f17`；全部标记 `baseline / disabled / read only`，仅有详情和 disabled 边界，没有 mutation 出口。
- local synthetic 演示对象覆盖 proposed、active、dead-letter、validation failed，并可新增第五条。
- 浏览器可见运行依次得到 `source_add`、`source_validate`、`source_activate`、`source_stop`、`source_retire`、`source_requeue` 六类脱敏收据。
- validation failed 行提供显式“重新验证”；它复用 validate controller，并在确认层表达 fresh command identity、fresh CSRF 和 fresh SourceExpected 的运行时生成边界，界面不显示或允许编辑这些值。dead-letter requeue 复用原 source_activation 业务事实，不表达第二 Outbox。

### 筛选和展示 alias

- platform、lifecycle、enabled、onboarding 四类筛选均存在。
- 11 个 alias 全部可见：`unknown`、`restricted`、`failed`、`disabled`、`enqueued`、`enabled`、`normalization_pending`、`dedupe_pending`、`adapter_check_pending`、`proposed`、`manual_only`。
- `unknown` 明确显示为“未核验 / unknown”；alias 和 capability badge 均为只读 read model，不允许回写 Source。

### 状态与恢复

- 原合同状态：loading、filter-empty、partial、error、conflict、stale、blocked、dead-letter、active、stopped、response-unknown。
- 安全补充状态：guard-shell。
- partial/error/conflict/stale/response-unknown/loading/guard-shell 均禁用 mutation。
- guard-shell 将 session、Host、Origin、CSRF 拒绝统一呈现为固定安全错误，页面无行、Add disabled、零写入；UI 没有 token、Cookie、CSRF、nonce 或 key 输入。
- conflict 明确覆盖 identity、source_id、canonical URL 碰撞，整笔零写入；恢复为刷新 Source 后以 fresh CAS 重新确认。
- response-unknown 只允许查询原 command operation 后刷新 Source，不允许换 command identity 盲重试。
