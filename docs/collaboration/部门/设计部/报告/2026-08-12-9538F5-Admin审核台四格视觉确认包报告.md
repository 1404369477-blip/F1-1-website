## 3. 本地渲染与视觉自检

- 使用本机 Google Chrome `151.0.7922.77` headless + 本地 CDP，直接加载 `file://` 冻结 HTML；CDP 同时拦截 HTTP/HTTPS。收据记录外部 HTTP(S) 请求观察数为 `0`。
- 四张图的实际 `innerWidth/innerHeight` 分别为 `1440×900`、`1440×900`、`390×844`、`390×844`，`devicePixelRatio=1`；输出 PNG 像素尺寸逐张一致。
- 两张 390 图均记录 `document.scrollWidth=document.clientWidth=390`，没有页面级横向溢出。为让首屏直接显示关键动作，深色图滚动到编辑区，浅色图滚动到批准后的动作区；这项滚动位置已写入 manifest，不冒充页面顶部首屏。
- 宽屏的 368px 队列与自适应详情保持清楚分工；详情中的来源证据、媒体、中文编辑和审核动作没有视觉混叠。深色待审核态以蓝色批准为主动作、红色描边拒绝为危险动作；浅色批准态只保留蓝色手动发布主动作，批准与发布的时序差异可见。
- 390 单列中，表单、保存按钮、审核状态卡与 DRAFT 工具没有页面级横向挤压；固定 DRAFT 工具仍是预览控制，不属于正式 Admin 信息架构。
- 目检未发现空白截图、主题错置、截断到不可判断、页面级横向溢出或把批准和发布合并成一个动作的证据问题。
