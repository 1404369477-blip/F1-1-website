# 公开前端 API 接线独立体验与视觉验收报告

## 1. 验收结论

本轮结论为 **FAIL**。

- P0：0
- P1：2
- P2：0
- 决策：`fail`

真实候选的首页与详情公开 API 均返回 closed `500 PUBLIC_READ_INTEGRITY_FAILED`，公开信息流、详情和相关内容的成功路径无法到达；同时，390 px 移动端筛选对话框被压缩在工具栏形成的局部区域内，实测可视高度仅 104 px，属于主操作路径的严重可用性问题。两项均达到 P1，未满足任务要求的 `P0=0、P1=0` 与 `decision=pass` 出口。

按统筹部收口约束，本轮在确认 P1 与成功态不可达后停止继续枚举页面和截图，没有开启第二轮浏览器检查，也没有修改实现或扩展设计范围。

## 3. P1 问题

### P1-01：公开首页与详情成功路径被 closed 500 阻断

**现象**

- `GET /api/public/feed` 返回 HTTP 500、`application/problem+json`、`cache-control: no-store`，`reasonCode=PUBLIC_READ_INTEGRITY_FAILED`。
- 已存在的公开 ID `public-demo-archive-gearbox` 对应详情 API 同样返回 HTTP 500 与 `PUBLIC_READ_INTEGRITY_FAILED`。
- 合法格式但不存在的公开 ID `public-demo-does-not-exist` 也在完整性检查处返回同一 500，因而无法抵达客户端 404 视图。
- 首页真实出口显示“公开信息流暂时不可用”；详情真实出口显示“公开内容暂时不可用”。重试按钮可触发新请求，但 250 ms 后仍返回同一闭合错误态。

**影响**

- 首页卡片、筛选结果、详情正文与相关内容全部不可用。
- loading、empty、no-more、restricted、media-missing、图片失败与 404 等状态无法在真实候选上完成视觉验收。
- 该问题阻断公开产品的核心阅读路径，判定为 P1。

**根因状态**

- 设计部只读验收能够确认 API 完整性失败这一外部表现。
- 数据链完整性失败的具体来源未在本任务内诊断，根因记为未知，交由开发部/测试部定位。

### P1-02：390 px 移动筛选对话框被压缩为局部滚动窗口

**现象**

- 打开“筛选公开内容”后，语义状态为 `role=dialog`、`aria-modal=true`，焦点正确进入“全部”。
- 对话框实测矩形为 `x=25、y=404、w=340、h=104`，没有覆盖预期的移动视口工作区。
- 对话框内部出现狭窄滚动区域；自动聚焦“全部”后，标题和关闭操作离开当前可视区域，分类控件与“查看 0 条内容”无法同时建立清晰的操作上下文。
- 所有可见筛选按钮高度均为 44 px，但 104 px 的容器高度显著削弱主筛选流程的可发现性与可操作性。

**影响**

- 移动端主筛选流程需要在一个异常狭窄的局部容器内滚动，关闭、分类与确认动作无法稳定同屏理解。
- 问题独立于 API 500；即使数据恢复，390 px 筛选仍存在严重可用性障碍，判定为 P1。

**根因状态**

- 只读检查观察到筛选面板使用 fixed 布局且其祖先工具栏使用玻璃效果；二者可能形成异常包含关系。
- 本任务没有修改实现或进行隔离实验，具体 CSS 根因仍记为待开发确认。

**证据**

## 4. 已验证项目

### 4.1 失败闭合与信息表达

- 首页与详情在 API 500 时均显示明确中文错误标题、原因说明与“重试”操作。
- 错误时没有回退到静态演示卡片，用户不会将伪造成功态误认为真实数据。
- 首页错误态使用 `role=alert`；详情错误态使用 `role=alert`。
- 390 与 1440 的错误态均无横向溢出：`documentElement.scrollWidth === clientWidth`。
- 390 浅色详情错误容器实测为 `358 × 253`，完整落在视口宽度内。

### 4.2 双主题与视觉层级

- 深浅主题切换可用，`html[data-theme]` 在 `dark` / `light` 间正确切换。
- 390 与 1440 的错误态在两主题下均保持标题、正文、边框和操作按钮可读。
- 1440 工具栏宽度 1376 px、分类面板宽度 1342 px，均落在视口内；桌面分类控件排列稳定。
- 视觉层级延续既有规范：深色默认、浅色清爽、蓝色动作强调克制，错误态没有引入突兀的警示色或误导性成功符号。

### 4.3 触控、焦点与语义

- 390 可见品牌入口、主题按钮、菜单、筛选触发器和重试按钮高度均为 44 px。
- 390 筛选面板中的关闭、五个分类和确认按钮高度均为 44 px。
- 品牌入口与筛选首项获得键盘焦点时，实测焦点样式为 3 px solid、2 px offset；焦点没有丢失。
- 移动筛选触发器正确更新 `aria-expanded`；关闭后恢复为 `false`。
- 当前分类通过 `aria-pressed=true` 表达，焦点打开后进入首个分类控件。

### 4.4 减少动效

- 浏览器模拟 `prefers-reduced-motion: reduce` 后媒体查询命中。
- HTML、BODY、主题按钮与错误容器的动画和过渡时长均降为 `1e-05s`，`transform=none`，滚动行为为 `auto`。
- 验证结束后已清除减少动效模拟并重置临时视口覆盖。

## 7. 复验准入条件

下一轮设计复验至少需要同时满足：

1. 唯一 `public-synthetic` 候选的 feed 与有效 detail API 返回 closed 200 DTO；合法缺失 ID 能进入约定 404 出口。
2. 390 px 移动筛选对话框恢复为可理解、可关闭、可完成分类选择与确认的完整工作区。
3. 开发部或测试部提供成功、空、失败、无更多、restricted、media-missing 与 404 的可达入口；无需新增演示 fallback。
4. 复验仍使用同一真实候选，覆盖 390/1440、深浅主题、键盘与减少动效。
