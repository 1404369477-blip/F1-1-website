## 1. 实现总则

### 1.1 页面壳层

四页共享同一 `F1PageShell`：

```text
F1PageShell
├─ F1TopBar
├─ F1DesktopNav / F1MobileMenu
├─ F1Main
│  ├─ F1PageHeader（页面标题、说明、操作区）
│  └─ page content
└─ F1ToastViewport
```

| 区域 | 桌面 | 平板 | 手机 | 约束 |
|---|---:|---:|---:|---|
| 顶部导航 | 64px | 60px | 56px | 玻璃只用于浮动功能层；内容必须保留顶部偏移 |
| 页面左右边距 | 32px | 24px | 16px | 宽屏最多 48px |
| 内容最大宽度 | 1440px | 100% | 100% | 详情正文另受 680px 限制 |
| 主栅格 | 12 列 | 8 列 | 4 列 | 沟槽分别 24 / 20 / 16px |
| 主触控目标 | 44px | 44px | 44px | 后台桌面可使用 36px 紧凑控件，但触控断点恢复 44px |

### 1.2 页面与路由提示

下表的 `route_hint` 只帮助开发组织页面，不冻结产品路由合同；实际路由应由产品与开发在 Kickoff 吸收。

| page_id | route_hint | 面向用户 | 默认主题 |
|---|---|---|---|
| `public-feed` | `/` 或 `/feed` | 公开访客 | 深色，可切换浅色 |
| `content-detail` | `/story/:storyId` | 公开访客 | 深色，可切换浅色 |
| `review-queue` | `/admin/review` | 审核者 | 深色，可切换浅色 |
| `source-management` | `/admin/sources` | 管理者 | 深色，可切换浅色 |

### 1.3 Appica／Base UI 交互映射

实现参考：[appica-dev/appica-ui](https://github.com/appica-dev/appica-ui)。本合同借用其公开组件的交互语义、状态组织和 Base UI 组合方式；不复制官网演示资产、品牌内容或页面版式。仓库代码的 MIT 标注不扩展到第三方演示素材。

| F1+1 组件 | 可参考 Appica 组件 | 必须保留的 F1+1 规则 |
|---|---|---|
| `F1Button` | Button / Button Group | 44px 触控高度、唯一 Primary、危险操作不使用信号橙红 |
| `F1Table` | Table | 语义表格、`aria-sort`、局部横向滚动、关键列优先 |
| `F1Dialog` | Dialog / Alert Dialog | 焦点陷阱、关闭后返回触发点、审核证据使用实色表面 |
| `F1Popover` | Popover / Dropdown Menu | 浮层玻璃可降级为不透明表面，Portal 主题类必须显式传递 |
| `F1Navigation` | Navigation / Navigation Menu | 当前项同时用文字重量与指示条表达，手机菜单独立表面 |
| `F1Breadcrumb` | Breadcrumb | 使用 `nav`、`aria-current="page"`，分隔符为装饰内容 |
| `F1Tabs` | Tabs | 选中态不依赖颜色，键盘方向键行为保持原生语义 |
| `F1Field` | Field / Form / Input | 常驻 label、错误信息关联、只读与禁用分离 |
| `F1StatusBadge` | Badge / Chip | 颜色 + 图标 + 文字三重表达，`unknown` 不隐藏 |
| `F1Skeleton` | Skeleton / Loader | 固定布局尺寸，减少动效时关闭 shimmer |
| `F1Toast` | Toast | 仅汇报轻量结果；需要决策的失败放入页面上下文 |

接入时不得把 Appica 的 `styles.css` 作为 F1+1 全局视觉基座；应使用适配层将 F1+1 Token 映射到组件变体。所有 `render` 组合必须遵守语义：链接保持链接、按钮保持按钮，视觉覆盖放在 wrapper 上，结构属性放在被渲染元素上。

## 3. 核心组件交接

### 3.1 `F1TopBar`

**用途**：四页共享的全局导航和主题工具。

**槽位**：`brand`、`primaryNav`、`search`、`themeToggle`、`accountOrMenu`。

**状态**：默认、滚动后、主题切换中、移动菜单关闭、移动菜单打开、菜单焦点内、减少动效。

**响应式**：

- 桌面：完整主导航，右侧显示搜索、主题切换和账户/菜单。
- 平板：保留主要栏目，低优先级入口收入更多菜单。
- 手机：品牌 + 搜索/主题工具 + 菜单按钮；菜单为独立不透明或玻璃表面。

**无障碍**：

- 使用 `header` + `nav`；当前栏目有 `aria-current="page"`。
- 菜单按钮有 `aria-expanded` 和 `aria-controls`。
- 打开菜单后焦点进入第一项；Escape 关闭并返回触发按钮。
- 主题切换按钮有当前主题的可读名称，不使用仅图标无名称。

### 3.2 `F1PageHeader`

**用途**：页面标题、说明、筛选/主操作。

**结构**：`eyebrow`（可选）→ `h1` → `description`（可选）→ `actions`。

**规则**：每页只有一个 H1；动作区不能压缩标题到不可读宽度；手机改为标题下方纵向排列。

### 3.3 `F1StoryCard`

**用途**：公开信息流和相关内容。

**结构**：`media` → `category/status` → `title` → `summary` → `sourceMeta` → `actions`。

**规则**：

- 内容层实色表面，`radius.editorial=4px`。
- 桌面标题最多 3 行，手机最多 4 行；不能截断唯一关键信息。
- 整卡可点击时，原文链接、收藏、分享等内部操作必须有独立焦点和语义。
- 图片缺失使用中性占位，不伪造赛车摄影。

### 3.4 `F1SourceMeta`

**字段**：平台/站点、作者、来源发布时间、采集时间（需要时）、原文入口、来源状态。

**规则**：未知字段显示“未知”或“未核验”；外链同时显示图标和“查看原文”文字；禁止用破折号隐藏未知语义。

### 3.5 `F1StatusBadge`

**状态映射**：

| status_id | 文案示例 | 角色 | 图标语义 |
|---|---|---|---|
| `unknown` | 未核验 | neutral | `circle-question` |
| `queued` | 已入队／处理中 | action | `loader` |
| `pending-review` | 待审核 | warning | `clock` |
| `success` | 已发布／正常 | success | `check` |
| `disabled` | 已停用／已拒绝 | neutral-strong | `ban` |
| `failed` | 处理失败 | danger | `triangle-alert` |
| `blocked` | 受限／阻断 | warning/danger | `lock` |

颜色、图标和文字必须同时存在；`LIVE` 可以使用信号橙红，但不能与后台错误共用相同语义。

### 3.6 `F1DataTable`

**规则**：

- 使用原生语义表格；表头 13px/600，正文 15px/400。
- 行高桌面 48px、双行 64px、触控端至少 56px。
- 数字使用等宽数字并右对齐；排序通过 `aria-sort` 表达。
- 仅局部分页／横向滚动，不允许页面级横向溢出。
- 手机只保留标识、状态、时间和主操作，次级字段进入详情行或抽屉。

### 3.7 `F1ReviewActionBar`

**操作**：`save-draft`、`approve`、`reject`。

- `approve`：Primary；必须显示绑定的内容版本/Bundle 摘要。
- `reject`：Destructive；必须要求拒绝理由或明确原因选择。
- `save-draft`：Secondary；保存后显示版本变化和“需要重新审核”的提示。
- 编辑已经通过的内容时，旧批准绑定失效；页面必须显示“编辑后需重新审核”。
- 所有操作均可键盘完成；危险动作通过确认 Dialog 二次确认。

### 3.8 `F1Dialog`、`F1Drawer`、`F1Toast`

- Dialog 用于确认和短内容；Drawer 用于审核详情、信源详情和手机筛选。
- 打开时焦点进入标题或首个可操作控件，关闭后返回触发点。
- 审核证据和错误详情使用实色表面，避免文字叠在透明背景上。
- Toast 只反馈轻量结果，不代替页面级错误或审核决定。
- Portal 渲染时显式传递主题类；玻璃不可用、减少透明度或强制色模式时使用不透明表面。

## 4. 页面一：公开信息流 `public-feed`

### 4.1 页面目标

让访客快速判断“发生了什么、来源是谁、是否值得深入阅读”，完成信息流 → 详情 → 原文的阅读闭环。

### 4.2 桌面布局（12 列）

```text
F1TopBar
PageHeader：栏目名 + 说明 + 搜索/主题工具
FeaturedGrid：主头条 8 列 + 次级内容 4 列
FeedToolbar：来源筛选、内容类型筛选、刷新状态
StoryGrid：3 列卡片，24px 沟槽
LoadMore / NoMore
```

- 首屏只保留一个主视觉重心；主头条不超过 1 条，次级内容最多 2 条。
- 普通信息流优先使用 3 列；页面内容不足时不强行填充空卡片。
- 头条可以使用 16:7 或 16:9，普通卡片使用 3:2。

### 4.3 平板与手机

| 设备 | 重排 |
|---|---|
| 平板 768–1199px | 主头条占 5 列，次级内容占 3 列；StoryGrid 2 列；筛选可横向换行 |
| 手机 320–767px | 主头条纵向图片在上；StoryGrid 1 列；筛选进入可关闭面板，已选条件保留为 Chip |

### 4.4 组件清单

- `F1TopBar`
- `F1PageHeader`
- `F1FeaturedStory`
- `F1StoryCard`
- `F1SourceMeta`
- `F1FilterBar`
- `F1FilterDrawer`
- `F1StatusBadge`
- `F1SkeletonCard`
- `F1EmptyState`
- `F1ErrorState`
- `F1NoMore`
- `F1Toast`

### 4.5 页面状态

| 状态 | 展示 | 主要动作 |
|---|---|---|
| `loading` | 保持头条与卡片比例的 Skeleton | 无 |
| `empty` | “暂时没有符合条件的内容” + 清除筛选 | `clear-filters` |
| `error` | 说明信息流加载失败 + 重试 | `retry` |
| `partial` | 已加载数量 + 失败来源提示 | `view-failures` 或继续阅读 |
| `offline/restricted` | 最近可用内容 + 更新时间 + 受限原因 | `retry` |
| `no-more` | “已无更多内容” | 无 |
| `live-refresh` | 不打断阅读的新增提示条 | `view-new` |

### 4.6 无障碍验收

- 主内容为 `main`，信息流为 `section`/`ul`，每张卡片有可读标题。
- 新内容提示使用 `aria-live="polite"`，不自动抢焦点。
- 筛选按钮有明确名称和选中状态；Drawer 打开后焦点留在面板内。
- 图片替代文本描述实际内容；纯装饰点阵和渐变 `aria-hidden="true"`。
- 主题切换、刷新和清除筛选都可用键盘完成。

## 5. 页面二：内容详情 `content-detail`

### 5.1 页面目标

展示可追溯的中文整理、来源证据、相关媒体和原文入口；保持正文阅读稳定，不让玻璃材质或赛事装饰干扰内容。

### 5.2 桌面布局（12 列）

```text
Breadcrumb / category / sourceMeta
ArticleHeader：标题 8 列 + 右侧状态/分享工具 4 列
LeadMedia：最大 960px，必要时跨 10–12 列
ArticleBody：正文最大 680px
EvidencePanel：正文右侧 4 列或正文下方折叠区
RelatedStories：3 列
```

- 正文最大宽度 680px，中文正文 17px/1.65。
- 主媒体保持原始比例或最大 16:9，不强制拉伸。
- 来源证据使用实色表面，外链入口始终可见。

### 5.3 平板与手机

- 平板：正文 5 列，证据 3 列；媒体跨 8 列。
- 手机：所有区域单列；标题、导语、媒体、正文、证据依次排列；证据可使用折叠面板，但原文入口不得隐藏在不可发现的二级层。
- 分享、收藏等工具放在标题下方或底部悬浮工具条，不遮挡正文。

### 5.4 组件清单

- `F1TopBar`
- `F1Breadcrumb`
- `F1ArticleMeta`
- `F1ArticleHeader`
- `F1LeadMedia`
- `F1ArticleBody`
- `F1KeyFacts`
- `F1SourceEvidence`
- `F1ExternalLink`
- `F1CorrectionBanner`
- `F1RelatedStoryList`
- `F1SkeletonArticle`
- `F1ErrorState`
- `F1NotFoundState`

### 5.5 页面状态

| 状态 | 展示 | 主要动作 |
|---|---|---|
| `loading` | 标题、媒体、正文骨架保持最终比例 | 无 |
| `not-found` | 内容不存在或已下架的说明 | `back-to-feed` |
| `error` | 内容加载失败 + 重试 | `retry` |
| `withdrawn` | 内容已撤回，保留必要更正说明 | `back-to-feed` |
| `media-missing` | 无图占位 + 来源信息 | `open-source` |
| `source-restricted` | 原文受限说明，不伪造可读正文 | `open-source` |
| `correction` | 更正标记、更新时间、新旧版本说明 | `view-source` |

### 5.6 无障碍验收

- 使用 `article`、`header`、`main`、`aside` 和 `nav` 语义结构。
- Breadcrumb 当前项使用 `aria-current="page"`。
- 主标题、导语、正文和证据区的标题层级连续，不跳级。
- 引用/来源链接提供明确的可读文本，不能只放外链图标。
- 媒体说明、署名和授权状态与媒体建立程序化关联。

## 6. 页面三：审核队列 `review-queue`

### 6.1 页面目标

让审核者在同一上下文中核对原文、中文整理、媒体候选、版本标识和审核动作，不依赖颜色或隐含状态作决定。

### 6.2 桌面布局（12 列）

```text
F1TopBar
ReviewPageHeader：待审核数量 + 刷新 + 视图工具
ReviewFilterBar：状态、来源、日期、内容类型
ReviewWorkspace
├─ ReviewList：4 列
├─ ReviewDetail：8 列
│  ├─ EvidenceBlock
│  ├─ DraftEditor
│  ├─ MediaCandidate
│  ├─ VersionMeta
│  └─ ReviewActionBar
```

- 列表项必须显示：标题、来源、发布时间、当前业务状态、更新时间、是否有媒体。
- 详情区顶部显示当前 `content_version`、Bundle/Hash 摘要和“编辑后需重新审核”提示。
- 审核动作靠近详情底部，但在长内容页面中保持可发现；可以使用非遮挡的粘性底栏。

### 6.3 平板与手机

- 平板：列表 3 列 + 详情 5 列，筛选独立一行。
- 手机：列表和详情分为两个连续视图；从列表打开详情页或全屏 Drawer；审核操作固定在底部安全区上方。
- 移动端拒绝理由使用全屏 Dialog/Drawer，不能使用小型 Popover 承载长文本。

### 6.5 页面状态与动作

| 状态 | 展示 | 可用动作 |
|---|---|---|
| `loading-list` | 列表骨架 | 无 |
| `empty` | 当前筛选无待审核项 + 清除筛选 | `clear-filters` |

| `saving` | 禁止重复提交，显示保存中 | 无或取消 |
| `saved-needs-review` | 显示新版本与“需要重新审核” | `approve`、`reject` |
| `approve-confirm` | 说明将发布绑定 Bundle | `confirm-approve`、`cancel` |
| `reject-confirm` | 说明拒绝原因将写入审计 | `confirm-reject`、`cancel` |
| `stale-version` | 当前项已被其他人更新 | `reload-latest` |
| `error` | 失败原因、错误编号、重试 | `retry` |
| `partial` | 证据可读但媒体缺失/受限 | `approve-without-media`（若业务合同允许）或返回 |

### 6.6 无障碍验收

- 队列使用 `section` + `ul` 或语义表格；选中项使用 `aria-current` 或明确选中状态。
- 详情编辑区的 label、帮助文本、错误文本均程序化关联。
- 保存、通过、拒绝动作有明确 accessible name，不能只读颜色。
- Dialog 具有名称、描述、焦点陷阱和 Escape 关闭；危险操作需要可读确认说明。
- `stale-version` 和保存结果使用 `aria-live="polite"`，不抢占正在编辑的输入焦点。

## 7. 页面四：信源管理 `source-management`

### 7.1 页面目标

让管理者查看白名单信源、启停状态、最近采集、适配器/授权状态和失败原因，并以可追溯方式处理信源配置。

### 7.2 桌面布局（12 列）

```text
F1TopBar
SourcePageHeader：信源数量 + 新增入口 + 刷新
SourceFilterBar：平台、生命周期、monitorability、状态
SourceTable：全宽 12 列
SourceDetailDrawer：点击行后打开，默认不覆盖关键表格语义
```

- 首要列：信源名称/URL、平台、生命周期、启用状态、最近采集、主要状态。
- 次要列：身份、相关性、适配器、授权复查时间、错误摘要；窄屏折叠到详情。
- `unknown` 必须显示为真实状态；不能显示成“正常”或空白。

### 7.3 平板与手机

- 平板：保留名称、平台、状态、最近采集、操作；其余字段进入展开行。
- 手机：卡片化详情行；主操作放在行末，详情 Drawer 负责编辑和错误详情。
- 新增信源表单使用全屏 Drawer；URL 字段可完整查看、复制和键盘操作。

## 8. 统一状态、响应式与无障碍验收矩阵

### 8.1 每页必须实现的状态

| 状态 | Feed | Detail | Review | Sources |
|---|:---:|:---:|:---:|:---:|
| 初始加载 | ✓ | ✓ | ✓ | ✓ |
| 空结果 | ✓ | — | ✓ | ✓ |
| 加载错误 | ✓ | ✓ | ✓ | ✓ |
| 部分成功/媒体缺失 | ✓ | ✓ | ✓ | ✓ |
| 受限/离线 | ✓ | ✓ | — | ✓ |
| 无更多 | ✓ | — | — | — |
| 无权限/不可访问 | — | ✓ | ✓ | ✓ |
| 危险动作确认 | — | — | ✓ | ✓ |
| 版本过期/并发冲突 | — | — | ✓ | — |

### 8.2 响应式验收宽度

| 宽度 | 重点 |
|---:|---|
| 320px | 页面无级别横向滚动；菜单、按钮和长中文可用 |
| 390px | 手机主要基准；筛选面板、详情 Drawer、审核底栏 |
| 768px | 平板 8 列；Feed 2 列；后台列表/详情并列 |
| 1024px | 平板上限；表格关键列和页面 Header 不拥挤 |
| 1200px | 桌面起点；12 列和完整后台工作区 |
| 1440px | 主验收宽度；常规内容不超过 1440px |
| 1600px | 宽屏；容器不无限拉宽，保留两侧呼吸区 |

### 8.3 无障碍统一清单

- 普通文字至少 4.5:1，大文字至少 3:1，关键非文本元素至少 3:1。
- 所有功能支持键盘；Focus-visible 使用 3px action 外环并保留 2px 偏移。
- 主要触控目标 44×44px；后台桌面紧凑控件不得在触控断点保留 36px。
- 语义区域、标题、列表、表格、表单和 Dialog 完整。
- 颜色不单独表达状态；`unknown`、失败、受限、已发布均有文字和图标。
- `prefers-reduced-motion: reduce` 取消位移、缩放、自动播放和 Skeleton shimmer。
- `forced-colors: active` 取消玻璃模糊，使用系统颜色、轮廓和文本状态。
- 200% 缩放不丢失内容和功能；只有局部表格/代码容器允许水平滚动。

## 9. 素材与许可边界

### 9.1 可用

- F1+1 设计规范中定义的原创几何、颜色、Token 和占位图形。

- 网络上下载但没有逐项授权证据的图片、图标、字体或视频。
- 付费资源、素材站水印图、未确认的 AI 生成素材许可。
- 直接复制 Appica 官网中的演示图片、品牌内容或页面资产；Appica 的 MIT 代码许可不等于其演示资产全部可复制。

### 9.3 失败降级

- 无授权图片：中性占位 + 原文入口。
- 字体许可/加载失败：系统字体栈，保持字号和层级。
- 视觉参考页面不可达：以已冻结规范和仓库本地样板为准，不编造素材来源。
