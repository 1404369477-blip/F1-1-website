## 0. 使用与变更规则

这份文件是页面设计的视觉与交互基础，不定义新功能、业务流程或数据合同。

- **已冻结原则**：用户在设计部会话中逐项确认，后续页面应直接复用。
- **首版默认值**：为让页面设计可执行而补齐的数值；页面验证发现问题时通过新版本调整。
- **待页面验证**：需要在公开信息流、详情页、审核队列和信源管理的真实页面上验证。
- 页面设计可以组合既有模式，不得擅自新增页面、主流程或业务状态。
- 修改核心颜色、字体家族、造型原则、主要断点或全局导航模式时，升级规范版本并记录原因。

### 0.1 已冻结的视觉决定

1. 品牌气质：专业、克制、高质量体育媒体感。
2. Apple OS 负责系统骨架、交互清晰度和极简高级感。
3. BMW M 负责硬朗标题、编辑结构和影像张力。
4. 赛车感集中在摄影、赛事数字和短促动效。
5. 默认深色，可切换浅色。
6. 毛玻璃克制用于导航、控件和浮层，不进入正文与常规资讯卡片。
7. 造型原则：**控件圆润，内容硬朗；系统清爽，影像有速度。**
8. 双字体体系：阅读字体 + 赛车展示字体。
9. 工业正体为主，速度斜体仅用于赛事强调。
10. 中英文兼容，开源或可自托管字体优先。
11. 字体组合：Inter + 思源黑体 CN + Barlow Condensed。
12. 中性色占绝对主体；低饱和交互蓝 + 少量信号橙红。
13. 真实新闻摄影为主，头条允许适度电影感，常规内容保持自然色彩。
14. 前台中等密度，后台高效密度。
15. 系统动效柔和，赛事动效短促且有方向感。

## 1. 设计定位

### 1.1 一句话设计目标

让用户在高密度 F1 资讯中快速判断“发生了什么、来源是谁、是否值得深入阅读”，同时维持克制、可信和具有赛车张力的品牌体验。

### 1.2 三层视觉分工

| 层 | 负责内容 | 视觉表达 |
|---|---|---|
| 系统层 | 导航、筛选、主题、表单、弹窗、反馈 | Apple 式清晰层级、轻量材质、圆润控件 |
| 编辑层 | 标题、栏目、卡片、页面节奏 | BMW M 式硬朗正体、方正框架、细分隔线 |
| 赛事层 | LIVE、排名、时间、专题与头条 | 紧凑数字、少量斜体、方向性动效、全幅影像 |

### 1.3 设计原则

- **内容优先**：视觉装饰不得压过中文摘要、来源和发布时间。
- **功能分层**：玻璃材质表示浮动功能层；实色表面承载内容。
- **少色高辨识**：大面积保持中性，颜色只表达交互、品牌瞬间或状态。
- **双密度**：前台保证阅读节奏，后台保证扫描与操作效率。
- **可追溯**：来源证据、原文入口、处理状态和失败原因必须可辨识。
- **跨设备一致**：组件语义稳定，布局随宽度重排，不按比例缩小桌面页。
- **可访问先行**：颜色、透明度、动效和字体都必须有降级路径。

#### 色彩占比

- 中性画布与表面：约 88–94%。
- 图片与媒体自然色：约 5–10%，随内容变化。
- 交互蓝：通常不超过当前视口可见面积的 2%。
- 信号橙红：通常不超过当前视口可见面积的 1%；不得铺满常规卡片或主按钮组。

#### 已验证的基础对比度

| 前景 / 背景 | 深色 | 浅色 | 结论 |
|---|---:|---:|---|
| 主文字 / 画布 | 18.06:1 | 15.46:1 | 通过普通文本 AA 与增强目标 |
| 次文字 / 画布 | 9.98:1 | 6.78:1 | 通过普通文本 AA |
| 第三级文字 / 画布 | 5.91:1 | 4.63:1 | 通过普通文本 AA；禁止降低透明度 |
| 白字 / 主按钮 | 4.65:1 | 6.08:1 | 通过普通文本 AA |
| 信号色 / 画布 | 7.48:1 | 4.74:1 | 可作文本与图标；仍需搭配标签或形状 |
| 强控件边界 / 相邻表面（最差值） | 3.33:1 | 3.11:1 | 通过非文本关键界面 3:1 |

> 玻璃表面与图片背景会改变实际对比度。任何覆盖图片的文字必须在最亮和最暗裁切区域复测；必要时添加实色遮罩，不使用平均色判断。

### 3.2 字体系统

#### 字体角色

| 角色 | 字体 | 用途 | 约束 |
|---|---|---|---|
| 拉丁正文与 UI | Inter Variable | 导航、按钮、英文正文、后台 | 400 / 500 / 600；启用等宽数字 |

```css
--font-display: "Barlow Condensed", "Inter", "Source Han Sans CN", "PingFang SC", sans-serif;
--font-cjk: "Source Han Sans CN", "PingFang SC", "Microsoft YaHei", sans-serif;
```

#### 混排规则

- 中文标题使用思源黑体 700；同一行的拉丁短词和数字可以切换 Barlow Condensed 700。
- 赛事数字启用 `font-variant-numeric: tabular-nums`，时间、名次和积分右对齐。
- 中文与英文之间由排版引擎或内容层补半角空格；数值与单位之间不随意断行。
- H1/H2 不整段使用斜体。中文禁止伪斜体。
- 正文单行建议 28–40 个全角中文字符；详情正文宽度以约 680px 为上限。
- 字体加载失败时保持信息层级和布局稳定，不使用依赖特定字体宽度才能成立的截断方案。

#### 字体交付约束

- 正式网页采用自托管 WOFF2；保存各字体许可证与来源版本。
- 思源黑体优先使用简体中文区域子集，并按实际字重或可变轴加载。
- 首屏只预载正文常用字重；展示字体延迟加载，禁止阻塞正文可读性。
- v0.1 HTML 样板未打包思源黑体文件；当前 macOS PNG 使用字体栈中的苹方回退。样板标签已显式标出 fallback，字形细节不能代替正式字体验收。

### 3.5 造型与圆角

| Token | 值 | 用途 |
|---|---:|---|
| `radius.editorial` | 4px | 新闻卡片、图片框、内容区 |
| `radius.field` | 10px | 输入框、下拉框、次级按钮 |
| `radius.control` | 12px | 常规按钮、切换控件 |
| `radius.glass` | 16px | 玻璃导航、Popover、浮层 |
| `radius.dialog` | 20px | 对话框与大型抽屉 |
| `radius.pill` | 999px | 状态、筛选 Chip、图标按钮 |

规则：

- 新闻图片与编辑容器保持 4px 硬边，不使用大面积 20px 以上圆角卡片。
- 可点击控件使用 10–16px 或胶囊圆角。
- 圆形只用于图标按钮、头像和明确的圆形数据标记。
- 同一组件不可混用两个圆角语法。

### 3.6 材质与层级

| 层级 | 表现 | 用途 |
|---|---|---|
| `elevation.base` | 无阴影、实色背景 | 页面与正文 |
| `elevation.content` | 实色表面 + 1px 分隔 | 新闻卡片、表格、表单 |
| `elevation.glass.control` | 72% 中性底 + 24px blur + 140% saturation | 顶部导航、悬浮筛选 |
| `elevation.glass.popover` | 84% 中性底 + 32px blur + 细边 + 柔和阴影 | 菜单、Popover、弹窗 |
| `elevation.glass.fallback` | 100% 不透明 `surface.1`，无 blur | 不支持模糊或减少透明度时的统一降级 |

玻璃规则：

- 仅用于浮在内容之上的功能层。
- `backdrop-filter` 不可用或用户开启减少透明度时，切换为不透明 `surface.1`。
- 文字较多、背景变化强或涉及审核证据时，优先实色表面。
- 不在玻璃上叠加第二层玻璃。
- 图片上的透明控件必须有局部暗化衬层并验证最差裁切对比度。

### 3.7 图标

- 采用统一的 1.75–2px 线性图标语言；实现库在 Kickoff 阶段决定。
- 默认 20px，紧凑处 16px，主操作 24px。
- 图标按钮至少 44×44px；图标本身不得代替可访问名称。
- 状态同时使用图标／形状和文字，不依赖颜色。
- 不直接分发 SF Symbols，也不复制 F1 或 BMW 专有图标。

## 4. 图片与媒体规范

### 4.1 视觉基调

- 真实新闻摄影为主，保持自然肤色、车身涂装与赛道环境。
- 头条允许适度提高对比、压低高光和强化主体分离；不套统一强滤镜。
- 不用大面积品牌色渐变替代内容图片。
- 图片缺失时使用中性赛事占位图、来源首字母或纯色结构，不能伪造现场照片。

### 4.2 比例与裁切

| 场景 | 桌面／平板 | 手机 | 规则 |
|---|---|---|---|
| 主头条 | 16:7 或 16:9 | 4:5 或 3:4 | 保留主体与标题安全区 |
| 常规资讯卡 | 3:2 | 16:9 | 同一列表内保持一致 |
| 横向信息流缩略图 | 4:3 | 4:3 | 不裁掉人物脸部与车号 |
| 详情正文媒体 | 原始比例，最大 16:9 | 原始比例 | 禁止强制拉伸 |
| 头像／来源标识 | 1:1 | 1:1 | 无标识时使用文字替代 |

- 内容数据应保存 `focal_point`；`object-position` 随断点调整。
- 图片必须提供准确替代文本；纯装饰背景使用空 `alt`。
- 图片署名、来源与授权信息位于媒体下方，12–13px，不覆盖关键画面。

### 4.3 图片状态

- 加载中：保持固定宽高比的中性 Skeleton，不使用高频闪烁。
- 加载失败：显示“图片加载失败”文字、重试入口与来源信息。
- 无授权或不可代理：不显示模糊盗链图，保留原文入口。
- 低清图片：不放大到头条；可以降级为列表缩略图。

## 5. 布局模式

### 5.1 公开信息流

1. 全局玻璃导航。
2. 一条主头条，可配最多两条次级内容。
3. 分类／来源筛选，保持在内容层上方但不遮挡标题。
4. 进入常规信息流后提高密度：桌面 3 列或“主列 + 侧列”，平板 2 列，手机 1 列。
5. 卡片优先顺序：图片 → 分类／状态 → 中文标题 → 摘要 → 来源与时间。
6. 首屏不得同时出现多个同等重量的大标题。

### 5.2 内容详情

1. 分类、来源与发布时间。
2. 中文标题与导语。
3. 主图及署名。
4. 进一步提炼内容。
5. 原始来源证据与清晰的外链入口。
6. 相关内容。

正文不使用毛玻璃；工具栏可以作为轻量玻璃浮层，但不得遮挡阅读。

### 5.3 审核队列

- 桌面使用“筛选／列表／详情”层级，列表扫描优先。
- 关键证据、中文整理结果、图片候选、版本 hash 与审核操作分区显示。
- 通过、拒绝、编辑后回审等操作必须靠近其作用对象，并显示不可逆影响。
- 危险或拒绝操作使用二次确认；普通通过操作仍需清楚展示绑定版本。
- 表格密度可以紧凑，但正文证据区域保持正常阅读字号。

### 5.4 信源管理

- 先展示信源名称／URL、平台、启停、最近采集与错误状态。
- `unknown` 作为真实状态显示，不用空白或“正常”代替。
- 状态与操作分列；错误原因提供可展开详情。
- 手机端将次级列折叠为详情行，保留名称、状态、最近采集和主要操作。

## 6. 组件规范

### 6.1 全局导航

- 桌面高度 64px，平板 60px，手机 56px。
- 玻璃层固定在视口顶部时必须保留内容偏移，不能遮挡锚点标题。
- 左侧为 F1+1，自身导航居中或紧随其后；主题切换、搜索等工具在右侧。
- 当前栏目用文字重量 + 2px 指示条／底色表达，不只改变颜色。
- 手机折叠菜单为独立表面，展开后焦点进入菜单并可返回触发按钮。

### 6.2 按钮

| 类型 | 用途 | 视觉 |
|---|---|---|
| Primary | 每个操作组唯一主操作 | 交互蓝实底、白字 |
| Secondary | 次级操作 | `surface.2` 实底或细边 |
| Ghost | 工具栏低优先操作 | 透明底，悬停出现中性底 |
| Destructive | 删除、拒绝、停用等 | 危险色文字／轮廓；确认层才允许实底 |
| Icon | 收藏、分享、展开 | 圆形或圆润方形，必须有名称 |

- 默认高度 44px；后台桌面紧凑按钮可为 36px，但触控断点恢复 44px。
- 文字按钮不得只在 hover 时显示下划线；键盘焦点始终可见。
- 信号橙红不作为全站主操作填充色。

### 6.3 筛选、Chip 与标签

- 可交互筛选使用按钮语义和胶囊外形；静态状态标签不可伪装成按钮。
- 选中状态同时使用背景、边框和字重。
- 分类文本使用正常大小写；`LIVE`、车手缩写、短赛事状态可大写。
- Chip 过多时换行或进入“更多筛选”，不在手机端水平堆叠到不可发现区域。

### 6.4 资讯卡片

- 内容框架 4px 圆角或近方形；不加大投影。
- 卡片整体可点击时，内部来源链接和操作必须保持独立焦点与语义。
- 标题桌面最多 3 行、手机最多 4 行；不能截掉唯一关键信息。
- 卡片悬停以图片轻微放大（≤1.02）、边框变化或标题颜色响应，避免整卡大幅漂浮。
- 重复事件、转载和原始来源使用明确文字标签。

### 6.5 来源证据模块

- 展示平台／站点、作者、发布时间、原始链接和采集时间。
- 外链图标与“查看原文”文字同时出现。
- 不确定字段显示 `未知` 或 `未核验`，不能用破折号掩盖语义。
- 审核页中的证据模块使用实色表面，不使用透明材质。

### 6.6 输入与表单

- 默认高度 44px；多行输入最小 120px。
- 标签常驻输入框上方；placeholder 只示例格式，不代替标签。
- 错误状态包含图标、错误文本和字段关联；颜色只作辅助。
- 禁用与只读状态必须区分：禁用降低交互提示，只读保持可读与可复制。
- URL 字段允许完整查看、复制和键盘操作。

### 6.7 表格与列表

- 表头 13px / 600，正文 15px / 400；数字采用等宽数字并右对齐。
- 桌面默认行高 48px；含两行信息时 64px；触控端至少 56px。
- 只用水平分隔线，不用高密度垂直网格。
- 关键列可吸附；横向滚动容器必须显示滚动提示并保持键盘可达。
- 排序状态由图标 + `aria-sort` 表达。

### 6.8 弹窗、抽屉与通知

- 确认对话框宽度 360–520px；复杂编辑使用侧边抽屉或独立页。
- 弹窗可使用较厚玻璃或高不透明表面，背景加遮罩。
- 打开后焦点进入标题或首个控件；关闭后返回触发点。
- Toast 只汇报已完成的轻量结果，不承载需要用户决定的错误。

## 7. 状态系统

### 7.1 通用交互状态

所有可交互组件至少定义：Default、Hover、Focus-visible、Pressed、Selected、Disabled、Loading、Error。

- Focus-visible：3px `color.action` 外环，2px 偏移；不能被 `overflow: hidden` 裁掉。
- Loading：保留原控件尺寸，防止布局跳动；按钮显示动词上下文，如“正在保存”。
- Disabled：不需要满足非文本对比豁免之外的交互要求，但原因必须在上下文中可理解。
- Error：错误信息与字段／任务建立程序化关联。

### 7.2 业务状态映射

| 业务语义 | 视觉角色 | 示例 |
|---|---|---|
| 未开始／未知 | Neutral + `?` 图标 + 文字 | `unknown`、待规范化 |
| 排队／处理中 | Action + 进度图标 + 文字 | 已入队、待整理、重试中 |
| 待人工决定 | Warning + 审核图标 + 文字 | 待审核、重复待判 |
| 正常／成功 | Success + 对勾 + 文字 | 已发布、授权有效、采集正常 |
| 停用／拒绝 | Neutral strong + 禁止图标 + 文字 | 已停用、已拒绝 |
| 失败／危险 | Danger + 警示图标 + 文字 | 采集失败、发布失败、授权失效 |
| 受限／阻断 | Warning 或 Danger + 锁／阻断图标 | 平台受限、适配器缺失 |

- 信号橙红主要用于 LIVE 与重大赛事强调；后台失败优先使用独立 Danger 色。
- 同一颜色不得同时表示“可点击”“直播”和“错误”。

### 7.3 页面状态

| 状态 | 必须包含 |
|---|---|
| Empty | 原因、当前筛选条件、下一步；无权限时不诱导创建 |
| Loading | 固定布局的 Skeleton 或明确进度；避免无限空白 |
| Error | 发生位置、可理解原因、重试／返回出口、必要时错误编号 |
| Offline / 受限 | 最近可用信息、更新时间、恢复条件 |
| No more | 明确“已无更多内容”，不继续显示加载动画 |
| Partial | 成功与失败数量、失败项入口，不能只报总体成功 |

## 8. 响应式规则

### 8.1 重排原则

- 断点由内容是否拥挤决定，表中宽度是首版默认值。
- 网格减少列数，卡片保持可读宽度；不缩小到桌面卡片的迷你版本。
- 主头条从左右分栏切换为图片在上、文字在下。
- 后台表格优先保留标识、状态、时间和主操作；次级字段进入展开详情。
- 筛选在手机端进入可关闭的底部／侧边面板，已选条件仍在页面可见。

### 8.2 设备规则

| 项目 | 手机 | 平板 | 桌面／宽屏 |
|---|---|---|---|
| 导航 | 品牌 + 2 个工具 + 菜单 | 精简水平导航 | 完整导航 |
| 信息流 | 1 列 | 2 列 | 3 列或主次双区 |
| 后台列表 | 卡片化详情行／横向表 | 关键列 + 展开 | 完整表格 |
| 主头条 | 纵向 4:5 / 3:4 | 16:9 | 16:7 / 16:9 |
| 页面边距 | 16px | 24px | 32–48px |
| 主要控件 | ≥44px | ≥44px | 44px；紧凑场景可 36px |

### 8.3 缩放与文本重排

- 浏览器缩放 200% 时不得丢失内容或功能。
- 320px 宽度不得产生页面级水平滚动；仅允许明确标识的表格／代码等局部容器滚动。
- 字体变大时，内联元数据改为纵向堆叠；重要操作不得被截断为图标且失去名称。

## 9. 动效规范

| Token | 时长 | 缓动 | 用途 |
|---|---:|---|---|
| `motion.instant` | 120ms | `ease-out` | 颜色、边框、按下反馈 |
| `motion.control` | 180ms | `cubic-bezier(.2,.8,.2,1)` | Hover、Popover、小控件 |
| `motion.system` | 240ms | `cubic-bezier(.2,.8,.2,1)` | 抽屉、主题切换、模块重排 |
| `motion.race` | 320ms | `cubic-bezier(.16,1,.3,1)` | 头条切换、LIVE 方向性进入 |
| `motion.exit` | 160ms | `ease-in` | 关闭与退出 |

规则：

- 常规系统动效使用淡入、2–8px 位移、轻微缩放；不模拟真实弹簧反复回弹。
- 赛车动效只用于头条、直播和赛事专题；后台表格不使用扫光或持续运动。
- 图片 hover 最大缩放 1.02，持续 240ms。
- 禁止自动循环闪烁、滚动劫持和长时间视差。
- `prefers-reduced-motion: reduce` 时取消位移、缩放和自动播放，只保留必要的即时状态变化。

## 10. 可访问性与性能

### 10.1 WCAG 2.2 导向基线

- 普通文本对比度至少 4.5:1；大文本至少 3:1。
- 控件边界、焦点和有意义图形至少 3:1。
- 指针目标至少满足 24×24 CSS px；F1+1 默认以 44×44px 作为主要触控目标。
- 所有功能可通过键盘完成；焦点顺序与视觉顺序一致。
- 颜色不单独承担状态、排名变化或错误含义。
- 页面语义使用标题、导航、主区域、列表、表格与表单标签。
- 图片提供替代文本，赛事数据表提供可理解表头。
- 状态更新使用合适的 live region，避免每次轮询都打断屏幕阅读器。

参考：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)、[Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

### 10.2 透明度与高对比降级

- 无 `backdrop-filter` 或用户开启减少透明度：玻璃层变为 100% 不透明 `surface.1`。
- `forced-colors: active`：使用系统颜色，保留轮廓与文字状态。
- 增强对比模式：加深分隔线、取消低透明度次级文字。
- 图片上的文字在高对比模式中切换为实色文字块。

### 10.3 性能预算方向

- 首屏字体：只预载正文常用字重；展示字不阻塞正文。
- 响应式图片提供尺寸、格式和懒加载；首图除外。
- 模糊只出现在少量固定尺寸功能层；移动端降低 blur 强度和透明区域面积。
- Skeleton 数量与最终内容结构一致，禁止无意义整页 shimmer。
- 动效只使用 transform 与 opacity 为主，避免持续触发布局计算。

## 11. 新页面套用顺序

1. 从 Spec 确认页面目标、用户、数据和状态。
2. 选择现有布局模式：公开信息流、内容详情、审核队列或信源管理。
3. 先排信息层级和失败路径，再选组件。
4. 应用统一栅格、字体和颜色 token。
5. 只在浮动功能层使用玻璃；内容层使用实色表面。
6. 补齐 Loading、Empty、Error、Partial、No more 状态。
7. 完成桌面、平板、手机三档设计。
8. 检查键盘焦点、对比度、200% 缩放、减少动态效果和透明度降级。
9. 提供可视化预览，由用户确认页面视觉与交互方向后再进入正式实现。

## 12. 推荐与禁止

### 推荐

- 用一条强头条建立首屏重心。
- 用来源、时间、状态和标题共同建立可扫描层级。
- 让摄影承担赛车张力，让系统 UI 保持安静。
- 交互蓝只表达操作，信号橙红只表达品牌瞬间和 LIVE。
- 在后台用实色表面、细线和紧凑排版提升效率。
- 为每个状态提供文字和图标双重识别。

### 禁止

- 整页或所有卡片使用毛玻璃。
- 大面积霓虹、彩色渐变、光晕与碳纤维纹理。
- 用 BMW M 三色条或 F1 官方红作为 F1+1 品牌捷径。
- 在正文和后台表格使用 Barlow Condensed 或斜体。
- 为追求速度感牺牲中文可读性。
- 只设计正常状态，遗漏空、错、慢、断网和部分成功。
- 移动端直接缩小桌面布局。
- 在图片上放低对比文字且没有实色保护层。

## 13. 页面设计验收清单

### 视觉一致性

- [ ] 符合“控件圆润、内容硬朗”。
- [ ] 中性色占主体，强调色面积受控。
- [ ] 正文和常规卡片没有毛玻璃。
- [ ] 展示字体只出现在短标题和赛事数字。
- [ ] 图片自然、无强制统一滤镜。

### 信息与状态

- [ ] 来源、作者、发布时间和原文入口可见。
- [ ] `unknown`、失败、受限、停用等状态没有被隐去。
- [ ] Loading、Empty、Error、Partial、No more 均有出口。
- [ ] 颜色之外还有文字或图标表达。

### 响应式

- [ ] 320px、768px、1200px 和 1600px 关键宽度无重叠或裁切。
- [ ] 手机端主要控件至少 44px。
- [ ] 表格有明确的窄屏策略。
- [ ] 200% 缩放不丢失内容与功能。

### 可访问性与性能

- [ ] 普通文字 4.5:1、非文本关键元素 3:1。
- [ ] 键盘焦点清楚、顺序正确。
- [ ] 减少动态效果和透明度降级有效。
- [ ] 图片有尺寸、替代文本、加载失败与授权状态。
- [ ] 字体和模糊没有造成首屏阻塞或移动端明显卡顿。

- 深色与浅色主题分别渲染为 1440×5397 PNG；主题按钮、URL 参数、可访问状态与色值展示同步切换。
- Chromium 在 320、390、768、1199、1200、1600px 下无页面级水平溢出；信息流分别重排为 1、1、2、2、3、3 列。
- 手机菜单通过 `aria-expanded` / `aria-controls` 表达展开状态；打开后焦点进入首个链接，Esc 关闭并回到触发按钮。
- 手机可见链接、按钮和输入控件均不小于 44×44px；页面只有一个 H1，无重复 ID、无缺名按钮／链接／输入框。
- 减少动态效果时，滚动平滑、按压位移与图片缩放均关闭；强制色模式下玻璃模糊关闭。
- 基础文字、主按钮与信号色组合通过 WCAG 2.2 AA 文本阈值；强控件边界在双主题相邻表面上的最差对比度分别为 3.33:1 与 3.11:1。
