# F1+1 VS-1 16 状态 UI 映射 v0.1

> 唯一结论：**proposed**。本文补齐 `/admin/sources` 的 16 个 `collection_onboarding_status` canonical machine key 到中文 label、UI alias、图标、现有 token、操作、ARIA 与 390/1440 呈现的一一映射。它是 C 层实现候选，不修改 accepted Spec/ADR/data，不构成页面实现或 VS-1 PASS。

## 1. 适用范围与权威顺序

本文只处理 Source 的 `collection_onboarding_status`。权威顺序固定为：

1. [`data/mvp-contract-v0/schema.json`](../../data/mvp-contract-v0/schema.json) 的 16 个 enum machine key；
2. [`data/mvp-contract-v0/state-machine.json`](../../data/mvp-contract-v0/state-machine.json) 的允许转换、guard 与 `platform > authorization > adapter` 优先级；
3. [`docs/spec.md`](../../docs/spec.md) 的 alias 只作展示、`unknown` 不得冒充正常、`paused` 只属于 `lifecycle_status` 等约束；
4. [`F1+1-首批页面实现级设计合同-v0.1.md`](F1+1-首批页面实现级设计合同-v0.1.md) 的 Sources 页面结构、组件和无障碍规则；
5. [`F1+1-首批页面token-map-v0.1.json`](F1+1-首批页面token-map-v0.1.json) 的现有颜色、Badge 角色、布局与可访问性 token；
6. [`VS-1 mock 采集链路测试计划`](../../docs/collaboration/部门/测试部/报告/2026-08-02-M4-VS-1-mock采集链路测试计划.md) §12、§16 的 `UI-STATE-01`、`UI-ALIAS-01`、390/1440 和对比度门槛。

以下内容不在本候选内：API route/DTO、权限实现、重试等待序列、validation job 形态、数据迁移、应用代码、真实 AT 和视觉截图。

## 2. 不变量

- `canonicalState` 必须逐字来自 data enum；UI alias 不写入数据库，不被 API 接受，不参与状态转换。
- 同一 canonical state 只有一个主中文 label 和一个主 UI alias；过滤器可以使用聚合分组，但分组不取代主 alias。
- Badge 始终同时显示图标和文字；颜色只作辅助。
- 所有可变操作仍受 loopback/session/Origin/CSRF、权限、三门、stop、五个 fence、重试预算和 operation/idempotency 约束；本文只定义按钮可见性与文案。
- `enabled`、`lifecycle_status`、`normalization_status`、`dedup_status`、identity/relevance/monitorability 与 canonical onboarding state 分列展示，不能互相覆盖。
- `paused` 只属于 `lifecycle_status`；空页、loading、error、partial 和 invalid/unknown guard 是页面/数据保护状态，不能计入 16 个 canonical states。

## 3. 组件消费接口

以下是展示适配器候选，不是领域 schema：

```ts
type SourceOnboardingCanonicalState =
  | "validating"
  | "activation_pending"
  | "queued"
  | "collecting"
  | "active"
  | "normalization_failed"
  | "dedup_needs_review"
  | "linked_existing"
  | "blocked_adapter_missing"
  | "blocked_authorization"
  | "blocked_platform"
  | "queue_failed"
  | "collection_failed"
  | "stopped"
  | "cancelled"
  | "dead_letter";

type SourceStatePresentation = {
  canonicalState: SourceOnboardingCanonicalState;
  uiAlias: string;              // display-only，禁止持久化
  labelZh: string;              // 本文冻结的唯一主文案
  badgeVariant: "queued" | "pending-review" | "success" | "disabled" | "failed" | "blocked";
  iconToken: "loader" | "clock" | "check" | "ban" | "triangle-alert" | "lock";
  colorToken: "color.action" | "color.success" | "color.warning" | "color.danger" | "color.text.secondary";
  ariaLabel: string;
  primaryActionId: string;
  primaryActionLabelZh: string;
  mutationAvailability: "read-only" | "contract-gated";
};
```

组件消费关系：

| 组件 | 必须消费 | 禁止行为 |
|---|---|---|
| `F1SourceStatusBadge` | `canonicalState` 经唯一映射得到 label、Badge variant、icon、token、`aria-label` | 直接接收任意 alias；用颜色替代文字；把 `unknown` 渲染为 success |
| `F1SourceRow` | canonical key、label、平台、lifecycle、enabled、最近采集、主操作 | 在 390px 隐藏状态；把状态按钮做成静态 Badge；页面级横滚 |
| `F1SourceFilterBar` | canonical key 过滤；可提供只读聚合分组 | 把 `failed/restricted/disabled` 聚合 alias 传回 API 当 machine key |
| `F1SourceDetailDrawer` | canonical key、machine transition 说明、gate/error、操作可用原因/禁用原因 | 省略失败原因；显示私密 URL、stack 或内部凭证；绕过安全门触发 mutation |
| `F1CapabilityList` | adapter/authorization/platform、identity/relevance/monitorability 独立状态 | 用 capability `unknown` 覆盖 onboarding canonical state |
| `F1DataTable` | 1440 下独立“生命周期／启用／采集状态／操作”列 | 合并为一个含义不清的“状态”列；排序无 `aria-sort` |

兼容现有设计 alias：`adapter_check_pending`、`enqueued`、`enabled`、`disabled` 保持原意；`normalization_pending` 和 `dedupe_pending` 作为 `validating` 的条件子文案；`restricted`、`failed` 是筛选聚合；`manual_only` 是策略 Badge；`unknown` 是字段/数据 guard。它们均不是第 17 个 onboarding state。

### 4.2 操作与禁止操作

操作 ID 是展示层候选，不冻结 HTTP 路径或 DTO。`contract-gated` 表示只有后续唯一 admin mutation 合同和全部安全/业务 guard 通过时才可启用。

| canonical machine key | 主操作 ID / 文案 | 可见条件 | 禁止操作与禁用原因 |
|---|---|---|---|
| `validating` | `view-validation` / 查看校验 | 始终只读可用 | 禁止启用、采集和 activation retry；规范化/查重完成前不得生成 activation/collection operation |
| `activation_pending` | `view-gates` / 查看激活检查 | 始终只读可用 | 禁止直接写 `enabled=true`；只能由原子激活事务进入 queued |
| `queued` | `view-task` / 查看任务 | 始终只读可用 | 禁止无 lease 进入 collecting；停止/取消另用确认操作并受安全门约束 |
| `collecting` | `view-collection` / 查看采集 | 始终只读可用 | 禁止重复启动；停止/取消须确认，旧 worker 不得提交 |
| `active` | `view-source` / 查看信源 | 始终只读可用 | 禁止重复启用；停止/取消须确认且写审计 |
| `normalization_failed` | `retry-validation` / 修正后重试 | `contract-gated`；URL 已修正且 canonical valid | 禁止原值盲重试、直接激活或入队 |
| `dedup_needs_review` | `review-duplicate` / 审核重复候选 | `contract-gated`；具备人工审核权限 | 禁止跳过重复判断、静默创建第二 Source 或直接激活 |
| `linked_existing` | `open-linked-source` / 查看已关联信源 | 已有可读关联目标 | 禁止重复入队、重复创建或把关联结果显示为 active |
| `blocked_adapter_missing` | `view-adapter-requirements` / 查看适配器要求 | 始终只读可用 | 禁止绕过 adapter；ready 后回 activation_pending 并重验全部门禁 |
| `blocked_authorization` | `view-authorization` / 查看授权原因 | 始终只读可用 | 禁止自动扩 scope、复用失效授权或直接入队 |
| `blocked_platform` | `view-platform-policy` / 查看平台限制 | 始终只读可用 | 禁止覆盖平台/合规阻断；恢复后先回 activation_pending 重验 |
| `queue_failed` | `retry-queue` / 重试入队 | `contract-gated`；预算未耗尽、same operation/key、gates/fences 通过 | 禁止无限重试、换 key 伪装重试或跳到 collecting |
| `collection_failed` | `retry-collection` / 重试采集 | `contract-gated`；预算未耗尽、新 lease、same operation/key | 禁止复用旧 lease、无限重试或跳到 active |
| `stopped` | `resume-source` / 恢复 | `contract-gated`；显式人工操作，全部门禁/fences 通过 | 禁止自动回弹；不创建第二 Source identity |
| `cancelled` | `reactivate-source` / 重新激活 | `contract-gated`；显式人工操作并创建新 operation id | 禁止复用已取消 operation、自动恢复或直接 collecting |
| `dead_letter` | `manual-requeue` / 人工复核 | `contract-gated`；人工审计、重新检查 normalization/dedup/gates/fences | 禁止自动重试、隐藏失败预算或直接 active |

所有 mutation 按钮都有 `pending/loading/success/error` 交互状态；pending 时保持原尺寸并禁用重复点击。危险停止、取消、恢复、重新激活和人工重新入队需要确认 Dialog，确认层必须写明影响对象、当前 canonical state 和 operation 约束。

### 4.3 ARIA 固定映射

Badge 作为状态文本，不使用按钮语义；图标 `aria-hidden="true"`。以下 `aria-label` 为唯一主读法：

| canonical machine key | `aria-label` | `aria-describedby` 必含信息 |
|---|---|---|
| `validating` | `采集状态：校验中` | 当前子步骤：待规范化或待查重；禁止直接启用 |
| `activation_pending` | `采集状态：待激活检查` | platform、authorization、adapter 与安全栅栏检查进度 |
| `queued` | `采集状态：已入队` | 尚未取得采集 lease |
| `collecting` | `采集状态：采集中` | 当前 operation 的可公开摘要与停止入口 |
| `active` | `采集状态：采集正常` | 生命周期和 enabled 字段另行读取 |
| `normalization_failed` | `采集状态：规范化失败` | 脱敏失败原因、最后检查时间、修正后重试条件 |
| `dedup_needs_review` | `采集状态：重复待审` | 重复候选数量和人工判断入口 |
| `linked_existing` | `采集状态：已关联现有信源` | 关联目标的可读名称；当前记录不重复入队 |
| `blocked_adapter_missing` | `采集状态：缺少适配器` | 缺失能力和恢复条件 |
| `blocked_authorization` | `采集状态：授权受阻` | 脱敏授权原因；禁止自动扩权 |
| `blocked_platform` | `采集状态：平台受限` | 平台/策略原因和恢复条件 |
| `queue_failed` | `采集状态：入队失败` | 错误摘要、重试计数/预算、同 key 限制 |
| `collection_failed` | `采集状态：采集失败` | 错误摘要、重试计数/预算、新 lease 条件 |
| `stopped` | `采集状态：已停止` | 停止原因、时间、恢复时需重新检查 |
| `cancelled` | `采集状态：已取消` | 取消原因、时间、重新激活将创建新 operation |
| `dead_letter` | `采集状态：等待人工处置` | 失败预算已耗尽；需要人工审计和重新入队 |

状态改变时，行内状态区域使用 `aria-live="polite"` 或统一页面级 polite live region。轮询不重复播报未变化状态；安全阻断仍由页面错误区提供可见文本，不自动抢焦点。

## 5. 390 与 1440 一一映射

### 5.1 共同布局规则

**390×844：** 使用卡片化详情行。第一行显示名称/平台，第二行显示完整图标+中文 label，第三行显示最近采集或失败摘要；行末只放一个主操作，其他可变/危险操作进入全屏 `F1SourceDetailDrawer`。所有目标 ≥44×44px，URL 可查看/复制/键盘操作，无页面级横滚。

**1440×900：** 使用 12 列 `F1DataTable`。名称/URL、平台、lifecycle、enabled、最近采集、canonical 状态和操作分列；Badge 不截中文 label，操作列不与状态列合并；次级 gate/error/identity/relevance/monitorability 进入 Detail Drawer。容器 ≤1440px，无页面级横滚。

## 6. alias、空、unknown 与 paused 边界

### 6.1 `validating` 的条件子文案

主映射始终是 `validating → validation_pending → 校验中`。现有 frozen alias 继续作为二级阶段文案：

| 条件 | 二级 alias | 二级中文文案 | 规则 |
|---|---|---|---|
| `normalization_status=pending` | `normalization_pending` | 待规范化 | 优先显示；仍不改变 canonical state |
| normalization 已完成且 `dedup_status=pending` | `dedupe_pending` | 待查重 | 只作为详情/副文案 |
| 两者值冲突或缺失 | `unknown` guard | 校验信息未核验 | fail closed；禁止激活/入队 |

### 6.2 过滤聚合 alias

| 聚合 alias | 包含 canonical states | 限制 |
|---|---|---|
| `restricted` | 三个 `blocked_*` | 只用于筛选组/计数；行 Badge 仍显示精确三种中文 label |
| `failed` | `normalization_failed`、`queue_failed`、`collection_failed`、`dead_letter` | 只用于筛选组；`dedup_needs_review` 不算失败 |
| `disabled` | `stopped` | `cancelled` 保留独立 alias，避免取消与停止混淆 |
| `manual_only` | 不映射 onboarding canonical state | 独立策略 Badge，不改变采集状态 |
| `unknown` | 缺失/非法 machine key 或 capability 未核验 | guard/能力状态，不是 canonical enum |

### 6.3 空页与无效状态

- `F1SourceEmptyState` 表示当前数据集/筛选无 Source，不渲染伪造的 onboarding Badge；提供“清除筛选”或按权限显示“新增信源”。
- loading/error/partial 属页面状态；错误态不暴露 stack、private URL 或内部拓扑。
- 若 API 返回缺失或不在 16 enum 内的 machine key，显示 guard：中文“状态数据无效”，使用 `failed` variant、`triangle-alert`、`color.danger`，`aria-label="采集状态：状态数据无效"`；所有 mutation 禁用，只允许刷新/返回/查看错误编号。这个 guard 不计入 16/16。
- capability 的 identity/relevance/monitorability/adapter/authorization `unknown` 使用 `unknown` variant、`circle-question` 和“未核验”，不能覆盖有效 onboarding Badge。

### 6.4 `paused` 边界

- `paused` 只写入 `lifecycle_status`；禁止传给 `collection_onboarding_status`、Badge mapper 或 onboarding filter。
- 390px：当 lifecycle=`paused` 时，卡片摘要主 Badge 显示“生命周期：已暂停”；canonical onboarding 状态移入同卡次行/Drawer 并标为“采集流程记录”，避免把 `active` 读成当前正在采集。
- 1440px：`lifecycle_status` 与 `collection_onboarding_status` 使用两列；生命周期列显示“已暂停”，采集状态列仍显示 canonical 映射。
- `aria-label` 组合示例：`生命周期：已暂停。采集流程记录：采集正常。当前暂停期间不得采集。`
- 恢复操作必须显式触发并重验 gates/fences；UI 不自动把 lifecycle 改回 active。

## 7. Token 与对比度合同

### 7.1 现有 token 映射

| Badge variant | icon | 前景 token | 表面 | 非文本边界 |
|---|---|---|---|---|
| `queued` | `loader` | `color.action` | `color.surface.1` 或 `.2` | `color.border.strong` |
| `pending-review` | `clock` | `color.warning` | `color.surface.1` 或 `.2` | `color.border.strong` |
| `success` | `check` | `color.success` | `color.surface.1` 或 `.2` | `color.border.strong` |
| `disabled` | `ban` | `color.text.secondary` | `color.surface.1` 或 `.2` | `color.border.strong` |
| `failed` | `triangle-alert` | `color.danger` | `color.surface.1` 或 `.2` | `color.border.strong` |
| `blocked` | `lock` | `color.warning` 或本表指定的 `color.danger` | `color.surface.1` 或 `.2` | `color.border.strong` |

不新增半透明 tint token。Badge 使用实色内容表面、现有前景 token、强边界、图标和文字；`forced-colors: active` 使用系统色和可见 outline，保留完整 label。

### 7.2 静态 token 对比度收据

按 WCAG 相对亮度公式对现有 hex token 机械计算；alpha 边界采用全站设计规范已经记录的最差相邻表面对比度。结果只证明 token 候选，真实 computed style 仍需 `UI-CONTRAST-01`：

| 前景 / 表面 | 深色 `surface.1` | 浅色 `surface.1` | 深色 `surface.2` | 浅色 `surface.2` | 结论 |
|---|---:|---:|---:|---:|---|
| `color.action` | 7.61:1 | 6.08:1 | 7.11:1 | 5.16:1 | 普通文字 ≥4.5:1 |
| `color.success` | 8.30:1 | 5.50:1 | 7.75:1 | 4.67:1 | 普通文字 ≥4.5:1 |
| `color.warning` | 11.29:1 | 5.93:1 | 10.54:1 | 5.03:1 | 普通文字 ≥4.5:1 |
| `color.danger` | 6.63:1 | 5.46:1 | 6.19:1 | 4.63:1 | 普通文字 ≥4.5:1 |
| `color.text.secondary` | 9.33:1 | 7.38:1 | 8.71:1 | 6.27:1 | 普通文字 ≥4.5:1 |
| `color.border.strong` / 相邻表面 | 3.33:1 | 3.11:1 | 同规范最差值 | 同规范最差值 | 关键非文本 ≥3:1 |

运行时必须在 dark/light、390/1440、normal/hover/focus/disabled、200% zoom 和 `forced-colors` 下读取 computed color。任何值低于文字 4.5:1 或关键非文本 3:1 时阻断，不得通过提高透明度或只改截图掩盖。

## 8. 键盘、焦点与读屏验收

- 状态 Badge 不进入 Tab 序；行展开按钮、复制 URL、筛选和操作按视觉顺序进入 Tab。
- 390 全屏 Drawer 打开后焦点进入标题/首控件，Tab 不逃出，Escape 关闭，焦点返回原行触发器；底部安全区不遮挡 44px 操作。
- 1440 sortable header 使用 `aria-sort`；展开按钮使用 `aria-expanded`/`aria-controls`；行与 Drawer 标题通过稳定 ID 关联。
- Focus-visible 固定为 `3px solid color.action`、2px offset，不能被 `overflow:hidden` 裁切。
- 状态变化使用 polite live region；错误详情、重试计数和禁用原因通过 `aria-describedby` 关联。
- 200% zoom 时状态 label、URL、原因和操作可重排，不截成无名称图标；只允许表格容器局部横滚。
- `prefers-reduced-motion: reduce` 关闭 loader 位移/旋转和 Drawer 位移动画，仍保留文字“校验中/已入队/采集中”。

## 9. 失败路径

1. **token/对比度失败：** 若真实 computed style 在任一主题低于文字 4.5:1 或关键非文本 3:1，状态实现阻断；最小修订只允许新增/调整语义 token 候选并重新测量，不把颜色或主观观感写成通过。
2. **machine key/alias 冲突：** data machine key 优先；未知、重复或 alias 被 API/DB 接受时 fail closed，显示“状态数据无效”，禁用 mutation，不另造 canonical state。
3. **390/1440 失败：** 390 出现页面横滚、目标小于 44px、Drawer 焦点丢失，或 1440 状态/操作混列、容器超过 1440px时，修订 UI 实现后重验；候选文档不能替代页面 PASS。
